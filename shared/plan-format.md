# 계획서 규격

`create-plan`, `implement`, `verify` 세 스킬이 주고받는 인계 문서의 형식이다. 사람이 읽는 문서인 동시에 스킬이 상태를 판별하는 근거이므로, 아래 표기는 고정한다. 표기가 어긋나면 읽는 쪽이 문서를 해석하지 못하고, 상태가 실제와 어긋난 채 커밋이 쌓인다.

## 파일 위치

기본 경로는 `docs/plans/YYYY-MM-DD-<주제>.md`다. 대상 프로젝트의 지시사항(`CLAUDE.md`, `AGENTS.md` 등)에 다른 규칙이 있으면 그쪽이 우선한다.

## 섹션 구성

다섯 섹션을 이 문자열, 이 순서로 둔다. 섹션을 추가하거나 이름을 바꾸지 않는다.

```
## 요약
## 상태
## 설계
## 구현 순서
## 테스트
```

문서 맨 위에 `# <제목>` 한 줄을 둘 수 있다. 각 섹션 안의 소제목(`###`)은 자유롭게 쓴다.

## 상태 표

`## 상태` 아래에 이 표를 둔다. 행 순서와 항목 이름은 고정이다.

```
| 항목 | 값 |
| --- | --- |
| 단계 | 계획 확정 |
| 마지막 갱신 | 2026-08-25 |
| 구현 진행률 | 3 / 13 |
```

| 항목 | 허용 값 |
| --- | --- |
| 단계 | `계획 확정`, `구현 중`, `구현 완료`, `완료` 중 하나 |
| 마지막 갱신 | `YYYY-MM-DD` 형식의 실제 날짜 |
| 구현 진행률 | `n / m` — n은 체크된 항목 수, m은 전체 항목 수 |

## 구현 순서 항목

`## 구현 순서` 아래에 체크박스 목록을 둔다. 번호는 1부터 빠짐없이 이어진다.

```
- [ ] **3. `create-plan` 골격 생성** — frontmatter와 섹션 목차를 넣는다. 완료 판정: 스킬 목록에 이름이 보인다.
```

항목을 끝내면 체크를 채우고, 바로 아래에 두 칸 들여쓴 기록 한 줄을 붙인다. 기록은 무엇이 왜 바뀌었는지를 남기는 자리이며, 나중에 `verify`가 사용자에게 제시한다.

```
- [x] **3. `create-plan` 골격 생성** — frontmatter와 섹션 목차를 넣는다. 완료 판정: 스킬 목록에 이름이 보인다.
  - 기록: description을 코드 변경 범위로 좁혔다. "계획"이라는 말이 일정 계획까지 끌어오기 때문이다.
```

기록 줄은 항목 수에 포함되지 않는다.

## 미해결 검토 표시

사용자가 결정하지 않은 채 AI가 초안을 채운 자리에는 `<!-- 사용자 검토 필요 -->`를 남긴다. 이 표시가 하나라도 남아 있으면 단계를 `계획 확정`으로 올릴 수 없다.

## 검사

```
python3 ${CLAUDE_PLUGIN_ROOT}/shared/check_plan_format.py <계획서 경로>
```

위반 항목을 줄 번호와 함께 출력하고, 하나라도 있으면 종료 코드 1을 반환한다. `implement`와 `verify`는 시작할 때 이 검사를 통과했는지 확인한다. 통과하지 못하면 추측해서 진행하지 않고 어긋난 지점을 사용자에게 알린다.

빈 양식 `plan-template.md`는 값 자리에 자리표시자가 들어 있어 이 검사를 통과하지 않는다. 양식이지 문서가 아니므로 정상이다.
