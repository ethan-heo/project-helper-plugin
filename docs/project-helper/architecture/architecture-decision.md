# 아키텍처 결정

## 목적과 문제

여러 계획이 따라야 할 구조·패턴·계약을 계획서마다 따로 정하면, 다음 계획은 앞선 결정을 찾아 참조할 수 없습니다. 이 영역은 구조 결정을 사용자와 하나씩 확정하고, 프로젝트마다 하나뿐인 아키텍처 문서에 결정 기록과 영역 설명으로 남깁니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 단일 문서 | 프로젝트마다 `<루트>/architecture/` 하나만 있습니다 |
| 형식 검증 | `validate-architecture.sh`를 통과합니다 |
| 이력 보존 | 결정을 지우지 않고 `대체됨` 상태와 대체 ID로 남깁니다 |
| 버전 일치 | 버전 표와 변경 이력 최신 행의 버전이 같습니다 |
| 해법 유보 | 목표·요구사항·가설을 나누기 전에 구성 요소를 제안하지 않습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 색인 | 버전 표와 영역 목록을 담은 `README.md` |
| 결정 기록 | `AD-NNN` 결정의 근거와 대체 관계 표 |
| 영역 파일 | 함께 책임지는 구성 요소를 일곱 절로 적은 파일 |
| 주 버전 | 기존 결정을 대체할 때 오르는 앞자리 |
| 부 버전 | 결정 추가나 서술 보완 때 오르는 뒷자리 |
| 가설 | 요청에 섞여 들어왔으나 검증하지 않은 해법 |

## 책임과 경계

`create-architecture`는 현재 구조 조사, 문제 재정의, 결정 목록 합의, 결정 확정, 시나리오 대조, 버전 반영과 커밋을 맡습니다. 결정 하나를 확정할 때마다 결정 기록과 관련 영역 파일을 함께 고칩니다.

필드 단위 스키마와 코드 구현은 계획 수립 영역이 맡고, 무엇을 왜 만들지는 요구사항 정의 영역이 맡습니다. 문서 루트와 표기는 공유 규칙 영역을 따릅니다.

## 실행 흐름

1. 문서 루트를 판정하고 `architecture/`가 있는지 확인합니다.
2. 문서가 없고 코드가 있으면 시스템 전체를 조사해 영역 목록과 결정 기록을 차례로 확인받고 1.0으로 확정합니다.
3. 요청을 목표·요구사항·가설로 나눠 확인한 뒤 결정 목록과 우선순위를 합의합니다.
4. 결정마다 사용자의 생각을 먼저 듣고, 선행 사례를 조사해 대안을 제시합니다. 사용자가 고른 내용을 결정 기록과 영역 파일에 반영합니다.
5. 실제 요청 두세 개로 실행 흐름을 끝까지 따라가, 흐름이 끊기거나 담당 구성 요소가 없는 단계를 찾습니다.
6. 검증 스크립트를 통과하면 버전과 변경 이력을 반영하고, 사용자 확인을 받아 아키텍처 디렉터리에서 바뀐 파일만 커밋합니다.
7. `create-plan`에서 이어서 실행했다면 그 스킬의 준비 단계로 돌아갑니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 버전 표의 `N.N` 버전 | 색인 | 계획 수립, 계획 실행 |
| 결정 ID와 상태 | 결정 기록 | 계획 수립 |
| 대체 ID와 도입 버전 | 결정 기록 | 계획 실행 |
| 원래 계획 요청 | `create-plan` | `create-architecture` |
| 형식 검증 스크립트 | 아키텍처 결정 | 계획 수립 |

확정 한 번에 가장 큰 변경을 기준으로 버전을 한 번 올립니다. 기존 결정을 대체하면 주 버전을, 결정을 추가하거나 서술만 보완하면 부 버전을 올립니다. 버전 표의 `N.N` 형식을 바꾸면 계획 실행 영역의 버전 대조가 동작하지 않으므로 두 영역을 함께 고칩니다. 따르는 결정은 AD-002, AD-011, AD-012, AD-013, AD-014입니다.

## 위험과 미해결 질문

- `create-plan`이 이 영역의 `SKILL.md`와 `validate-architecture.sh`를 경로로 직접 참조합니다. 스킬 디렉터리나 스크립트 위치가 바뀌면 계획 수립 영역의 참조도 함께 끊깁니다.
- 이 참조 방식은 AD-004에서 기각한 대안(다른 스킬의 내부 구조 참조)과 같은 형태입니다. 검증 스크립트를 `_shared/`로 옮길지는 아직 정하지 않았습니다.
- 사용자가 커밋을 거절하면 문서의 버전과 git 이력이 어긋날 수 있습니다.
