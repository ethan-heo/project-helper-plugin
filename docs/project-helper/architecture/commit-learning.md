# 커밋 학습

## 목적과 문제

커밋이 쌓이면 변경을 만든 사람도 무엇을 왜 바꿨는지 설명하기 어려워집니다. 이 영역은 지정한 커밋마다 학습 문서 한 편을 만들어, 코드를 다시 열지 않고도 그 변경을 설명할 수 있게 합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 일대일 대응 | 커밋 하나에 문서 한 편이 대응합니다 |
| 근거 한정 | 사실 서술이 diff, 커밋 메시지, 연결된 계획서에서만 나옵니다 |
| 사전 검사 | 입력 커밋이 하나라도 저장소에 없으면 문서를 만들지 않습니다 |
| 형식 검증 | `validate-commit-doc.sh`를 통과합니다 |
| 코드 불변 | 코드를 고치거나 품질을 평가하지 않습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 학습 문서 | 커밋 하나를 일곱 절로 설명하는 문서 |
| 서술 근거 | 커밋 diff, 커밋 메시지, 연결된 계획서 |
| 확인 필요 표시 | 근거를 찾지 못한 곳에 남기는 주석 |
| 범위 표기 | `A..B` 형식의 커밋 구간 지정 |

## 책임과 경계

`explain-commit`은 대상 수집과 정렬, 목록 확인, 커밋별 조사, 문서 생성과 검증, 결과 보고를 맡습니다. 문서는 그 커밋 시점의 기록이며, 최신 코드의 구조를 설명하지 않습니다.

코드 변경은 계획 실행 영역이 맡고, 이 영역은 커밋된 결과만 읽습니다. 계획서는 커밋 메시지에 적힌 항목 ID로만 찾으며, ID가 없으면 계획서를 근거에서 뺍니다.

## 실행 흐름

1. 해시 나열이나 범위 표기를 커밋 목록으로 펼치고, 저장소의 시간 순서로 정렬합니다.
2. 모든 입력이 저장소에 있는지 문서를 만들기 전에 검사합니다.
3. 대상 목록을 보여 주고, 이미 문서가 있는 커밋은 건너뜀으로 표시합니다.
4. 커밋마다 diff·메시지·연결된 계획서를 읽어 양식의 일곱 절을 채우고 검증합니다.
5. 만든 문서, 건너뛴 커밋, 실패한 커밋을 나눠 보고합니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 커밋 메시지의 항목 ID | 계획 실행 | 커밋 학습 |
| 기능 계획서 경로 | 계획 수립 | 커밋 학습 |
| `commits/` 경로 | 공유 규칙 | 커밋 학습 |

학습 문서는 커밋 시점의 기록이므로 코드나 양식이 바뀌어도 갱신하지 않습니다. 따르는 결정은 AD-001, AD-003, AD-006, AD-017, AD-020입니다.

## 위험과 미해결 질문

- 계획서는 `.gitignore`로 제외되므로, 계획서를 만든 환경이 아니면 링크 대상이 없어 계획서를 근거로 쓰지 못합니다.
- 학습 문서를 커밋할지 로컬에 둘지는 스킬이 정하지 않습니다. 이 저장소는 `commits/`를 `.gitignore`로 제외하고 있습니다.
