# 배포와 안내

## 목적과 문제

스킬을 고쳐도 설치본이 따라오지 않거나 두 런타임의 설치본이 서로 다르면, 사용자는 어느 스킬이 어떻게 동작할지 알 수 없습니다. 이 영역은 Claude Code와 Codex가 같은 저장소에서 같은 스킬을 설치하도록 매니페스트와 버전을 관리합니다. 사용 안내 문서도 현재 스킬 구성과 맞춥니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 두 런타임 지원 | 두 런타임이 같은 `skills/` 디렉터리를 설치합니다 |
| 버전 일치 | 두 `plugin.json`의 버전이 같습니다 |
| 설명 일치 | 마켓플레이스와 두 매니페스트의 설명이 현재 스킬 구성과 맞습니다 |
| 설치본 완결성 | 스킬이 참조하는 파일이 모두 설치본 안에 있습니다 |
| 안내 일치 | README와 튜토리얼의 스킬 목록이 실제 스킬과 같습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 마켓플레이스 | 플러그인 목록을 담은 `helpers` 저장소 등록 단위 |
| 매니페스트 | 런타임별 `plugin.json` |
| 플러그인 버전 | 매니페스트의 `MAJOR.MINOR.PATCH` 값 |

## 책임과 경계

`.claude-plugin/marketplace.json`은 마켓플레이스 이름과 플러그인의 경로·설명을 정합니다. `plugins/project-helper/` 아래의 `.claude-plugin/plugin.json`과 `.codex-plugin/plugin.json`은 런타임별 매니페스트이며, Codex 쪽은 `skills` 경로와 표시용 `interface`를 추가로 가집니다.

설치하면 저장소 전체가 클론되지만, 플러그인 캐시에는 `.claude-plugin`, `.codex-plugin`, `skills`만 복사됩니다. 그래서 스킬이 실행 중 읽는 문서는 `skills/` 안에 둡니다.

`README.md`와 `docs/project-helper/스킬_사용법_튜토리얼.md`는 설치·갱신 방법과 스킬 사용법을 안내합니다. 스킬의 동작은 각 스킬 영역이 정하고, 이 영역은 그 결과를 설명과 버전에 반영합니다.

## 실행 흐름

1. 스킬을 추가하거나 규칙을 바꾸면 변경 종류에 따라 부 버전이나 수 버전을 정합니다.
2. 두 `plugin.json`의 버전과 설명, `marketplace.json`의 설명을 함께 고칩니다.
3. 스킬 구성이 바뀌면 README의 스킬 표와 튜토리얼을 고칩니다.
4. 원격 저장소에 올리면 사용자는 마켓플레이스를 갱신한 뒤 플러그인을 다시 설치하고, 새로 시작한 세션부터 바뀐 스킬을 씁니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 플러그인 `source` 경로 | 마켓플레이스 | 두 런타임 |
| 플러그인 버전 | 매니페스트 | 두 런타임의 설치 절차 |
| 스킬 디렉터리 | 설치본 | 두 런타임의 스킬 로더 |
| `_shared/` 디렉터리 | 설치본 | 스킬 문서의 참조 |

스킬을 추가하면 부 버전을, 규칙을 개정하면 수 버전을 올리고, 두 매니페스트를 같은 값으로 맞춥니다. 따르는 결정은 AD-004, AD-007, AD-021, AD-022입니다.

## 위험과 미해결 질문

- 두 매니페스트의 버전과 설명을 따로 고치며 일치 여부를 검사하는 스크립트가 없으므로, 한쪽만 고치면 런타임마다 설명이 달라집니다.
- `_shared/`에 `SKILL.md`가 없어서 스킬 로더가 이 디렉터리를 건너뜁니다. 설치본 구성이 이 동작을 전제로 삼고 있습니다.
- 미해결 질문은 없습니다.
