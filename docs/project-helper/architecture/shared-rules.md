# 공유 규칙

## 목적과 문제

스킬마다 산출물 경로와 문체를 각자 정하면, 한 저장소 안에서도 산출물이 여러 곳에 흩어지고 문서마다 표기가 달라집니다. 이 영역은 문서 루트 판정 규칙과 산출물 표기 기준을 정본 하나씩으로 두어, 모든 스킬이 같은 위치에 같은 문체로 산출물을 남기게 합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 규칙 단일성 | 같은 규칙이 스킬 문서에 다시 적혀 있지 않습니다 |
| 설치본 포함 | 정본이 `skills/_shared/` 아래에 있습니다 |
| 저장소 우선 | 대상 저장소의 지시사항이나 표기 문서가 있으면 그것을 먼저 적용합니다 |
| 판정 재현성 | 같은 저장소에서 어느 스킬이 판정해도 같은 문서 루트가 나옵니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 탐색 순서 | 지시사항, `plans/`, `prds/`, `docs/` 순의 루트 판정 |
| 루트 기록 | 계획 최상위 문서에 남긴 판정 결과 |
| 표기 기준 | 문체·서술 길이·표 셀·어휘·용어·파일 이름 규칙 |

## 책임과 경계

`docs-root.md`는 문서 루트의 탐색 순서, 후보가 여럿일 때 좁히는 기준, 판정 결과를 남기는 방식을 정합니다. 루트 아래의 산출물별 하위 경로(`plans/`, `prds/`, `commits/`, `architecture/`)도 이 문서가 정하며, 각 디렉터리 안의 파일 형식은 해당 산출물을 만드는 스킬의 영역이 정합니다.

`writing-style.md`는 모든 산출물의 문체·표기·용어를 정합니다. 스킬의 참조 문서는 이 문서 위에 자기 산출물에만 해당하는 규칙을 더합니다.

PRD 두 스킬만 쓰는 `_shared/prd/`는 요구사항 정의 영역이 맡습니다. 스킬 문서 자체를 쓰는 기준은 저장소 규칙 영역이 맡습니다.

## 실행 흐름

1. 스킬이 준비 단계에서 `docs-root.md`를 읽습니다.
2. 계획 최상위 문서에 루트 기록이 있으면 탐색하지 않고 그 기록을 씁니다.
3. 기록이 없으면 지시사항, `plans/`, `prds/` 순서로 탐색하고, 후보가 없으면 `docs/`를 쓰고 사용자에게 알립니다.
4. 후보가 여럿이면 작업 대상의 가장 가까운 조상, 요구사항과 이름이 겹치는 후보 순으로 좁히고, 그래도 여럿이면 사용자에게 묻습니다.
5. 산출물을 쓸 때 대상 저장소의 표기 문서를 먼저 적용하고, 다루지 않는 항목만 `writing-style.md`로 채웁니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 문서 루트 경로 | 공유 규칙 | 산출물을 만드는 모든 스킬 |
| 산출물별 하위 경로 | 공유 규칙 | 해당 산출물의 스킬 |
| 루트 기록 | 계획 수립 | 계획 실행 |
| 표기 규칙 | 공유 규칙 | 산출물을 쓰는 모든 스킬 |

이 영역의 규칙이 바뀌면 플러그인 버전만 올리고(AD-022), 산출물에는 규칙의 버전을 기록하지 않습니다. 따르는 결정은 AD-003, AD-004, AD-005입니다.

## 위험과 미해결 질문

- `plans/`와 `prds/` 탐색은 저장소 루트에서 네 단계 깊이까지만 찾으므로, 더 깊은 곳에 산출물을 두는 저장소에서는 루트를 찾지 못하고 `docs/`로 판정합니다.
- 미해결 질문은 없습니다.
