# 저장소 규칙

## 목적과 문제

스킬 문서를 제각각 쓰면 스킬마다 켜질 때 읽는 분량과 구성이 달라집니다. 스킬 문서에 쓴 표현은 그대로 산출물로 옮겨 갑니다. 이 영역은 이 저장소에서 스킬 문서를 쓰고 고치는 기준과 커밋·병합 규칙, 스킬 발동 평가 사례를 관리합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 본문 분리 | 명령과 분기만 `SKILL.md`에 있습니다 |
| 근거 배치 | 근거와 예외가 `references/`에 있습니다 |
| 공유 참조 | 새 스킬이 `writing-style.md`를 참조합니다 |
| 발동 사례 | 발동해야 할 요청과 근접 요청이 함께 기록되어 있습니다 |
| 커밋 형식 | Conventional Commits와 스킬 이름 scope를 따릅니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 프로젝트 지시사항 | `AGENTS.md`와 `CLAUDE.md`의 저장소 전체 규칙 |
| 본문 | 스킬이 켜질 때 통째로 읽히는 `SKILL.md` |
| 참조 문서 | 필요한 시점에 절 단위로 읽는 `references/` 파일 |
| 발동 사례 | 특정 스킬이 켜져야 하는 요청 예시 |
| 근접 사례 | 비슷하지만 다른 스킬이 켜져야 하는 요청 |

## 책임과 경계

`AGENTS.md`와 `CLAUDE.md`는 커밋 규칙, 병합 규칙, 참조할 기준 문서를 지정합니다. 기준 문서는 세 편입니다. `docs/문서_작성_기준.md`는 문서 배치와 스킬 문서 구조를 정합니다. `docs/한국어_작성_규칙.md`는 한국어 문체와 용어·표기를 정합니다. `docs/프롬프트_작성_가이드.md`는 문서와 프롬프트를 만들고 고치는 방법을 다룹니다. `evals/`에는 발동 사례와 계획서 검증 시나리오가 있습니다.

산출물의 문체는 공유 규칙 영역이 맡습니다. 이 영역은 스킬 문서 자체와 저장소 운영 규칙만 다룹니다.

## 실행 흐름

1. 스킬을 만들거나 고칠 때 `문서_작성_기준.md`로 본문과 참조 문서의 배치를 정합니다.
2. 산출물 문체에 관한 규칙은 `writing-style.md`에 두고, 스킬 문서는 그 문서를 참조만 합니다.
3. 스킬의 description을 바꾸면 `evals/trigger-eval.json`의 사례로 오발동이 없는지 확인합니다.
4. 구현 항목마다 스킬 이름을 scope로 삼아 커밋하고, `main`에는 fast-forward를 우선해 병합합니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 스킬 문서 구조 기준 | 저장소 규칙 | 모든 스킬 영역 |
| 발동·근접 사례 | 저장소 규칙 | 스킬 description 개정 |
| 커밋 규칙 | 프로젝트 지시사항 | 계획 실행 |

이 영역의 문서는 설치본에 포함되지 않으므로 플러그인 버전에 영향을 주지 않습니다. 따르는 결정은 AD-005, AD-006, AD-007, AD-008, AD-023입니다.

## 위험과 미해결 질문

- `AGENTS.md`와 `CLAUDE.md`의 저장소 성격 절은 스킬을 두 개로 설명하지만, 실제 스킬은 여섯 개입니다.
- 두 지시사항 파일이 같은 내용을 따로 가지므로, 한쪽만 고치면 서로 어긋납니다.
- `evals/plan-validation.md`의 정상 계획서 사례는 `계획 확정` 단계를 쓰지만, 검증 스크립트가 받는 단계 값은 `계획 완료`입니다.
- 발동 사례는 자동으로 실행되지 않고, 플러그인을 설치한 세션에서 직접 질의를 던져 측정합니다.
