# project-helper 스킬 사용법 튜토리얼

브라우저에서 도는 Todo 리스트를 소재로, `project-helper`의 스킬 다섯 개를 부르는 순서와 각 스킬이 남기는 산출물을 따라갑니다.

## 0장. 이 문서를 읽는 방법

### 이 문서가 다루는 것

`project-helper`의 스킬 다섯 개를 부르는 순서와, 각 스킬이 남기는 산출물의 모양을 보여 줍니다. 소재는 브라우저 한 화면에서 도는 Todo 리스트입니다.

Todo 리스트 코드는 만들지 않습니다. 4장과 5장은 실행 기록 대신 구현이 어떤 순서로 진행되는지를 표로 서술합니다.

### 장 구성

| 장 | 스킬 | 남는 산출물 |
| --- | --- | --- |
| 1 | `create-prd` | PRD 한 편 |
| 2 | `create-sub-prd` | 하위 PRD 두 편 |
| 3 | `create-plan` | 계획서 네 파일 |
| 4 | `impl-plan` | 커밋과 갱신된 계획서 |
| 5 | `explain-commit` | 커밋별 학습 문서 |

1장부터 3장까지는 아래 다섯 절을 같은 순서로 둡니다.

- 언제 쓰는가
- 부르는 방법
- 대화 흐름
- 만들어진 산출물
- 다음 단계

4장과 5장은 실행 결과가 없으므로 `대화 흐름` 자리에 진행 표가 들어갑니다.

### 산출물을 확인하는 자리

각 장의 `만들어진 산출물` 절에서 부록 링크를 답니다. 전문은 문서 끝의 [부록 A](#부록-a-todo-리스트-prd-전문), [부록 B](#부록-b-하위-prd-전문), [부록 C](#부록-c-todo-리스트-구현-계획서-전문)에 모여 있습니다.

### 시작하기 전에

플러그인이 설치되어 있어야 스킬을 부를 수 있습니다.

```
/plugin marketplace add ethan-heo/project-helper-plugin
/plugin install project-helper@helpers
```

설치 후에는 새 대화부터 스킬이 잡힙니다. `claude plugin list`로 설치 결과를 확인합니다.

### 다섯 스킬을 언제 쓰는가

| 지금 상태 | 부를 스킬 |
| --- | --- |
| 무엇을 만들지 정하지 못했다 | `create-prd` |
| PRD가 커서 요구사항이 뭉뚱그려져 있다 | `create-sub-prd` |
| 무엇을 만들지는 정했고 방법을 정해야 한다 | `create-plan` |
| 계획서가 `계획 완료` 상태다 | `impl-plan` |
| 커밋은 쌓였는데 내용이 기억나지 않는다 | `explain-commit` |

## 1장. create-prd — 무엇을 만들지 정합니다

## 2장. create-sub-prd — 요구사항을 묶음으로 가릅니다

## 3장. create-plan — 어떻게 만들지 정합니다

## 4장. impl-plan — 계획서대로 구현합니다

## 5장. explain-commit — 남은 커밋을 학습 문서로 정리합니다

## 부록 A. Todo 리스트 PRD 전문

1장의 대화로 만들어진 `docs/plans` 바깥의 PRD 한 편입니다. 2장에서 분해한 뒤의 저장 경로는 `docs/prds/2026-09-04-todo-list/README.md`입니다.

```markdown
# Todo 리스트

**마지막 갱신** — 2026-09-04

## 한 줄 요약

브라우저 하나만 열면 오늘 할 일을 적고 지울 수 있는 단일 화면 Todo 리스트다.

## 배경과 문제

**현재 상황** — 할 일을 메모 앱이나 종이에 적고, 끝난 항목은 줄을 그어 지운다.

**문제** — 끝난 항목과 남은 항목이 한 화면에 섞여 남은 일의 개수를 바로 알 수 없다.

**지금인 이유** — 항목이 쌓일수록 훑는 시간이 늘어난다. 지금 정리하지 않으면 목록을 새로 만드는 일이 반복된다.

## 목적과 목표

**목적** — 오늘 할 일을 한 화면에서 적고, 끝냈는지 표시하고, 지울 수 있게 한다.

| 목표 | 성공 판정 기준 |
| --- | --- |
| 항목을 적는 데 걸리는 손이 적다 | 입력 후 Enter 한 번으로 목록에 붙는다 |
| 남은 일의 개수를 바로 안다 | 화면 위에 미완료 개수가 보인다 |
| 브라우저를 닫아도 목록이 남는다 | 새로고침 후 항목이 그대로 있다 |

## 사용자와 사용 상황

| 사용자 | 언제 쓰는가 | 지금은 어떻게 하는가 |
| --- | --- | --- |
| 혼자 일하는 사람 | 하루를 시작하며 할 일을 적을 때 | 메모 앱에 줄글로 적는다 |
| 같은 사람 | 일을 하나 끝냈을 때 | 줄을 긋거나 지운다 |

## 요구사항

| ID | 구분 | 요구사항 | 충족 판정 | 하위 PRD |
| --- | --- | --- | --- | --- |
| R1 | 필수 | 항목을 입력해 목록에 추가한다 | 빈 문자열은 추가되지 않는다 | [R1-항목관리](R1-항목관리.md) |
| R2 | 필수 | 항목의 완료 여부를 표시한다 | 완료 항목에 취소선이 보인다 | [R1-항목관리](R1-항목관리.md) |
| R3 | 필수 | 항목을 목록에서 지운다 | 지운 항목이 새로고침 후에도 없다 | [R1-항목관리](R1-항목관리.md) |
| R4 | 필수 | 목록을 브라우저에 저장한다 | 새로고침 후 목록이 그대로다 | [R4-저장과현황](R4-저장과현황.md) |
| R5 | 필수 | 미완료 항목의 개수를 보여 준다 | 완료 표시와 동시에 숫자가 바뀐다 | [R4-저장과현황](R4-저장과현황.md) |
| R6 | 선택 | 완료 항목만 한 번에 지운다 | 버튼 한 번으로 완료 항목이 사라진다 | [R1-항목관리](R1-항목관리.md) |

## 범위 밖

| 하지 않는 것 | 이유 |
| --- | --- |
| 서버 저장과 계정 | 한 사람이 한 브라우저에서 쓰는 것이 전제다 |
| 마감일과 알림 | 오늘 할 일만 다루므로 날짜 개념이 필요 없다 |
| 항목 정렬과 검색 | 한 화면에 담기는 분량을 전제로 한다 |

## 제약과 전제

| --- | --- |
| 기술 | 빌드 도구 없이 정적 파일 세 개로 동작한다 |
| 일정 | 하루 안에 끝나는 분량으로 한정한다 |
| 조직 | 혼자 만들고 혼자 쓴다 |
| 전제 | 최신 브라우저의 로컬 저장소를 쓸 수 있다 |

해당 없음
```

```markdown
| 삭제가 항목 줄에서 끝난다 | 항목 줄의 버튼 한 번으로 지워진다 |

| R1-2 | 필수 | 공백만 있는 입력을 막는다 | 목록 길이가 늘지 않는다 |
| R1-3 | 필수 | 항목의 완료 여부를 바꾼다 | 취소선이 붙거나 사라진다 |
```

## 부록 C. Todo 리스트 구현 계획서 전문

3장의 대화로 만들어진 계획서입니다. 저장 경로는 `docs/plans/2026-09-04-todo-list/`이며, 아래 네 파일로 이루어집니다.

```
docs/plans/2026-09-04-todo-list/
├── README.md          최상위 — 도메인 목록과 선행 관계
└── TODO/
    ├── README.md      도메인 — 기능 목록
    ├── item.md        기능 계획서 — 항목 관리
    └── store.md       기능 계획서 — 저장과 현황
```

### C-1. 최상위 `README.md`

```markdown
# Todo 리스트

## 요약

**목표** — 브라우저 한 화면에서 할 일을 적고 완료 표시하고 지우는 Todo 리스트를 만든다.

**배경** — 메모 앱에서는 끝난 항목과 남은 항목이 섞여 남은 일의 개수를 바로 알 수 없다.

**변경점** — 정적 파일 세 개가 새로 생긴다. 항목 조작이 먼저 동작하고, 그 위에 저장과 미완료 개수 표시가 붙는다.

목록 상태는 배열 하나로 다루고, 화면은 그 배열을 다시 그리는 방식으로 갱신한다. 상태를 여러 곳에 두면 저장분과 화면이 어긋난다.

### 문서 루트

| 항목 | 값 |
| --- | --- |
| 문서 루트 | `docs/` |
| 판정 근거 | 사용자 선택 |

### ID 용어 표

| 도메인 | 뜻 |
| --- | --- |
| TODO | 할 일 목록 화면 전체 |

### 선행 관계

| 대상 ID | 선행 ID |
| --- | --- |
| TODO-STORE-001 | TODO-ITEM-004 |

### 예외 상황

| 예외 조건 | 할 일 |
| --- | --- |
| 로컬 저장소를 쓸 수 없다 | 저장 없이 화면만 동작시킨다 |

## 구현 순서

1. **TODO** 할 일 목록 — 항목 조작과 저장을 한 화면에 만든다

## 테스트

| ID | 입력 상황 | 기대 동작 | 실행 시점 |
| --- | --- | --- | --- |
| S1 | 항목을 넣고 새로고침한다 | 목록과 완료 표시가 유지된다 | TODO-STORE-004 이후 |
```
