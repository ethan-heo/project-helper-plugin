# project-helper 스킬 사용법 튜토리얼

브라우저에서 도는 Todo 리스트를 소재로, `project-helper`의 스킬 다섯 개를 부르는 순서와 각 스킬이 남기는 산출물을 따라갑니다.

## 0장. 이 문서를 읽는 방법

## 1장. create-prd — 무엇을 만들지 정합니다

## 2장. create-sub-prd — 요구사항을 묶음으로 가릅니다

## 3장. create-plan — 어떻게 만들지 정합니다

## 4장. impl-plan — 계획서대로 구현합니다

## 5장. explain-commit — 남은 커밋을 학습 문서로 정리합니다

## 부록 A. Todo 리스트 PRD 전문

1장의 대화로 만들어진 `docs/plans` 바깥의 PRD 한 편입니다. 2장에서 분해한 뒤의 저장 경로는 `docs/prds/2026-09-04-todo-list/README.md`입니다.

```markdown
# Todo 리스트

**마지막 갱신** — 2026-09-04

## 한 줄 요약

브라우저 하나만 열면 오늘 할 일을 적고 지울 수 있는 단일 화면 Todo 리스트다.

## 배경과 문제

**현재 상황** — 할 일을 메모 앱이나 종이에 적고, 끝난 항목은 줄을 그어 지운다.

**문제** — 끝난 항목과 남은 항목이 한 화면에 섞여 남은 일의 개수를 바로 알 수 없다.

**지금인 이유** — 항목이 쌓일수록 훑는 시간이 늘어난다. 지금 정리하지 않으면 목록을 새로 만드는 일이 반복된다.

## 목적과 목표

**목적** — 오늘 할 일을 한 화면에서 적고, 끝냈는지 표시하고, 지울 수 있게 한다.

| 목표 | 성공 판정 기준 |
| --- | --- |
| 항목을 적는 데 걸리는 손이 적다 | 입력 후 Enter 한 번으로 목록에 붙는다 |
| 남은 일의 개수를 바로 안다 | 화면 위에 미완료 개수가 보인다 |
| 브라우저를 닫아도 목록이 남는다 | 새로고침 후 항목이 그대로 있다 |

## 사용자와 사용 상황

| 사용자 | 언제 쓰는가 | 지금은 어떻게 하는가 |
| --- | --- | --- |
| 혼자 일하는 사람 | 하루를 시작하며 할 일을 적을 때 | 메모 앱에 줄글로 적는다 |
| 같은 사람 | 일을 하나 끝냈을 때 | 줄을 긋거나 지운다 |

## 요구사항

| ID | 구분 | 요구사항 | 충족 판정 | 하위 PRD |
| --- | --- | --- | --- | --- |
| R1 | 필수 | 항목을 입력해 목록에 추가한다 | 빈 문자열은 추가되지 않는다 | [R1-항목관리](R1-항목관리.md) |
| R2 | 필수 | 항목의 완료 여부를 표시한다 | 완료 항목에 취소선이 보인다 | [R1-항목관리](R1-항목관리.md) |
| R3 | 필수 | 항목을 목록에서 지운다 | 지운 항목이 새로고침 후에도 없다 | [R1-항목관리](R1-항목관리.md) |
| R4 | 필수 | 목록을 브라우저에 저장한다 | 새로고침 후 목록이 그대로다 | [R4-저장과현황](R4-저장과현황.md) |
| R5 | 필수 | 미완료 항목의 개수를 보여 준다 | 완료 표시와 동시에 숫자가 바뀐다 | [R4-저장과현황](R4-저장과현황.md) |
| R6 | 선택 | 완료 항목만 한 번에 지운다 | 버튼 한 번으로 완료 항목이 사라진다 | [R1-항목관리](R1-항목관리.md) |

## 범위 밖

| 하지 않는 것 | 이유 |
| --- | --- |
| 서버 저장과 계정 | 한 사람이 한 브라우저에서 쓰는 것이 전제다 |
| 마감일과 알림 | 오늘 할 일만 다루므로 날짜 개념이 필요 없다 |
| 항목 정렬과 검색 | 한 화면에 담기는 분량을 전제로 한다 |

## 제약과 전제

| 구분 | 내용 |
| --- | --- |
| 기술 | 빌드 도구 없이 정적 파일 세 개로 동작한다 |
| 일정 | 하루 안에 끝나는 분량으로 한정한다 |
| 조직 | 혼자 만들고 혼자 쓴다 |
| 전제 | 최신 브라우저의 로컬 저장소를 쓸 수 있다 |
```

### B-1. R1-항목관리

저장 경로는 `docs/prds/2026-09-04-todo-list/R1-항목관리.md`입니다.

```markdown
# 항목 관리

**마지막 갱신** — 2026-09-04

**상위 PRD** — [Todo 리스트](README.md) · 담당 요구사항 R1, R2, R3, R6

## 한 줄 요약

한 화면에서 할 일을 적고, 끝냈다고 표시하고, 지우는 조작을 담당한다.

## 배경과 문제

**현재 상황** — 메모 앱에서는 항목을 지우려면 줄을 선택해 삭제해야 한다.

**문제** — 조작이 목록 밖의 메뉴에 흩어져 있어 항목마다 손이 여러 번 간다.

**지금인 이유** — 조작 방식을 먼저 정해야 저장할 데이터의 모양이 정해진다.

## 목적과 목표

**목적** — 항목 하나에 필요한 조작을 그 항목 줄 안에서 끝낸다.

| 목표 | 성공 판정 기준 |
| --- | --- |
| 추가에 손이 적게 든다 | 입력창에서 Enter 한 번으로 끝난다 |
| 완료 표시가 눈에 보인다 | 표시한 항목에 취소선이 남는다 |
| 삭제가 항목 줄에서 끝난다 | 항목 줄의 버튼 한 번으로 지워진다 |

## 사용자와 사용 상황

| 사용자 | 언제 쓰는가 | 지금은 어떻게 하는가 |
| --- | --- | --- |
| 혼자 일하는 사람 | 할 일을 떠올렸을 때 | 메모 앱에 줄을 보탠다 |
| 같은 사람 | 일을 끝냈을 때 | 줄을 긋거나 지운다 |

## 요구사항

| ID | 구분 | 요구사항 | 충족 판정 |
| --- | --- | --- | --- |
| R1-1 | 필수 | 입력창의 값을 항목으로 추가한다 | 추가 후 입력창이 빈다 |
| R1-2 | 필수 | 공백만 있는 입력을 막는다 | 목록 길이가 늘지 않는다 |
| R1-3 | 필수 | 항목의 완료 여부를 바꾼다 | 취소선이 붙거나 사라진다 |
| R1-4 | 필수 | 항목 하나를 지운다 | 그 줄이 목록에서 사라진다 |
| R1-5 | 선택 | 완료 항목을 한 번에 지운다 | 미완료 항목만 남는다 |

## 범위 밖

| 하지 않는 것 | 이유 |
| --- | --- |
| 항목 내용 수정 | 지우고 다시 적는 편이 손이 덜 간다 |
| 실행 취소 | 되돌릴 이력을 담을 자리가 없다 |

## 제약과 전제

| 구분 | 내용 |
| --- | --- |
| 기술 | 목록 상태를 배열 하나로 다룬다 |
| 일정 | 저장 기능보다 먼저 끝낸다 |
| 조직 | 혼자 만들고 혼자 쓴다 |
| 전제 | 항목 수가 한 화면에 담긴다 |

## 미해결 질문

해당 없음
```

### B-2. R4-저장과현황

```markdown
# 저장과 현황

**마지막 갱신** — 2026-09-04

**상위 PRD** — [Todo 리스트](README.md) · 담당 요구사항 R4, R5

## 한 줄 요약

목록을 브라우저에 남기고, 남은 일의 개수를 화면 위에 보여 준다.

## 배경과 문제

**현재 상황** — 브라우저를 닫으면 화면에 있던 목록이 사라진다.

**문제** — 목록을 매번 다시 적어야 해서 도구를 계속 쓰지 못한다.

**지금인 이유** — 저장이 없으면 앞의 조작 기능도 쓸모를 얻지 못한다.

## 목적과 목표

**목적** — 목록이 브라우저에 남고, 남은 일의 개수가 항상 맞는다.

| 목표 | 성공 판정 기준 |
| --- | --- |
| 목록이 유지된다 | 새로고침 후 항목과 완료 표시가 같다 |
| 개수가 실시간으로 맞는다 | 완료 표시 즉시 숫자가 바뀐다 |

## 사용자와 사용 상황

| 사용자 | 언제 쓰는가 | 지금은 어떻게 하는가 |
| --- | --- | --- |
| 혼자 일하는 사람 | 다음 날 화면을 다시 열 때 | 메모 앱에서 이어서 본다 |
| 같은 사람 | 남은 일을 셀 때 | 줄을 눈으로 센다 |

## 요구사항

| ID | 구분 | 요구사항 | 충족 판정 |
| --- | --- | --- | --- |
| R4-1 | 필수 | 목록이 바뀔 때마다 저장한다 | 새로고침 후 상태가 같다 |
| R4-2 | 필수 | 화면을 열 때 저장분을 읽는다 | 첫 화면에 이전 목록이 보인다 |
| R4-3 | 필수 | 저장분이 깨지면 빈 목록으로 연다 | 오류 화면 없이 화면이 뜬다 |
| R4-4 | 필수 | 미완료 개수를 화면 위에 보여 준다 | 표시 변경 즉시 숫자가 바뀐다 |

## 범위 밖

| 하지 않는 것 | 이유 |
| --- | --- |
| 서버 동기화 | 한 브라우저에서만 쓰는 것이 전제다 |
| 저장 이력 보관 | 되돌리기를 다루지 않는다 |

| --- | --- |

| 일정 | 항목 관리 기능 이후에 붙인다 |
| 조직 | 혼자 만들고 혼자 쓴다 |
| 전제 | 저장 용량이 목록 크기에 충분하다 |
```
