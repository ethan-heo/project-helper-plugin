# 문서_루트_판정(docs-root) — API 명세

## 엔드포인트 목록

HTTP 엔드포인트는 없다. 이 도메인의 인터페이스는 네 스킬이 공용 참조 문서를 읽는 지점이다.

| 호출자 | 읽는 시점 | 참조 경로 | 판정 결과의 쓰임 |
| --- | --- | --- | --- |
| `create-plan` | 준비 절차 4번 | `../_shared/docs-root.md` | `<루트>/plans/`를 계획서 경로로 삼고 `.gitignore` 등록을 확인한다 |
| `create-prd` | 준비 절차 2번 | `../_shared/docs-root.md` | `<루트>/prds/`를 보관 경로로 삼는다 |
| `create-docs` | 배치 단계 | `../../_shared/docs-root.md` | `<루트>`를 개발 문서의 최상위로 삼는다 |
| `impl-plan` | 재개·준비 단계 | `../_shared/docs-root.md` | `<루트>/plans/`에서 계획서 후보를 찾는다 |

`create-docs`의 참조 경로가 한 단계 더 깊은 이유는, 그 스킬에서 읽는 주체가 `SKILL.md`가 아니라 `references/structure.md`이기 때문이다.

## 요청과 응답

판정에 들어가는 입력과 나오는 출력은 다음과 같다.

| 구분 | 항목 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 입력 | 프로젝트 지시사항의 경로 지정 | path | 아니오 | `CLAUDE.md`나 `AGENTS.md`에 적힌 값 |
| 입력 | 작업 대상 파일 경로 | path | 아니오 | 조상 기준에 쓴다. `create-prd`에는 없다 |
| 입력 | 요구사항에 등장한 대상 이름 | string | 아니오 | 이름 일치 기준에 쓴다 |
| 입력 | 계획 최상위 문서의 루트 기록 | path | 아니오 | 있으면 탐색을 건너뛴다 |
| 출력 | 문서 루트 | path | 예 | 저장소 루트 기준 상대 경로 |
| 출력 | 판정 근거 | string | 예 | 어느 단계에서 결정되었는지 |

판정 결과의 예시다.

```
문서 루트: docs/project-helper
판정 근거: 개발 문서 위치 (글로벌_아키텍처_가이드.md와 도메인_문서/가 함께 있음)
계획서 경로: docs/project-helper/plans/
```

후보가 여럿이어서 사용자에게 물을 때는 번호 매김 목록으로 제시한다.

```
문서 루트 후보가 둘입니다. 어느 쪽을 쓸까요?

1. packages/api/docs
2. docs
```

## 에러 코드

| 상황 | 반응 |
| --- | --- |
| 지시사항의 경로가 존재하지 않음 | 탐색으로 넘어가지 않고 경로를 확인받는다 |
| 기록된 루트가 저장소에 없음 | 진행을 멈추고 사용자에게 알린다 |
| 정한 루트에 다른 문서 체계가 있음 | 덮어쓰지 않고 경로를 확인받는다 |
| 후보 없음 | `docs/`로 정하고 그 사실을 알린다. 디렉터리가 없으면 만든다 |

검증 스크립트가 내는 오류 문구는 [`공통_에러_코드.md`](../../공통_인프라_및_컨벤션/공통_에러_코드.md)에 있다. 이 도메인은 별도의 오류 문구를 정의하지 않는다.

## 이벤트 메시징

해당 없음. 스킬 사이에 메시지를 주고받는 경로가 없으며, 판정 결과는 계획 최상위 문서의 기록으로만 전달된다.
