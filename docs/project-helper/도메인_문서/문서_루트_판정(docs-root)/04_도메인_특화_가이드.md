# 문서_루트_판정(docs-root) — 도메인 특화 가이드

## 외부 의존성

| 대상 | 종류 | 용도 |
| --- | --- | --- |
| `find` | 셸 명령 | 탐색 2번과 3번에서 표지 파일과 계획 디렉터리를 찾는다 |
| `grep` | 셸 명령 | 프로젝트 지시사항에서 경로 지정을 확인한다 |

런타임 의존성은 없다. 판정은 스킬이 참조 문서를 읽고 저장소를 조사하는 방식으로 이루어진다.

## 설정

| 항목 | 출처 | 비고 |
| --- | --- | --- |
| 문서 루트 경로 | 프로젝트 지시사항(`CLAUDE.md`, `AGENTS.md`) | 적어 두면 탐색 1번에서 끝난다. 지정이 없어도 동작한다 |
| 루트 기록 | 계획 최상위 문서의 `문서 루트` 절 | `create-plan`이 남기고 `impl-plan`과 `create-docs`가 읽는다 |
| 탐색 깊이 | `_shared/docs-root.md` | 저장소 루트에서 네 단계 |
| 탐색 제외 대상 | `_shared/docs-root.md` | `.git`, `node_modules`, 빌드 산출물 |

## 핵심 테스트 시나리오

| ID | 상황 | 기대 동작 |
| --- | --- | --- |
| S1 | 지시사항에 경로 지정이 없고 개발 문서가 `docs/project-helper/`에 있다 | 탐색 2번에서 `docs/project-helper`를 문서 루트로 판정한다 |
| S2 | `docs/`만 있고 개발 문서도 계획서도 없다 | 탐색 4번으로 내려가 `docs/`를 쓰고 그 사실을 알린다 |
| S3 | 문서 루트가 두 곳이고 한쪽 패키지의 코드를 고치는 중이다 | 조상 기준으로 그 패키지 쪽 루트를 골라 사용자에게 묻지 않는다 |
| S4 | 계획 최상위 문서에 루트 기록이 없는 옛 계획서로 `impl-plan`을 실행한다 | 멈추지 않고 탐색으로 판정한 뒤 결과를 알린다 |
| S5 | 지시사항에 적힌 경로가 저장소에 없다 | 탐색으로 넘어가지 않고 사용자에게 경로를 확인받는다 |

## 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 개발 문서가 있는데도 "문서 없음"으로 판정한다 | 표지 파일 두 개 중 하나가 없거나 이름이 다르다 | `글로벌_아키텍처_가이드.md`와 `도메인_문서/`가 같은 디렉터리에 있는지 확인한다 |
| 산출물이 서로 다른 위치에 흩어진다 | 계획 최상위 문서에 루트 기록이 없어 스킬마다 다시 판정했다 | 기록을 추가하거나 프로젝트 지시사항에 경로를 명시한다 |
| 후보 선택을 매번 묻는다 | 문서 루트가 여럿이고 이름으로도 갈리지 않는다 | 고른 경로를 프로젝트 지시사항에 적어 둔다. 다음부터 탐색 1번에서 끝난다 |
| 설치된 스킬이 판정 규칙을 읽지 못한다 | `_shared/`가 설치본에 복사되지 않았다 | 그 디렉터리가 `plugins/project-helper/skills/` 아래에 있는지 확인하고 재설치한다 |
| 빌드 산출물 안의 문서가 루트로 잡힌다 | 탐색 제외 대상에 그 디렉터리가 없다 | 제외 목록에 추가하거나 프로젝트 지시사항에 경로를 명시한다 |
