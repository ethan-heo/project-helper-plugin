# 계획_관리(plan-management) — 도메인 개요

## 도메인 정의

계획서라는 산출물 자체의 형식과 수명을 정하는 영역이다. 세 층 문서 계층, 상태 전이, ID와 항목 표기, 그리고 이미 진행 중이거나 완료된 계획에 추가 작업이 들어왔을 때의 반영 기준을 담당한다.

이 규칙의 정본은 `create-plan`의 `references/documents/` 아래에 있지만, 규칙을 소비하는 쪽은 `create-plan`과 `impl-plan` 양쪽이다. 두 스킬은 서로의 파일을 읽지 않고 같은 계획서 규격을 전제로만 삼는다. 여러 스킬이 함께 읽어야 하는 규칙은 `skills/_shared/`에 두며, 계획서 규격은 아직 그 방식으로 옮기지 않았다.

### 책임 범위

| 구분 | 내용 |
| --- | --- |
| 담당한다 | 최상위·도메인·기능 세 층의 책임 구분, 상태 값과 전이 조건, ID·체크박스·진행률 표기, 초안에서 구조로의 이전, 추가 작업의 반영 판정 |
| 담당하지 않는다 | 계획 내용을 좁히는 질의응답(계획_작성), 계획서의 실행과 커밋(impl-plan), 계획서 보관 경로의 결정(문서_루트_판정) |

## 유비쿼터스 용어 사전

| 용어 | 영문 표기 | 정의 |
| --- | --- | --- |
| 최상위 문서 | `<계획 디렉터리>/README.md` | 도메인 목록과 선행 관계, ID 용어 표를 담는 층 |
| 도메인 문서 | `<도메인>/README.md` | 기능 목록을 담는 층 |
| 기능 계획서 | `<도메인>/<기능>.md` | 상태와 구현 항목을 담는 층. 상태를 관리하는 유일한 층이다 |
| 단계 | 단계 | `초안 작성`, `계획 완료`, `완료` 세 값 중 하나 |
| 선행 관계 | prerequisite | 대상 ID가 시작되기 전에 닫혀 있어야 하는 다른 구현 항목의 ID |
| 추후 작업 | 추후 작업 | 현재 계획과 연관되지 않은 요청을 기록해 두는 절 |
| 기록 줄 | `- 기록:` | 구현 항목을 마칠 때 계획서에 남기는 실행 결과 한 줄 |

## 핵심 비즈니스 규칙

1. 계획서는 규모와 무관하게 최상위·도메인·기능 세 층으로 완성한다. 기능이 하나뿐이어도 층을 생략하지 않는다.
2. 각 층의 책임은 겹치지 않는다. 최상위는 도메인 목록과 선행 관계, 도메인은 기능 목록, 기능 계획서는 구현 항목과 상태를 관리한다.
3. 상태는 기능 계획서에서만 관리한다. 최상위와 도메인 문서에는 상태 표를 두지 않는다.
4. 단계는 `초안 작성 → 계획 완료 → 완료` 순서로만 나아간다. `계획 완료`는 구조 이전과 인계 점검이 끝난 뒤에 붙이고, `완료`는 모든 구현 항목이 체크되고 대응하는 테스트가 통과한 뒤에 붙인다.
5. 구현 항목 ID는 `DOMAIN-FEATURE-001` 세 조각 형식이다. 앞 두 조각으로 기능 계획서를 역추적할 수 있어야 한다.
6. 구현 항목은 번호 매김 목록으로 쓴다. 기존 계획서의 `- [ ]` 표기도 검증에서 허용한다.
7. 진행률의 전체 수는 구현 항목 수와 일치해야 한다.
8. 추가 작업이 들어오면 먼저 연관성을 판단한다. 판단 대상은 현재 계획의 기능과 사용자 흐름이다. 연관되면 상태가 `진행 중`이거나 `완료`여도 기존 계획서의 설계·구현 순서·테스트를 고치고 단계를 `계획 완료`로 되돌린다. 연관되지 않으면 `추후 작업` 절에 기록만 남긴다.
9. 계획서는 로컬에 두고 커밋하지 않는다. 보관 경로를 `.gitignore`에 등록한다.
10. 계획서에서 `impl-plan`이 고치는 부분은 상태 표, 체크박스, 마지막 갱신, 기록 줄뿐이다.

### 예외 케이스

| 상황 | 처리 |
| --- | --- |
| 검증 지점이 하나뿐이다 | 기능도 하나로 두되 세 층 구조는 유지한다 |
| 날짜 디렉터리 바로 아래에 문서가 있다 | 정식 기능 계획서로 인정하지 않고 구조 이전 절차로 돌려보낸다 |
| 구조 이전 중 분류할 수 없는 문장이 있다 | 임의로 옮기지 않고 검토 대상으로 남긴다 |
| 여러 문서에 걸치는 내용이다 | 원문을 복제하지 않고 참조 경로만 적는다 |
| 완료된 계획에 연관 작업이 들어왔다 | 새 계획서를 만들지 않고 기존 계획서를 갱신한 뒤 단계를 `계획 완료`로 되돌린다 |
