# 계획_관리(plan-management) — API 명세

이 도메인은 사용자가 직접 호출하는 명령을 갖지 않는다. 두 스킬이 계획서를 다룰 때 지켜야 할 형식과 검증 수단이 이 도메인의 인터페이스다.

## 엔드포인트 목록

| 메서드 | 경로 | 설명 | 인증 |
| --- | --- | --- | --- |
| `실행` | `create-plan/scripts/validate-plan.sh <계획 디렉터리>` | 계획 디렉터리 전체의 구조·상태·항목 형식을 검사한다 | 불필요 |
| `실행` | `impl-plan/scripts/validate-plan.sh <기능 계획서>` | 기능 계획서 한 편이 구현을 시작할 수 있는 상태인지 검사한다 | 불필요 |
| `읽기` | 최상위 문서의 선행 관계 표 | `impl-plan`이 진행 가능 여부를 판정할 때 읽는다. 쓰지 않는다 | 불필요 |

두 스크립트는 이름이 같지만 검사 단위가 다르다. 앞의 것은 디렉터리를, 뒤의 것은 파일 하나를 받는다.

## `create-plan/scripts/validate-plan.sh <계획 디렉터리>`

계획을 확정하기 직전에 실행한다. 모든 도메인의 모든 기능 계획서를 훑는다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 인자 1 | 계획 디렉터리 | path | 예 | `<루트>/plans/2026-08-31-plugin-distribution` |

```bash
bash plugins/project-helper/skills/create-plan/scripts/validate-plan.sh docs/plans/2026-08-31-plugin-distribution
```

### 응답

```
계획서 검증 통과: docs/plans/2026-08-31-plugin-distribution
```

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 1 | `최상위 README.md가 없습니다.` | 계획 디렉터리에 README가 없다 |
| 1 | `도메인 디렉터리가 없습니다.` | 하위 디렉터리가 없다 |
| 1 | `<경로>/README.md가 없습니다.` | 도메인에 README가 없다 |
| 1 | `<경로>의 단계가 허용된 값이 아닙니다.` | 단계가 세 값 중 하나가 아니다 |
| 1 | `<경로>의 구현 진행률 형식이 잘못되었습니다.` | 진행률이 `숫자 / 숫자`가 아니다 |

## `impl-plan/scripts/validate-plan.sh <기능 계획서>`

구현을 시작하기 직전에 실행한다. 인자로 받은 파일의 위치에서 도메인 디렉터리와 계획 루트를 역산해 함께 검사한다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 인자 1 | 기능 계획서 | path | 예 | `README.md`를 넘기면 거부한다 |

```bash
bash plugins/project-helper/skills/impl-plan/scripts/validate-plan.sh docs/plans/2026-08-31-plugin-distribution/local-install/guide.md
```

### 응답

```
구현 전 계획서 검증 통과: docs/plans/2026-08-31-plugin-distribution/local-install/guide.md
```

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 1 | `README.md는 기능 계획서가 아닙니다.` | 인자로 README를 넘겼다 |
| 1 | `도메인 README.md가 없습니다.` | 계획서와 같은 디렉터리에 README가 없다 |
| 1 | `기능 계획서가 도메인 바로 아래에 있지 않습니다.` | 계층이 세 층을 벗어났다 |
| 1 | `기능 계획서 아래에 잘못된 하위 디렉터리가 있습니다.` | 도메인 디렉터리에 하위 디렉터리가 있다 |
| 1 | `계획 완료 상태가 아닙니다.` | 단계가 `계획 완료`가 아니다 |
| 1 | `사용자 검토 표시가 남아 있습니다.` | `<!-- 사용자 검토 필요 -->`가 있다 |
| 1 | `구현 항목 형식이 잘못되었습니다.` | 세 조각 ID 형식의 항목이 없다 |

## 이벤트 메시징

해당 없음. 계획서의 상태 전이는 이벤트로 발행되지 않는다. 상태 표의 값이 곧 두 스킬 사이의 유일한 신호이며, 다음 스킬은 사용자가 호출할 때 그 값을 직접 읽는다.
