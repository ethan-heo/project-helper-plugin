# 스킬_실행_맥락(skill-trigger) — API 명세

이 도메인의 인터페이스는 사용자가 스킬을 부르는 두 가지 경로, 곧 자연어 요청에 의한 자동 발동과 슬래시 명령에 의한 명시 호출이다.

## 엔드포인트 목록

| 메서드 | 경로 | 설명 | 인증 |
| --- | --- | --- | --- |
| `자동 발동` | 자연어 요청 | `description`의 발동 조건에 걸리는 요청에서 스킬이 켜진다 | 불필요 |
| `호출` | `/create-prd` | 제품 단위 요구사항 확정을 시작한다 | 불필요 |
| `호출` | `/create-plan` | 구현 계획서 작성을 시작한다 | 불필요 |
| `호출` | `/impl-plan` | `계획 완료` 계획서의 구현을 시작하거나 재개한다 | 불필요 |
| `호출` | `/create-docs` | 구현이 끝난 계획서를 개발 문서로 옮긴다 | 불필요 |

## `자동 발동`

사용자의 요청 문장을 네 `description`과 대조해 스킬을 고른다. 판정은 모델이 수행하므로 결정적이지 않으며, 사례 기반으로만 측정한다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 대화 | 사용자 요청 | string | 예 | 자연어 문장 |

```
알림 시스템을 큐 기반으로 바꾸려는데 설계부터 같이 봐줘
```

### 응답

발동한 스킬 하나, 또는 아무 스킬도 켜지지 않은 일반 답변이다. 위 요청의 기대 결과는 `create-plan`이다.

```json
{
  "query": "알림 시스템을 큐 기반으로 바꾸려는데 설계부터 같이 봐줘",
  "expect": "create-plan"
}
```

발동하면 안 되는 근접 요청은 `expect`가 비어 있고 이유가 붙는다.

```json
{
  "query": "다음 스프린트 계획 좀 잡아줘",
  "expect": null,
  "why": "코드 변경이 아닌 일정 계획"
}
```

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 해당 없음 | 미발동 | 요청이 어느 `description`과도 충분히 겹치지 않는다. 사용자가 슬래시 명령으로 직접 호출한다 |
| 해당 없음 | 오발동 | 근접 요청에 스킬이 켜진다. `description`의 부정 조건을 보완하고 사례를 추가한다 |
| 해당 없음 | 맥락 오인 | 설명 요청을 실행 요청으로 해석한다. 실행 원칙의 설명 요청 예외를 적용한다 |

## `호출`(슬래시 명령)

명시 호출은 발동 판정을 건너뛴다. 호출 이후의 답변은 해당 스킬의 작업 입력으로 해석되며, 종료 조건이 성립할 때까지 그 해석이 유지된다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 명령 | 스킬 이름 | string | 예 | `create-prd`, `create-plan`, `impl-plan`, `create-docs` |
| 명령 인자 | 작업 입력 | string | 아니오 | 비어 있으면 각 스킬의 준비 단계에서 되묻는다 |

### 응답

각 스킬의 산출물이다. 인계가 필요한 요청은 작업을 시작하지 않고 대상 스킬을 안내한다.

| 호출한 스킬 | 인계 조건 | 안내 대상 |
| --- | --- | --- |
| `create-prd` | 기능 하나의 구현 방식을 묻는다 | `/create-plan` |
| `create-plan` | 계획서가 이미 `계획 완료`다 | `/impl-plan` |
| `impl-plan` | 계획의 전제가 깨졌다 | `/create-plan` |
| `create-docs` | 단계가 `계획 완료`인 계획서가 남아 있다 | `/impl-plan` |

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 해당 없음 | 명령 없음 | 플러그인이 설치되지 않았거나 세션이 갱신되지 않았다 |
| 해당 없음 | 진입 거부 | 스킬의 진입 조건을 만족하지 못했다. 위 인계 표를 따른다 |

## 이벤트 메시징

해당 없음. 스킬 사이에 이벤트를 발행하거나 구독하지 않는다. 인계는 사용자가 다음 슬래시 명령을 직접 호출하는 방식으로만 일어난다.
