# 계획_작성(create-plan) — 도메인 특화 가이드

## 외부 의존성

| 대상 | 종류 | 용도 |
| --- | --- | --- |
| `grep` | 명령줄 도구 | `scripts/validate-plan.sh`가 상태 표와 구현 항목 형식을 검사할 때 사용한다 |
| `bash` | 실행 환경 | 검증 스크립트가 `set -euo pipefail`로 동작한다 |

검증 스크립트는 POSIX 도구만 쓰므로 별도 설치 없이 동작한다. 프로젝트 전반의 실행 환경은 [`글로벌_아키텍처_가이드.md`](../../글로벌_아키텍처_가이드.md)에 있다.

### 설정

| 항목 | 값의 출처 | 비고 |
| --- | --- | --- |
| 계획서 보관 경로 | [문서_루트_판정](../문서_루트_판정%28docs-root%29/01_도메인_개요.md)의 탐색 순서 | `<루트>/plans/`를 사용하고 `.gitignore`에 추가한다 |
| 커밋 규칙 | 프로젝트 지시사항 | 계획서의 구현 항목 하나가 커밋 하나에 대응한다 |
| 개발 문서 경로 | 확정한 문서 루트 | 루트 안의 `글로벌_아키텍처_가이드.md`와 `도메인_문서/`가 함께 있으면 `create-docs` 산출물로 본다 |

## 핵심 테스트 시나리오

| ID | 상황 | 기대 동작 |
| --- | --- | --- |
| T1 | 모호한 카테고리 답변과 선택지 밖 답변을 차례로 제시한다 | 추가 질문을 거쳐 작성 가능한 상태가 된 뒤 다음 카테고리로 이동한다 |
| T2 | 판단용 대안과 일반 안내 목록을 함께 제시한다 | 대안에만 번호가 붙는다 |
| T3 | 개발 문서가 있는 저장소에서 계획을 시작한다 | 코드보다 먼저 글로벌 아키텍처 가이드와 해당 도메인 개요를 읽는다 |
| T4 | 개발 문서와 코드의 기술이 어긋난다 | 코드를 사실로 삼아 계획하고 어긋난 지점을 보고한다 |
| T5 | 개발 문서가 없는 저장소에서 계획을 시작한다 | 코드만 조사했다고 알리고 진행한다 |
| T6 | 검토 표시가 남은 계획서를 확정하려 한다 | 확정하지 않고 해당 자리를 사용자와 정리한다 |
| T7 | 구현 항목이 하나뿐인 요구사항을 다룬다 | 세 층 구조를 그대로 만든다 |

### 실행 방법

```bash
bash -n plugins/project-helper/skills/create-plan/scripts/validate-plan.sh
bash plugins/project-helper/skills/create-plan/scripts/validate-plan.sh docs/plans/<계획 디렉터리>
```

T1부터 T7까지는 자동화된 테스트가 아니라 플러그인을 설치한 세션에서 직접 확인하는 시나리오다. 스킬 발동 여부의 회귀 사례는 `evals/trigger-eval.json`에, 검증 스크립트의 회귀 사례는 `evals/plan-validation.md`에 있다.

## 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 고친 스킬 내용이 대화에 반영되지 않는다 | 설치된 플러그인 캐시가 갱신되지 않았다 | [`배포와_설치(distribution)/03_API_명세.md`](../배포와_설치%28distribution%29/03_API_명세.md)의 로컬 테스트 설치 절차를 따르고 세션을 다시 시작한다 |
| 계획 요청에 스킬이 켜지지 않는다 | 요청이 `description`의 발동 조건과 겹치지 않는다 | `/create-plan`을 직접 호출한다. 반복되면 `evals/trigger-eval.json`에 사례를 추가한다 |
| 검증 스크립트가 `unbound variable`로 멈춘다 | 오류 문구에서 변수 뒤에 한글이 곧바로 붙어 셸이 변수 이름의 일부로 읽는다 | 해당 변수를 `${plan}`처럼 중괄호로 감싼다 |
| 구현 항목이 있는데 "올바른 구현 항목이 없습니다"가 나온다 | ID가 세 조각 대문자 형식이 아니거나 체크박스 표기가 어긋났다 | `1. [ ] **DOMAIN-FEATURE-001** 제목 — 설명` 형식으로 고친다 |
| 진행률의 전체 수가 항목 수와 다르다 | 확정 단계에서 전체 수를 맞추지 않았다 | 확정 절차 4번에 따라 구현 항목 수로 맞춘다 |
| 초안 파일과 세 층 구조가 함께 남아 있다 | 구조 이전 후 초안을 지우지 않았다 | 이전이 끝난 초안 파일을 삭제한다 |
