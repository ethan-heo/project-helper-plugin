# 개발문서_생성(create-docs) — 도메인 특화 가이드

## 외부 의존성

| 대상 | 종류 | 용도 |
| --- | --- | --- |
| `grep` | 명령줄 도구 | `scripts/validate-docs.sh`가 절 제목과 미확인 주석을 검사한다 |
| `find` | 명령줄 도구 | 도메인 디렉터리와 미확인 검사 대상 파일을 열거한다 |
| `find` | 명령줄 도구 | 도메인 디렉터리와 검사 대상 마크다운 파일을 열거한다 |
| Mermaid | 다이어그램 문법 | 엔티티 관계도와 구성도를 문서에 담는다. 렌더링은 문서 뷰어가 맡는다 |

### 설정

| 항목 | 값의 출처 | 비고 |
| --- | --- | --- |
| 보관 경로 | 계획 최상위 문서의 루트 기록, 없으면 [문서_루트_판정](../문서_루트_판정%28docs-root%29/01_도메인_개요.md)의 탐색 순서 | 확정한 루트를 개발 문서의 최상위로 삼는다 |
| 도메인 디렉터리 이름 | 계획서의 도메인 README | 영문 코드뿐이면 사용자에게 한글 이름을 확인받는다 |
| 필수 절 목록 | `scripts/validate-docs.sh`의 `require_sections` 호출 | 양식의 절 제목을 바꾸면 스크립트도 함께 고친다 |

## 핵심 테스트 시나리오

| ID | 상황 | 기대 동작 |
| --- | --- | --- |
| T1 | 단계가 `계획 완료`인 계획서가 섞여 있다 | 문서를 만들지 않고 `/impl-plan`을 안내한다 |
| T2 | PRD가 없는 저장소에서 실행한다 | 코드와 계획서만으로 쓰고, 근거에 PRD가 없다는 점을 알린다 |
| T3 | 보관 경로에 기존 문서가 있다 | 덮어쓸 목록을 보이고 동의를 받기 전에는 아무것도 쓰지 않는다 |
| T4 | 도메인 이름이 영문 코드뿐이다 | 한글 이름을 확인받아 `한글_이름(code)` 형태로 짓는다 |
| T5 | 해당 사항이 없는 절이 있다 | 절을 지우지 않고 "해당 없음"과 이유를 적는다 |
| T6 | 미확인 주석이 남은 상태로 확정하려 한다 | 검증이 실패하고 확정하지 않는다 |
| T7 | 코드와 계획서의 기술이 어긋난다 | 코드를 본문에 쓰고 어긋난 지점을 따로 모아 보고한다 |

### 실행 방법

```bash
bash -n plugins/project-helper/skills/create-docs/scripts/validate-docs.sh
bash plugins/project-helper/skills/create-docs/scripts/validate-docs.sh docs
```

T6만 스크립트로 판정할 수 있다. 나머지는 설치된 세션에서 대화로 확인한다.

## 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 절이 있는데 "절이 없습니다"가 나온다 | 절 제목이 4단계 이상 헤더이거나 문구가 다르다 | 2단계나 3단계 헤더로 두고 양식의 문구를 그대로 쓴다 |
| 도메인 디렉터리를 만들었는데 검사되지 않는다 | `도메인_문서/` 바로 아래가 아니라 더 깊은 곳에 있다 | 한 단계 아래로 옮긴다 |
| 검증은 통과하는데 내용이 비어 있다 | 스크립트는 절의 존재만 확인하고 내용은 보지 않는다 | 절마다 필수 항목이 채워졌는지 직접 확인한다 |
| 문서가 계획서 경로를 가리키고 있다 | 입력을 출처로 기록했다 | 경로와 항목 ID를 지운다. 계획서는 나중에 정리될 수 있다 |
| 같은 내용이 여러 도메인 문서에 반복된다 | 공통 내용을 상위 층으로 올리지 않았다 | 상위 층에 한 번만 두고 도메인 문서에는 참조 경로만 남긴다 |
| 문서화 중 코드의 결함을 발견했다 | 문서와 코드가 어긋나 있다 | 코드를 고치지 않고 발견 사실만 보고한다 |
