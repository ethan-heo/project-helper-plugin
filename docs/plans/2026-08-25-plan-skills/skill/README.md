# SKILL — 스킬 본문과 참조 문서

## 요약

**목표** — 계획을 세우고, 구현하고, 검증하는 세 스킬을 만든다. 각 스킬의 본문, 참조 문서, 이름이 여기 속한다.

**배경** — 한 스킬로 다 하면 정반대의 자세를 한 지시서에 담게 된다. 계획을 세울 때 AI는 뒤로 물러서서 질문만 하고, 구현할 때는 앞에 나서서 코드를 쓴다. 어느 쪽도 선명해지지 않는다.

**변경점** — 스킬 셋을 하나씩 만들고, 세 이름을 한 세트로 묶고, 본문의 지시 형식을 통일한다.

## 설계

### 왜 스킬을 셋으로 나누는가

나누면 세 가지를 얻는다.

- **상태 전환이 구조로 보장된다.** '계획 확정 → 구현 중'이 "사용자가 지시하면"이라는 문장이 아니라 `/impl-plan` 호출이라는 행위로 고정된다. '완료' 표시는 `/verify-plan`을 거치지 않으면 일어날 수 없다.
- **AI가 자기 일을 자기가 합격시키지 않는다.** 구현한 주체와 검증을 진행하는 주체를 분리한다. `verify-plan`은 판정하지 않고 증거를 내놓는 쪽이며, 판정은 사용자가 한다.
- **컨텍스트가 필요한 만큼만 로드된다.** 계획을 쓰는 동안 커밋 규칙이 컨텍스트에 있을 이유가 없다.

### 스킬은 자기 폴더 안만 참조한다

계획서 형식이 세 스킬의 인터페이스가 되므로 공용 규격 파일을 하나 두는 방법도 있다. 쓰지 않는다.

세 스킬이 필요로 하는 부분이 애초에 다르다. `create-plan`은 문서를 쓰므로 표기 전부가 필요하고, `impl-plan`은 단계와 진행률과 체크박스만, `verify-plan`은 단계와 체크 수와 테스트 섹션만 본다. 공용 규격은 각자에게 필요 없는 부분까지 매번 읽히게 만든다. 또 스킬이 자기 폴더 바깥을 참조하면 하나만 떼어 갔을 때 깨진다.

그래서 형식의 정본은 문서를 쓰는 `create-plan`이 갖고, `impl-plan`과 `verify-plan`은 받는 문서가 만족해야 할 전제와 자기가 고치는 자리만 자기 본문에 적는다. **제어는 참조가 아니라 제약으로 한다.** 전제를 만족하지 않는 문서는 받지 않는다.

형식을 바꿀 때 세 군데를 봐야 하는 것이 이 선택의 비용이다. 잊지 않도록 규격 문서 앞머리에 그 사실을 적어 둔다.

검토했으나 기각: 공용 디렉터리 `shared/` — 만들었다가 걷어냈다. 되살릴 조건은 세 스킬이 정말 같은 전체 규격을 필요로 하게 되고, 중복된 서술이 실제로 어긋나기 시작할 때다.

### 스킬 사이의 경계

계획서의 유무와 상태를 유일한 판별 기준으로 삼는다. 각 스킬은 시작할 때 상태를 확인하고, 자기 차례가 아니면 알맞은 스킬을 안내한다.

description이 발동을 가르는 실제 장치다. 세 스킬의 어휘가 겹치므로 어느 하나가 남의 요청까지 가져갈 수 있다. 트리거 문구와 오탐 후보, 측정 방법은 `REL-INTEG`이 정본이다.

## 구현 순서

- [ ] **SKILL-CREATE** `create-plan` — 사용자가 해법을 직접 설계하도록 이끌면서 다섯 섹션을 채우는 스킬. 선행: REPO-SETUP
- [ ] **SKILL-IMPL** `impl-plan` — '계획 확정' 문서를 받아 항목마다 구현하고 커밋하는 스킬. 선행: SKILL-CREATE
- [ ] **SKILL-VERIFY** `verify-plan` — '구현 완료' 문서를 받아 증거를 내놓고 사용자 승인으로 닫는 스킬. 선행: SKILL-IMPL, FMT-SPLIT
- [ ] **SKILL-NAMING** 이름 정리 — 세 스킬 이름을 한 세트로 묶는다. 선행: SKILL-CREATE, SKILL-IMPL, SKILL-VERIFY
- [ ] **SKILL-SHAPE** 지시 형식 정리 — 본문의 지시사항을 명령·분기·근거 세 층으로 고치고 근거를 참조로 내린다. 선행: SKILL-NAMING

### 통합 시나리오

| ID | 입력 상황 | 기대 동작 |
| --- | --- | --- |
| S1 자세 전환 | 같은 세션에서 계획 수립 뒤 바로 구현으로 넘어간다 | 계획 중에는 해법을 내지 않고, 구현으로 넘어간 뒤에는 되묻지 않고 진행한다 |
| S2 자가 합격 금지 | `impl-plan`이 모든 항목을 끝낸 직후다 | '완료'로 바꾸지 않고 `/verify-plan`을 안내한다 |
| S3 폴더 경계 | 스킬 폴더 하나만 떼어 다른 저장소에 둔다 | 끊긴 참조가 없다. 다른 스킬 폴더를 가리키는 경로가 없다 |
| S4 이름 인계 | 각 스킬이 다음 스킬을 안내한다 | 새 이름으로 부른다. 옛 이름이 남아 있지 않다 |
