# 문서 작성 기준

이 문서는 저장소의 계획서·스킬 문서·참조 문서를 작성하거나 수정할 때 적용한다. `AGENTS.md`의 공통 규칙을 보완하며, 충돌할 경우 `AGENTS.md`를 우선한다.

문장을 쓰는 규칙은 [`한국어_작성_규칙.md`](한국어_작성_규칙.md)가 따로 정한다. 이 문서는 문서의 배치·구조·참조를 다룬다.

## 기본 원칙

- 문서의 목적과 독자를 먼저 정한다.
- 한 문서는 하나의 주된 역할을 맡긴다. 실행 지침, 판단 기준, 근거, 예외 처리가 섞이면 문서를 나눈다.
- 실제로 필요한 정보만 남긴다. 짧은 문서를 억지로 여러 파일로 나누지 않는다.
- 같은 내용을 여러 문서에 반복하지 말고, 기준 문서를 하나 정해 참조한다.
- 문서가 설명하는 현재 상태와 코드·파일의 실제 상태를 일치시킨다.

## 문서 배치

저장소는 플러그인을 여러 개 담을 수 있으므로, 문서는 적용 범위에 따라 나눠 둔다.

| 적용 범위 | 위치 | 예 |
| --- | --- | --- |
| 저장소 전체 | 최상위 `docs/` | 이 문서, `프롬프트_작성_가이드.md` |
| 플러그인 하나 | `docs/<플러그인>/` | 글로벌 아키텍처 가이드, 도메인 문서, 계획서 |

`CLAUDE.md`와 `AGENTS.md`가 모든 작업에 공통으로 적용하는 규칙은 최상위 `docs/`에 둔다. 특정 플러그인의 구현을 설명하는 문서는 `docs/` 아래에 플러그인 이름으로 디렉터리를 나눠 담는다. 플러그인 설치본은 `plugins/<플러그인>/` 전체를 복사하므로, 문서를 그 안에 두면 배포본에 함께 실린다.

## 문서 구조

문서는 다음 순서로 구성한다.

1. 제목과 목적
2. 핵심 지시 또는 결론
3. 절차·조건·분기
4. 예외와 실패 처리
5. 근거·예시·참조

절차를 설명하는 절은 `명령 → 분기 → 근거` 순서를 따른다. 명령은 한 문장으로 쓰고 굵게 표시한다. 조건이 둘 이상이면 표를 사용하며, 표의 행동 열 이름은 `할 일`로 통일한다.

## 문체와 용어

문체, 문단 구성, 어휘, 용어, 날짜·경로 표기는 [`한국어_작성_규칙.md`](한국어_작성_규칙.md)를 따른다. 문서를 쓰기 전에 읽고, 초안을 마친 뒤 그 문서의 점검 목록으로 확인한다.

## 서식 선택

- 목록은 짧은 항목에는 `-`, 순서가 있는 절차에는 번호 목록을 사용한다.
- 표는 비교·매핑·조건 분기에 사용하고, 단순한 설명에는 문단을 사용한다.

## 스킬 문서

`SKILL.md`에는 실행 명령, 분기, 적용 시점만 둔다. 세부 근거·예외·형식 예시는 `references/`에 둔다.

스킬이 만드는 산출물의 문체·표기·용어는 `plugins/project-helper/skills/_shared/writing-style.md`가 정한다. 스킬마다 같은 규칙을 다시 적지 않고, `SKILL.md`의 참조 표와 문서를 쓰는 절차에서 이 문서를 가리킨다. 새 스킬을 만들 때도 같은 방식으로 연결한다.

스킬 참조 문서에는 그 스킬에만 해당하는 규칙만 남긴다. 공유 문서와 같은 내용이 스킬 쪽에 있으면 지우고 참조로 바꾼다.

참조 파일은 역할과 읽는 시점이 분명해야 한다. 문서가 하나뿐인 디렉터리는 만들지 않고 상위 `references/`에 둔다. 여러 참조 파일이 같은 판단 흐름을 구성할 때만 디렉터리로 묶는다.

절차를 지시하는 절은 `명령 → 분기 → 근거` 순서로 쓴다. 명령은 한 문장으로 쓰고 굵게 표시한다. 분기가 둘 이상이면 표를 사용하고, 행동을 담는 열 이름은 `할 일`로 통일한다. 조건을 담는 열 이름은 `선행 상태`, `발견한 것`, `어긋난 것`처럼 분기 기준을 드러낸다.

| | 본문(`SKILL.md`) | 참조(`references/`) |
| --- | --- | --- |
| 담는 것 | 명령, 분기, 그 자리에서 판단이 갈리는 것 | 근거, 예외, 실패 처리, 형식 예시 |
| 읽는 시점 | 스킬이 켜질 때 통째로 | 절 단위로, 필요한 시점에 |
| 분량 기준 | 절마다 여섯 줄 안쪽 | 제한 없음 |

같은 주제를 본문과 참조에서 반복하지 않는다. 근거가 참조에 있으면 본문에서 지우고, 본문의 참조 표에는 파일을 읽는 절과 시점을 적는다.

## 문단 구성과 지침 통합

**문단마다 하나의 판단이나 행동을 다루고, 같은 지침은 적용 범위에 맞는 기준 문서 한 곳에서 관리합니다.**

- 실행 순서는 번호 목록으로, 조건별 행동은 표로 구분합니다.
- 조건·예외는 해당 행동과 함께 두고, 근거·기록 형식 등 역할이 다른 내용은 별도 문단이나 담당 절로 옮깁니다.
- 문장을 고치기 전에 같은 스킬의 본문·참조 문서와 공통 문서에 동일한 지침이 있는지 확인합니다. 표현이 달라도 조건과 행동이 같으면 중복으로 봅니다.
- 한 스킬에서만 쓰는 지침은 그 스킬에, 여러 스킬이 쓰는 지침은 플러그인의 공통 문서에 둡니다. 이미 담당 문서가 있으면 그 문서를 보완합니다.
- 중복 부분을 지울 때는 고유한 조건·예외를 기준 문서에 보존하고, 호출 지점에는 읽을 시점과 해당 절의 링크를 남깁니다. 참조 내용을 다시 요약해 적지 않습니다.
- 호출을 식별하는 메타데이터와 실행 지침의 참조는 유지합니다. 별도로 설치되는 플러그인 사이에는 설치본 밖의 파일을 가리키는 링크를 만들지 않습니다.

## 작성 전 점검

- 이 문서의 주 독자와 목적이 한 문장으로 설명되는가?
- 기존 기준 문서와 내용이 중복되거나 충돌하지 않는가?
- 각 문단이 하나의 판단이나 행동을 다루며, 통합한 지침의 조건·예외와 참조 시점이 보존됐는가?
- 파일을 나눈 이유와 읽는 순서가 분명한가?
- 조건과 행동이 표에서 구분되는가?
- 목록과 표가 내용에 맞는 서식으로 쓰였는가?
- `한국어_작성_규칙.md`의 점검 목록을 통과했는가?
- 링크와 참조 경로가 실제 파일을 가리키는가?
- 문서를 읽은 사람이 다음 행동을 결정할 수 있는가?
