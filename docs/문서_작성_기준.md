# 문서 작성 기준

이 문서는 저장소의 문서를 배치·작성·수정·참조할 때 적용합니다. 대상은 최상위 `docs/`의 공통 문서, `docs/<플러그인>/`의 계획서와 설계 기록, 플러그인 설치본 안의 스킬 문서입니다.

문장을 쓰는 규칙은 [`한국어_작성_규칙.md`](한국어_작성_규칙.md)가 정합니다. 이 문서는 문장 규칙을 다시 정의하지 않습니다.

## 기본 원칙

**문서를 쓰기 전에 독자와 적용 범위를 한 문장으로 정합니다.**

- 한 문서는 하나의 주된 역할을 맡습니다. 역할이 다른 내용을 나눌지는 「문서를 나누는 기준」으로 판단합니다.
- 같은 지침은 담당 기준 문서 한 곳에서 관리하고, 나머지 문서는 그곳을 참조합니다.
- 실행에 필요한 조건·예외·참조 시점은 분량을 줄이려고 빼지 않습니다.
- 문서가 적은 경로·명령·구조를 저장소의 실제 상태와 일치시킵니다.

## 문서 배치와 참조

### 적용 범위별 위치

| 적용 범위 | 위치 | 예 |
| --- | --- | --- |
| 저장소 전체 | 최상위 `docs/` | 이 문서, [`한국어_작성_규칙.md`](한국어_작성_규칙.md), [`프롬프트_작성_가이드.md`](프롬프트_작성_가이드.md) |
| 플러그인 하나의 설계 기록 | `docs/<플러그인>/` | `plans/`, `prds/`, `architecture/`, `commits/` |
| 플러그인 하나의 실행 규칙 | `plugins/<플러그인>/` 안의 공통 문서 | 산출물 문체 기준, 여러 스킬이 함께 쓰는 계약 문서 |
| 스킬 하나 | `plugins/<플러그인>/skills/<스킬>/` | `SKILL.md`, `references/` |

`CLAUDE.md`와 `AGENTS.md`가 모든 작업에 공통으로 적용하는 규칙은 최상위 `docs/`에 둡니다.

### 배포 범위

플러그인 설치본은 `plugins/<플러그인>/` 전체를 복사합니다. 스킬이 실행 중에 읽어야 하는 문서는 이 디렉터리 안에 둡니다. `docs/` 아래 문서는 설치본에 실리지 않으므로, 스킬 실행에 필요한 규칙을 그곳에만 두면 설치 후 읽을 수 없습니다.

설치본 안에서는 그 플러그인 밖의 파일을 링크하지 않습니다. 플러그인은 서로 따로 설치되므로 다른 플러그인의 경로가 유효하다고 보장할 수 없습니다.

플러그인 공통 문서의 위치는 플러그인마다 다릅니다. 참조를 적기 전에 그 플러그인의 실제 경로를 확인합니다.

| 플러그인 | 공통 문서 위치 |
| --- | --- |
| `project-helper` | `plugins/project-helper/skills/_shared/` |
| `study-helper` | `plugins/study-helper/references/` |

### 문서를 나누는 기준

**한 문서에 담을지 나눌지는 분량이나 내용의 종류가 아니라 읽고 고치는 방식으로 판단합니다.**

다음 중 하나에 해당하면 나눕니다.

- 다른 문서에서도 같은 내용을 참조합니다.
- 본문과 따로 읽거나 고칠 일이 반복됩니다.
- 본문의 실행 흐름을 끊는 상세 설명입니다.
- 나누면 읽는 사람이 필요한 부분만 골라 읽을 수 있습니다.

목적이 다른 내용이라도 그 문서를 이해하거나 실행하는 데 바로 필요하면 함께 둡니다. 파일이나 디렉터리를 나누는 것 자체는 목적이 아닙니다. 문서가 하나뿐인 디렉터리는 만들지 않고 상위 디렉터리에 둡니다. 여러 참조 파일이 하나의 판단 흐름을 이룰 때만 디렉터리로 묶습니다.

### 참조를 적는 방법

참조에는 읽을 파일과 읽는 시점을 함께 적습니다. 시점은 작업 단계나 관찰할 수 있는 조건으로 씁니다. `필요할 때`, `관련된 경우`처럼 읽는 사람이 다시 판단해야 하는 표현은 쓰지 않습니다.

참조한 문서의 내용을 호출 지점에서 다시 요약하지 않습니다. 참조 파일이 하나뿐이면 참조 표를 만들지 않고 본문에서 한 줄로 가리킵니다.

## 문서 구조와 서식

### 절 순서

문서는 아래 순서를 기본으로 하고, 그 문서의 목적에 없는 절은 생략합니다.

1. 제목과 목적
2. 핵심 지시 또는 결론
3. 절차·조건·분기
4. 예외와 실패 처리
5. 근거·예시·참조

모든 문서에 같은 목차를 강제하지 않습니다. 순서를 바꿀 때도 독자가 가장 먼저 알아야 할 지시나 결론을 앞에 둡니다.

### 절차를 지시하는 절

**절차를 지시하는 절은 `명령 → 분기 → 근거` 순서로 쓰고, 명령은 한 문장으로 써서 굵게 표시합니다.**

이 규칙은 절차를 지시하는 절에만 적용합니다. 기준·배경·근거를 설명하는 절에는 적용하지 않습니다.

### 예외와 실패 처리의 위치

| 담는 내용 | 두는 곳 |
| --- | --- |
| 실행 중 행동을 바꾸는 조건과 예외 | 그 조건이 걸리는 절차 안 |
| 실행을 멈추거나 되돌리는 행동 | 본문 |
| 상세 원인, 판단 근거, 복구 사례 | 참조 문서 |
| 여러 스킬에 함께 걸리는 예외 | 플러그인 공통 문서 |

본문을 짧게 만들려고 실행에 필요한 조건이나 실패 처리를 참조 문서로 옮기지 않습니다. 참조 문서를 읽어야 다음 행동이 정해지면 본문에 읽는 시점과 참조 위치를 적습니다.

### 서식 선택

- 목록: 순서가 없는 짧은 항목은 `-`, 실행 순서는 번호 목록
- 표: 조건에 따라 행동이 갈리는 분기가 둘 이상일 때, 또는 항목을 나란히 비교하거나 대응시킬 때
- 문단: 한두 문장으로 설명되는 내용

행동을 담는 열 이름은 `할 일`로 통일합니다. 조건을 담는 열 이름은 `선행 상태`, `발견한 것`, `어긋난 것`처럼 분기 기준을 드러냅니다.

서식을 맞추려고 내용을 쪼개지 않습니다. 분기가 하나뿐이면 표 대신 문장으로 씁니다.

## 스킬 문서

일반 문서 규칙에 더해 아래를 적용합니다.

| | 본문(`SKILL.md`) | 참조(`references/`) |
| --- | --- | --- |
| 담는 것 | 실행 명령, 분기, 적용 시점, 다음 행동을 정하는 조건과 예외 | 상세 근거, 설명, 형식 예시, 복잡한 예외와 실패 사례 |
| 읽는 시점 | 스킬이 켜질 때 통째로 | 본문이 지정한 작업 단계에서 |
| 분량 | 절마다 여섯 줄 안쪽을 목표로 점검합니다 | 제한 없음 |

분량 기준은 간결한지 점검하는 잣대이지 상한이 아닙니다. 여섯 줄을 넘더라도 실행에 필요한 조건과 예외는 본문에 남깁니다.

같은 주제를 본문과 참조에서 되풀이하지 않습니다. 근거를 참조로 옮겼으면 본문에서 지우고 읽는 절과 시점만 남깁니다.

스킬 참조 문서에는 그 스킬에만 해당하는 규칙만 남깁니다. 플러그인 공통 문서와 같은 내용이 스킬 쪽에 있으면 지우고 참조로 바꿉니다.

스킬이 만드는 산출물의 문체·표기·용어는 그 플러그인의 `writing-style.md`가 정합니다. 산출물은 사용자의 저장소에 놓이므로 이 저장소의 문서와 적용 대상이 다릅니다. 스킬마다 같은 규칙을 다시 적지 않고, 참조 표와 문서를 쓰는 절차에서 그 문서를 가리킵니다. 새 스킬도 같은 방식으로 연결합니다.

## 지침 통합과 수정

### 중복과 충돌의 구분

| 판정 | 기준 | 할 일 |
| --- | --- | --- |
| 중복 | 적용 범위가 겹치고 조건과 행동이 같습니다. 표현이 달라도 같게 봅니다 | 담당 기준 문서 한 곳으로 합치고, 호출 지점에는 읽는 시점과 링크만 남깁니다 |
| 충돌 | 적용 범위가 겹치는데 요구하는 행동이 다릅니다 | 각 지침의 적용 범위와 목적을 확인해 담당 문서를 하나로 정한 뒤 나머지를 참조로 바꿉니다 |

충돌하는 지침을 근거 없이 한쪽만 지우지 않습니다. 적용 범위가 실제로 다르면 충돌이 아니므로, 각 지침에 적용 범위를 적어 구분합니다.

### 지침을 둘 곳

한 스킬에서만 쓰는 지침은 그 스킬에, 여러 스킬이 쓰는 지침은 플러그인 공통 문서에, 저장소 전체에 걸리는 지침은 최상위 `docs/`에 둡니다. 이미 담당 문서가 있으면 새 문서를 만들지 말고 그 문서를 보완합니다.

좁은 범위의 규칙이 넓은 범위의 규칙을 구체화하면 둘 다 적용합니다. 같은 조건에서 서로 다른 행동을 요구하면 저장소에 이미 명시된 우선순위를 따릅니다. 명시된 우선순위가 없으면 임의로 정하지 말고, 적용 범위와 목적을 확인해 담당 문서를 정합니다.

### 지침을 고칠 때

수정 범위에 따라 점검할 대상이 달라집니다.

| 수정 유형 | 할 일 |
| --- | --- |
| 문장만 다듬는 수정 | 해당 문서의 문체와 용어를 확인합니다 |
| 실행 행동이 달라지는 수정 | 그 문서를 참조하는 다른 문서와 스킬을 찾아 함께 고칩니다 |

지침을 합치거나 지울 때는 고유한 조건·예외·참조 시점이 남았는지 확인합니다. 호출을 식별하는 메타데이터와 실행 지침의 참조는 그대로 둡니다.

## 작성 전·후 점검

작성 전에 확인합니다.

- 이 문서의 독자와 적용 범위를 한 문장으로 말할 수 있는가?
- 같은 지침을 이미 담당하는 문서가 있는가?
- 문서를 나눈다면 「문서를 나누는 기준」의 어느 항목에 해당하는가?

작성 후에 확인합니다.

- 조건과 행동이 같은 지침이 여러 곳에 남아 있지 않은가?
- 통합하거나 지운 지침의 조건·예외·참조 시점이 보존됐는가?
- 실행 중 걸리는 조건과 실패 처리가 본문에 있는가?
- 참조마다 읽을 파일과 읽는 시점이 적혀 있는가?
- 서식이나 분량 기준 때문에 실행에 필요한 정보가 빠지지 않았는가?
- 링크와 경로가 실제 파일을 가리키며, 설치본 안에서도 유효한가?
- 문서가 적은 명령·경로·설정값이 저장소의 실제 상태와 같은가?
- [`한국어_작성_규칙.md`](한국어_작성_규칙.md)의 점검 목록을 통과했는가?
- 문서를 읽은 사람이 다음 행동을 결정할 수 있는가?
