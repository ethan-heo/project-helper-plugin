# 문서 작성 기준

이 문서는 저장소의 계획서·스킬 문서·참조 문서를 작성하거나 수정할 때 적용한다. `AGENTS.md`의 공통 규칙을 보완하며, 충돌할 경우 `AGENTS.md`를 우선한다.

문서와 커밋 메시지는 한국어로 쓰며, 코드 식별자와 파일명은 영문 kebab-case를 사용한다.

## 기본 원칙

- 문서의 목적과 독자를 먼저 정한다.
- 한 문서는 하나의 주된 역할을 맡긴다. 실행 지침, 판단 기준, 근거, 예외 처리가 섞이면 문서를 나눈다.
- 실제로 필요한 정보만 남긴다. 짧은 문서를 억지로 여러 파일로 나누지 않는다.
- 같은 내용을 여러 문서에 반복하지 말고, 기준 문서를 하나 정해 참조한다.
- 문서가 설명하는 현재 상태와 코드·파일의 실제 상태를 일치시킨다.

## 문서 배치

저장소는 플러그인을 여러 개 담을 수 있으므로, 문서는 적용 범위에 따라 나눠 둔다.

| 적용 범위 | 위치 | 예 |
| --- | --- | --- |
| 저장소 전체 | 최상위 `docs/` | 이 문서, `프롬프트_작성_가이드.md` |
| 플러그인 하나 | `plugins/<플러그인>/docs/` | 글로벌 아키텍처 가이드, 도메인 문서, 계획서 |

`CLAUDE.md`와 `AGENTS.md`가 모든 작업에 공통으로 적용하는 규칙은 최상위 `docs/`에 둔다. 특정 플러그인의 구현을 설명하는 문서는 그 플러그인 디렉터리 안에 두고, 다른 플러그인이 생겨도 서로 섞이지 않게 한다.

## 문서 구조

문서는 다음 순서로 구성한다.

1. 제목과 목적
2. 핵심 지시 또는 결론
3. 절차·조건·분기
4. 예외와 실패 처리
5. 근거·예시·참조

절차를 설명하는 절은 `명령 → 분기 → 근거` 순서를 따른다. 명령은 한 문장으로 쓰고 굵게 표시한다. 조건이 둘 이상이면 표를 사용하며, 표의 행동 열 이름은 `할 일`로 통일한다.

## 한국어 문체

- 기술 문서는 간결한 해요체가 아닌 `~합니다`체를 기본으로 한다.
- 주어가 분명하면 생략하고, 번역투의 긴 수식과 불필요한 수동 표현을 피한다.
- 한 문단은 하나의 중심 생각만 다룬다.
- `이를 통해`, `또한`, `따라서`, `특히`, `기반으로`, `효과적으로` 같은 연결어는 논리상 필요할 때만 쓴다.
- 추상적인 명사보다 구체적인 동사를 우선한다.
- 같은 문단에서 종결어미·용어·호칭을 섞지 않는다.

## 용어와 표기

- 동일한 개념에는 문서 전체에서 하나의 용어를 사용한다.
- 프로젝트 용어는 `AGENTS.md`와 기존 스킬 문서를 우선한다.
- 파일명과 코드 식별자는 영문 kebab-case를 사용한다.
- 파일 경로·명령·코드 식별자는 인라인 코드로 표시한다.
- 날짜는 `YYYY-MM-DD` 형식을 사용한다.
- 목록은 짧은 항목에는 `-`, 순서가 있는 절차에는 번호 목록을 사용한다.
- 표는 비교·매핑·조건 분기에 사용하고, 단순한 설명에는 문단을 사용한다.

## 스킬 문서

`SKILL.md`에는 실행 명령, 분기, 적용 시점만 둔다. 세부 근거·예외·형식 예시는 `references/`에 둔다.

참조 파일은 역할과 읽는 시점이 분명해야 한다. 문서가 하나뿐인 디렉터리는 만들지 않고 상위 `references/`에 둔다. 여러 참조 파일이 같은 판단 흐름을 구성할 때만 디렉터리로 묶는다.

절차를 지시하는 절은 `명령 → 분기 → 근거` 순서로 쓴다. 명령은 한 문장으로 쓰고 굵게 표시한다. 분기가 둘 이상이면 표를 사용하고, 행동을 담는 열 이름은 `할 일`로 통일한다. 조건을 담는 열 이름은 `선행 상태`, `발견한 것`, `어긋난 것`처럼 분기 기준을 드러낸다.

| | 본문(`SKILL.md`) | 참조(`references/`) |
| --- | --- | --- |
| 담는 것 | 명령, 분기, 그 자리에서 판단이 갈리는 것 | 근거, 예외, 실패 처리, 형식 예시 |
| 읽는 시점 | 스킬이 켜질 때 통째로 | 절 단위로, 필요한 시점에 |
| 분량 기준 | 절마다 여섯 줄 안쪽 | 제한 없음 |

같은 주제를 본문과 참조에서 반복하지 않는다. 근거가 참조에 있으면 본문에서 지우고, 본문의 참조 표에는 파일을 읽는 절과 시점을 적는다.

## 작성 전 점검

- 이 문서의 주 독자와 목적이 한 문장으로 설명되는가?
- 기존 기준 문서와 내용이 중복되거나 충돌하지 않는가?
- 파일을 나눈 이유와 읽는 순서가 분명한가?
- 조건과 행동이 표에서 구분되는가?
- 한국어 어조·용어·날짜·목록 형식이 일관적인가?
- 링크와 참조 경로가 실제 파일을 가리키는가?
- 문서를 읽은 사람이 다음 행동을 결정할 수 있는가?
