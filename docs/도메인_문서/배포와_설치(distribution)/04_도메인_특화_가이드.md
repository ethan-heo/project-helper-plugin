# 배포와_설치(distribution) — 도메인 특화 가이드

## 외부 의존성

| 대상 | 종류 | 용도 |
| --- | --- | --- |
| Claude Code CLI | 명령줄 도구 | 마켓플레이스 등록, 설치, 갱신, 목록 확인 |
| Codex CLI | 명령줄 도구 | 같은 진입점을 읽어 설치하고 캐시에 복사한다 |
| Git | 버전 관리 | 원격 등록과 버전 태그. 마켓플레이스 소스가 저장소를 가리킨다 |

### 설정

| 항목 | 값의 출처 | 비고 |
| --- | --- | --- |
| 마켓플레이스 이름 | `.claude-plugin/marketplace.json`의 `name` | `project-helpers` |
| 플러그인 버전 | 두 `plugin.json`의 `version` | 현재 `0.4.2`. 항상 함께 올린다 |
| Claude Code 마켓플레이스 클론 위치 | 설치 시 자동 | `~/.claude/plugins/marketplaces/<이름>/` |
| Codex 캐시 위치 | 설치 시 자동 | `~/.codex/plugins/cache/project-helpers/project-helper/<버전>`. 버전마다 디렉터리가 따로 생긴다 |
| Codex 원격 마켓플레이스 클론 위치 | 원격 등록 시 자동 | `~/.codex/.tmp/marketplaces/project-helpers` |
| Codex 마켓플레이스 등록 | `~/.codex/config.toml` | 직접 고치지 않고 플러그인 명령으로 다룬다 |
| Codex의 다른 진입점 | `~/.agents/plugins/marketplace.json` | `personal` 마켓플레이스가 쓴다. 이 저장소는 사용하지 않는다 |

### 반영 조건

| 조건 | 할 일 |
| --- | --- |
| Claude Code에서 변경을 버전으로 구분해야 한다 | `plugins/project-helper/.claude-plugin/plugin.json`의 버전을 올린 뒤 재설치한다 |
| Codex에서 변경을 버전으로 구분해야 한다 | `plugins/project-helper/.codex-plugin/plugin.json`의 버전을 올린 뒤 재설치한다. 두 환경이 각자의 매니페스트를 읽으므로 버전을 함께 올린다 |
| Claude Code CLI에서 확인한다 | 세션을 종료하고 다시 실행한다 |
| VS Code 확장에서 확인한다 | 명령 팔레트의 `Developer: Reload Window`로 창을 새로 고친 뒤 세션을 다시 시작한다 |
| Codex에서 확인한다 | 재설치 후 새 대화를 연다 |

## 확인한 근거

두 환경이 같은 진입점을 읽는다는 판정의 근거다.

| 확인한 것 | 근거 |
| --- | --- |
| Codex가 별도 마켓플레이스 매니페스트를 요구하지 않는다 | `codex plugin list`의 출력에서 `project-helpers` 마켓플레이스의 루트가 이 저장소의 `.claude-plugin/marketplace.json`으로 표시된다 |
| 등록된 소스가 저장소 루트를 가리킨다 | `~/.codex/config.toml`의 `[marketplaces.project-helpers]` 항목에 저장소 경로가 `source`로 적혀 있다 |
| 등록 소스로 받을 수 있는 형태 | `codex plugin marketplace add --help`이 로컬 경로, `owner/repo[@ref]`, HTTPS Git URL, SSH Git URL을 받는다고 밝힌다. `--ref`로 특정 ref를, `--sparse`로 일부 경로만 받을 수 있다 |
| 원격 등록이 두 환경에서 동작한다 | `claude plugin marketplace add ethan-heo/project-helper-plugin`은 소스를 `GitHub (ethan-heo/project-helper-plugin)`으로 등록하고, `codex plugin marketplace add`는 `~/.codex/config.toml`의 `source_type`을 `git`으로 바꾼다. 두 환경 모두 이어지는 설치에서 `0.4.2`를 받았다 |
| 등록 소스를 로컬에서 원격으로 바꿀 수 있다 | 같은 이름의 마켓플레이스가 이미 있으면 먼저 제거해야 한다. 플러그인을 지우고 마켓플레이스를 지운 뒤 다시 등록하는 순서로 전환된다 |
| 이 저장소가 쓰지 않는 진입점 | Codex의 `personal` 마켓플레이스는 `~/.agents/plugins/marketplace.json`을 진입점으로 쓴다. Codex는 두 경로를 모두 인식하지만 이 저장소는 `.claude-plugin/marketplace.json` 하나로 두 환경을 함께 처리한다 |

## 핵심 테스트 시나리오

| ID | 상황 | 기대 동작 |
| --- | --- | --- |
| T1 | 두 매니페스트의 버전을 올리고 재설치한다 | 두 환경의 목록에 같은 버전이 표시된다 |
| T2 | 스킬 파일을 고치고 재설치한 뒤 같은 세션에서 확인한다 | 옛 정의가 그대로 쓰인다. 세션을 다시 시작해야 반영된다 |
| T3 | Codex에서 캐시 디렉터리를 지우지 않고 재설치한다 | 고친 내용이 반영되지 않는다 |
| T4 | 배포 대상 판정을 적용한다 | `docs/`, `evals/`, `README.md`, 지시사항 파일이 설치본에 들어가지 않는다 |
| T5 | 저장소를 원격에 올린 뒤 상대 경로 `source`로 설치한다 | 경로를 고치지 않고 그대로 동작한다 |
| T6 | `.gitignore`의 규칙을 점검한다 | 남은 규칙이 모두 실제로 생성되는 경로에 대응하고 `git status`가 깨끗하다 |

### 실행 방법

```bash
claude plugin list
codex plugin list
git status
```

이 도메인에는 자동화된 테스트가 없다. 설치 결과를 목록 명령으로 직접 확인한다.

## 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 고친 스킬이 반영되지 않는다 | 설치본이 갱신되지 않았거나 세션이 옛 정의를 쓰고 있다 | 재설치한 뒤 세션을 다시 시작한다. VS Code 확장에서는 `Developer: Reload Window`로 창을 새로 고친다 |
| Codex에서만 옛 내용이 보인다 | 캐시 디렉터리가 남아 있다 | 해당 플러그인의 캐시 디렉터리만 지우고 다시 설치한다 |
| 두 환경의 버전이 다르게 표시된다 | 한쪽 매니페스트의 버전만 올렸다 | 두 `plugin.json`의 버전을 같은 값으로 맞춘다 |
| 버전에 타임스탬프가 붙어 있다 | 캐시를 피하려고 버전을 조작했다 | 실제 버전으로 되돌리고 캐시 디렉터리를 지우는 방식으로 바꾼다 |
| 다른 플러그인까지 사라졌다 | 전체 캐시 디렉터리를 지웠다 | 해당 플러그인만 지운다. 사라진 플러그인은 다시 설치한다 |
| 마켓플레이스 등록이 깨졌다 | 설정 파일을 직접 고쳤다 | 플러그인 명령으로 다시 등록한다 |
| 심링크를 걸었는데 실행 중 내용이 그대로다 | 심링크는 재설치 시점의 소스만 바꾼다 | 재설치하고 세션을 다시 시작한다 |
