# 문서와 검증

## 목적과 문제

세 스킬이 같은 학습 설계와 기록 계약을 읽고, 저장소의 동작이 설치본과 일치하는지 확인합니다. 공통 기준이 한 스킬에 섞이거나 설치본 검사가 없으면 문서와 실제 대화가 달라집니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 공통 기준의 단일 관리 | 같은 계약이 한 참조 문서에만 있음 |
| 실행 지침의 책임 분리 | `SKILL.md`에 실행 절차와 분기만 있음 |
| 계획 이력의 탐색 | 색인에서 현재·완료·대체 상태 확인 |
| 설치본 일치 | 배포 전 소스와 설치본 차이 없음 |
| 형식 회귀 방지 | 문서·링크·기록 검사 통과 |
| 대화 회귀 방지 | 시나리오별 상태와 금지 동작 명시 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 공통 참조 | 여러 스킬이 함께 읽는 기준 문서 |
| 실행 지침 | 스킬의 호출 조건·순서·분기 문서 |
| 계획 색인 | 계획의 현재 상태를 찾는 문서 |
| 시나리오 명세 | 입력과 예상 상태·기록·금지 동작 |
| 설치본 비교 | 저장소 소스와 설치 파일의 대조 |

## 책임과 경계

| 구성 요소 | 맡는 일 |
| --- | --- |
| PRD | 제품 목표와 필수 요구사항 관리 |
| 아키텍처 | 스킬 책임과 공통 계약 관리 |
| 공통 `references/` | 학습 설계와 기록 기준 관리 |
| `SKILL.md` | 호출 조건·실행 순서·분기 관리 |
| 계획 색인 | 계획 상태와 대체 관계 관리 |
| 검사 스크립트 | 문서·링크·기록 형식 검사 |
| 시나리오 명세 | 대화 동작의 회귀 기준 관리 |

사용자에게 보이는 스킬 이름은 `init`·`tutor`·`manager`로 통일합니다. 매니페스트와 사용 안내는 세 스킬의 역할과 시작 예시를 모두 보여 줍니다(AD-025).

## 실행 흐름

1. 공통 계약을 바꾸면 아키텍처와 참조 문서를 갱신합니다.
2. 각 `SKILL.md`는 참조 시점과 실행 분기만 갱신합니다.
3. 정적 검사로 문서·링크·기록 형식을 확인합니다.
4. 영향받는 시나리오의 예상 상태와 금지 동작을 확인합니다.
5. 개발 중에는 같은 버전으로 플러그인을 다시 설치합니다.
6. 저장소 소스와 설치본의 차이를 확인합니다.
7. 전체 개선이 끝나면 실제 릴리스 버전을 올립니다.

## 계약

문서의 우선순위는 PRD의 제품 요구사항, 아키텍처의 책임·계약, 공통 참조의 판정 기준, `SKILL.md`의 실행 절차 순서입니다. 하위 문서는 상위 문서의 요구사항을 바꾸지 않습니다.

계획 문서는 기존 경로를 유지합니다. `plans/README.md`가 계획마다 현재·완료·대체 상태와 대체 문서를 가리킵니다.

시나리오 명세는 8~10개를 유지합니다. 각 시나리오는 입력, 예상 상태 전이, 기록 변화, 실행하면 안 되는 동작을 포함합니다. 실제 대화 자동 실행은 필수 검사에 포함하지 않습니다(AD-025).

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| 모델별 응답 차이 | 같은 지침도 Claude Code와 Codex의 표현 차이 가능 |
| 수동 시나리오 대조 | 대화 내용의 자동 회귀 검사가 아님 |
| 같은 버전 재설치 | 세션을 다시 시작하기 전에는 이전 설치본 사용 가능 |
