# 학습 작업 공간

## 목적과 문제

사용자가 예제 코드를 작성하고 실행할 폴더를 만들고, 마친 예제의 기록을 모을 곳을 정합니다. 환경이 준비되지 않으면 사용자가 설치 문제에 시간을 쓰고, 기록이 예제 폴더에만 흩어지면 복습 대상을 고를 수 없습니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 추가 설치 없는 실행(R1) | 예제 폴더를 만든 직후 예제 코드를 작성하고 실행한다 |
| 환경의 동작 확인(R1-4) | 설치 뒤 실행 결과를 사용자에게 보여 준다 |
| 예제 사이의 독립 | 한 예제 폴더의 의존성을 바꿔도 다른 예제가 그대로 실행된다 |
| 폴더 밖에서의 기록 열람(R10-2) | 예제 폴더를 열지 않고 기록 전체를 읽는다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 학습 공간 | `init`을 부른 디렉터리. 예제 폴더들과 기록이 함께 놓인다 |
| 예제 폴더 | 예제 하나의 코드·의존성·예제 정보를 담는 폴더 |
| 기록 디렉터리 | 예제 폴더들과 같은 높이의 `.study/records/` |
| 작업 계획 | 사용자가 설계·구현 단계·막힌 점·설계 변경을 적는 `PLAN.md` |

## 책임과 경계

| 구성 요소 | 맡는 일 |
| --- | --- |
| `init` | 예제 폴더 생성, 예제 정보와 `PLAN.md` 양식 기록, 의존성 설치와 실행 확인 |
| 사용자 | 예제 폴더 안에서의 구현과 실행, `PLAN.md` 작성 |
| `tutor` | 예제 정보와 `PLAN.md`와 코드 읽기, 기록에 답변 단계 남기기 |
| `manager` | 기록 디렉터리의 파일 생성과 갱신 |

예제 폴더에는 예제를 완성하는 코드를 넣지 않습니다. 다만 입문 수준에서는 실행되는 예제를 주고 동작을 설명하며, 사용자는 그 예제를 고쳐 가며 배웁니다. 어느 스킬이 언제 읽고 쓰는지는 [학습 진행](learning-flow.md)이 정합니다.

## 실행 흐름

1. `init`이 현재 디렉터리 바로 아래에 새 예제 폴더를 만듭니다.
2. 그 폴더에 예제 정보와 `PLAN.md` 양식을 기록합니다.
3. 예제에 필요한 의존성을 설치하고 실행해 동작을 확인합니다.
4. 사용자가 `PLAN.md`에 설계와 구현 단계를 적고 폴더에서 구현·실행합니다.
5. `tutor`가 답할 때마다 그 예제의 기록 파일에 바뀐 답변 단계를 남깁니다.
6. 예제를 마치면 `manager`가 같은 파일에 학습 목표와 배운 내용, 마친 날짜를 적습니다.

## 계약

예제 정보는 예제 폴더 안 문서 한 편에 두고 별도 JSON을 두지 않습니다(AD-010). 학습 기록은 예제마다 파일 하나로 `.study/records/` 아래에 두며, 파일 하나에 학습 목표·배운 내용·마친 날짜·답변 단계 이력이 들어갑니다(AD-011). `PLAN.md`는 사용자만 쓰고 다른 스킬은 읽기만 합니다(AD-013). 스킬 사이의 전달은 [학습 진행](learning-flow.md)의 계약을 따릅니다.

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| 반복 설치 | 같은 기술의 예제마다 같은 의존성을 다시 설치하는 시간과 용량 |
| 설치 실패 | 사용자 환경에 런타임이 없어 R1을 충족하지 못하는 경우의 처리 미정 |
| 기록과 폴더의 어긋남 | 사용자가 예제 폴더를 지워도 기록 파일이 남아 복습 대상에 나타남 |
| 학습 공간의 이동 | 다른 디렉터리에서 `init`을 부르면 앞선 기록을 읽지 못함 |
