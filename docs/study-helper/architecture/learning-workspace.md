# 학습 작업 공간

## 목적과 문제

사용자가 예제 코드를 작성하고 실행할 폴더를 만들고, 마친 예제의 기록을 모을 곳을 정합니다. 환경이 준비되지 않으면 사용자가 설치 문제에 시간을 쓰고, 기록이 예제 폴더에만 흩어지면 복습 대상을 고를 수 없습니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 추가 설치 없는 실행(R1) | 예제 폴더를 만든 직후 예제 코드를 작성하고 실행한다 |
| 환경의 동작 확인(R1-4) | 설치 뒤 실행 결과를 사용자에게 보여 준다 |
| 과제 요구사항 제공 | 모든 수준에 요구 동작과 산출물 경로가 있다 |
| 사용자 산출물 보호 | 사용자가 작성할 구현 코드가 비어 있다 |
| 초기 상태 확인 | 핵심 테스트 실패나 문제 증상이 재현된다 |
| 완료 검증 가능성 | 제공·사용자 테스트의 존재와 성공을 확인한다 |
| 예제 사이의 독립 | 한 예제 폴더의 의존성을 바꿔도 다른 예제가 그대로 실행된다 |
| 폴더 밖에서의 기록 열람(R10-2) | 예제 폴더를 열지 않고 기록 전체를 읽는다 |
| 준비 작업의 범위 제한 | 설치·실행·커밋이 예제 경로 밖을 바꾸지 않는다 |
| 실행 자원 정리 | 확인 뒤 포트와 자식 프로세스가 남지 않는다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 학습 공간 | `init`을 부른 디렉터리. 예제 폴더들과 기록이 함께 놓인다 |
| 예제 폴더 | 예제 하나의 코드·의존성·예제 정보를 담는 폴더 |
| 과제 요구사항 | 요구 동작과 산출물 경로를 정한 명세 |
| 시작 자료 | 구현 전에 제공하는 검증 코드와 실행 환경 |
| 사용자 산출물 | 사용자가 활동을 마치며 남기는 결과 |
| 기록 디렉터리 | 예제 폴더들과 같은 높이의 `.study/records/` |
| 작업 계획 | 권장 설계와 작업 목록을 사용자가 고치는 `PLAN.md` |
| 예제 ID | 폴더 이름과 무관한 기록 식별자 |
| 예제 상태 | `preparing`부터 `completed`까지의 네 단계 |

## 책임과 경계

| 구성 요소 | 맡는 일 |
| --- | --- |
| `init` | 예제 준비·계획 초안 작성과 `ready` 전환 |
| 사용자 | 구현·실행과 `PLAN.md` 검토·수정 |
| `tutor` | 질문 이력 기록과 완료 조건 확인 |
| `manager` | 완료된 예제의 학습·복습 기록 관리 |

예제 폴더는 과제 요구사항·시작 자료·사용자 산출물을 구분합니다. `init`은 모든 수준에 활동별 요구 동작과 산출물 경로를 제공하고, 만들기 활동에는 구현 전 실패하는 검증 테스트를 둡니다. 사용자가 작성할 구현 코드는 채우지 않습니다(AD-027). 시작 자료는 활동과 목표에 맞게 추천한 뒤 사용자가 확정합니다(AD-028).

## 실행 흐름

1. `init`이 예제 ID와 `preparing` 상태의 기록을 만듭니다.
2. 현재 디렉터리 바로 아래에 새 예제 폴더를 만듭니다.
3. 예제 정보와 과제별 `PLAN.md` 초안을 기록합니다.
4. 설치 스크립트가 있으면 사용자 동의를 받습니다.
5. 의존성을 설치하고 시작 상태의 검증 결과를 확인합니다.
6. 실행 확인이 끝나면 포트와 자식 프로세스를 종료합니다.
7. 상위 저장소가 없으면 예제 전용 기준 커밋을 만듭니다.
8. 상위 저장소가 있으면 동의받아 예제 경로만 커밋합니다.
9. 기준 커밋 해시를 기록에 남깁니다.
10. 준비가 끝나면 상태를 `ready`로 바꿉니다.
11. 준비가 실패하면 원인을 남기고 다음 `init`에서 재개합니다.
12. 첫 `tutor` 호출에서 상태를 `in_progress`로 바꿉니다.
13. `tutor`가 질문 주제별 이력을 누적합니다.
14. 제공·사용자 테스트와 모든 완성 조건을 확인하면 상태를 `completed`로 바꿉니다.
15. `manager`가 완료된 기록에 학습·복습 내용을 적습니다.

## 계약

예제 정보는 예제 폴더 안 문서 한 편에 두고 별도 JSON을 두지 않습니다(AD-017). 예제 폴더 이름은 `<기술>-<학습 활동 요약>`입니다. 학습 기록은 예제 ID마다 파일 하나로 `.study/records/` 아래에 둡니다. 상태·수준·날짜처럼 기계가 읽는 값은 YAML 머리말에 두고, 질문·학습·복습 내용은 Markdown 본문에 둡니다(AD-020). `init`은 `PLAN.md` 초안을 만들고 사용자가 수정하며 다른 스킬은 읽기만 합니다(AD-030).

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| 반복 설치 | 같은 기술의 예제마다 같은 의존성을 다시 설치하는 시간과 용량 |
| 설치 동의 거절 | 설치 스크립트 없이 준비할 대체 방법이 없을 수 있음 |
| 기록과 폴더의 어긋남 | 폴더 삭제 뒤 진행 중 기록의 처리 방식 미정 |
| 학습 공간의 이동 | 다른 디렉터리에서 `init`을 부르면 앞선 기록을 읽지 못함 |
