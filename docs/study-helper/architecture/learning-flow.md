# 학습 진행

## 목적과 문제

사용자가 예제를 받고, 구현하다 막히면 물어보고, 마친 뒤 배운 내용을 다시 꺼내는 동작을 어느 스킬이 맡는지 정합니다. 동작의 경계가 모호하면 요청하지 않은 도움이 응답에 섞이고, 사용자가 들여야 할 노력이 줄어듭니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 동작마다 스킬 하나 | 예제 생성·진행 중 답변·기록 관리가 각각 다른 스킬에서만 일어난다 |
| 스킬 전환 없는 수준 판정(R3) | `init`을 부른 사용자가 `tutor`를 따로 부르지 않는다 |
| 사용자가 고른 학습 활동(R17) | 예제를 내기 전에 사용자가 추천 후보에서 고르거나 고친 활동이 확정되어 있다 |
| 근거가 있는 수준 추천(R5) | 활동별 질문과 답에서 추천 수준의 근거를 말할 수 있다 |
| 사용자가 확정한 수준 | 추천과 달라도 사용자가 고른 수준이 예제에 반영되어 있다 |
| 요청한 범위까지만 답변(R8) | 사용자가 더 알려 달라고 하지 않았는데 단계가 올라간 답변이 없다 |
| 기존 시도의 재사용 | 시도와 막힌 지점을 다시 묻지 않는다 |
| 근거가 있는 질문 해결 | 실행·측정·코드 근거를 확인한 주제만 해결됨이다 |
| 예제 중복 방지(R2) | 같은 디렉터리에서 같은 기술로 낸 예제끼리 산출물이 다르거나, 산출물이 같으면 활동이 요구하는 동작이 다르다 |
| 복습 시점의 판정 가능성(R11) | 호출 시 기록만 읽고 밀린 복습을 빠짐없이 찾는다 |
| 일관된 복습 진단(R12) | 같은 진단 기준으로 목표별 답변을 가른다 |
| 호출 없는 동작 금지(R11-3) | 사용자가 부르지 않았는데 먼저 알린 응답이 없다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 예제 | 학습 활동과 완성 조건을 적은 과제 하나 |
| 예제 정보 | 예제 폴더에 기록한 기술·학습 활동과 세 속성·수준·학습 목표·완성 조건 |
| 학습 활동 | 예제에서 사용자가 하는 일. 만들기뿐 아니라 원인 찾기, 동작 관찰도 포함한다 |
| 활동 속성 | 학습 활동을 예제로 옮길 때 쓰는 시작 상태·산출물·확인 방법의 세 값 |
| 활동 후보 | 사용자의 계기와 원하는 일을 근거로 추천한 학습 활동 2~3개 |
| 추천 수준 | 활동별 질문의 답으로 `tutor` 기준이 정한 수준 |
| 최종 수준 | 추천을 확인한 사용자가 확정한 수준 |
| 수준별 제공 형태 | 수준에 따라 예제를 어디까지 만들어 주는지 정한 기준 |
| 답변 단계 | 질문에 어디까지 알려 줄지 정한 다섯 단계 |
| 예제 상태 | 준비부터 완료까지의 네 단계 |
| 질문 이력 | 주제별 학습 목표·최대 단계·해결 여부 |
| 학습 기록 | 상태·수준·질문 이력·배운 내용·복습 이력 |
| 진단 기준 | 목표별 필수 개념·근거·대표 오개념 |
| 진단 결과 | 독립 설명·부분 이해·재학습 필요 |
| 복습 시점 | 예제를 마친 날로부터 1일·3일·7일·14일이 지난 네 시점 |

## 책임과 경계

| 스킬 | 맡는 일 | 요구사항 |
| --- | --- | --- |
| `init [기술 또는 자료]` | 예제 생성·준비와 실패한 준비 재개 | R1, R2, R3, R4, R15 |
| `tutor` | 단계별 답변과 완료 조건 확인 | R5, R6, R7, R8, R9, R16, R17 |
| `manager` | 완료된 예제의 기록과 복습 관리 | R10, R11, R12, R13, R14 |

`init`은 활동을 먼저 확정한 뒤 그 활동에 맞는 수준 확인 질문을 최대 세 번까지 냅니다. `tutor` 기준으로 추천 수준과 근거를 보이고 사용자가 최종 수준을 확정합니다. 추천과 다른 수준을 골라도 사용자 결정을 유지하며 두 수준과 근거를 기록합니다(AD-021). 사용자는 `tutor`를 따로 부르지 않습니다(AD-016).

`tutor`는 시도와 막힌 지점이 있으면 3단계에서, 없으면 2단계에서 시작합니다. 다음 힌트나 더 직접적인 방법을 요청할 때만 단계를 올리고, 재설명·예시 요청은 같은 단계에서 답합니다. 5단계에서도 필요한 최소 코드 조각만 보이고 파일을 고치지 않습니다(AD-022). 결과 확인 요청에는 같은 단계 규칙을 적용합니다(AD-019).

`manager`는 진단 기준과 주제별 질문 이력만 사용하며 코드와 `TASK.md`를 열지 않습니다. 기본 복습에서 재학습이 필요한 목표는 다음 날 보충 복습으로 다시 묻습니다. 여러 목표의 결과가 다르면 가장 낮은 목표부터 다음 학습을 제안합니다(AD-023). 제안을 `init`에 옮기는 일은 사용자가 합니다(AD-015).

학습 원칙은 별도 문서에 두지 않고 세 스킬 문서의 요구사항에 녹여 적습니다(AD-014). 예제 폴더와 기록 파일의 위치는 [학습 작업 공간](learning-workspace.md)이 정합니다.

## 실행 흐름

### 예제를 시작할 때

1. 사용자가 `init`을 부르며 배울 기술이나 관련 자료를 건넵니다.
2. `init`이 입력이 로컬 경로·외부 링크·코드 조각·붙여넣은 글 중 무엇인지 가리고, 경로와 링크는 내용을 읽어 옵니다.
3. `init`이 배우려는 계기와 마쳤을 때 할 수 있게 되고 싶은 일을 묻습니다.
4. `tutor` 기준으로 활동 후보 2~3개를 만들고 사용자가 하나를 확정합니다.
5. 확정한 활동에 맞는 수준 확인 질문을 최대 세 번까지 냅니다.
6. 답이 분명해지면 질문을 멈추고 추천 수준과 근거를 보입니다.
7. 사용자가 최종 수준을 확정합니다.
8. 추천과 다르면 추천·최종 수준과 근거를 모두 기록합니다.
9. 언어와 런타임이 하나이면 추론 근거를 보입니다.
10. 선택지가 둘 이상이면 사용자가 언어와 런타임을 고릅니다.
11. 학습 목표·진단 기준·완성 조건·뺀 기능을 정하고 확인받습니다.
12. 앞선 예제와 학습 활동이 겹치는지 확인합니다(AD-017).
13. 예제 ID와 `preparing` 상태의 기록을 만듭니다.
14. 예제 폴더와 수준별 시작 상태를 준비합니다.
15. 의존성을 설치하고 시작 상태의 동작을 확인합니다.
16. 준비가 끝나면 상태를 `ready`로 바꿉니다.

준비가 실패하면 실패 단계와 원인을 기록하고 `preparing`을 유지합니다. 다음 `init` 호출은 새 폴더를 만들지 않고 실패한 단계부터 이어서 수행합니다(AD-020).

### 구현 중 질문할 때

1. 사용자가 예제 폴더에서 `tutor`를 부르며 질문합니다.
2. 첫 호출이면 예제 상태를 `in_progress`로 바꿉니다.
3. `tutor`가 예제 정보와 `PLAN.md`와 코드와 질문 이력을 읽습니다.
4. 기존 주제의 연속인지 모호하면 사용자에게 한 번 확인합니다.
5. 새 주제에 시도와 막힌 지점이 있으면 3단계에서 시작합니다.
6. 필요한 정보가 없으면 2단계에서 확인합니다.
7. 다음 힌트를 요청하면 한 단계 올리고, 재설명 요청은 단계를 유지합니다.
8. 5단계에서는 필요한 최소 코드 조각까지만 보입니다.
9. 사용자가 해결을 알리면 실행·측정·코드 근거를 확인합니다.
10. 근거가 맞으면 주제를 해결됨으로 기록합니다.
11. 사용자가 결과를 확인해 달라고 하면 코드와 기록을 대조합니다(AD-019).
12. 모든 완성 조건이 맞으면 상태를 `completed`로 바꿉니다.

만들기 활동은 실행·측정 결과로 확인합니다. 진단·관찰·비교 활동은 결과와 사용자가 제시한 근거를 함께 확인합니다(AD-020).

### 마친 뒤 복습할 때

1. 사용자가 `manager`를 부릅니다.
2. `completed` 상태의 기록만 관리 대상으로 고릅니다.
3. 배운 내용이 비어 있으면 학습 목표에 대한 설명을 받아 적습니다.
4. 기록 전체에서 복습 시점이 지난 예제를 찾습니다.
5. 그 예제의 학습 목표로 복습 질문을 만들어 냅니다.
6. 진단 기준과 주제별 질문 이력으로 답변을 세 단계로 가릅니다.
7. 재학습이 필요한 목표는 다음 날 보충 복습으로 예약합니다.
8. 목표별 결과가 다르면 가장 낮은 목표부터 다음 학습을 제안합니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 예제 구성 질문의 답 | 사용자 | `init` |
| 활동 추천·수준 판정·목표·범위의 판단 기준 | `tutor` 문서 | `init` |
| 활동별 답·추천 수준·근거 | `init`이 적용한 `tutor` 기준 | 사용자 |
| 최종 수준 | 사용자 | 예제 정보와 학습 기록 |
| 학습 활동·학습 목표·진단 기준·예제 범위 | `init`이 `tutor` 기준으로 판단한 결과 | 예제 정보와 학습 기록 |
| 예제 정보 | `init` | `tutor`, `manager`, 이후의 `init` |
| 상태와 질문 이력 | `init`, `tutor` | 학습 기록, 이후의 세 스킬 |
| 배운 내용·진단 결과·복습 일정 | `manager` | 학습 기록 |
| 다음 학습 제안 | `manager` | 사용자 |

예제 정보는 예제 폴더 안 문서 한 편에 두고 별도 JSON을 두지 않습니다(AD-017). 학습 기록은 변하지 않는 예제 ID마다 파일 하나로 예제 폴더 밖에 모읍니다. 기계가 읽는 값은 YAML 머리말에, 사용자가 읽는 내용은 Markdown 본문에 둡니다(AD-020). `PLAN.md`는 사용자만 쓰고 `tutor`는 읽기만 합니다(AD-013). 필드 구성은 계획서에서 정합니다.

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| 서브에이전트 진단 | `manager`의 복습 진단을 대화와 분리된 서브에이전트로 할지 미정. 사용자의 말에 영향을 받지 않아야 하는 판단이다 |
| 수동 복습 호출 | 사용자가 `manager`를 부르지 않으면 복습 시점을 알 수 없음 |
| 수준 확인의 반복 | 같은 기술의 새 활동에서 질문을 줄일 조건 미정 |
| 주제 확인의 반복 | 모호한 질문이 이어지면 확인 질문이 자주 생길 수 있음 |
| 제안의 유실 | `manager`의 다음 학습 제안을 사용자가 옮기지 않으면 반영되지 않음 |
| 예제 폴더 밖에서의 호출 | 예제 정보가 없는 위치에서 `tutor`를 부르면 대상 예제를 정할 수 없음 |
| 기술 이름의 표기 차이 | `WebRTC Signaling`과 `WebRTC 시그널링`을 같은 기술로 판정하는 방법 미정 |
