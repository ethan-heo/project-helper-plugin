# 학습 진행

## 목적과 문제

사용자가 예제를 받고, 구현하다 막히면 물어보고, 마친 뒤 배운 내용을 다시 꺼내는 동작을 어느 스킬이 맡는지 정합니다. 동작의 경계가 모호하면 요청하지 않은 도움이 응답에 섞이고, 사용자가 들여야 할 노력이 줄어듭니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 동작마다 스킬 하나 | 예제 생성·진행 중 답변·기록 관리가 각각 다른 스킬에서만 일어난다 |
| 스킬 전환 없는 수준 판정(R3) | `init`을 부른 사용자가 `tutor`를 따로 부르지 않는다 |
| 사용자가 고른 학습 활동(R17) | 예제를 내기 전에 사용자가 추천 후보에서 고르거나 고친 활동이 확정되어 있다 |
| 요청한 범위까지만 답변(R8) | 사용자가 더 알려 달라고 하지 않았는데 단계가 올라간 답변이 없다 |
| 예제 중복 방지(R2) | 같은 디렉터리에서 같은 기술로 낸 예제끼리 산출물이 다르거나, 산출물이 같으면 활동이 요구하는 동작이 다르다 |
| 복습 시점의 판정 가능성(R11) | 기록만 읽고 어느 예제의 복습 시점이 지났는지 가린다 |
| 호출 없는 동작 금지(R11-3) | 사용자가 부르지 않았는데 먼저 알린 응답이 없다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 예제 | 학습 활동과 완성 조건을 적은 과제 하나 |
| 예제 정보 | 예제 폴더에 기록한 기술·학습 활동과 세 속성·수준·학습 목표·완성 조건 |
| 학습 활동 | 예제에서 사용자가 하는 일. 만들기뿐 아니라 원인 찾기, 동작 관찰도 포함한다 |
| 활동 속성 | 학습 활동을 예제로 옮길 때 쓰는 시작 상태·산출물·확인 방법의 세 값 |
| 활동 후보 | 사용자의 계기와 원하는 일을 근거로 추천한 학습 활동 2~3개 |
| 학습자 수준 | 입문·초급·중급·숙련의 네 구분 |
| 수준별 제공 형태 | 수준에 따라 예제를 어디까지 만들어 주는지 정한 기준 |
| 답변 단계 | 질문에 어디까지 알려 줄지 정한 다섯 단계 |
| 학습 기록 | 마친 예제의 학습 목표·배운 내용·마친 날짜·답변 단계 이력 |
| 복습 시점 | 예제를 마친 날로부터 1일·3일·7일·14일이 지난 네 시점 |

## 책임과 경계

| 스킬 | 맡는 일 | 요구사항 |
| --- | --- | --- |
| `init [기술 또는 자료]` | 입력 해석, 예제 구성 질문과 답변 수집, `tutor` 기준에 따른 판단 수행, 예제와 환경 생성 | R1, R2, R3, R4, R15 |
| `tutor` | 활동 후보 추천·수준 판정·학습 목표·예제 범위의 판단 기준, 진행 중 질문과 요청받은 결과 확인에 단계별 답변 | R5, R6, R7, R8, R9, R16, R17 |
| `manager` | 학습 기록 작성, 복습 질문, 이해 수준 진단, 다음 학습 제안 | R10, R11, R12, R13, R14 |

`init`은 예제를 만들기 전에 무엇을 어떤 순서로 물을지 정하고 답을 모읍니다. 모은 답은 `tutor` 문서의 판단 기준으로 같은 대화에서 판단합니다. 스킬을 전환하지 않으므로 사용자는 `tutor`를 따로 부르지 않습니다(AD-016).

`tutor`는 질문에 답할 때 정해진 단계의 범위까지만 답하고, 묻지 않은 내용을 먼저 알려 주지 않습니다. 단계는 사용자가 더 알려 달라고 할 때만 올라갑니다(AD-012). 사용자가 찾은 원인이나 관찰 결과가 맞는지 확인해 달라고 하면, 그 요청도 같은 단계 규칙으로 답합니다(AD-019).

`manager`는 다음 학습의 주제와 난이도를 제안만 하고, 그 내용을 `init`에 옮기는 일은 사용자가 합니다(AD-015).

학습 원칙은 별도 문서에 두지 않고 세 스킬 문서의 요구사항에 녹여 적습니다(AD-014). 예제 폴더와 기록 파일의 위치는 [학습 작업 공간](learning-workspace.md)이 정합니다.

## 실행 흐름

### 예제를 시작할 때

1. 사용자가 `init`을 부르며 배울 기술이나 관련 자료를 건넵니다.
2. `init`이 입력이 로컬 경로·외부 링크·코드 조각·붙여넣은 글 중 무엇인지 가리고, 경로와 링크는 내용을 읽어 옵니다.
3. `init`이 배우려는 계기와 마쳤을 때 할 수 있게 되고 싶은 일을 한 번에 묻습니다. 첫 요청에 활동이 이미 드러나 있으면 이 질문을 건너뛰고 그 활동을 확인받습니다.
4. `init`이 `tutor` 문서의 기준으로 활동 후보 2~3개를 만들고, 후보와 함께 수준을 묻습니다. 읽어 온 자료는 추천과 수준 판정의 근거에 더합니다.
5. 사용자가 후보 하나를 고르거나 고쳐서 확정하고, 수준을 고릅니다.
6. `init`이 `tutor` 문서의 기준으로 학습 목표와 예제 범위를 정하고, 뺀 기능과 그 이유를 남깁니다.
7. 현재 디렉터리의 예제 폴더들에서 예제 정보를 읽어 같은 기술의 앞선 예제와 겹치는지 확인합니다. 산출물이 다르면 겹치지 않고, 같으면 활동이 요구하는 동작을 비교합니다(AD-017).
8. 겹치지 않는 예제로 폴더를 만들고, 언어와 런타임을 받아 의존성을 설치한 뒤 실행해 동작을 확인합니다.
9. 수준별 제공 형태에 맞는 예제와 의존성 설명을 예제 정보에 적습니다.

### 구현 중 질문할 때

1. 사용자가 예제 폴더에서 `tutor`를 부르며 질문합니다.
2. `tutor`가 예제 정보와 `PLAN.md`와 폴더의 코드, 그리고 그 예제의 기록에서 마지막 답변 단계를 읽습니다.
3. 앞 질문과 같은 내용이면 기록된 단계를 잇고, 다른 내용이면 2단계로 되돌립니다.
4. 정해진 단계의 범위까지만 답하고, 바뀐 단계를 기록에 남깁니다.
5. 사용자가 더 알려 달라고 하면 한 단계 올려 다시 답합니다.
6. 사용자가 찾은 원인이나 관찰 결과를 확인해 달라고 하면, `tutor`가 코드와 대조합니다. 맞으면 맞다고 답하고, 어긋나면 현재 단계의 범위에서 어긋난 지점만 짚습니다(AD-019).

### 마친 뒤 복습할 때

1. 사용자가 `manager`를 부릅니다.
2. 예제를 막 마친 상태이면 학습 목표와 배운 내용, 마친 날짜를 기록에 적습니다.
3. 기록 전체에서 복습 시점이 지난 예제를 찾습니다.
4. 그 예제의 학습 목표로 복습 질문을 만들어 냅니다.
5. 답변과 예제를 구현할 때의 진행 결과로 이해한 부분과 못한 부분을 가릅니다.
6. 진단 결과로 다음 예제의 주제나 난이도를 정해 사용자에게 제안합니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 예제 구성 질문의 답 | 사용자 | `init` |
| 활동 추천·수준 판정·목표·범위의 판단 기준 | `tutor` 문서 | `init` |
| 학습 활동·수준·학습 목표·예제 범위 | `init`이 `tutor` 기준으로 판단한 결과 | 예제 정보 |
| 예제 정보 | `init` | `tutor`, `manager`, 이후의 `init` |
| 답변 단계 | `tutor` | 학습 기록, 이후의 `tutor` |
| 학습 목표·배운 내용·마친 날짜 | `manager` | 학습 기록 |
| 다음 학습 제안 | `manager` | 사용자 |

예제 정보는 예제 폴더 안 문서 한 편에 두고 별도 JSON을 두지 않습니다(AD-017). 학습 기록은 예제마다 파일 하나로 예제 폴더 밖에 모읍니다(AD-011). `PLAN.md`는 사용자만 쓰고 `tutor`는 읽기만 합니다(AD-013). 문서의 항목 구성은 계획서에서 정합니다.

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| 서브에이전트 진단 | `manager`의 복습 진단을 대화와 분리된 서브에이전트로 할지 미정. 사용자의 말에 영향을 받지 않아야 하는 판단이다 |
| 수준 판정의 반복 | 같은 기술로 예제를 다시 낼 때 수준을 다시 판정할지 미정 |
| 같은 질문의 판정 | 앞 질문과 같은 내용인지 가리는 기준이 AI 판단에 남음 |
| 제안의 유실 | `manager`의 다음 학습 제안을 사용자가 옮기지 않으면 반영되지 않음 |
| 예제 폴더 밖에서의 호출 | 예제 정보가 없는 위치에서 `tutor`를 부르면 대상 예제를 정할 수 없음 |
| 기술 이름의 표기 차이 | `WebRTC Signaling`과 `WebRTC 시그널링`을 같은 기술로 판정하는 방법 미정 |
