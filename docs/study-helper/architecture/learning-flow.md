# 학습 진행

## 목적과 문제

사용자가 과제를 받고, 다음에 할 일을 몰라 멈추면 그 일을 정해 받고, 푸는 방법에 막히면 힌트를 얻고, 완성하면 피드백을 받는 동작을 어느 스킬이 맡는지 정합니다. 동작의 경계가 모호하면 요청하지 않은 힌트나 정답이 응답에 섞이고, 사용자가 들여야 할 노력이 줄어듭니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 동작마다 스킬 하나 | 과제 생성·다음 할 일 결정·힌트·피드백이 각각 다른 스킬에서만 일어난다 |
| 요청한 동작만 수행 | `hint`를 부르지 않은 응답에 힌트가 없다 |
| 정답 코드 미제공 | 어느 스킬의 응답에도 과제를 완성하는 코드가 없다 |
| 과제 중복 방지(R3) | 같은 디렉터리에서 같은 기술로 낸 과제의 만들 대상이 서로 겹치지 않는다 |
| 다음 할 일의 단위 | `tutor` 한 번의 응답에 다음 할 일이 하나만 들어 있다 |
| 작업 계획의 결정권 | `tutor`가 고친 `PLAN.md`의 줄 중 사용자가 동의하지 않은 것이 없다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 과제 | 만들 대상과 완성 조건을 적은 구현 과제 하나 |
| 과제 정보 | 과제 폴더에 기록한 기술·만들 대상·완성 조건 |
| 작업 계획 | 설계·구현 단계·막힌 점·설계 변경을 기록하는 `PLAN.md` |
| 멈춘 지점 | 과제 진행이 더 나아가지 못한 위치 |
| 다음 할 일 | 멈춘 지점에서 이어서 할 작업 하나와 그 접근 방향 |

## 책임과 경계

| 스킬 | 맡는 일 | 요구사항 |
| --- | --- | --- |
| `study [기술]` | 배울 범위 구체화와 겹치지 않는 과제·의존성·작업 계획 문서 생성 | R1, R2, R3, R4 |
| `tutor` | 멈춘 지점 판정과 다음 할 일 하나의 결정, 작업 계획 갱신 | 미해결 질문 참조 |
| `hint` | 과제 정보와 작업 계획을 참고한 정답 코드 없는 힌트 제시 | R5 |
| `review` | 과제 정보와 작업 계획을 참고한 완성 조건 충족 여부와 고칠 곳 제시 | R6 |

`tutor`와 `hint`는 사용자가 모르는 것이 무엇인지에 따라 갈립니다. 무엇을 할지 모르면 `tutor`를 부르고, 할 일을 정한 뒤 그것을 어떻게 푸는지 막히면 `hint`를 부릅니다. `tutor`가 정해 준 일에서 막혔을 때도 먼저 부르는 스킬은 `hint`입니다(AD-006).

`tutor`는 다음 할 일에 접근 방향까지 적고 그 일을 완성하는 코드는 적지 않습니다. 고칠 파일과 함수를 지정하는 일도 하지 않습니다.

과제 폴더를 만들고 의존성을 설치하는 방식은 [학습 작업 공간](learning-workspace.md)이 정합니다. 결과에 원칙을 반영하는 방식은 [학습 기조](learning-principles.md)가 정합니다.

## 실행 흐름

1. 사용자가 `study [기술]`을 부르면 배울 범위를 질문으로 구체화합니다.
2. `study`가 현재 디렉터리의 과제 정보를 읽어 같은 기술의 과제를 확인합니다.
3. 겹치지 않는 과제로 과제 폴더를 만들고, 과제와 의존성 설명을 제시합니다.
4. 사용자가 과제 폴더에서 직접 구현하고, 막히면 그 폴더에서 `hint`를 부릅니다.
5. 완성하면 그 폴더에서 `review`를 불러 피드백을 받습니다.
6. 같은 기술로 더 연습하려면 상위 디렉터리에서 `study [기술]`을 다시 부릅니다.

사용자가 다음에 할 일을 몰라 멈추면 과제 폴더에서 `tutor`를 부르고, `tutor`는 아래 순서로 동작합니다.

1. `PLAN.md`와 `TASK.md`와 과제 폴더의 코드를 읽어 진행 상태를 파악합니다.
2. 어디서 멈췄는지 사용자에게 한 번 묻고, 답을 판정의 근거에 더합니다(AD-008).
3. 다음 할 일 하나를 접근 방향까지 정해 제시합니다.
4. 그 내용을 `PLAN.md`의 해당 절에 기록합니다. 사용자가 이미 쓴 줄을 고쳐야 하면 고칠 곳과 이유를 먼저 제시하고 동의를 받습니다(AD-007).
5. 같은 할 일에서 `tutor`를 다시 부르면 그 일을 더 작은 일로 쪼개 하나를 제시합니다.

`hint`와 `review`는 과제 정보와 과제 폴더의 코드를 함께 읽습니다. 새 세션에서도 부른 위치만으로 대상 과제가 정해집니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 과제 정보 | `study` | `tutor`, `hint`, `review`, 이후의 `study` |
| 작업 계획 | 사용자, `tutor` | `tutor`, `hint`, `review` |
| 멈춘 지점 | 사용자 | `tutor` |

과제 정보와 작업 계획은 과제 폴더 안에만 둡니다(AD-004, AD-007). `hint`와 `review`는 작업 계획을 읽기만 하며, 문서가 비어 있어도 실행합니다. `tutor`는 작업 계획을 읽고 고치며, 문서가 비어 있으면 설계부터 채웁니다. 필드 구성은 계획서에서 정합니다.

## 위험과 미해결 질문

| 위험·질문 | 내용 |
| --- | --- |
| PRD에 대응 요구사항 없음 | `tutor`의 동작에 대응하는 PRD 요구사항 번호가 없어, R 번호로 충족을 판정할 수 없음 |
| 노력의 감소 | 다음 할 일을 받는 일이 반복되면 사용자가 스스로 설계하는 경험이 줄어듦(P1, P9) |
| 과제 폴더 밖에서의 호출 | 과제 정보가 없는 위치에서 부르면 대상 과제를 정할 수 없음 |
| 하위 폴더에서의 호출 | 과제 폴더의 하위 폴더에서 불렀을 때 과제 폴더를 찾는 방법 미정 |
| 기술 이름의 표기 차이 | `WebRTC Signaling`과 `WebRTC 시그널링`을 같은 기술로 판정하는 방법 미정 |
