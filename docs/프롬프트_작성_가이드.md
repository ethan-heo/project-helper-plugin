# 프롬프트 작성 가이드

이 문서는 이미 있는 프롬프트를 개선할 때 적용합니다. 스킬의 `SKILL.md`와 참조 문서, 사용자가 건넨 프롬프트가 대상입니다. 프롬프트를 처음부터 새로 쓰는 일은 다루지 않습니다.

문장을 쓰는 규칙은 [`한국어_작성_규칙.md`](한국어_작성_규칙.md)가, 문서의 배치와 구조는 [`문서_작성_기준.md`](문서_작성_기준.md)가 정합니다.

## 보존 원칙

**원문의 목적, 요구사항, 조건, 예외, 금지사항, 출력 요구사항을 보존합니다.**

다음 항목은 근거를 밝히지 않은 채 삭제하거나 바꾸지 않습니다.

- 구체적인 수치와 조건
- 예외와 금지사항
- 고유명사와 정의된 용어
- 출력 형식과 작업 순서
- 사용자가 강조한 요구사항

원문에 없는 요구사항은 추가하지 않습니다. 뜻이 모호하거나 지시가 서로 충돌하면 임의로 결정하지 말고 「확인이 필요한 사항」에 적습니다.

## 작업 절차

### 1. 기존 프롬프트 분석

**전체 프롬프트를 읽고 지시의 역할을 분류합니다.** 아래 범주 중 원문에 있는 것만 고릅니다.

- 목적과 AI의 역할
- 작업 대상과 입력
- 수행 작업과 작업 절차
- 필수 요구사항
- 제약조건·금지사항·예외사항
- 우선순위
- 출력 형식
- 품질 기준과 참고사항

### 2. 문제점 진단

**아래 항목을 원문에서 찾습니다.** 해당하는 문제가 없는 부분은 고치지 않습니다.

- 긴 줄글과 복잡한 문장
- 서로 다른 목적의 지시가 한 곳에 섞인 부분
- 중복되거나 서로 멀리 떨어진 관련 지시
- 모호한 표현과 불명확한 우선순위
- 지시 사이의 충돌
- AI가 자의적으로 해석할 여지가 큰 부분
- 불명확한 출력 형식

### 3. 정보 구조 재설계

**진단 결과에 따라 제목, 하위 제목, 목록, 번호로 지시를 다시 배치합니다.**

- 서로 다른 목적의 지시는 분리합니다.
- 관련된 지시는 같은 절에 묶습니다.
- 상위 원칙과 세부 조건의 계층을 드러냅니다.
- 절대적인 제약조건은 일반 참고사항과 구분합니다.
- 조건과 행동이 같은 지시는 한 곳으로 합칩니다.
- 구조화에 필요하지 않은 설명이나 장식은 추가하지 않습니다.

### 4. 최종 프롬프트 작성

**재설계한 구조로 복사해 쓸 수 있는 전체 프롬프트를 작성합니다.**

긴 문단은 의미 단위로 나누고, 조건은 그 조건이 걸리는 지시 옆에 둡니다. 분량을 줄이는 것이 목표가 아니라, 사람이 고치기 쉽고 AI가 실행하기 쉬운 형태로 만드는 것이 목표입니다.

## 최종 검증

최종본을 원문과 대조해 확인합니다.

1. 핵심 목적과 작업 순서를 유지했는가?
2. 요구사항·조건·예외·금지사항을 누락하지 않았는가?
3. 새로운 요구사항을 추가하지 않았는가?
4. 조건과 행동이 같은 지시가 한 곳으로 합쳐졌는가?
5. 관련 정보가 같은 절에 묶였는가?
6. 지시의 계층과 우선순위가 드러나는가?
7. 사람이 읽고 수정하기 쉬운가?
8. AI가 지시를 구분해 실행하기 쉬운가?

## 출력 형식

아래 순서로 결과를 제시합니다.

### 구조적 문제점

2단계에서 찾은 문제를 간략히 설명합니다.

### 개선 방향

구조를 바꾼 기준을 설명합니다.

### 개선된 프롬프트

복사해 쓸 수 있는 완성된 전체 프롬프트를 제공합니다.

### 확인이 필요한 사항

원문이 모호하거나 지시가 충돌해 사용자의 판단이 필요한 내용만 적습니다. 그런 내용이 없으면 이 절을 생략합니다.
