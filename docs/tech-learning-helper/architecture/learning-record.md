# 학습 기록

## 목적과 문제

학습 상태가 남지 않으면 이미 공개한 설명을 되풀이하고, 질의응답이 남지 않으면 학습자가 배운 내용을 다시 정리할 근거가 없습니다. Claude Code의 새 세션은 이전 대화를 기억하지 못하므로, 이 영역은 학습 상태와 질의응답을 파일로 남깁니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 세션 안 상태 | 세션 도중 발견한 개념과 다음 탐색 후보를 확인할 수 있습니다 |
| 세션 간 복원 | 새 세션에서 상태 파일을 읽어 직전 학습 상태를 이어 받습니다 |
| 질의응답 기록 | 세션 없이 기록 파일만 읽어도 질의응답을 따라갈 수 있습니다 |
| 주제와 날짜로 찾기 | 학습 패키지 폴더와 날짜 파일 이름만으로 기록을 찾습니다 |
| 학습 과정 이력 | 설명 경로 하나가 끝날 때마다 커밋이 하나 남습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 상태 파일 | 누적 학습 상태를 담는 `state.md`와 재개 상태를 담는 `state.json` |
| 기록 파일 | 학습 패키지 하나에서 하루 동안 나눈 질의응답 파일 |
| 발견한 개념 | 학습 중에 공개된 개념 |
| 부분 이해 개념 | 공개했지만 아직 전체 설명에 이르지 않은 개념 |
| 미공개 개념 | 기술 지식에 있지만 아직 공개하지 않은 개념 |
| 다음 탐색 후보 | 직전 질문과 이어져 다음에 다룰 수 있는 개념 |

## 책임과 경계

이 영역은 `state.md`, `state.json`, 기록 파일을 쓰고 읽는 일과 설명 경로가 끝날 때의 커밋을 맡습니다(AD-012). 상태를 바꿀지는 학습 진행 영역이 판단하고, 이 영역은 받은 내용을 남깁니다. 이 영역의 규칙은 공용 참조 문서로 두고, `learn`과 `review`가 해당 단계에서 읽습니다(AD-007).

기술 저장소와 학습 패키지를 만드는 일은 학습 작업 공간 영역이 맡습니다. 두 영역은 같은 기술 저장소를 쓰지만, 이 영역은 예제 파일을 고치지 않습니다.

## 실행 흐름

1. 기술 이름 없이 이어 하기를 요청받으면, 학습 폴더의 기술 저장소를 최근 커밋 순으로 정렬해 학습 진행 영역에 목록으로 넘깁니다. 기술 이름만 받았는데 그 저장소가 있으면, 저장소의 학습 패키지 목록과 마지막 학습 패키지를 넘깁니다.
2. 학습을 시작하면 `state.json`을 먼저 읽고, 누적 학습 상태가 필요할 때 `state.md`를 읽어 학습 진행 영역에 넘깁니다.
3. 질의응답이 오갈 때마다 `state.json`과 해당 학습 패키지의 그날 기록 파일을 갱신합니다.
4. 설명 경로 하나가 끝나면 `state.md`를 확정하고, 기록 파일·상태 파일·새로 저장된 지식을 함께 커밋합니다.
5. `review`가 정리를 요청하면 `state.json`의 진행 상태와 `state.md`, 정리할 학습 패키지의 기록 파일을 학습 진행 영역에 넘깁니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 학습 상태와 질의응답 | 학습 진행 | 학습 기록 |
| 이전 학습 상태 | 학습 기록 | 학습 진행 |
| 정리할 질의응답 기록 | 학습 기록 | 학습 진행 |
| 최근 순 기술 저장소 목록 | 학습 기록 | 학습 진행 |
| 학습 패키지 목록과 마지막 학습 패키지 | 학습 기록 | 학습 진행 |
| 설명 경로 종료 신호 | 학습 진행 | 학습 기록 |

파일 형식과 커밋 메시지 규칙은 계획서에서 정합니다. 따르는 결정은 AD-007, AD-012입니다.

## 위험과 미해결 질문

- `state.json`과 기록 파일의 갱신 중 하나가 실패하면 재개 상태와 기록이 어긋날 수 있습니다.
- 여러 주제에 걸쳐 날짜로 찾으려면 학습 패키지 폴더를 가로질러 검색해야 합니다.
