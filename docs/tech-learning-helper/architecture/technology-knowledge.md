# 기술 지식

## 목적과 문제

학습 대상 기술을 제한하지 않으므로, 모든 기술의 지식을 미리 준비할 수 없습니다. 이 영역은 요청 시점에 기술 지식을 만들고 저장해, 같은 기술을 다시 배울 때 같은 기준으로 이어 가게 합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 기술 무제한 | 저장된 지식이 없는 기술도 곧바로 학습을 시작합니다 |
| 개념 재사용 | 같은 기술 저장소 안 다른 패키지에서 이미 다룬 개념은 다시 설명하지 않습니다 |
| 예제 안 질문 | 탐색 질문마다 속한 예제가 하나 있습니다 |
| 선형 설명 | 설명 경로 하나가 갈라지지 않고 한 줄로 이어집니다 |
| 즉시 실행 | 예제를 고치지 않고 바로 실행할 수 있습니다 |
| 예제 언어 | 웹·JavaScript 생태계는 TypeScript, 그 밖은 원래 언어로 씁니다 |
| 변경 이력 | 저장한 지식의 변경이 기술 저장소의 git 이력에 남습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 개념 | 설명 경로 서술 안에서만 다루는, 기술을 이해하는 데 필요한 단위 지식. 뜻을 별도로 저장하지 않습니다 |
| 예제 후보 | 개념을 보여 줄 예제의 아이디어 |
| 설명 경로 | 탐색 질문 하나를 현상→원인→개념 순서로 푸는 한 줄의 단계 |

## 책임과 경계

이 영역은 기술 지식의 생성·재사용을 맡습니다(AD-001). 개념은 별도 목록으로 저장하지 않고 설명 경로의 서술 안에만 두며, 예제별 탐색 질문과 설명 경로는 학습 패키지에 저장합니다(AD-014). 생성 지침은 Example Builder 역할 문서에 두고, 사용자 스킬이 필요한 단계에서 읽습니다(AD-007).

원인이 둘 이상이면 설명 경로 안에서 차례로 나열하고, 경로를 둘로 가르지 않습니다. 선수 개념이 필요하면 경로의 한 단계로 넣습니다. 다른 패키지에서 같은 개념을 다시 설명하지 않도록, 학습 진행 영역을 거쳐 받은 발견한 개념 이름 목록(학습 기록 영역의 저장소 루트 상태 파일에서 옴, AD-014)에 있는 개념은 새로 설명하지 않고 경로 안에서 참조만 합니다.

가르치는 순서와 공개 단계는 학습 진행 영역이 정하며, 이 영역은 가르치는 규칙을 저장하지 않습니다. 기술 저장소와 학습 패키지를 만드는 일은 학습 작업 공간 영역이 맡습니다.

## 실행 흐름

1. 학습 진행 영역에서 기술 이름과 학습 목표, 발견한 개념 이름 목록을 받습니다.
2. 학습 목표를 담은 예제가 없으면 예제를 만들어 학습 패키지에 저장합니다. 가져온 자료가 있으면 링크 같은 공개 자료는 원본 구간을 옮겨 부족한 부분만 채우고, 로컬 파일과 출처를 알 수 없는 붙여 넣은 코드는 질문한 동작만 남긴 최소 예제로 줄입니다. 원본에 접근할 수 없거나 기반으로 삼기에 너무 작으면 같은 동작의 예제를 새로 만듭니다(AD-010).
3. 탐색 질문과 설명 경로가 없으면 만들어 학습 패키지에 저장합니다. 경로 안의 개념이 발견한 개념 이름 목록에 이미 있으면 새로 설명하지 않고 참조만 합니다.
4. 학습 중에 저장되지 않은 질문이 나오면 설명 경로를 새로 만들어 해당 패키지에 더합니다.
5. 예제·탐색 질문·설명 경로를 학습 진행 영역에 넘깁니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 기술 이름과 학습 목표, 발견한 개념 이름 목록 | 학습 진행 | 기술 지식 |
| 예제·탐색 질문·설명 경로 | 기술 지식 | 학습 진행 |
| 예제 코드와 원본 자료 | 기술 지식 | 학습 작업 공간 |

저장 파일의 형식은 계획서에서 정합니다. 따르는 결정은 AD-001, AD-007, AD-010, AD-014입니다.

## 위험과 미해결 질문

- 요청 시점에 만든 지식에 사실 오류가 있으면, 저장되어 이후 학습에서도 반복됩니다.
- 설명 경로가 한 줄이므로, 원인이 여럿인 질문에서 일부 원인을 빠뜨릴 수 있습니다.
