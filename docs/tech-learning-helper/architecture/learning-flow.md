# 학습 진행

## 목적과 문제

정답을 먼저 알려 주면 학습자가 원리를 스스로 찾을 기회가 사라집니다. 이 영역은 기술이 달라도 같은 순서로 가르쳐, 학습자가 예제를 관찰하고 질문하며 원리에 다가가게 합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 목표 확인 | 학습 목표가 모호하면 개념과 예제를 만들기 전에 목표를 확인합니다 |
| 필요 개념 한정 | 설명한 개념마다 현재 질문에 필요한 이유가 있습니다 |
| 공개 단계 | 사전 안내 뒤 관찰 유도부터 순서대로 올리고, 지정하면 그 단계로 갑니다 |
| 선행 지식 보완 | 안내에 담긴 용어를 되물으면 요청 없이 그 용어부터 다시 설명합니다 |
| 안내 재료 | 예제에서 드러나는 값·로그·호출이 안내에 모두 쓰입니다 |
| 확인 방법 | 설명마다 코드 변경이나 구조 비교 같은 확인 방법이 하나 이상 있습니다 |
| 두 관점 | 같은 예제에 구조 관점과 실행 관점의 설명을 각각 요청할 수 있습니다 |
| 질문 방향 | 다음 탐색 후보가 직전 질문과 이어지는 개념입니다 |
| 범위 유지 | 실행한 예제에서 관찰되지 않는 개념은 다음 후보로 보류합니다 |
| 선형 진행 | 질문 하나의 설명이 설명 경로를 벗어나 옆 개념이나 학습자 환경 진단으로 가지 않습니다 |
| 기술 무관 | 역할 문서에 특정 기술의 이름이나 사실이 없습니다 |
| 단일 진입점 | `learn` 하나만 호출해도 학습을 끝까지 진행할 수 있습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 역할 문서 | 내부 역할 하나의 지침을 담은 공용 참조 문서 |
| 공개 단계 | 관찰 유도·힌트·부분 설명·전체 설명의 네 단계 |
| 구조 관점 | 역할·책임·경계·의존성처럼 정적인 구조를 보는 관점 |
| 실행 관점 | 이벤트·함수 호출·데이터 흐름처럼 동적인 과정을 보는 관점 |
| 질문 방향 | 학습자가 현재 개념에서 더 탐색하려는 방향 |
| 확인 방법 | 설명을 이해했는지 학습자가 직접 확인하는 실험이나 비교 |

## 책임과 경계

이 영역은 기술과 무관한 규칙만 가집니다(AD-014). 학습자에게는 다섯 사용자 스킬만 보이고, 내부 역할은 공용 참조 문서로 둡니다(AD-006, AD-007).

| 사용자 스킬 | 하는 일 | 먼저 읽는 역할 문서 |
| --- | --- | --- |
| `learn` | 학습 시작과 이어 하기, 자연어 질문의 역할 배정 | 없음(절차가 조율을 맡음) |
| `structure` | 구조 관점으로 바로 전환 | Structure Explainer |
| `trace` | 실행 관점으로 바로 전환 | Logic Explainer |
| `experiment` | 확인 방법 제안과 실험 진행 | Experiment Designer |
| `review` | 학습 상태와 질의응답 정리 | 없음(학습 정리 규칙을 읽음) |

| 역할 문서 | 맡는 일 | 속한 영역 |
| --- | --- | --- |
| Question Gate | 공개 단계 조절과 선행 지식 판정 | 학습 진행 |
| Knowledge Navigator | 질문에 맞는 설명 경로 선택과 다음 탐색 후보 제시 | 학습 진행 |
| Structure Explainer | 구조 관점 설명 | 학습 진행 |
| Logic Explainer | 실행 관점 설명 | 학습 진행 |
| Experiment Designer | 확인 방법 설계 | 학습 진행 |
| Example Builder | 기술 지식·예제·설명 경로 생성 | 기술 지식 |

Question Gate는 학습자의 되묻기를 처리할 때 기술 지식 영역에서 받은 사전 안내를 판정 근거로 읽습니다. 되묻는 용어가 그 안내에 있으면 선행 지식 부족으로 보고, 없으면 다음 탐색 후보로 넘깁니다(AD-026).

전체 조율(Top-down Tutor)은 별도 문서 없이 `learn`의 절차가 맡습니다. 학습 작업 공간과 학습 기록의 규칙도 각 영역의 공용 참조 문서로 두고, 사용자 스킬이 해당 단계에서 읽습니다.

## 실행 흐름

1. 학습 작업 공간 영역이 학습 폴더 위치를 찾지 못하면, 학습자에게 위치를 묻고 설정 파일에 저장하게 합니다(AD-011).
2. `learn` 요청의 입력이 기술 이름·코드·링크·파일 경로 중 무엇인지 판별하고, 기술 이름과 학습 목표를 정합니다. 목표가 모호하면 먼저 확인합니다.
3. 가져온 자료가 있으면 동작을 결정하는 가장 좁은 기술을 판정해 학습자에게 확인받습니다(AD-009). 기술 이름이 없는 이어 하기 요청이면 학습 기록 영역이 넘긴 기술 저장소 목록에서 고르게 합니다. 기술 이름만 있고 그 저장소가 이미 있으면, 새 예제 후보보다 먼저 기존 학습 패키지 목록과 마지막 학습 패키지를 보여 줍니다.
4. 학습 작업 공간에서 기술 저장소와 학습 패키지를 확보합니다.
5. 학습 기록 영역에서 이전 학습 상태를 받습니다.
6. Example Builder로 예제·탐색 질문·설명 경로를 받습니다. 가져온 자료가 있으면 그 자료를 기반으로 예제를 만듭니다(AD-010).
7. 관찰 유도 단계부터 학습을 시작합니다.
8. 학습자의 자연어 질문을 아래 표에 따라 역할 문서로 보냅니다.
9. 새 질문은 생소한 주제로 보고, 설명 경로에 들어가기 전에 학습자가 실행한 예제에서 관찰할 수 있는 범위로 안내를 받습니다(AD-023).
10. 사전 안내는 범위와 용어 설명, 관찰 대상으로 이루어집니다. 용어마다 정체·역할·구성 요소·사용 시점을 쓰고 다른 개념과의 관계도 그 안에 함께 담습니다(AD-024). 선행 관계가 앞에 오도록 배열된 저장 순서를 그대로 보여 준 뒤 곧바로 첫 관찰 유도로 넘어갑니다(AD-025).
11. Knowledge Navigator가 고른 설명 경로를 한 단계씩 따라가며 Question Gate로 공개 단계를 조절합니다(AD-014).
12. 학습자가 되묻는 용어가 사전 안내에 담겨 있으면 요청을 기다리지 않고 그 용어부터 다시 설명하고(AD-026), 안내에 없는 개념을 향한 질문은 다음 탐색 후보로 남깁니다.
13. 경로가 끝나면 Experiment Designer로 확인 방법을 제안하고, 다음 탐색 후보를 제시합니다.
14. 학습 상태와 질의응답, 경로 종료 신호를 학습 기록 영역에 넘깁니다.

| 질문 유형 | 질문 예 | 거치는 역할 문서 |
| --- | --- | --- |
| 개념의 이유나 동작 | 왜 이 상태 변수를 쓰는 거야? | Question Gate → Knowledge Navigator → 관점에 맞는 Explainer |
| 구조 | 이 컴포넌트는 왜 따로 분리했어? | Question Gate → Knowledge Navigator → Structure Explainer |
| 실행 순서 | 버튼을 누른 다음 어떤 순서로 실행돼? | Question Gate → Knowledge Navigator → Logic Explainer |
| 직접 확인 | 직접 확인해 보고 싶어 | Experiment Designer |
| 정리 | 지금까지 이해한 내용을 정리해 줘 | `review`와 같은 절차 |

단축키 스킬(`structure`, `trace`, `experiment`, `review`)은 진행 중인 학습이 없으면 `learn`의 1~7단계를 먼저 거칩니다. 다만 `review`는 예제를 준비하거나 학습을 시작하지 않으므로, 1단계와 3단계의 이어 하기 목록 선택, 5단계만 거친 뒤 학습 기록 영역에서 받은 상태와 질의응답을 정리합니다. 학습 폴더에 기술 저장소가 하나도 없으면 정리할 학습이 없다고 알리고 끝냅니다.

역할 문서를 고치면 그 문서를 읽는 사용자 스킬이 모두 영향을 받습니다. 역할 문서의 목록과 이름을 바꿀 때는 이 파일의 두 표를 함께 고칩니다. 따르는 결정은 AD-006, AD-007, AD-009, AD-010, AD-011, AD-014, AD-015, AD-017, AD-018, AD-020, AD-023, AD-024, AD-025, AD-026입니다.

## 위험과 미해결 질문

- 학습 목표가 명확한지 판단하는 기준이 흐리면 목표 확인 질문이 지나치게 잦거나 드물어집니다.
- Example Builder가 기술 지식을 처음 만들 때 대화 맥락을 많이 차지할 수 있습니다. 문제가 되면 이 역할만 서브에이전트로 옮깁니다.
- 스킬 지침이 세션 끝까지 남는다는 전제(AD-006)는 Claude Code 문서로 확인했습니다. Codex에서도 같은지는 확인하지 않았습니다.
