# 학습 진행

## 목적과 문제

정답을 먼저 알려 주면 학습자가 원리를 스스로 찾을 기회가 사라집니다. 이 영역은 기술이 달라도 같은 순서로 가르쳐, 학습자가 예제를 관찰하고 질문하며 원리에 다가가게 합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 목표 확인 | 학습 목표가 모호하면 개념과 예제를 만들기 전에 목표를 확인합니다 |
| 필요 개념 한정 | 설명한 개념마다 현재 질문에 필요한 이유가 있습니다 |
| 공개 단계 | 요청이 없으면 관찰 유도부터 순서대로 올리고, 지정하면 그 단계로 갑니다 |
| 확인 방법 | 설명마다 코드 변경이나 구조 비교 같은 확인 방법이 하나 이상 있습니다 |
| 두 관점 | 같은 예제에 구조 관점과 실행 관점의 설명을 각각 요청할 수 있습니다 |
| 질문 방향 | 다음 탐색 후보가 직전 질문과 이어지는 개념입니다 |
| 선형 진행 | 질문 하나의 설명이 설명 경로를 벗어나 옆 개념으로 가지 않습니다 |
| 기술 무관 | 역할 문서에 특정 기술의 이름이나 사실이 없습니다 |
| 단일 진입점 | `learn` 하나만 호출해도 학습을 끝까지 진행할 수 있습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 역할 문서 | 내부 역할 하나의 지침을 담은 공용 참조 문서 |
| 공개 단계 | 관찰 유도·힌트·부분 설명·전체 설명의 네 단계 |
| 구조 관점 | 역할·책임·경계·의존성처럼 정적인 구조를 보는 관점 |
| 실행 관점 | 이벤트·함수 호출·데이터 흐름처럼 동적인 과정을 보는 관점 |
| 질문 방향 | 학습자가 현재 개념에서 더 탐색하려는 방향 |
| 확인 방법 | 설명을 이해했는지 학습자가 직접 확인하는 실험이나 비교 |

## 책임과 경계

이 영역은 기술과 무관한 규칙만 가집니다(AD-002). 학습자에게는 다섯 사용자 스킬만 보이고, 내부 역할은 공용 참조 문서로 둡니다(AD-006, AD-007).

| 사용자 스킬 | 하는 일 | 먼저 읽는 역할 문서 |
| --- | --- | --- |
| `learn` | 학습 시작과 이어 하기, 자연어 질문의 역할 배정 | 없음(절차가 조율을 맡음) |
| `structure` | 구조 관점으로 바로 전환 | Structure Explainer |
| `trace` | 실행 관점으로 바로 전환 | Logic Explainer |
| `experiment` | 확인 방법 제안과 실험 진행 | Experiment Designer |
| `review` | 학습 상태와 질의응답 정리 | 없음(학습 기록 규칙을 읽음) |

| 역할 문서 | 맡는 일 | 속한 영역 |
| --- | --- | --- |
| Question Gate | 공개 단계 조절 | 학습 진행 |
| Knowledge Navigator | 질문에 맞는 설명 경로 선택과 다음 탐색 후보 제시 | 학습 진행 |
| Structure Explainer | 구조 관점 설명 | 학습 진행 |
| Logic Explainer | 실행 관점 설명 | 학습 진행 |
| Experiment Designer | 확인 방법 설계 | 학습 진행 |
| Example Builder | 기술 지식·예제·설명 경로 생성 | 기술 지식 |

전체 조율(Top-down Tutor)은 별도 문서 없이 `learn`의 절차가 맡습니다. 학습 작업 공간과 학습 기록의 규칙도 각 영역의 공용 참조 문서로 두고, 사용자 스킬이 해당 단계에서 읽습니다.

## 실행 흐름

1. `learn` 요청의 입력이 기술 이름·코드·링크·파일 경로 중 무엇인지 판별하고, 기술 이름과 학습 목표를 정합니다. 목표가 모호하면 먼저 확인합니다.
2. 가져온 자료가 있으면 동작을 결정하는 가장 좁은 기술을 판정해 학습자에게 확인받습니다(AD-009). 기술 이름이 없는 이어 하기 요청이면 학습 기록 영역이 찾은 최근 기술 저장소를 확인받습니다.
3. 학습 작업 공간에서 기술 저장소와 학습 패키지를 확보합니다.
4. 학습 기록 영역에서 이전 학습 상태를 받습니다.
5. Example Builder로 개념·선수 관계·예제·탐색 질문·설명 경로를 받습니다. 가져온 자료가 있으면 그 자료를 기반으로 예제를 만듭니다(AD-010).
6. 관찰 유도 단계부터 학습을 시작합니다.
7. 학습자의 자연어 질문을 아래 표에 따라 역할 문서로 보냅니다.
8. Knowledge Navigator가 고른 설명 경로를 한 단계씩 따라가며 Question Gate로 공개 단계를 조절합니다(AD-004).
9. 경로가 끝나면 Experiment Designer로 확인 방법을 제안하고, 다음 탐색 후보를 제시합니다.
10. 학습 상태와 질의응답, 경로 종료 신호를 학습 기록 영역에 넘깁니다.

| 질문 유형 | 질문 예 | 거치는 역할 문서 |
| --- | --- | --- |
| 개념의 이유나 동작 | 왜 이 상태 변수를 쓰는 거야? | Question Gate → Knowledge Navigator → 관점에 맞는 Explainer |
| 구조 | 이 컴포넌트는 왜 따로 분리했어? | Question Gate → Knowledge Navigator → Structure Explainer |
| 실행 순서 | 버튼을 누른 다음 어떤 순서로 실행돼? | Question Gate → Knowledge Navigator → Logic Explainer |
| 직접 확인 | 직접 확인해 보고 싶어 | Experiment Designer |
| 정리 | 지금까지 이해한 내용을 정리해 줘 | `review`와 같은 절차 |

단축키 스킬(`structure`, `trace`, `experiment`, `review`)은 진행 중인 학습이 없으면 `learn`의 1~6단계를 먼저 거칩니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 기술 이름과 학습 목표 | 학습 진행 | 기술 지식 |
| 개념·선수 관계·예제·탐색 질문·설명 경로 | 기술 지식 | 학습 진행 |
| 기술 이름과 학습 주제 | 학습 진행 | 학습 작업 공간 |
| 패키지 경로와 실행 방법 | 학습 작업 공간 | 학습 진행 |
| 이전 학습 상태 | 학습 기록 | 학습 진행 |
| 학습 상태·질의응답·경로 종료 신호 | 학습 진행 | 학습 기록 |

역할 문서를 고치면 그 문서를 읽는 사용자 스킬이 모두 영향을 받습니다. 역할 문서의 목록과 이름을 바꿀 때는 이 파일의 두 표를 함께 고칩니다. 따르는 결정은 AD-002, AD-004, AD-006, AD-007, AD-009, AD-010입니다.

## 위험과 미해결 질문

- 학습 목표가 명확한지 판단하는 기준이 흐리면 목표 확인 질문이 지나치게 잦거나 드물어집니다.
- 질문 유형이 둘에 걸치면(예: 구조이면서 실행 순서) 어느 역할로 보낼지 기준이 필요합니다.
- Example Builder가 기술 지식을 처음 만들 때 대화 맥락을 많이 차지할 수 있습니다. 문제가 되면 이 역할만 서브에이전트로 옮깁니다.
