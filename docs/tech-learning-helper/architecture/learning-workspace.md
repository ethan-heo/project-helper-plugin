# 학습 작업 공간

## 목적과 문제

설명만 읽어서는 동작을 확인할 수 없습니다. 이 영역은 학습자가 예제를 실행하고 고쳐 보며 설명을 직접 확인할 공간을 제공합니다.

## 요구사항과 품질 속성

| 요구사항 | 판정 기준 |
| --- | --- |
| 즉시 실행 | 예제를 고치지 않고 바로 실행할 수 있습니다 |
| 실험 | 학습자가 예제를 고쳐 다시 실행할 수 있습니다 |
| 실험 전후 비교 | 실험으로 무엇이 바뀌었는지 git으로 비교할 수 있습니다 |
| 독립 실행 | 다른 학습 패키지 없이 그 패키지의 예제가 실행됩니다 |
| 프로젝트 분리 | 학습자가 작업 중인 프로젝트에 예제 파일이 생기지 않습니다 |
| 저장소 중복 방지 | 같은 기술의 저장소가 비슷한 이름으로 둘 이상 생기지 않습니다 |
| 원본 참조 | 가져온 자료로 만든 패키지마다 원본 위치와 발췌가 남습니다 |

## 개념 모델

| 개념 | 뜻 |
| --- | --- |
| 학습 폴더 | 모든 기술 저장소를 담는, 학습자가 첫 `learn`에서 정한 폴더 |
| 설정 파일 | 학습 폴더 위치를 담은, 홈 디렉터리 아래 고정 경로의 파일 |
| 기술 저장소 | 기술 하나의 학습 패키지를 모은 git 저장소 |
| 학습 패키지 | 학습 주제 하나의 예제를 담아 따로 실행하는 단위 |
| 원본 자료 | 가져온 자료의 원본 참조와 질문에 해당하는 발췌 |
| 실험 | 학습자가 예제를 고쳐 결과를 확인하는 일 |

## 책임과 경계

이 영역은 학습 폴더와 기술 저장소, 학습 패키지를 만들고 예제를 실행할 환경을 갖추는 일을 맡습니다(AD-003). 학습 폴더의 위치는 첫 `learn`에서 학습자가 정하며, Claude Code와 Codex의 모든 스킬이 같은 설정 파일에서 읽습니다(AD-011). 기술 저장소 안의 패키지는 의존성을 공유할 수 있지만, 각 패키지는 따로 실행되어야 합니다.

가져온 자료는 동작을 결정하는 가장 좁은 기술의 저장소에 넣으며, 비슷한 이름의 저장소가 있으면 새로 만들지 않고 그 저장소를 제안합니다(AD-009). 판정 결과를 학습자에게 확인받는 일은 학습 진행 영역이 맡습니다. 가져온 자료로 만든 패키지에는 원본 자료를 함께 둡니다(AD-010).

예제의 내용은 기술 지식 영역이 만들고, 실험을 제안하는 일은 학습 진행 영역이 맡습니다. 이 영역의 규칙은 공용 참조 문서로 두고, 사용자 스킬이 저장소와 패키지를 확보하는 단계에서 읽습니다(AD-007).

## 실행 흐름

1. 설정 파일에서 학습 폴더 위치를 읽습니다. 파일이 없거나 가리키는 폴더가 없으면 학습 진행 영역에 위치 확인을 요청합니다.
2. 학습 진행 영역에서 기술 이름과 학습 주제를 받습니다.
3. 학습 폴더에 해당 기술 저장소가 없으면 비슷한 이름의 저장소를 먼저 찾아 제안하고, 없으면 새로 만들어 git 저장소로 초기화합니다.
4. 학습 주제의 패키지가 없으면 만들고, 패키지 경로를 학습 진행 영역에 넘깁니다.
5. 기술 지식 영역이 만든 예제와, 가져온 자료가 있으면 원본 자료를 패키지에 넣습니다.
6. 예제를 처음 넣은 상태를 커밋해, 실험 뒤 달라진 내용을 비교할 기준으로 삼습니다.
7. 패키지의 실행 방법을 학습 진행 영역에 넘깁니다.

## 계약

| 정보 | 보내는 쪽 | 받는 쪽 |
| --- | --- | --- |
| 학습 폴더 위치 | 학습 진행 | 학습 작업 공간 |
| 기술 이름과 학습 주제 | 학습 진행 | 학습 작업 공간 |
| 예제 코드와 원본 자료 | 기술 지식 | 학습 작업 공간 |
| 패키지 경로와 실행 방법 | 학습 작업 공간 | 학습 진행 |

기술 저장소와 패키지의 이름 규칙은 계획서에서 정합니다. 설정 파일의 경로와 형식은 계획서에서 정합니다. 따르는 결정은 AD-003, AD-007, AD-009, AD-010, AD-011입니다.

## 위험과 미해결 질문

- 학습자 컴퓨터에 예제 언어의 실행 환경이 없으면 예제를 실행할 수 없습니다.
- 로컬 파일의 발췌는 질문에 필요한 줄로 한정하지만, 그 줄은 학습 저장소의 git 이력에 남습니다.
