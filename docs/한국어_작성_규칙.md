# 한국어 작성 규칙

이 문서는 저장소의 문서와 커밋 메시지를 한국어로 쓸 때 적용한다. 문서의 배치·구조·참조는 [`문서_작성_기준.md`](문서_작성_기준.md)가 정하고, 이 문서는 그 안에 들어갈 문장을 어떻게 쓸지만 다룬다. `AGENTS.md`의 공통 규칙과 충돌하면 `AGENTS.md`를 우선한다.

스킬이 만드는 산출물에는 [`plugins/project-helper/skills/_shared/writing-style.md`](../plugins/project-helper/skills/_shared/writing-style.md)를 적용한다. 산출물은 사용자의 저장소에 놓이므로 규칙을 따로 관리한다.

## 언어 선택

- 문서 본문과 커밋 메시지는 한국어로 쓴다.
- 코드 식별자와 파일명은 영문 kebab-case를 사용한다.
- 이름이 커밋 제목이나 사용자가 정한 주제에서 그대로 오는 산출물은 한국어 이름을 유지한다. 원본과 이름이 어긋나면 대상을 되짚어 찾아야 하기 때문이다.

## 문체

- 기술 문서는 간결한 해요체가 아닌 `~합니다`체를 기본으로 한다.
- 주어가 분명하면 생략하고, 번역투의 긴 수식과 불필요한 수동 표현을 피한다.
- 추상적인 명사보다 구체적인 동사를 우선한다.
- 같은 문단에서 종결어미·용어·호칭을 섞지 않는다.

## 문단

- 한 문단은 하나의 중심 생각만 다룬다.
- `이를 통해`, `또한`, `따라서`, `특히`, `기반으로`, `효과적으로` 같은 연결어는 논리상 필요할 때만 쓴다.
- 한 문장에 독립된 지시가 여럿 있으면 문장을 나눈다.

## 어휘

문자 그대로 읽어도 뜻이 통하는 말을 쓴다. 비유 어휘는 읽는 사람이 가리키는 대상을 짐작하게 만들고, 그 짐작은 사람마다 다르다.

스킬 문서에도 `plugins/project-helper/skills/_shared/writing-style.md`의 어휘 절을 적용한다. 스킬 문서에 쓴 비유 어휘는 스킬이 만드는 산출물에 그대로 옮겨 간다.

## 용어

- 동일한 개념에는 문서 전체에서 하나의 용어를 사용한다.
- 프로젝트 용어는 `AGENTS.md`와 기존 스킬 문서를 우선한다.
- 정착된 번역어가 있으면 쓰고, 없으면 원어를 그대로 둔다.

## 표기

| 대상 | 표기 |
| --- | --- |
| 파일명과 코드 식별자 | 영문 kebab-case |
| 파일 경로·명령·코드 식별자 | 인라인 코드 |
| 날짜 | `YYYY-MM-DD` |

## 작성 전 점검

- 종결어미와 용어가 문서 전체에서 일관적인가?
- 각 문단이 하나의 중심 생각만 다루는가?
- 번역투 수식이나 불필요한 수동 표현이 남아 있는가?
- 연결어가 논리상 필요한 자리에만 있는가?
- 같은 개념을 가리키는 용어가 문서마다 다르지 않은가?
- 날짜·경로·식별자 표기가 위 표를 따르는가?
