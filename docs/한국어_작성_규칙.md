# 한국어 작성 규칙

이 문서는 저장소의 문서와 커밋 메시지를 한국어로 쓸 때 적용합니다. 다루는 대상은 문장 자체이며, 문서의 배치·구조·참조는 [`문서_작성_기준.md`](문서_작성_기준.md)가 정합니다. `AGENTS.md`의 공통 규칙과 충돌하면 `AGENTS.md`를 우선합니다.

스킬이 만드는 산출물에는 그 플러그인의 `writing-style.md`를 적용합니다. 산출물은 이 저장소가 아니라 사용자의 저장소에 놓이므로 규칙을 따로 둡니다.

## 핵심 원칙

**독자가 한 번에 이해하는 문장을 씁니다. 문법적 정확성은 그다음입니다.**

문법에 맞아도 두 번 읽어야 뜻이 잡히는 문장은 고칩니다. 번역문이 아니라 한국어로 직접 쓴 실무 보고서의 문체를 씁니다. 문장을 짧게 쓰고 군더더기 수식을 덜어냅니다.

## 문장

- 한 문장에는 핵심 정보 하나만 담습니다. 독립된 지시가 여럿이면 문장을 나눕니다.
- 추상명사와 명사형 표현을 구체적인 동사로 바꿉니다.
- 완곡한 표현 대신 단정적인 서술을 씁니다. 표현이 완곡하면 읽는 사람이 지시인지 참고인지 되짚어야 합니다.
- 번역투의 긴 수식과 불필요한 수동 표현을 피합니다.
- 앞 문장에서 주어가 분명하면 생략합니다.

| 쓰지 않는 표현 | 쓰는 표현 |
| --- | --- |
| 검토를 진행합니다 | 검토합니다 |
| 적용이 이루어집니다 | 적용합니다 |
| 중요하다고 할 수 있습니다 | 중요합니다 |
| 필요성이 제기됩니다 | 필요합니다 |

## 문단

- 첫 문장에 핵심을 적고 근거와 설명을 뒤에 둡니다. 문맥상 다른 순서가 자연스러우면 그 순서를 따릅니다.
- 한 문단은 하나의 중심 생각만 다룹니다.
- 인과관계는 접속어를 덧붙이기보다 정보 순서와 문장 구조로 드러냅니다. 두 문장의 관계를 읽는 사람이 짐작하게 두지 않습니다.
- `이를 통해`, `나아가`, `이러한 맥락에서`, `또한`, `따라서`, `특히`, `기반으로`, `효과적으로` 같은 연결어는 논리상 필요할 때만 씁니다. 같은 연결어를 연달아 반복하지 않습니다.

## 문체

- 저장소의 문서는 `~합니다`체로 씁니다. 해요체는 쓰지 않습니다.
- 같은 문단에서 종결어미·용어·호칭을 섞지 않습니다.

## 어휘

문자 그대로 읽어도 뜻이 통하는 말을 씁니다. 비유 어휘를 쓰면 읽는 사람이 그 말의 대상을 짐작해야 하고, 짐작은 사람마다 갈립니다.

스킬 문서를 쓸 때는 그 플러그인 `writing-style.md`의 어휘 절도 함께 적용합니다. 스킬 문서에 쓴 비유 어휘는 스킬이 만드는 산출물에 그대로 옮겨 가기 때문입니다.

## 용어

- 동일한 개념에는 문서 전체에서 하나의 용어를 사용합니다.
- 프로젝트 용어는 `AGENTS.md`와 기존 스킬 문서를 우선합니다.
- 정착된 번역어가 있으면 쓰고, 없으면 원어를 그대로 둡니다.

## 표기

문서 본문과 커밋 메시지는 한국어로 씁니다. 이름이 커밋 제목이나 사용자가 정한 주제에서 그대로 오는 산출물은 한국어 이름을 유지합니다. 이름이 원본과 어긋나면 읽는 사람이 대상을 다시 찾아야 하기 때문입니다.

| 대상 | 표기 |
| --- | --- |
| 새로 만드는 파일과 코드 식별자의 이름 | 영문 kebab-case |
| 본문에 적는 파일 경로·명령·코드 식별자 | 인라인 코드 |
| 날짜 | `YYYY-MM-DD` |

## 사실 보존

문장을 고칠 때 원문의 사실관계와 의미를 유지합니다. 근거가 없는 내용을 새로 넣지 않습니다. 분량을 줄이려고 조건이나 예외를 빼지 않습니다.

## 작성 후 점검

아래 질문에 모두 '예'로 답할 수 있어야 합니다.

- 두 번 읽어야 뜻이 잡히는 문장을 모두 고쳤는가?
- 각 문단이 핵심을 먼저 제시하는가?
- 한 문장이 핵심 정보 하나만 담고 있는가?
- 추상명사로 뭉뚱그린 서술을 구체적인 동사로 바꿨는가?
- 완곡한 표현을 단정적인 서술로 바꿨는가?
- 같은 연결어가 반복되지 않는가?
- 문장 사이의 인과관계가 드러나는가?
- 종결어미와 용어가 문서 전체에서 일관적인가?
- 고치기 전후로 사실관계가 그대로인가?
- 날짜·경로·식별자 표기가 위 표를 따르는가?
