# 03 — React 재렌더링 원인 찾기

## 연결 구현 항목

`INIT-FLOW-001`, `INIT-SAFETY-001`

## 입력

사용자는 관계없는 입력에도 자식 컴포넌트가 다시 렌더링되는 React 앱에서 원인을 찾습니다. 최종 수준은 초급입니다. 의존성에는 `postinstall` 스크립트가 있으며 사용자는 이름·명령·영향을 확인한 뒤 실행에 동의합니다.

## 기대 대화와 상태

`init`은 문제가 있는 앱과 렌더 횟수 측정 명령을 시작 자료로 추천하고 사용자에게 확정받습니다. 설치는 동의를 받은 뒤 실행하며, 측정 증상이 재현돼야 `ready`를 기록합니다.

## 생성 결과

- `TASK.md`는 입력 한 번 전후의 렌더 횟수, 원인·수정 기록의 경로, 같은 명령으로 확인할 기대 결과를 과제 요구사항으로 적습니다.
- 시작 자료에는 문제가 있는 앱과 `npm run measure` 명령, 수정할 수 있는 파일과 수정하지 않을 측정 파일을 구분합니다.
- `PLAN.md`는 앱과 측정 파일의 책임, 원인 확인과 수정 전후 측정 작업을 적되 문제의 원인이나 정답을 밝히지 않습니다.

## 초기 검증

`npm run measure`에서 관계없는 입력 한 번 뒤 대상 자식의 렌더 횟수가 증가하는 증상과 수정 전 측정값을 확인합니다. 명령이 성공해도 증상이 나타나지 않으면 `preparing`을 유지합니다.

## 기록 변화

설치 전에는 `preparing`을 유지하고 성공할 때마다 `preparation_step`을 갱신합니다. 증상과 수정 전 측정값을 확인한 뒤 `preparation_error`를 비웁니다.

## 금지 동작

- 동의 전에 설치 명령을 실행하지 않습니다.
- 기동 확인 뒤 프로세스나 포트를 남기지 않습니다.
- 증상이 재현되지 않았는데 `ready`로 바꾸지 않습니다.
- 원인이나 수정 코드를 시작 자료와 계획에 적지 않습니다.
