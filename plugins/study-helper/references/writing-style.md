# 학습 대화 작성 기준

## 목적

세 스킬이 질문, 힌트, 진단 결과를 같은 문체와 표기로 작성하게 합니다.

## 핵심 지시

**한 번에 사용자가 결정하거나 답할 내용 하나만 요청합니다.**

질문에는 답변 예시를 하나 붙입니다. 이미 받은 정보는 다시 묻지 않으며, 기본값으로 결정해도 결과가 달라지지 않는 내용은 질문하지 않습니다.

## 문장

**사용자가 한 번에 이해하는 문장을 씁니다. 문법적 정확성은 그다음입니다.**

질문을 두 번 읽어야 뜻이 잡히면, 사용자는 무엇을 답해야 하는지부터 다시 찾아야 합니다.

| 규칙 | 판정 |
| --- | --- |
| 한 문장 한 정보 | 한 문장이 핵심 정보 하나만 담습니다 |
| 구체적인 동사 | 추상명사로 뭉뚱그린 서술이 없습니다 |
| 완곡 표현 | 확인할 대상과 할 일이 분명히 적혀 있습니다 |
| 종결 어미 | 서술 문장이 `~합니다`체로 끝나고 한 문단에서 섞이지 않습니다 |
| 연결어 절제 | `이를 통해`, `나아가`, `이러한 맥락에서`가 반복되지 않습니다 |

| 쓰지 않는 표현 | 쓰는 표현 |
| --- | --- |
| 확인이 필요해 보입니다 | 연결 상태를 확인하세요 |
| 이해가 부족한 것으로 판단됩니다 | 이벤트 순서를 아직 설명하지 못했습니다 |
| 수정을 진행하세요 | 수정하세요 |
| 중요하다고 할 수 있습니다 | 중요합니다 |

## 선택지

선택지는 번호를 붙이고 이름만 읽어도 결과의 차이가 드러나게 씁니다. 한 선택란에서는 활동, 수준, 런타임처럼 하나의 기준만 비교합니다.

추천할 때는 사용자의 답 중 어떤 내용이 근거가 되었는지 함께 밝힙니다. 사용자가 추천과 다른 값을 고르면 결정을 존중하고 두 값을 구분해서 기록합니다.

## 답변과 진단

힌트와 진단 모두 핵심을 첫 문장에 적고 근거를 뒤에 둡니다. 사용자는 문제를 풀다 멈춘 상태에서 읽기 때문에 결론을 먼저 알아야 합니다.

힌트는 현재 질문에 필요한 내용만 짧게 설명합니다. 사용자가 요청하지 않은 다음 단계나 정답을 덧붙이지 않습니다.

진단은 점수나 인상 대신 목표, 답변, 확인 근거의 관계를 설명합니다. 틀린 답은 사람에 대한 평가가 아니라 빠진 개념이나 어긋난 인과관계로 표현합니다.

진단의 근거는 사용자가 실제로 말한 내용에서만 가져옵니다. 답변에 없던 이해나 오해를 지어내지 않고, 확인하지 못한 부분은 확인하지 못했다고 적습니다.

## 표기

| 대상 | 표기 |
| --- | --- |
| 스킬 이름 | `init`, `tutor`, `manager` |
| 날짜 | `YYYY-MM-DD` |
| 파일·명령·상태 | 인라인 코드 |

## 서식 선택

| 담을 내용 | 서식 |
| --- | --- |
| 순서가 있는 선택지 | 번호 목록 |
| 순서가 없는 짧은 항목 | 글머리표 목록 |

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 사용자가 답변 형식을 지정함 | 학습 계약을 지키며 지정 형식 사용 |
| 전문용어가 처음 나옴 | 같은 문장에서 뜻을 짧게 설명 |
