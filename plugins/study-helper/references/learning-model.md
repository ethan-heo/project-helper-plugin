# 학습 모델

## 목적

세 스킬이 학습 활동, 수준, 목표, 진단 결과를 같은 뜻으로 사용하게 합니다.

## 학습 활동

**학습 활동은 예제에서 사용자가 직접 하는 일로 정합니다.**

| 활동 유형 | 사용자가 남기는 것 | 확인 방법 |
| --- | --- | --- |
| 만들기 | 실행 가능한 코드 | 실행·측정 결과 |
| 원인 찾기 | 원인과 수정 기록 | 수정 전후 측정값 |
| 동작 관찰 | 관찰 기록 | 재현 결과 |
| 방식 비교 | 비교 결과와 선택 근거 | 같은 조건의 비교 결과 |

활동은 시작 상태, 산출물, 확인 방법의 세 속성으로 설명합니다. 후보마다 활동 한 문장, 세 속성, 추천 근거를 제시합니다.

같은 기술의 앞선 예제와 산출물이 다르면 겹치지 않습니다. 산출물이 같을 때는 활동이 요구하는 동작까지 같아야 겹친 것으로 판정합니다.

## 학습 수준

**수준은 활동을 바꾸지 않고 제공할 도움의 깊이를 정합니다.**

| 수준 | 판정 기준 | 만들기 활동의 시작 상태 | 진행 방향과 의존성 설명 |
| --- | --- | --- | --- |
| 입문 | 기술을 처음 접함 | 동작하는 예제 | 읽는 순서·수정 위치·의존성 역할 |
| 초급 | 예제를 따라 해 봄 | 핵심이 빈 뼈대 | 채우는 순서·사용 시점 |
| 중급 | 직접 만들어 봄 | 빈 폴더 | 핵심 질문·개념 키워드·사용 시점 |
| 숙련 | 설계 대안을 비교함 | 빈 폴더 | 설계 쟁점·비교 기준·역할 |

만들기가 아닌 활동의 시작 상태는 수준과 관계없이 활동이 정합니다. 어느 수준에서도 정답이나 사용자가 남길 산출물을 미리 채우지 않습니다.

## 학습 목표와 진단 기준

**목표는 예제를 마친 뒤 확인할 수 있는 행동으로 작성합니다.**

목표 하나에는 조건, 결과, 이유, 행동을 담습니다. 문장은 `<조건>이면 <결과>가 되는 이유를 <행동한다>` 형식으로 쓰며 행동에는 `설명한다`, `재현한다`, `예측한다` 중 하나를 사용합니다.

목표마다 배경의 어느 문제와 이어지는지 적습니다. 완성 조건은 연결된 목표를 표시하고 모든 목표에 하나 이상의 완성 조건을 둡니다.

**각 목표에는 다음 진단 기준을 함께 기록합니다.**

| 기준 | 뜻 |
| --- | --- |
| 필수 개념 | 설명에 반드시 들어가야 하는 개념 |
| 필수 근거 | 결론을 뒷받침해야 하는 관찰·실행 결과 |
| 대표 오개념 | 원인과 결과를 잘못 연결한 판단 |

## 진단 결과

**`manager`는 목표마다 다음 세 결과 중 하나를 기록합니다.**

| 결과 | 판정 기준 |
| --- | --- |
| 독립 설명 | 필수 개념과 근거를 도움 없이 연결하고 대표 오개념이 없음 |
| 부분 이해 | 방향은 맞지만 개념·근거가 빠지거나 도움 이력에 의존함 |
| 재학습 필요 | 설명이 목표에 닿지 않거나 대표 오개념을 고치지 못함 |

결과가 섞이면 `재학습 필요`, `부분 이해`, `독립 설명` 순으로 낮은 목표를 먼저 다룹니다.

## 예제 범위

**학습 목표에 직접 필요한 기능만 예제에 넣습니다.**

기능이 어느 목표에 쓰이는지 한 문장으로 설명할 수 없거나, 그 기능을 먼저 이해해야 목표에 닿을 수 있으면 범위에서 뺍니다. 제외한 기능은 이유와 함께 `TASK.md`에 남깁니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 활동의 확인 방법을 정할 수 없음 | 완료 여부를 무엇으로 확인할지 질문 |
| 목표와 연결되지 않은 완성 조건 | 조건 삭제 또는 목표 연결 보완 |
| 진단 근거가 부족함 | 결과를 추측하지 않고 필요한 설명 요청 |
