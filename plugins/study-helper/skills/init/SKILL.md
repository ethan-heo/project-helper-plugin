# init

## 역할과 목적

`init`은 배우고 싶은 기술 하나를 받아, 사용자가 직접 구현할 예제를 낸다. 예제를 만들기 전에 `tutor` 문서의 절차로 학습자 수준과 학습 목표를 정하고, 그 수준에 맞는 형태로 예제와 환경을 준비한다.

사용자는 무엇을 배울지 정하는 결정권자이고, AI는 질문·예제 선정·환경 준비를 맡는다.

## 실행 원칙

**수준을 받기 전에 예제를 만들지 않고, 그 수준이 정한 범위를 넘겨 만들어 주지 않는다.**

## 읽는 것과 쓰는 것

| 대상 | 권한 |
| --- | --- |
| 사용자가 건넨 경로·링크·코드 조각·글 | 읽기만 한다 |
| `tutor/SKILL.md`의 `예제 구성 방향` 절 | 읽기만 한다 |
| 현재 디렉터리의 예제 폴더들의 `TASK.md` | 읽기만 한다 |
| 새 예제 폴더의 `README.md`·`TASK.md`·`PLAN.md` | 만들고 쓴다 |
| `.study/records/` 아래 그 예제의 기록 파일 | 만들고 `예제` 절만 쓴다 |

`PLAN.md`는 빈 양식으로 만들고 내용을 채우지 않는다. 사용자가 쓰는 문서이기 때문이다.

예제 폴더에 예제를 완성하는 코드를 만들지 않는다. 다만 입문 수준에서는 실행되는 예제를 주고 동작을 설명한다. 어느 수준에서 무엇을 주는지는 `tutor` 문서의 `예제 구성 방향` 절이 정한다.

## 참조 문서 규칙

이 문서가 `init`의 실행 지시사항을 정하는 기준 문서다.

| 문서 | 역할 | 읽는 시점 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 판정 기준 | `init` 전체 |
| `../tutor/SKILL.md`의 `예제 구성 방향` 절 | 수준·학습 목표·예제 범위 결정 절차 | 예제를 만들기 전 |
| `assets/readme-template.md` | 예제 폴더 `README.md` 양식 | 예제를 기록할 때 |
| `assets/task-template.md` | `TASK.md` 양식 | 예제를 기록할 때 |
| `assets/plan-template.md` | `PLAN.md` 양식 | 예제를 기록할 때 |
| `assets/record-template.md` | 기록 파일 양식 | 예제를 기록할 때 |

## 실행 절차

### 1. 입력을 해석한다

**사용자가 기술 이름과 함께 자료를 건넸으면 무엇을 건넸는지 가리고 내용을 읽어 온다.**

| 형식 | 판정 기준 | 읽는 방법 |
| --- | --- | --- |
| 로컬 경로 | 현재 디렉터리 기준으로 존재하는 파일이나 폴더다 | 그 경로의 코드를 읽는다 |
| 외부 링크 | `http`나 `https`로 시작한다 | 문서를 받아 본문을 읽는다 |
| 코드 조각 | 여러 줄이고 들여쓰기나 문법 기호를 담는다 | 그대로 판정 재료로 쓴다 |
| 붙여넣은 글 | 위 셋에 해당하지 않는 여러 줄 텍스트다 | 그대로 판정 재료로 쓴다 |

가린 형식을 응답에 한 줄로 적는다. 사용자가 무엇을 건넸다고 해석했는지 드러내기 위해서다.

읽어 온 내용은 다음 단계의 수준 판정 근거로만 쓴다. 예제 정보에 옮겨 적지 않는다. 사용자의 코드가 예제 폴더로 흘러들지 않게 하기 위해서다.

기술 이름만 주고 자료를 건네지 않았으면 이 단계를 건너뛴다.

### 2. 예제 방향을 정하고 범위를 확인한다

**`tutor/SKILL.md`의 `예제 구성 방향` 절을 읽고 그 절차를 이 대화에서 수행한다.**

읽는 범위는 그 절 하나다. `질문에 답하기` 절은 읽지 않는다. 그 절은 사용자가 `tutor`를 부를 때 쓰는 절차다.

그 절의 순서는 수준 받기, 건넨 자료 더하기, 학습 목표 정하기, 예제 범위 정하기다.

**수준을 묻는 질문과 배울 범위를 묻는 질문은 한 번에 던진다.**

| 묻는 것 | 형식 |
| --- | --- |
| 학습자 수준 | 네 수준의 선택지 |
| 배울 범위 | 무엇을 만들 수 있게 되고 싶은지 자유 서술 |

따로 던지면 사용자가 비슷한 질문을 두 번 받는다. 배울 범위의 답으로 만들 대상 하나를 한 문장으로 적을 수 있어야 하며, 그렇지 않으면 질문을 이어 간다.

**현재 디렉터리의 예제 폴더들에서 `TASK.md`의 맨 위 표를 읽어 겹치는지 확인한다.**

| 판정 | 기준 |
| --- | --- |
| 같은 기술 | 표의 기술 값이 이번 호출의 기술과 같다 |
| 겹침 | 앞선 만들 대상과 이번 만들 대상이 같은 동작을 요구한다 |

기술 이름의 표기가 달라 같은 기술인지 판단하기 어려우면 추측하지 않고 사용자에게 확인한다. 겹치지 않는 만들 대상을 찾지 못하면 앞선 예제 목록을 보여 주고 범위를 다시 묻는다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 기술 이름도 자료도 없이 불렀다 | 무엇을 공부할지 묻고 기다린다 |
| `tutor/SKILL.md`를 읽을 수 없다 | 예제를 만들지 않고 읽지 못한 경로를 알린다 |
| 사용자가 예제 코드를 대신 써 달라고 한다 | 수준이 정한 범위를 넘겨 쓰지 않는다 |
| 건넨 경로가 존재하지 않는다 | 그 사실을 알리고 자료 없이 진행할지 묻는다 |
| 건넨 링크를 받아 오지 못했다 | 읽지 못한 주소를 알리고 자료 없이 진행할지 묻는다 |
| 건넨 자료가 지나치게 크다 | 전부 읽지 않고 읽은 범위를 알린다 |
| 입력의 형식을 가릴 수 없다 | 붙여넣은 글로 보고 진행한다 |
| `TASK.md`를 읽을 수 없는 폴더가 있다 | 그 폴더를 겹침 판정에서 빼고 건너뛴 폴더를 알린다 |
| 사용자가 수준 선택을 건너뛰려 한다 | 예제를 만들지 않고 네 수준을 다시 보인다 |
| 사용자가 예제를 바로 달라고 한다 | 묶은 질문을 한 번은 하고, 답을 받은 뒤 진행한다 |

## 경계

**사용자가 하려는 일에 따라 부르는 스킬이 갈린다.**

| 사용자가 하려는 것 | 부르는 스킬 |
| --- | --- |
| 예제를 새로 받기 | `init` |
| 구현 중 모르는 것 묻기 | `tutor` |
| 마친 예제를 복습하고 진단받기 | `manager` |

수준 판정과 학습 목표 결정은 `tutor` 문서의 절차를 읽어 이 스킬의 대화에서 수행한다. 사용자가 `tutor`를 따로 부르지 않는다.

- 예제를 완성하는 코드와 정답은 제시하지 않는다.
- 개념을 풀어 주는 강의는 이 스킬의 범위가 아니다.
