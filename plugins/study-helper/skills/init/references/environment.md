# 언어와 런타임 결정

## 목적

확정한 학습 활동을 실행할 언어와 런타임을 불필요한 질문 없이 결정합니다.

## 후보 판정

**기술, 사용자가 건넨 자료, 확정한 활동, 로컬 설치 상태에서 실행 가능한 후보를 찾습니다.**

| 후보 수 | 할 일 |
| --- | --- |
| 0개 | 설치를 시도하지 않고 지원할 환경 질문 |
| 1개 | 후보와 선택 근거를 알리고 그대로 기록 |
| 2개 이상 | 차이가 드러나는 선택지를 보이고 하나씩 확정 |

언어가 정해진 뒤 해당 언어에서 런타임이 여러 개면 런타임만 다시 묻습니다. 사용자가 이미 언어와 런타임을 지정했고 실행할 수 있으면 다시 묻지 않습니다.

## 기록

선택한 언어와 런타임 이름·버전을 기록의 `language`, `runtime`에 씁니다. `TASK.md`에는 같은 값을 사람이 읽는 이름으로 적습니다.

## 의존성 설치

**설치 명령을 실행하기 전에 패키지 생명주기 스크립트를 확인합니다.**

루트 패키지와 설치될 의존성이 실행할 `preinstall`, `install`, `postinstall`, 빌드 훅을 찾습니다. 스크립트가 있으면 이름, 실행 명령, 파일·네트워크·시스템에 줄 수 있는 영향을 알리고 사용자 동의를 받습니다.

동의하기 전에는 설치 명령을 실행하지 않습니다. 거절하면 대체 패키지나 스크립트를 끄는 설치 방법이 있는지 확인하고, 없으면 준비 실패로 기록합니다.

## 기동 확인과 종료

**끝나지 않는 프로세스는 식별자를 보관하고 기동 확인 뒤 종료합니다.**

기본 제한은 60초입니다. 예제 특성상 더 필요하면 최대 120초까지 늘릴 수 있으며, 제한 시간과 이유를 `TASK.md`에 기록합니다.

기동 성공이나 시간 초과 뒤에는 사용한 포트, 시작한 프로세스, 자식 프로세스가 남았는지 확인하고 모두 종료합니다. 종료를 확인하기 전에는 준비 완료로 기록하지 않습니다.

## 초기 상태 검증

**시작 자료를 만든 뒤 활동에 맞는 명령으로 사용자가 작업하기 전 상태를 확인합니다.**

| 활동 | 실행할 검증 | 통과 조건 |
| --- | --- | --- |
| 만들기 | `TASK.md`에 적은 제공 테스트 명령 | 테스트가 한 개 이상 발견되고 `STUDY_NOT_IMPLEMENTED` 오류로 실패 |
| 원인 찾기 | 증상 재현과 측정 명령 | 증상과 수정 전 측정값 재현 |
| 동작 관찰 | 결과 재현 명령 | 관찰할 결과 재현 |
| 방식 비교 | 두 대상의 공통 측정 명령 | 같은 조건에서 두 결과 측정 |

만들기 활동에서는 테스트 실행기의 요약과 종료 코드를 함께 확인합니다. 테스트가 0개이면 종료 코드가 0이어도 실패입니다. 한 개 이상이 통과해도 전체 결과에서 `STUDY_NOT_IMPLEMENTED`를 확인할 수 있어야 합니다.

다음 결과는 예상한 미구현 실패가 아닙니다.

- 테스트가 한 개도 발견되지 않음
- 테스트가 모두 통과함
- 문법·설정·의존성 오류로 실패함
- 실패 출력에 `STUDY_NOT_IMPLEMENTED`가 없음

통과 조건을 충족하지 못하면 기록의 `status`를 `preparing`으로 유지합니다. `preparation_error`에는 테스트 개수와 실제 실패 원인을 적고 기준 커밋을 만들지 않습니다.

원인 찾기·동작 관찰·방식 비교 활동은 성공 종료만으로 준비를 완료하지 않습니다. `TASK.md`에 적은 증상이나 결과, 측정값이 실제로 나왔는지 확인합니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 지정한 런타임이 설치되지 않음 | 설치하지 않고 다른 후보 선택 요청 |
| 후보 차이가 학습 목표에 영향 없음 | 준비 시간이 짧은 후보 추천과 근거 제시 |
| 자료와 사용자 지정 환경이 다름 | 차이를 알리고 사용자 지정 환경 유지 |
| 설치 스크립트 실행을 거절함 | 대체 방법 안내 또는 준비 실패 기록 |
| 기동 확인이 120초를 넘김 | 프로세스 종료와 실패 단계 기록 |
| 포트나 자식 프로세스가 남음 | 강제 종료 후 남은 자원 재확인 |
| 만들기 테스트가 0개임 | 테스트 검색 설정을 고치고 `preparing` 유지 |
| 만들기 테스트가 처음부터 통과함 | 핵심 테스트의 요구 동작을 확인하고 `preparing` 유지 |
| 미구현 표식 없이 테스트가 실패함 | 실제 오류를 고치고 `preparing` 유지 |
