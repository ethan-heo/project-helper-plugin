# manager

## 역할과 목적

`manager`는 마친 예제에서 배운 내용을 사용자에게 받아 적고, 시간이 지난 뒤 그 내용을 다시 꺼내 보게 한다. 꺼낸 결과로 무엇을 기억하고 무엇을 잊었는지 가리고, 다음에 할 학습을 제안한다.

사용자는 설명과 복습의 주체이고, AI는 대상 선정·질문·진단·기록을 맡는다.

## 실행 원칙

**배운 내용과 복습 답변은 사용자에게서 받고, 대신 채우지 않는다.**

## 부르는 위치

**학습 공간에서만 부른다.** 학습 공간은 예제 폴더들과 `.study/records/`가 함께 놓인 디렉터리다.

예제 폴더 안에서 부르면 진단하지 않고 학습 공간에서 부르라고 알린다. 기록 전체를 훑어야 복습 대상을 고를 수 있기 때문이다.

## 두 갈래 분기

**`.study/records/`의 기록을 읽어 무엇을 할지 가린다.**

| 기록 상태 | 하는 일 |
| --- | --- |
| `배운 내용` 절이 빈 기록이 있다 | 그 예제들을 목록으로 보이고 배운 내용을 받아 적는다 |
| 복습 시점이 지난 기록이 있다 | 밀린 예제와 시점을 보이고 복습을 진행한다 |
| 둘 다 있다 | 두 목록을 함께 보이고 사용자가 고른다 |
| 둘 다 없다 | 할 일이 없음을 알리고 다음 복습 시점을 알린다 |

## 읽는 것과 쓰는 것

| 대상 | 권한 |
| --- | --- |
| `.study/records/`의 기록 파일 | `배운 내용`과 `복습 이력` 절만 쓴다 |
| 기록의 `예제`·`질문 이력` 절 | 읽기만 한다 |
| 예제 폴더의 `TASK.md`·`PLAN.md`·코드 | 읽지 않는다 |

예제 폴더를 읽지 않는 이유는, 배운 내용을 사용자가 코드를 보지 않고 설명한 답으로 채우기 때문이다. `manager`가 코드를 읽으면 그 답을 대신 채우기 쉬워진다.

## 참조 문서 규칙

이 문서가 `manager`의 실행 지시사항을 정하는 기준 문서다.

| 문서 | 역할 | 읽는 시점 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 판정 기준 | `manager` 전체 |
| `../../references/learning-model.md` | 학습 목표와 세 단계 진단 기준 | 대상을 고르고 답변을 진단할 때 |
| `../../references/record-contract.md` | ID·상태·복습 이력·기존 기록 변환 | 기록 목록을 읽거나 쓰기 전에 |
| `../../references/writing-style.md` | 복습 질문과 진단 결과의 문체 | 사용자에게 질문하거나 결과를 알릴 때 |
| `.study/records/`의 기록 파일 | 학습 목표, 답변 단계, 마친 날짜, 복습 이력 | 분기를 가릴 때와 진단할 때 |

## 실행 절차

### 1. 배운 내용을 받아 적는다

**`배운 내용` 절이 빈 기록을 모아 목록으로 보인다.**

| 열 | 값 |
| --- | --- |
| 예제 | 기록의 `예제` 절에 적힌 학습 활동 |
| 기술 | 같은 절의 기술 |
| 시작 날짜 | 같은 절의 시작 날짜 |

여러 개면 사용자가 고르고, 하나면 그 예제로 바로 진행한다.

**코드와 `TASK.md`를 열지 말고 설명해 달라고 요청한다.**

기록의 `예제` 절에 적힌 학습 목표를 그대로 보이고, 그 목표에 답하는 설명을 받는다. 목표가 여럿이면 하나씩 묻는다.

질문에 예시를 붙이지 않는다. 예시가 답의 방향을 정해 주면 스스로 꺼내 보는 노력이 줄어든다.

설명이 짧아도 되묻지 않고 받은 답을 그대로 적는다. 무엇을 기억하지 못했는지도 기록으로 남아야 나중에 비교할 수 있다.

**받은 설명을 기록에 적는다.**

| 적는 것 | 자리 |
| --- | --- |
| 마친 날짜 | `배운 내용` 절의 `마친 날짜` 줄 |
| 사용자의 설명 | 같은 절의 본문 |

마친 날짜는 `manager`를 부른 날짜다. 이 값이 복습 시점을 재는 기준이 된다.

사용자의 설명을 다듬거나 고쳐 적지 않는다. 답한 말 그대로 두어야 나중에 같은 질문의 답과 견줄 수 있다.

### 2. 복습 질문을 낸다

**복습 시점은 마친 날로부터 1일·3일·7일·14일이다. 아래 순서로 밀린 시점을 찾는다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 기록의 `배운 내용` 절에서 마친 날짜를 읽는다 |
| 2 | 오늘까지 지난 날수를 세어 어느 시점을 넘겼는지 가린다 |
| 3 | `복습 이력` 절의 날짜들로 이미 복습한 시점을 가린다 |
| 4 | 넘겼지만 복습하지 않은 시점만 남긴다 |

3번에서 이력의 날짜도 마친 날짜와의 차이로 환산한다. 마친 날이 9월 1일이고 이력에 9월 2일이 있으면 1일 시점은 복습한 것으로 본다. 차이가 시점 사이에 들면 더 작은 쪽 시점을 복습한 것으로 본다.

`배운 내용` 절이 비어 있는 기록은 복습 대상이 아니다. 마친 날짜가 없어 시점을 잴 수 없다.

**밀린 예제를 목록으로 보인다.**

| 열 | 값 |
| --- | --- |
| 예제 | 기록의 학습 활동 |
| 밀린 시점 | 넘겼지만 복습하지 않은 시점 |
| 지난 날수 | 마친 날로부터 오늘까지의 날수 |

여러 예제가 걸리면 모두 보이고 사용자가 고른다. 한 번에 하나씩 진행한다.

한 예제에 밀린 시점이 둘 이상이면 가장 늦은 시점 하나로 복습한다. 지나간 시점의 질문을 모두 내지 않는다.

**기록의 `예제` 절에 적힌 학습 목표로 질문을 만든다.**

`배운 내용` 절의 설명은 질문을 만들 때 읽지 않는다. 그 설명을 보고 질문을 만들면 사용자가 앞서 답한 범위 안에서만 묻게 된다.

목표가 여럿이면 하나씩 묻는다. 질문에 예시나 힌트를 붙이지 않는다.

### 3. 답변을 진단한다

**복습 질문을 보이기 전에 사용자가 지금 이 주제를 어느 정도 아는지 매기게 한다.**

| 단계 | 뜻 |
| --- | --- |
| 설명할 수 있다 | 자료를 보지 않고 말할 수 있다 |
| 짐작은 간다 | 방향은 알지만 정확히는 모르겠다 |
| 기억나지 않는다 | 무엇을 했는지 떠오르지 않는다 |

평가를 받은 뒤에 질문을 보인다. 질문을 먼저 보이면 그 내용이 자기 평가에 영향을 준다.

사용자가 평가를 건너뛰면 그대로 진행한다. 자기 평가가 없어도 진단은 성립한다.

**공통 학습 모델과 기록의 목표별 진단 기준으로 답변을 가른다.**

목표가 여럿이면 각각 진단하고 공통 학습 모델의 세 결과 중 하나를 기록한다.

**기록의 `질문 이력`에 남은 답변 단계를 근거에 더한다.**

| 마지막 답변 단계 | 근거에 적는 것 |
| --- | --- |
| 2나 3 | 스스로 풀었음 |
| 4나 5 | 그 부분은 도움을 받아 풀었음 |

단계가 4나 5까지 올라갔던 부분은 복습에서 설명이 되더라도 근거에 남긴다. 설명할 수 있는 것과 스스로 푼 것은 다르다.

**자기 평가와 진단 결과가 어긋나면 알린다.**

| 자기 평가 | 진단 결과 | 알리는 것 |
| --- | --- | --- |
| 설명할 수 있다 | 이해하지 못함 | 어느 목표에서 설명이 닿지 않았는지 |
| 기억나지 않는다 | 이해함 | 설명이 목표에 닿았다는 사실 |
| 나머지 조합 | | 알리지 않는다 |

어긋남을 지적이 아니라 확인으로 전한다. 이 값은 사용자가 자기 이해를 가늠하는 재료이지 점수가 아니다.

**진단 결과를 `복습 이력` 절에 한 행으로 적는다.**

| 열 | 값 |
| --- | --- |
| 날짜 | `manager`를 부른 날짜 |
| 복습 질문 | 낸 질문을 한 줄로 |
| 진단 결과 | 이해한 목표와 못한 목표, 답변 단계 근거, 자기 평가와 어긋난 사실 |

### 4. 다음 학습을 제안한다

**진단 결과로 다음에 할 학습을 정한다.**

| 진단 결과 | 제안 |
| --- | --- |
| 못한 부분이 있다 | 같은 학습 목표를 다른 상황으로 바꾼 변형 예제 |
| 모두 이해했고 답변 단계가 3 이하였다 | 한 단계 높은 수준의 새 주제 |
| 모두 이해했지만 답변 단계가 4 이상이었다 | 같은 수준에서 다른 학습 활동 |

두 번째 줄의 `한 단계 높은 수준`은 기록에 적힌 학습자 수준의 다음 단계다. 숙련이면 같은 수준에서 다른 주제를 제안한다.

**제안에 세 가지를 담는다.**

| 담는 것 | 형식 |
| --- | --- |
| 다음에 할 것 | 주제나 학습 활동을 한 문장으로 |
| 그렇게 정한 이유 | 어느 진단에서 나왔는지 |
| 부르는 방법 | `init`에 그 내용을 넣어 부르라는 안내 |

예제를 실제로 만드는 일은 `init`이 한다. `manager`는 제안만 하고 예제 폴더를 만들지 않는다.

제안을 기록에 적지 않는다. 사용자가 `init`에 옮겨 쓰는 것으로 반영되며, 옮기지 않으면 반영되지 않는다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 예제 폴더 안에서 불렀다 | 진단하지 않고 학습 공간에서 부르라고 알린다 |
| `.study/records/`가 없다 | 진단하지 않고 `init`으로 예제를 먼저 만들라고 알린다 |
| 기록 파일을 읽을 수 없다 | 그 파일을 빼고 건너뛴 파일을 알린다 |
| 사용자가 설명을 건너뛰려 한다 | 기록을 비우지 않고 무엇이 기억나지 않는지만 적는다 |
| 사용자가 코드를 보고 답했다고 말한다 | 그 사실을 기록에 함께 적는다 |
| 학습 목표가 기록에 없다 | 목표 없이 무엇을 했는지만 묻고 그 사실을 알린다 |
| 기록의 `예제` 표에 `학습 활동` 대신 `만들 대상`이 있다 | 옛 형식으로 보고 `만들 대상` 값을 학습 활동으로 보인다 |
| 기록에 쓰지 못했다 | 받은 설명을 기록한 것처럼 두지 않고 실패한 경로를 알린다 |
| 밀린 복습 시점이 없다 | 다음 복습 시점과 남은 날수를 알린다 |
| 마친 날짜의 형식이 다르다 | 그 기록을 빼고 형식이 어긋난 파일을 알린다 |
| 14일 시점까지 모두 복습했다 | 그 예제를 목록에서 빼고 복습이 끝났음을 알린다 |
| 사용자가 복습 답변을 건너뛴다 | 이해하지 못함으로 적고 그 사실을 알린다 |
| `질문 이력`이 비어 있다 | 답변 단계 근거 없이 학습 목표로만 가린다 |
| 사용자가 자기 평가를 건너뛴다 | 그대로 진행하고 어긋남은 알리지 않는다 |
| 같은 학습 목표의 변형 상황을 찾지 못했다 | 제안하지 않고 그 사실을 알린다 |
| 진단 결과가 없다 | 제안하지 않고 복습을 먼저 하라고 알린다 |
| 사용자가 제안을 원하지 않는다 | 진단 결과만 보이고 끝낸다 |

## 경계

**사용자가 하려는 일에 따라 부르는 스킬이 갈린다.**

| 사용자가 하려는 것 | 부르는 스킬 |
| --- | --- |
| 예제를 새로 받기 | `init` |
| 구현 중 모르는 것 묻기 | `tutor` |
| 마친 예제를 복습하고 진단받기 | `manager` |

- 배운 내용과 복습 답변을 대신 쓰지 않는다.
- 예제 폴더를 만들거나 고치지 않는다.
- 개념을 풀어 주는 강의는 이 스킬의 범위가 아니다.
