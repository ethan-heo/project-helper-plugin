# tutor

## 역할과 목적

`tutor`는 과제를 구현하다 멈춘 사용자에게 다음에 할 일 하나를 정해 준다. 그 일을 푸는 코드는 주지 않는다. 사용자는 설계와 구현의 결정권자이고, AI는 멈춘 지점 판정·할 일 결정·계획 기록을 맡는다.

## 실행 원칙

**한 번 부르면 다음 할 일을 하나만 정하고, 접근 방향까지만 적는다.**

학습 기조는 [`learning-principles.md`](../_shared/learning-principles.md)에 있다. 다음 할 일을 정하고 적을 때의 적용 규칙은 이 문서가 정하고, 근거가 된 원칙을 `P<번호>`로 가리킨다.

## 참조 문서 규칙

이 문서가 `tutor`의 실행 지시사항을 정하는 기준 문서다.

| 문서 | 역할 | 읽는 시점 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 판정 기준 | `tutor` 전체 |
| [`learning-principles.md`](../_shared/learning-principles.md) | 학습 원칙의 목록 | 적용 규칙의 근거를 확인할 때 |
| 과제 폴더의 `PLAN.md` | 사용자가 쓴 설계와 구현 단계 | 멈춘 지점을 판정할 때, 할 일을 적을 때 |
| 과제 폴더의 `TASK.md` | 만들 대상과 완성 조건 | 멈춘 지점을 판정할 때 |

## 읽는 것과 쓰는 것

**`PLAN.md`만 고치고, 나머지는 읽기만 한다.**

| 대상 | 권한 |
| --- | --- |
| `PLAN.md` | 설계·구현 단계·막힌 점·설계 변경 네 절을 읽고 쓴다 |
| `TASK.md` | 읽기만 한다 |
| 과제 폴더의 코드 | 읽기만 한다 |
| `.study/task.json` | 읽지 않는다 |

과제 코드는 쓰지 않는다. 사용자가 써 달라고 해도 쓰지 않고 다음 할 일만 정한다.

## 경계

**사용자가 모르는 것이 무엇인지에 따라 부르는 스킬이 갈린다.**

| 사용자가 모르는 것 | 부르는 스킬 |
| --- | --- |
| 다음에 무엇을 할지 | `tutor` |
| 정한 일을 어떻게 풀지 | `hint` |
| 만든 것이 완성 조건을 채웠는지 | `review` |
| 이 기술로 또 무엇을 만들지 | `study` |

`tutor`가 정해 준 일에서 막혔을 때도 먼저 부르는 스킬은 `hint`다. 푸는 방법을 묻는 요청에는 답하지 않고 `hint`를 안내한다.

- 과제를 푸는 코드와 정답은 제시하지 않는다.
- 개념을 설명하는 강의는 이 스킬의 범위가 아니다.
