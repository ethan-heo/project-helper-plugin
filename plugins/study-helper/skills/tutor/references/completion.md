# 질문 해결과 예제 완료

## 목적

사용자의 완료 선언이 아니라 확인한 결과와 근거로 질문 해결과 예제 완료를 기록합니다.

## 진행 상태

**기록 상태를 확인한 뒤 질문에 답합니다.**

| 현재 상태 | 할 일 |
| --- | --- |
| `preparing` | 답하지 않고 `init`으로 준비 재개 안내 |
| `ready` | `in_progress`와 `started_at` 기록 후 진행 |
| `in_progress` | 상태 유지 후 진행 |
| `completed` | 새 구현을 시작하지 않고 `manager` 복습 안내 |

## 질문 해결

**사용자가 해결되었다고 알린 뒤 해당 활동의 근거를 확인합니다.**

| 활동 유형 | 확인할 근거 |
| --- | --- |
| 만들기 | 제공 테스트 보존, 추가 테스트, 전체 테스트 결과와 개념 설명 |
| 원인 찾기 | 수정 전후 결과와 사용자가 설명한 원인 근거 |
| 동작 관찰 | 관찰 결과와 결과가 나온 이유 |
| 방식 비교 | 같은 조건의 비교 결과와 선택 근거 |

근거가 확인되면 질문 행의 `해결 여부`를 `예`로 바꾸고 `확인 근거`에 실행 명령, 측정값, 사용자 설명 중 확인한 내용을 적습니다.

사용자의 해결 보고가 없거나 근거가 없으면 해결로 기록하지 않습니다. 결과가 예상과 다르면 현재 도움 단계의 범위에서 다음 확인 지점만 안내합니다.

## 예제 완료

**사용자가 완료를 요청하면 모든 학습 목표의 완성 조건을 하나씩 확인합니다.**

### 만들기 활동

**`TASK.md`의 과제 요구사항과 검증 파일 표를 읽고 다음 순서로 확인합니다.**

1. 기록의 `baseline_commit`과 현재 제공 테스트를 비교합니다.
2. 추가 테스트 경로에 사용자가 작성할 필수 사례가 있는지 확인합니다.
3. 제공 테스트와 추가 테스트가 각각 한 개 이상 실행되는지 확인합니다.
4. 전체 테스트 명령을 실행해 모두 성공하는지 확인합니다.
5. 연결된 학습 목표마다 사용자가 개념과 실행 결과를 이어 설명했는지 확인합니다.

제공 테스트가 기준선과 다르면 테스트가 통과해도 완료로 기록하지 않습니다. 사용자가 되돌릴 파일을 알리고 `in_progress`를 유지합니다.

추가 테스트는 파일 존재만으로 인정하지 않습니다. `TASK.md`에 적힌 필수 사례가 테스트로 작성됐고 실행 결과에서 해당 경로의 테스트를 한 개 이상 확인해야 합니다. 부족하면 작성할 사례 하나만 알립니다.

기준 커밋이 없으면 제공 테스트를 `TASK.md`의 과제 요구사항과 직접 대조합니다. 기준선 보존을 확인할 수 없었다는 사실과 직접 확인한 근거를 기록합니다.

전체 테스트가 성공해도 개념 설명이 없으면 완료로 기록하지 않습니다. 한 번에 연결 목표 하나의 설명만 요청하고, 필수 개념과 실행 근거가 이어지는지 확인합니다.

### 나머지 활동

원인 찾기·동작 관찰·방식 비교 활동은 기존과 같이 결과와 사용자가 설명한 근거를 함께 확인합니다.

모든 목표가 근거를 충족하면 `status: completed`와 `completed_at`을 기록합니다. 한 조건이라도 확인되지 않으면 `in_progress`를 유지하고 부족한 조건 하나만 알립니다.

질문 이력에 해결되지 않은 행이 있어도 다른 완성 근거로 해당 목표를 확인했다면 그 행의 근거를 함께 갱신합니다. 근거 없이 일괄 해결로 바꾸지 않습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 활동 유형을 확인할 수 없음 | `TASK.md`의 학습 활동 확인 요청 |
| 실행 결과가 없음 | 실행 명령과 필요한 결과 요청 |
| 사용자 근거가 없음 | 결론을 낸 이유 하나 질문 |
| 일부 목표만 충족함 | 충족 근거만 기록하고 `in_progress` 유지 |
| 제공 테스트가 기준선과 다름 | 되돌릴 파일을 알리고 `in_progress` 유지 |
| 추가 테스트 경로가 없거나 비어 있음 | 작성할 필수 사례 하나를 알림 |
| 추가 테스트에서 필수 사례를 찾을 수 없음 | 빠진 사례 하나를 알림 |
| 추가 테스트가 실행되지 않음 | 테스트 검색 설정과 실행 명령 확인 요청 |
| 기준 커밋이 없음 | 과제 요구사항과 제공 테스트를 직접 대조하고 그 사실 기록 |
| 테스트 성공 뒤 개념 설명이 없음 | 연결 목표 하나의 설명 요청 |
| 기록 쓰기 실패 | 완료를 알리지 않고 실패 경로 안내 |
