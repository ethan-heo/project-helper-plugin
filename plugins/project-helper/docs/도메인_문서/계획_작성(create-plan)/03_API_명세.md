# 계획_작성(create-plan) — API 명세

이 플러그인은 HTTP 서버가 아니므로 엔드포인트는 사용자가 호출하는 슬래시 명령과 검증 스크립트의 명령줄 인터페이스를 뜻한다.

## 엔드포인트 목록

| 메서드 | 경로 | 설명 | 인증 |
| --- | --- | --- | --- |
| `호출` | `/create-plan` | 계획 작성 절차를 시작한다. 명시 후의 답변은 계획 작성의 입력으로 해석된다 | 불필요 |
| `자동 발동` | 자연어 요청 | `description`의 발동 조건에 맞는 요청에서 스킬이 켜진다 | 불필요 |
| `실행` | `scripts/validate-plan.sh <계획 디렉터리>` | 확정 직전에 문서 구조·상태·항목 형식을 검사한다 | 불필요 |

## `/create-plan`

계획서가 없는 상태에서 코드 변경이 필요한 요구사항을 받았을 때 호출한다. 호출 이후의 실행 맥락은 계획이 완료되거나 사용자가 다른 스킬 또는 일반 질문을 명시할 때까지 유지된다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 명령 인자 | 요구사항 | string | 아니오 | 무엇을 바꾸고 싶은지. 비어 있으면 준비 단계에서 되묻는다 |
| 대화 | 섹션별 답변 | string | 예 | 카테고리 질문에 대한 사용자의 결정. 번호 또는 선택지 내용으로 답한다 |

```
/create-plan 결제 실패 시 재시도 로직을 넣고 싶은데 어디를 건드릴지 정리하자
```

### 응답

산출물은 계획서 파일이다. 절차가 끝나면 아래 구조가 만들어지고 초안 파일은 삭제된다.

```
docs/plans/2026-08-31-payment-retry/
├── README.md
└── billing/
    ├── README.md
    └── retry.md
```

`retry.md`의 상태 표는 다음과 같다.

```markdown
| 항목 | 값 |
| --- | --- |
| 단계 | 계획 완료 |
| 마지막 갱신 | 2026-08-31 |
| 구현 진행률 | 0 / 3 |
```

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 해당 없음 | 진입 거부 | 상태가 `계획 완료`인 계획서가 이미 있다. `/impl-plan`으로 안내한다 |
| 해당 없음 | 확정 거부 | 검토 표시가 남아 있거나 인계 점검을 통과하지 못했다 |
| 해당 없음 | 범위 이탈 | 요청이 일정 수립이나 한 단계로 끝나는 수정이다. 계획서를 만들지 않는다 |

상태 코드 열이 비어 있는 것은 이 인터페이스가 HTTP 응답을 반환하지 않기 때문이다. 공통 에러 응답 형식은 [`공통_에러_코드.md`](../../공통_인프라_및_컨벤션/공통_에러_코드.md)를 참조한다.

## `scripts/validate-plan.sh <계획 디렉터리>`

계획 디렉터리 전체를 훑어 최상위 README, 도메인 README, 기능 계획서의 상태와 항목 형식을 검사한다. `rg`(ripgrep)를 사용하며, 오류가 하나라도 있으면 종료 코드 1을 반환한다.

### 요청

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 인자 1 | 계획 디렉터리 | path | 예 | `docs/plans/YYYY-MM-DD-<주제>` |

```bash
bash plugins/project-helper/skills/create-plan/scripts/validate-plan.sh docs/plans/2026-08-31-payment-retry
```

### 응답

```
계획서 검증 통과: docs/plans/2026-08-31-payment-retry
```

### 에러 코드

| 상태 코드 | 코드 | 발생 조건 |
| --- | --- | --- |
| 1 | `최상위 README.md가 없습니다.` | 계획 디렉터리에 README가 없다 |
| 1 | `도메인 디렉터리가 없습니다.` | 하위 디렉터리가 하나도 없다 |
| 1 | `<경로>에 사용자 검토 표시가 남아 있습니다.` | 기능 계획서에 `<!-- 사용자 검토 필요 -->`가 있다 |
| 1 | `<경로>의 단계가 허용된 값이 아닙니다.` | 단계가 세 값 중 하나가 아니다 |
| 1 | `<경로>의 구현 진행률 형식이 잘못되었습니다.` | `숫자 / 숫자` 형식이 아니다 |
| 1 | `<경로>에 올바른 구현 항목이 없습니다.` | 세 조각 ID 형식의 항목이 하나도 없다 |

## 이벤트 메시징

해당 없음. 스킬 사이에 메시지 브로커나 이벤트 버스를 두지 않는다. 다음 단계로의 인계는 사용자가 다른 슬래시 명령을 호출하는 방식으로만 이루어지며, 계획서 파일이 유일한 매개다.
