# 계획_작성(create-plan) — 도메인 개요

## 도메인 정의

`create-plan` 스킬이 담당하는 영역이다. 코드 변경이 필요한 요구사항을 받으면 곧바로 구현하지 않고, 사용자와의 질의응답으로 설계 결정을 좁혀 구현 가능한 계획서로 남긴다. 결정권은 사용자에게 있고 스킬은 조사·질문·반례 제시·기록을 맡는다.

계획서의 파일 형식과 세 층 구조 자체는 [계획_관리(plan-management)](../계획_관리%28plan-management%29/01_도메인_개요.md)가 정의하며, 이 도메인은 그 형식을 채우는 대화 절차를 담당한다.

### 책임 범위

| 구분 | 내용 |
| --- | --- |
| 담당한다 | 요구사항 확인, 기존 개발 문서 조사, 카테고리별 질의응답, 설계 유형 선택, 구현 순서와 테스트 작성, 확정 전 검증 |
| 담당하지 않는다 | 계획서의 실행과 커밋(impl-plan), 제품 단위 요구사항 확정(요구사항_정의), 계획서 형식과 계층 규칙의 정의(계획_관리) |

## 유비쿼터스 용어 사전

| 용어 | 영문 표기 | 정의 |
| --- | --- | --- |
| 초안 | `초안 작성` | 세 층 구조로 나누기 전, 날짜 디렉터리 밖의 단일 파일에 내용을 쌓는 상태 |
| 카테고리 | category | 계획서의 한 섹션을 채우기 위해 한 번에 다루는 질문 묶음 |
| 설계 유형 | design type | 구조·의사결정·상태와 흐름·데이터·외부 연동·품질 속성 여섯 가지 중 요구사항에 해당하는 서술 형식 |
| 인계 점검 | handover check | 구현 항목만 읽고 무엇을 어디에 할지 정해지는지 확인하는 절차 |
| 검토 표시 | `<!-- 사용자 검토 필요 -->` | 결정되지 않은 자리를 계획서에 남기는 주석 |
| 구현 항목 | implementation item | 되돌릴 수 있는 최소 단위 하나. 커밋 하나에 대응한다 |

## 핵심 비즈니스 규칙

1. 요구사항을 받으면 구현하지 않고 계획서를 먼저 만든다. 이미 `계획 완료` 상태의 계획서가 있으면 이 도메인이 아니라 `impl-plan`으로 넘긴다.
2. 준비 단계에서 코드보다 개발 문서를 먼저 읽는다. 다만 문서와 코드가 어긋나면 코드를 사실로 삼고 그 차이를 사용자에게 보고한다.
3. 섹션은 요약(가제) → 상태 → 설계 → 구현 순서 → 경계 → 테스트 → 요약 확정 순서로 채운다. 섹션마다 통과 조건을 확인받은 뒤에만 다음으로 넘어간다.
4. 요약의 변경점은 설계와 구현 순서가 확정된 뒤에 쓴다. 먼저 쓰면 실제 변경 범위와 어긋난다.
5. 사용자가 결정할 대안이 둘에서 셋이면 `1.`, `2.`, `3.` 형식으로 번호를 붙인다. 단순 안내 목록에는 번호를 붙이지 않는다.
6. 답변이 선택지 밖으로 나오면 기존 선택지에 맞추지 않는다. 그 답변을 새 기준으로 삼아 질문을 이어가고, 구현자가 추가 질문 없이 작성할 수 있을 때 카테고리를 닫는다.
7. 확인받지 못한 결정은 확정된 사실처럼 쓰지 않고 검토 표시를 남긴다. 검토 표시가 하나라도 남아 있으면 확정할 수 없다.
8. 구현 항목 하나는 커밋 하나이며, 모든 구현 항목은 최소 하나의 검증에 대응해야 한다.
9. 구현 항목이 하나뿐이어도 최상위·도메인·기능 세 층 구조를 만든다.

### 예외 케이스

| 상황 | 처리 |
| --- | --- |
| 요구사항이 모호하다 | 한 번에 하나씩 질문해 범위를 좁힌다. 준비 단계에서 해결한다 |
| 개발 문서가 없다 | 코드만 조사했다고 알리고 진행한다 |
| 요구사항에 걸리는 도메인을 판단할 수 없다 | 추측하지 않고 사용자에게 대상 도메인을 확인한다 |
| 사용자가 설계 유형을 승인하지 않는다 | 범위를 다시 좁힌다. 해당하지 않는 유형은 계획서에 넣지 않는다 |
| 사용자가 결정을 위임한다 | 선택 근거를 설명하고 동의를 받은 뒤 기록한다 |
| 같은 우려를 세 번 짚어도 사용자가 결정을 유지한다 | 우려를 기록하고 진행한다 |
| 사용자가 빠른 진행을 요청한다 | 미결정 지점에 검토 표시를 남긴다. 상태는 `계획 완료`로 바꾸지 않는다 |
| `impl-plan`이 계획의 결함을 발견해 돌려보냈다 | 요약부터 다시 쓰지 않고 어긋난 곳만 고친다 |
