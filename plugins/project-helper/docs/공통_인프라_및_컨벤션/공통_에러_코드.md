# 공통 에러 코드

이 플러그인에는 HTTP 응답이 없다. 실패는 두 가지 형태로만 나타난다. 검증 스크립트는 종료 코드와 표준 오류의 메시지로, 스킬은 작업을 멈추고 사용자에게 알리는 방식으로 실패를 전한다.

## 에러 응답 형식

### 검증 스크립트

세 스크립트는 모두 같은 형식을 따른다. 오류를 발견해도 즉시 멈추지 않고 끝까지 검사한 뒤, 누적된 오류가 하나라도 있으면 종료 코드 1을 반환한다.

```
오류: docs/plans/2026-08-31-example/auth/login.md의 단계가 허용된 값이 아닙니다.
오류: docs/plans/2026-08-31-example/auth/login.md의 구현 진행률 형식이 잘못되었습니다.
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| 접두사 | string | 항상 `오류: `이며 표준 오류로 출력된다 |
| 메시지 | string | 무엇이 어긋났는지 한국어 한 문장. 대상 경로를 포함한다 |
| 종료 코드 | int | 오류가 없으면 0, 하나 이상이면 1 |

성공하면 표준 출력으로 통과 메시지 한 줄을 낸다.

```
계획서 검증 통과: docs/plans/2026-08-31-example
```

인자를 넘기지 않으면 셸의 매개변수 확장으로 사용법을 알리고 즉시 종료한다.

```
validate-plan.sh: line 4: 1: 사용법: validate-plan.sh <계획 디렉터리>
```

### 스킬

스킬의 실패에는 코드가 없다. 무엇이 진행을 막았는지와 다음에 무엇을 할지를 사용자에게 알리고 작업을 멈춘다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| 멈춘 지점 | string | 어느 단계에서 멈췄는가 |
| 이유 | string | 어떤 조건을 만족하지 못했는가 |
| 다음 행동 | string | 어느 스킬로 가거나 무엇을 고쳐야 하는가 |

## 공통 코드 목록

상태 코드 대신 종료 코드를 쓴다. 세 검증 스크립트가 공유하는 실패 유형은 아래와 같다.

| 상태 코드 | 코드 | 의미 | 발생 조건 |
| --- | --- | --- | --- |
| 1 | `<대상> 파일이 없습니다.` | 필수 파일 부재 | 검사 대상이 되어야 할 파일이 없다 |
| 1 | `<대상> 디렉터리가 없습니다.` | 필수 디렉터리 부재 | 인자가 가리키는 디렉터리가 없다 |
| 1 | `사용자 검토 표시가 남아 있습니다.` | 미결정 잔존 | `<!-- 사용자 검토 필요 -->`가 남아 있다 |
| 1 | `<대상>에 미확인 표시가 남아 있습니다.` | 미확인 잔존 | 미확인 주석이 남아 있다 |
| 1 | `<대상>에 '<절 이름>' 절이 없습니다.` | 필수 절 부재 | 절 제목이 규정된 문구와 일치하지 않는다 |
| 1 | 형식 불일치 메시지 | 표기 오류 | 상태·진행률·항목 ID·요구사항 구분의 형식이 어긋난다 |
| 0 | `<대상> 검증 통과: <경로>` | 성공 | 누적된 오류가 없다 |

스킬이 진행을 멈추는 공통 조건은 다음과 같다.

| 코드 | 의미 | 발생 조건 |
| --- | --- | --- |
| 진입 거부 | 스킬의 전제를 만족하지 못함 | 계획서 상태가 요구하는 단계와 다르다 |
| 확정 거부 | 산출물을 확정할 수 없음 | 미결정이나 미확인이 남아 있다 |
| 범위 이탈 | 이 스킬이 다룰 요청이 아님 | 다른 스킬로 인계한다 |
| 동의 없음 | 파괴적 작업의 동의를 받지 못함 | 덮어쓰기 대상 목록에 동의하지 않았다 |

## 도메인별 코드 규칙

도메인마다 자체 에러 코드 체계를 두지 않는다. 검증 스크립트의 메시지는 코드가 아니라 한국어 문장이며, 스크립트를 소유한 도메인이 그 문구를 정한다.

| 도메인 | 소유한 스크립트 | 메시지의 대상 |
| --- | --- | --- |
| 계획_작성 | `create-plan/scripts/validate-plan.sh` | 계획 디렉터리 전체 |
| 계획_관리 | 위 스크립트와 `impl-plan/scripts/validate-plan.sh` | 계획서의 구조·상태·항목 형식 |
| 요구사항_정의 | `create-prd/scripts/validate-prd.sh` | PRD의 절과 요구사항 표기 |
| 개발문서_생성 | `create-docs/scripts/validate-docs.sh` | 개발 문서의 파일과 절 구성 |

메시지 문구를 바꿀 때는 대상 경로를 포함하고 무엇이 어긋났는지 한 문장으로 밝히는 형식을 유지한다. 각 도메인의 전체 메시지 목록은 해당 도메인의 `03_API_명세.md`에 있다.
