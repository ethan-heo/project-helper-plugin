# 인증 및 인가 가이드

이 플러그인은 사용자를 식별하지 않고 토큰이나 자격 증명을 다루지 않는다. 그래서 이 문서가 정하는 것은 사람의 신원이 아니라, 어떤 문서가 어떤 권한을 갖고 무엇을 고칠 수 있는지다.

## 인증 방식

해당 없음. 로그인, 세션, 토큰 발급 경로가 존재하지 않는다. 스킬은 실행 환경이 이미 열어 둔 대화 안에서 동작하며 사용자를 구분하지 않는다.

| 항목 | 내용 |
| --- | --- |
| 방식 | 해당 없음. 사용자 식별을 하지 않는다 |
| 발급 경로 | 해당 없음 |
| 유효 기간 | 해당 없음 |
| 갱신 방법 | 해당 없음 |

저장소 접근 권한만이 유일한 외부 조건이다. 마켓플레이스를 등록하려면 저장소를 읽을 수 있어야 하며, 비공개 저장소의 인증 처리 방식은 아직 확인되지 않았다. 확인 계획은 [`배포와_설치(distribution)`](../도메인_문서/배포와_설치%28distribution%29/01_도메인_개요.md)의 예외 케이스에 있다.

### 토큰 구조

해당 없음. 발급되는 토큰이 없다.

## 인가 규칙

권한의 주체는 문서다. 어떤 문서가 실행 지시의 정본이고 어떤 문서가 근거에 그치는지를 계층으로 정한다. 위층의 지시가 아래층과 충돌하면 위층을 따른다.

| 역할 | 권한 범위 |
| --- | --- |
| 저장소 지시사항(`CLAUDE.md`, `AGENTS.md`) | 저장소 전체의 규칙. 스킬 본문보다 우선한다 |
| `SKILL.md` | 해당 스킬의 실행 정본. 절차와 분기를 정한다 |
| `references/` | 근거·예외·세부 판정. 본문이 지정한 절차에서만 읽는다 |
| `assets/` | 양식. 실행 지시사항으로 해석하지 않는다 |
| `scripts/` | 검증 도구. 실행 범위를 만들지 않는다 |
| 계획서·PRD | 스킬의 입력. 범위와 확정된 결정을 담는다 |

참조 문서는 본문에 없는 실행 범위를 추가하지 못한다. 이 제약이 인가 규칙의 핵심이다.

### 엔드포인트 보호

보호 대상은 경로가 아니라 쓰기 권한이다. 각 스킬은 자신이 고치기로 선언한 파일만 고친다.

| 경로 패턴 | 요구 조건 |
| --- | --- |
| 계획서의 상태 표·체크박스·마지막 갱신·기록 줄 | `impl-plan`이 고칠 수 있다 |
| 계획서의 설계·구현 순서·테스트 | `create-plan`이 고칠 수 있다. `impl-plan`은 연관된 추가 작업을 반영할 때만 갱신한다 |
| 소스 코드 | `impl-plan`만 고친다. `create-docs`는 읽기만 한다 |
| 개발 문서(`docs/글로벌_아키텍처_가이드.md`, `docs/도메인_문서/`) | `create-docs`가 생성하고 재생성한다. `create-plan`은 읽기만 한다 |
| 최상위 계획서의 선행 관계 표 | `impl-plan`은 읽기만 한다 |
| PRD | `create-prd`가 쓴다. 다른 스킬은 읽기만 한다 |
| 기존 문서의 덮어쓰기 | 사용자 동의가 필요하다. 동의 전에는 아무것도 쓰지 않는다 |

## 실패 처리

권한을 벗어난 요청은 거부되는 대신 다른 스킬로 인계되거나, 사용자의 결정을 기다린다.

| 상황 | 상태 코드 | 코드 |
| --- | --- | --- |
| 스킬의 진입 조건을 만족하지 못했다 | 해당 없음 | 진입 거부. 대상 스킬을 안내한다 |
| 확정되지 않은 결정이 남아 있다 | 해당 없음 | 확정 거부. 검토 표시나 미확인 주석을 남긴다 |
| 계획서에 없는 변경을 요구받았다 | 해당 없음 | 범위 이탈. 알리되 고치지 않는다 |
| 덮어쓰기 동의를 받지 못했다 | 해당 없음 | 동의 없음. 경로를 다시 확인하거나 중단한다 |
| 검증 스크립트가 형식 위반을 발견했다 | 1 | 해당 메시지. [`공통_에러_코드.md`](공통_에러_코드.md) 참조 |

세부 문구는 [`공통_에러_코드.md`](공통_에러_코드.md)와 일치시킨다.
