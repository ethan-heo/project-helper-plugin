# 설계 유형 카탈로그

설계 섹션을 작성하기 전에 요구사항과 코드베이스에서 실제로 판단이 필요한 유형만 골라 사용한다. 모든 유형을 넣지 않으며, 한 사실이 여러 유형에 걸치면 정본을 한 곳에 두고 나머지에서는 관계만 설명한다.

## 구조

구성 요소의 책임과 경계를 정하거나 기존 구조를 바꿀 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 구성 요소 | 새로 만들거나 바꾸는 요소 |
| 책임 | 각 요소가 맡는 일과 맡지 않는 일 |
| 경계 | 요소 사이에 허용하는 계약 |
| 흐름 | 호출·데이터가 이동하는 순서 |

```markdown
### 구조
- 구성 요소: <요소와 책임>
- 경계: <요소 사이의 계약>
- 흐름: <입력부터 결과까지의 순서>
```

## 의존관계

모듈·서비스·라이브러리 사이의 결합이나 변경 영향을 판단할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 주체와 대상 | 누가 무엇에 의존하는가 |
| 의존 이유 | 의존이 필요한 이유 |
| 결합 방식 | 호출, 이벤트, 공유 데이터 등 연결 방식 |
| 영향 | 대상 변경·실패가 주체에 미치는 영향 |

```markdown
### 의존관계
| 주체 | 대상 | 결합 방식 | 변경·실패 영향 |
| --- | --- | --- | --- |
| <주체> | <대상> | <방식> | <영향> |
```

## 의사결정

둘 이상의 실행 가능한 대안 중 하나를 선택할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 맥락과 문제 | 무엇을 결정해야 하는가 |
| 판단 기준 | 기능·품질·제약 중 무엇을 우선하는가 |
| 검토한 대안 | 선택지와 기각 사유 |
| 결정과 근거 | 선택한 안과 확인된 근거 |
| 결과 | 긍정적·부정적 영향과 재검토 조건 |

```markdown
### 의사결정
| 결정 | 선택한 안 | 근거 | 기각한 대안 |
| --- | --- | --- | --- |
| <결정할 것> | <선택> | <근거> | <대안> — <기각 사유> |
```

## 트레이드오프

한 품질이나 이점을 얻기 위해 다른 품질·비용·위험을 받아들일 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 평가 기준 | 비교할 성능·운영성·비용·변경 용이성 등 |
| 선택지 비교 | 기준별로 얻는 점과 잃는 점 |
| 수용한 위험 | 의도적으로 받아들이는 단점 |
| 완화책 | 위험을 줄이는 방법 |

```markdown
### 트레이드오프
| 평가 기준 | 선택한 안의 이점 | 수용한 비용·위험 | 완화책 |
| --- | --- | --- | --- |
| <기준> | <이점> | <비용·위험> | <완화책> |
```

## 상태와 흐름

상태가 바뀌고, 재시도·취소·복구가 필요한 동작을 설계할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 상태 | 가능한 상태와 의미 |
| 전이 조건 | 상태가 바뀌는 사건과 조건 |
| 실패 처리 | 실패 시 상태와 사용자·시스템 결과 |
| 재시도·복구 | 재시도 횟수, 멱등성, 복구 경로 |

```markdown
### 상태와 흐름
| 현재 상태 | 사건·조건 | 다음 상태 | 할 일 |
| --- | --- | --- | --- |
| <상태> | <조건> | <상태> | <처리> |
```

## 데이터

입력부터 저장·변환·출력까지 데이터의 의미와 정합성을 정할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 입력·출력 | 형식, 필수값, 변환 전후 의미 |
| 저장 위치 | 원본과 파생값의 위치 |
| 정합성 | 중복·순서·동시성·트랜잭션 규칙 |
| 보존·삭제 | 수명과 개인정보·민감정보 처리 |

```markdown
### 데이터
| 단계 | 데이터 | 저장·전달 위치 | 정합성 규칙 |
| --- | --- | --- | --- |
| <단계> | <데이터> | <위치> | <규칙> |
```

## 외부 연동

다른 서비스·시스템·플랫폼의 계약과 실패를 설계할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 계약 | 요청·응답·인증·버전 규칙 |
| 시간 제한 | 타임아웃과 취소 방식 |
| 실패 처리 | 오류 매핑과 사용자·시스템 결과 |
| 재시도 | 대상 오류, 횟수, 백오프, 중복 방지 |

```markdown
### 외부 연동
| 연동 대상 | 정상 계약 | 실패 조건 | 할 일 |
| --- | --- | --- | --- |
| <대상> | <계약> | <조건> | <처리> |
```

## 품질 속성

성능·가용성·보안·운영성처럼 수치나 관찰 결과로 검증해야 하는 요구사항을 설계할 때 사용한다.

| 항목 | 작성 내용 |
| --- | --- |
| 자극 상황 | 어떤 부하·장애·공격이 발생하는가 |
| 시스템 반응 | 시스템이 어떻게 반응해야 하는가 |
| 측정 기준 | 무엇을 어떻게 측정하는가 |
| 목표값 | 통과로 볼 수 있는 수치나 관찰 결과 |

```markdown
### 품질 속성
- 상황: <자극 상황>
- 반응: <시스템 반응>
- 측정: <측정 기준과 목표값>
```
