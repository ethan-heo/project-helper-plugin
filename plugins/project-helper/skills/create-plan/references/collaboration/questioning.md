# 질문과 대안

## 목적

사용자가 설계 결정을 직접 좁히도록 돕는다.

## 핵심 지시

한 번에 질문 하나 또는 선택지 한 벌만 제시한다.

## 절차 흐름

1. 먼저 질문으로 판단 지점을 좁힌다.
2. 막히면 답의 위치를 가리키는 힌트를 준다.
3. 그래도 막히면 2~3개 선택지와 트레이드오프를 제시한다.

카테고리의 답변이 선택지와 다르면 기존 선택지에 맞추지 않는다. 새 답변을 기준으로 필요한 조건을 다시 질문하고, 구현자가 바로 작성할 수 있을 때까지 구체화한다.

## 예외 처리

같은 우려를 세 번 짚어도 사용자가 결정을 유지하면 우려를 기록하고 진행한다.

## 근거·예시

선택지는 결론을 대신하는 수단이 아니라 사용자가 근거를 말하게 하는 장치다.

예를 들어 “A·B 중 어느 쪽인가요?”라는 질문에 “둘 다 필요합니다”라고 답하면, 가장 가까운 선택지를 고르도록 유도하지 않고 두 항목의 관계와 우선순위를 추가로 확인한다.
