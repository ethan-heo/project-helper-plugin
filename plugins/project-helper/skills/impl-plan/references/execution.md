# 구현 실행

## 구현 항목

## 적용 순서

**상태·구조·선행 관계를 확인한 뒤에만 항목을 실행하고, 실행 중 발견한 사실은 계획 결함과 구분한다.**

| 확인 순서 | 판단 대상 | 통과 결과 |
| --- | --- | --- |
| 1 | 계획 상태와 문서 구조 | 구현할 계획서가 특정된다 |
| 2 | 검토 표시와 항목 명확성 | 사용자 판단 없이 실행할 수 있다 |
| 3 | 선행 관계 | 선행 항목의 검증이 끝났다 |
| 4 | 작업 트리와 브랜치 | 변경을 잃지 않고 커밋할 수 있다 |

## 구현 항목

체크되지 않은 첫 항목의 범위만 구현하고, 대응하는 테스트를 통과시킨다.

## 진행 기록

항목 완료 후 체크박스·진행률·마지막 갱신과 `기록` 줄을 계획서에 남긴다.

구현 항목은 아래 두 하위 줄을 가진다. 계획을 쓸 때 완료 판정 줄이 먼저 생기고, 구현이 끝나면 그 아래에 기록 줄이 붙는다.

```markdown
1. [x] **DOMAIN-FEATURE-001** <제목> — <무엇을 어디에>
   - 완료 판정: <무엇을 보면 끝난 줄 아는가>
   - 기록: <무엇을 어떻게 했는가>
```

완료 판정이 항목 줄 끝에 이어 붙은 계획서도 있다. 그런 계획서는 표기를 고치지 않고 기록 줄만 붙인다.

## 커밋

항목 하나를 한 커밋으로 만들고 커밋 메시지에 항목 ID를 포함한다.
