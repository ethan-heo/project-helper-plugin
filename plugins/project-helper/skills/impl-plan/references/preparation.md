# 구현 준비

## 작업 재개

중단된 작업은 작업 트리와 현재 브랜치를 먼저 확인하고, 상태가 `계획 완료`인 계획서의 첫 미완료 항목부터 이어간다.

계획서를 찾을 경로는 계획 최상위 문서에 기록된 문서 루트를 기준으로 정한다. 기록이 없으면 탐색으로 판정한다.

## 구현 전제

계획 상태·검토 표시·항목 형식·문서 구조를 확인하고 하나라도 어긋나면 구현을 시작하지 않는다.

## 브랜치

계획 묶음은 `feature/<주제>`, 기능 계획서는 `<도메인>/<기능>` 브랜치에서 작업한다.

구현을 마치면 기능 브랜치를 `feature/<주제>`로 병합하고 거기에 머문다. `feature/<주제>`는 기본 브랜치로 병합하지 않는다.

## 아키텍처 버전 대조

**계획서를 찾으면 구현을 시작하거나 재개하기 전에 기준 버전과 현재 버전을 비교한다.**

계획 최상위 문서의 기준 아키텍처 표에서 경로와 기준 버전을 읽고, 그 경로의 `README.md` 버전 표와 비교한다. `N.N`에서 점 앞의 숫자가 주 버전이다. 문자열의 첫 글자만 비교하지 않는다.

| 비교 결과 | 할 일 |
| --- | --- |
| 주 버전이 같다 | 구현 진행 |
| 주 버전이 다르다 | 구현 중단과 `/create-plan` 재검토 안내 |
| 계획에 기준 버전 기록이 없다 | 기존 계획으로 보고 구현 진행 |

부 버전만 다르면 결정 추가나 서술 보완이므로 진행한다. 주 버전이 다르면 기준 버전과 현재 버전을 함께 알리고, 두 버전 사이에 대체된 결정의 ID를 보고한다. 이때 계획서를 임의로 최신 버전으로 고치지 않는다.

### 대체된 결정 확인

**결정 기록에서 옛 결정의 대체 ID를 따라 새 결정의 도입 버전을 확인한다.**

옛 행의 도입 버전은 대체 시점이 아니다. `대체됨` 행의 마지막 열에 적힌 새 결정의 도입 버전이 두 비교 버전 사이에 있으면 옛 ID와 새 ID를 함께 보고한다. 하한 버전은 제외하고 상한 버전은 포함하며, 주·부 버전을 각각 숫자로 비교한다. 연속 대체는 각 연결을 확인한다. 기록만으로 시점을 확인할 수 없으면 추정하지 말고 확인하지 못한 ID를 알린다.

### 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 기준 버전은 있는데 아키텍처 문서가 없다 | 구현 중단과 문서 누락 보고 |
| 구현 도중 문서의 주 버전이 오른다 | 현재 항목 완료 후 다음 항목 전에 중단 |

각 항목에 들어가기 전에 현재 버전을 다시 확인한다. 버전 표가 없거나 `N.N` 형식이 아니면 비교할 수 없으므로 구현을 시작하지 않고 잘못된 표를 알린다. 기준 버전이 없는 옛 계획은 문서 존재 여부와 관계없이 위의 기존 계획 분기를 따른다.
