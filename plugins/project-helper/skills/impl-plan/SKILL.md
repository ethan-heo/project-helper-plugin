# impl-plan

## 역할과 목적

`impl-plan`은 `계획 완료` 상태의 계획서를 입력으로 받아, 계획서에 정한 구현 순서를 항목별로 실행하고 검증·기록·커밋까지 처리합니다.

## 실행 원칙

**확정된 계획의 범위와 순서를 지키고, 전제가 바뀌면 구현을 멈춥니다.**

**호출 후 입력은 [스킬 실행 맥락](../_shared/session.md#입력-해석)에 따라 해석합니다.**

추가 작업은 [계획에 추가 작업 반영](../_shared/session.md#계획에-추가-작업-반영)에 따라 처리합니다.

확정된 계획서의 구현은 AI가 주도합니다. 계획 결함은 [실패와 중단](references/failure.md#계획-결함)을 따릅니다.

## 참조 문서 규칙

이 문서가 `impl-plan`의 실행 지시사항을 정하는 기준 문서입니다. 작업을 시작할 때 이 문서를 먼저 읽고, 참조 문서는 [참조 파일](#참조-파일) 표가 지정한 실행 단계에 진입할 때만 읽습니다. 참조 문서는 본문에 없는 실행 범위를 추가하지 않습니다.

대상 저장소의 `AGENTS.md`가 이 문서보다 우선합니다. 계획서는 구현 범위와 확정된 결정을 담은 이 스킬의 입력이며, 구현을 시작하기 전에 `scripts/`의 검증 스크립트로 형식을 확인합니다.

## 구현 절차

### 준비

**계획서를 찾은 뒤 구현을 시작하거나 재개하기 전에 아래 대조를 수행합니다.**

기준 아키텍처 버전은 [준비 규칙](references/preparation.md#아키텍처-버전-대조)에 따라 주 버전을 비교합니다.

재개 절차에서 6번으로 바로 이동하는 경우에도 버전 대조를 생략하지 않습니다.

#### 0. 이어서 하는 경우라면

**중단했던 작업으로 돌아왔다면, 작업 트리가 깨끗한지 확인하고 현재 브랜치로 이어서 할 항목을 찾습니다.**

| 현재 브랜치 | 이어서 할 것 |
| --- | --- |
| `<도메인>/<기능>` | 계획서 저장 경로에서 해당 기능 계획서를 찾아 이어서 합니다. 여럿이면 사용자에게 묻습니다 |
| `feature/<주제>` | 그 계획에서 기능 계획서를 찾아 상태가 `계획 완료`인 것부터 이어서 합니다 |
| 그 외 | [`docs-root.md`](../_shared/docs-root.md)로 판정한 `<루트>/plans/`에서 후보를 찾아 사용자에게 고르게 합니다 |

**작업 트리에 변경이 있으면 멈추고 남은 변경을 보여 줍니다.**

| 계획서 상태 | 다음 단계 |
| --- | --- |
| `계획 완료` | 5번을 건너뛰고 6번으로 갑니다 |
| 그 외 | 이어서 실행할 계획서를 알리고 1번으로 갑니다 |

**최상위 문서나 도메인 문서를 받으면 기능 목록에서 상태가 `계획 완료`인 계획서를 찾아 진입합니다.**

### 검증

#### 1. 전제를 확인합니다

**계획서를 열어 아래 전제를 확인합니다. 하나라도 통과하지 못하면 진행을 멈추고 해당 항목을 사용자에게 알립니다.**

| 확인 대상 | 통과 조건 |
| --- | --- |
| 단계 | 상태 표가 `계획 완료`입니다 |
| 검토 표시 | `<!-- 사용자 검토 필요 -->`가 없습니다 |
| 항목 표기 | `1. [ ] **DOMAIN-FEATURE-001** 제목 — 설명`처럼 번호 매김 목록이다 (기존 계획서의 `- [ ]` 표기도 허용합니다) |
| 완료 판정 | 항목 아래 `- 완료 판정:` 줄에 있다 (기존 계획서의 항목 줄 표기도 허용합니다) |
| 항목 내용 | 항목만 읽고 무엇을 어디에 할지 정해진다 |
| 문서 구조 | `<루트>/plans/YYYY-MM-DD-주제/<도메인>/<기능>.md`인 기능 계획서이며 최상위·도메인 README가 함께 있습니다 |

| 발견한 계획서 | 할 일 |
| --- | --- |
| 정식 기능 계획서 | 전제 검증을 계속합니다 |
| 단일 초안 또는 날짜 디렉터리 바로 아래 문서 | 구현을 시작하지 않고 `create-plan`의 구조 이전 절차로 돌려보낸다 |

구현을 시작하기 전에 `scripts/validate-plan.sh <기능 계획서>`를 실행해 정식 구조와 확정 상태와 항목 형식을 다시 검사합니다.

**계획서를 지정받지 못했으면 저장 경로에서 찾고, 후보가 여럿이면 사용자에게 선택받습니다.**

저장 경로의 `<루트>`는 계획 최상위 문서에 기록된 문서 루트를 씁니다. 기록이 없거나 계획서를 아직 찾지 못했으면 [`docs-root.md`](../_shared/docs-root.md)의 탐색 순서로 판정합니다.

| 루트 기록 | 할 일 |
| --- | --- |
| 최상위 문서에 있음 | 탐색하지 않고 그 기록을 씁니다 |
| 기록이 없음 | 탐색으로 판정하고, 기록이 없는 옛 계획서라는 점을 알린 뒤 진행합니다 |
| 기록된 루트가 현재 저장소에 없음 | 진행을 멈추고 사용자에게 알립니다 |

무엇을 할지 정해지지 않은 항목은 시작 전에 모아서 한 번에 짚습니다.

#### 2. 선행을 확인합니다

**최상위 문서의 선행 관계 표에서 이 계획서의 대상 ID를 찾고, 연결된 선행 ID가 닫혔는지 읽어서 확인합니다. 쓰지는 않습니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| 선행 기능 계획서의 해당 항목이 체크됨 | 진행합니다 |
| 항목은 미체크지만 선행 기능 계획서가 `완료` | 검증 전이라는 점을 알리고 사용자가 정합니다 |
| 선행 계획서가 없거나 상태가 `계획 완료`가 아님 | 멈추고 어느 것이 먼저인지 알립니다 |

**선행 ID는 다른 도메인을 가리킬 수 있습니다.** 세 조각 ID의 앞 두 조각으로 기능 계획서를 찾아 해당 구현 항목을 확인합니다.

선행 관계가 닫히지 않으면 뒤 단계의 구현을 시작할 수 없으므로 커밋 규칙과 브랜치보다 먼저 확인합니다.

#### 3. 커밋 규칙을 확인합니다

**프로젝트 지시사항에서 찾고, 없으면 최근 커밋 열 개로 형식을 추정해 사용자에게 확인받습니다.**

임의로 정하지 않습니다. 커밋 메시지는 나중에 통째로 고치기 어렵습니다.

#### 4. 브랜치를 준비합니다

**`feature/<주제>`가 없으면 기본 브랜치에서 만들고, 계획서를 시작할 때 거기서 `<도메인>/<기능>`을 땁니다.**

브랜치 이름은 계획 디렉터리 아래 경로에서 `.md`를 뺀 값입니다. 예를 들어 `fmt/split.md`의 브랜치 이름은 `fmt/split`입니다.

계획 구조가 단일 문서라면 `feature/<주제>` 브랜치를 사용합니다.

### 구현

#### 5. 구현을 시작합니다

**계획서의 `마지막 갱신` 날짜를 현재 날짜로 바꿉니다. 구현하는 동안 단계는 `계획 완료`로 유지합니다.**

#### 6. 항목을 하나씩 끝냅니다

**체크되지 않은 첫 항목부터, 아래 절차를 한 묶음으로 반복합니다.**

항목별 버전 확인과 변경 시 중단 시점은 [아키텍처 버전 대조](references/preparation.md#아키텍처-버전-대조)를 따릅니다.

| 순서 | 할 일 |
| --- | --- |
| 1 | 항목에 적힌 범위만 구현합니다 |
| 2 | `## 테스트`에서 이 항목에 대응하는 검증을 찾아 통과시킨다 |
| 3 | [진행 기록](references/execution.md#진행-기록)에 따라 계획서를 갱신합니다 |
| 4 | 코드 변경만 커밋합니다. 계획서 갱신은 로컬에 남깁니다 |

커밋 메시지는 [커밋 규칙](references/execution.md#커밋)을 따릅니다. 항목이 끝날 때마다 변경 내용을 사용자에게 한두 줄로 알립니다.

#### 7. 계획이 틀렸으면 멈춥니다

**설계 전제와 다른 사실을 발견하면 [계획 결함 판정](references/failure.md#계획-결함)에 따라 중단 여부를 정합니다.**

### 완료

#### 8. 끝냈으면 넘깁니다

**모든 항목이 체크되고 대응하는 테스트가 통과하면 단계를 `완료`로 바꾸고 마지막 갱신을 고칩니다.**

**그다음 브랜치를 정리합니다. 병합은 `feature/<주제>`까지만 하고, 거기서 멈춥니다.**

| 현재 브랜치 | 할 일 |
| --- | --- |
| `<도메인>/<기능>` | 확인을 받지 않고 `feature/<주제>`로 병합한 뒤 그 브랜치에 머뭅니다 |
| `feature/<주제>` | 병합할 대상이 없으므로 그대로 둡니다 |

**`feature/<주제>`를 기본 브랜치로 병합하지 않습니다.** 사용자가 직접 요청하기 전까지 작업 결과는 `feature/<주제>`에 남깁니다. 프로젝트 지시사항의 병합 규칙은 사용자가 기본 브랜치에 병합할 때 적용하며, 이 스킬이 병합을 시작하는 근거가 아닙니다.

병합하다 충돌이 나면 병합을 멈추고 충돌 파일을 사용자에게 알립니다.

이 스킬은 여기서 종료합니다. 별도의 검증 스킬이나 후속 명령을 전제로 하지 않으며, 구현 결과의 추가 검토가 필요하면 사용자의 별도 요청으로 진행합니다.

## 경계

- 계획서가 없으면 이 스킬이 아닙니다. 계획서를 먼저 만들어야 합니다.
- 계획서가 `계획 완료`가 아니면 이 스킬을 시작하지 않습니다.
- 계획서에서 정한 범위 밖의 문제는 알리되 고치지 않습니다.
- 계획서에서 수정하는 부분은 상태 표, 체크박스, 마지막 갱신, 기록 줄뿐입니다.
