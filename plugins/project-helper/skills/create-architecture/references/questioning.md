# 결정 목록과 질문

재정의한 문제에서 구조 결정을 추출하고, 사용자와 하나씩 확정합니다.

## 결정 목록 합의

**필요한 결정과 서로의 선행 관계를 적어 우선순위를 합의합니다.**

목표와 요구사항을 충족하려면 무엇을 정해야 하는지 묻고, 가설은 선택 가능한 후보로 둡니다.

구조 결정의 범위는 [공통 판단 기준](../../_shared/architecture.md#구조-결정의-범위)을 따릅니다. 한 계획 안에서 끝나는 세부 구현은 `create-plan`으로 넘깁니다.

| 우선순위 기준 | 먼저 다룰 결정 |
| --- | --- |
| 다른 결정의 전제가 되는가 | 전제가 되는 결정 |
| 되돌리기 어려운가 | 계약이나 책임 경계를 바꾸는 결정 |
| 불확실성이 큰가 | 대안 사이의 차이가 큰 결정 |

두 결정이 서로의 전제라면 각각 독립적으로 확인할 조건을 나눠 먼저 정할 전제를 사용자와 확인합니다. 목록의 순서만 바꿔서는 의존 관계가 풀리지 않습니다.

## 결정 확정

**한 번에 결정 하나만 아래 순서로 다룹니다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 열린 질문으로 사용자의 생각 확인 |
| 2 | 선행 사례 조사 후 비교 자료 제시 |
| 3 | 대안 두세 개와 선택의 차이 제시 |
| 4 | 사용자 선택을 결정 기록에 추가 |
| 5 | 영향을 받는 영역 파일의 절 갱신 |

대안은 번호 목록으로 제시하고, 질문과 대안에는 [질문 예시](../../_shared/questioning-examples.md)에 따라 예시를 붙입니다. 조사는 [검증 절차](verification.md)를, 기록은 [문서 작성 규칙](document.md)을 따릅니다. 사용자가 선택하기 전에 AI가 권하는 대안을 결정으로 확정하지 않습니다.

## 목록 재검토

**결정 하나를 확정할 때마다 남은 결정이 아직 필요한지와 그 순서를 다시 봅니다.**

새 결정이 필요해지거나 기존 결정이 불필요해지면 목록을 고치고 사용자에게 알립니다. 다음 결정은 갱신한 목록을 따릅니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 사용자가 목록 도중에 중단함 | 확정한 결정만 반영 |
| 남은 결정을 확정하지 못함 | 영역 파일의 미해결 질문에 기록 |

중단을 전체 문서 확정이나 커밋 동의로 해석하지 않습니다.
