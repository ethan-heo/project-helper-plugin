# 결정 검증

결정마다 선행 사례를 비교하고, 결정 전체를 실제 요청에 대입합니다.

## 선행 사례 조사

**사용자의 생각을 들은 뒤, 대안을 제시하기 직전에 선행 사례를 조사합니다.**

공식 문서나 원본 구현처럼 확인 가능한 자료를 읽습니다. 이번 결정과 관련된 선택만 비교하며 출처를 함께 적습니다.

| 기록 항목 | 내용 |
| --- | --- |
| 이름 | 사례의 이름과 출처 |
| 택한 방식 | 해당 결정에서 사용한 방식 |
| 이번 요청과 다른 점 | 규모·제약·책임 범위의 차이 |

사례가 있다는 이유만으로 같은 방식을 채택하지 않습니다. 차이를 대안 비교에 반영하고 선택은 사용자에게 맡깁니다.

## 시나리오 대조

**모든 결정을 확정한 뒤 실제 요청 두세 개를 사용자와 정합니다.**

요청마다 영역 파일의 실행 흐름을 처음부터 끝까지 따라갑니다. 각 단계의 담당 구성 요소와 경계를 넘는 정보가 계약에 있는지 확인합니다.

| 기록 항목 | 내용 |
| --- | --- |
| 요청 | 사용자가 실제로 할 요청 |
| 실행 경로 | 구성 요소별 처리와 정보 이동 |
| 대조 결과 | 완료 여부와 끊기는 단계 |

흐름이 끊기거나 책임을 맡은 구성 요소가 없으면 통과하지 못한 것으로 봅니다. 검토 결과는 관련 영역의 실행 흐름에 반영하고, 해결하지 못한 내용은 위험과 미해결 질문에 적습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 선행 사례를 조사할 수 없다 | 알고 있는 사례에 확인 필요 표시 |
| 시나리오에서 흐름이 막힌다 | 확정 보류 후 해당 결정을 목록에 재추가 |

확인할 수 없는 사례의 출처를 만들거나 조사한 것처럼 쓰지 않습니다. 막힌 결정을 다시 확정한 뒤 영향을 받는 시나리오를 재검토합니다.
