# 아키텍처 문서 작성 규칙

프로젝트의 구조 결정을 `<루트>/architecture/` 한 곳에서 갱신합니다.

## 파일 구성과 작성 기준

**색인·결정 기록·영역 파일을 양식에 맞춰 작성합니다.**

| 파일 | 양식 | 맡는 일 |
| --- | --- | --- |
| `README.md` | [색인](../assets/readme-template.md) | 버전과 영역의 색인 |
| `decisions.md` | [결정 기록](../assets/decisions-template.md) | 결정의 선택 근거와 대체 관계 |
| `<영역>.md` | [영역](../assets/area-template.md) | 책임을 함께 지는 구성 요소의 설명 |

영역 파일명은 `agentic-ui.md`처럼 영문 kebab-case로 씁니다. 버전과 마지막 갱신 시각은 색인 첫머리의 버전 표에서만 관리합니다. 갱신 시각은 `YYYY-MM-DD HH:MM` 형식입니다. 영역 파일마다 버전을 두지 않습니다.

| 색인 절 | 작성 기준 |
| --- | --- |
| 버전 표 | 디렉터리 전체의 버전과 마지막 갱신 |
| 시스템의 목적 | 해결할 문제와 제공할 결과 |
| 공통 개념 모델 | 여러 영역이 함께 쓰는 용어와 관계 |
| 영역 목록 | 영역 이름, 파일 링크, 담당 범위 |
| 변경 이력 | 버전, 갱신 시각, 바뀐 파일, 변경 요약 |

변경 이력은 최신 행을 맨 위에 둡니다. 최신 버전과 시각은 버전 표와 맞춥니다.

| 영역 절 | 작성 기준 |
| --- | --- |
| 목적과 문제 | 이 영역이 해결할 문제와 결과 |
| 요구사항과 품질 속성 | 필수 조건과 충족 여부의 판정 기준 |
| 개념 모델 | 영역 안에서만 쓰는 개념과 관계 |
| 책임과 경계 | 구성 요소별 책임과 다른 영역의 책임 |
| 실행 흐름 | 요청부터 결과까지의 이동과 분기 |
| 계약 | 경계를 넘는 정보 항목과 버전 정책 |
| 위험과 미해결 질문 | 실패 가능성과 미확정 질문 |

계약에 필드 단위 스키마를 쓰지 않습니다. 필드는 `create-plan`에서 코드와 함께 정합니다. 따르는 결정은 `AD-001`처럼 ID로 연결합니다. 미해결 질문이 없으면 그 사실을 적습니다.

## 영역 판정

**요청이 영향을 주는 책임 범위로 갱신할 영역을 정합니다.**

| 요청 범위 | 할 일 |
| --- | --- |
| 기존 영역 하나에 속한다 | 해당 영역 파일 갱신 |
| 여러 영역에 걸친다 | 해당 영역 파일 모두 갱신 |
| 어느 영역에도 속하지 않는다 | 사용자 확인 후 새 영역 추가 |

## 버전 규칙

**확정할 변경 중 가장 큰 변경을 기준으로 버전을 한 번 올립니다.**

| 변경 내용 | 버전 |
| --- | --- |
| 첫 확정 | 1.0 |
| 결정 추가 | 부 버전 1 증가 |
| 결정 변경 없는 서술 보완 | 부 버전 1 증가 |
| 기존 결정의 대체 | 주 버전 1 증가, 부 버전 0 |

한 실행에서 대체와 추가가 겹치면 주 버전만 올립니다. 파일마다 올리거나 결정 수만큼 올리지 않습니다. 현재 구조를 먼저 1.0으로 확정한 뒤 요청을 다루는 경우에는 현재 구조 기록과 요청 변경을 별도로 확정합니다. 내용 변경이 없으면 새 변경 이력이나 커밋을 만들지 않습니다.

## 결정 기록

**결정은 삭제하지 않고 새 ID와 대체 관계로 이력을 남깁니다.**

표의 열은 ID, 결정, 근거, 기각한 대안, 상태, 도입 버전, 관련 영역, 대체한 결정 순서입니다. ID는 `AD-001` 형식의 연속 번호이며 사용한 번호를 다시 쓰지 않습니다. 관련 영역에는 영역 목록의 이름을 적습니다.

| 상태 | 뜻 | 대체한 결정 열 |
| --- | --- | --- |
| `채택` | 현재 따르는 결정 | 빈칸 |
| `대체됨` | 새 결정으로 바뀐 결정 | 새 결정의 ID |

예를 들어 `AD-002`가 `AD-001`을 대체하면 옛 행 `AD-001`의 상태를 `대체됨`으로 바꾸고 마지막 열에 `AD-002`를 적습니다. 새 행 `AD-002`는 `채택`이며 마지막 열은 비웁니다. 도입 버전은 각 결정이 처음 채택된 버전으로 유지합니다.

`대체됨`을 다시 `채택`으로 바꾸지 않습니다. 예전 방식으로 되돌릴 때도 새 결정을 추가합니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 같은 경로에 다른 양식의 문서가 있다 | 덮어쓰기 전 처리 방식 확인 |
| 영역 목록과 실제 파일이 어긋난다 | 확정 보류와 해당 파일 보고 |
| 영역 하나를 둘로 나눠야 한다 | 새 영역 둘 추가 후 옛 파일 삭제 |

영역 분리는 결정 추가로 기록합니다. 분리와 함께 기존 결정을 대체했다면 버전은 대체 규칙을 따릅니다.
