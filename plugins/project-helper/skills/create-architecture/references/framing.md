# 문제 재정의

요청에 섞인 결과·필수 조건·해법을 구분해 결정 목록의 입력을 만듭니다.

## 판정 기준

**요청을 목표·요구사항·가설로 나눠 사용자와 확정합니다.**

| 구분 | 판정 기준 |
| --- | --- |
| 목표 | 구현 방식이 바뀌어도 남는 결과 |
| 요구사항 | 충족 여부를 판정할 수 있는 필수 조건 |
| 가설 | 다른 해법으로 바꿀 수 있는 사용자의 해법 |

분류가 끝나기 전에 스키마나 컴포넌트 구성을 제안하지 않습니다. 가설은 버리지 않고 다음 단계의 결정 후보로 넘깁니다. 사용자가 정한 기술적 제약인지 바꿀 수 있는 해법인지 모호하면 먼저 확인합니다.

## Agentic UI 예시

사용자가 질문하거나 지시하면 답변과 함께 서비스 기능을 쓸 UI를 보여 주려 합니다. 단계가 있는 요청은 단계형 UI로 표현해야 하며, 메타데이터 기반 렌더링으로 기존 컴포넌트를 조합하는 패턴을 생각하고 있습니다.

| 구분 | 요청에서 분리한 내용 |
| --- | --- |
| 목표 | 답변과 함께 서비스 기능을 쓸 UI 제공 |
| 요구사항 | 단계가 있는 요청의 단계형 UI 표현 |
| 가설 | 메타데이터 렌더링으로 기존 컴포넌트 조합 |

목표와 요구사항을 확인한 뒤 렌더링 방식을 결정 목록에 넣습니다. 메타데이터 방식을 이미 채택한 것으로 기록하지 않습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 가설만 있고 목표가 없다 | 해법으로 이루려는 결과부터 질문 |
| 필수 조건인지 해법인지 모호하다 | 바꿀 수 있는 조건인지 사용자 확인 |
