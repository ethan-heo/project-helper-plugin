# 현재 구조 조사

코드가 있고 아키텍처 문서가 없을 때 시스템 전체의 현재 구조를 기록합니다.

## 조사 순서

**요청 관련 영역만 고르지 말고 시스템 전체의 영역을 먼저 파악합니다.**

| 순서 | 조사 대상 | 기록 위치 |
| --- | --- | --- |
| 1 | 프로젝트 지시사항과 기존 문서 | 시스템의 목적, 공통 개념 모델 |
| 2 | 디렉터리 구조와 진입점 | 영역 목록 |
| 3 | 영역 사이의 호출과 데이터 이동 | 책임과 경계, 실행 흐름, 계약 |
| 4 | 코드에 드러난 설계 선택 | 결정 기록 |

각 영역의 진입점부터 호출과 데이터 이동을 따라가며 실제 코드 경로를 확인합니다. 문서와 코드가 다르면 코드를 현재 사실로 보고 어긋난 결정을 알립니다. 영역 파일의 나머지 절은 [문서 작성 규칙](document.md)에 따라 확인된 내용으로 채웁니다.

## 추정과 확인

**영역 목록과 결정 기록을 각각 사용자에게 확인받습니다.**

1. 디렉터리와 진입점을 조사한 뒤 영역 목록을 확정합니다.
2. 영역 조사 후 코드에서 읽어 낸 결정 기록을 확정합니다.

코드에 드러난 선택과 그 선택의 이유를 구분합니다. 이유가 코드에 없으면 결정 기록의 근거 열에 `추정`을 붙입니다. 사용자가 확인한 항목에서만 `추정`을 뗍니다. 응답이 없는 항목을 확인된 것으로 처리하지 않습니다.

색인·영역·결정 기록을 모두 채우고 본문의 확정 절차로 검증·버전 반영·커밋을 처리합니다. 현재 구조를 1.0으로 확정한 뒤 요청의 문제 재정의로 넘어갑니다. 현재 구조 기록만 요청받았다면 여기서 끝냅니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 코드가 없어 조사할 구조가 없다 | 현재 구조 기록 생략 |
| 전체 조사에 시간이 오래 걸린다 | 영역 목록 확정 후 영역별 조사 |
| 코드로 선택 이유를 확인할 수 없다 | 근거에 추정 표시 후 사용자 확인 |
| 문서와 코드가 어긋난다 | 코드의 현재 동작과 차이 보고 |
