# 절 항목과 서술 규칙

## 목적

각 문서의 필수 항목이 무엇이고, 그 내용을 어느 입력에서 가져오며, 어떤 문장으로 쓰는지 정한다.

## 입력의 우선순위

| 입력 | 무엇을 얻는가 |
| --- | --- |
| PRD | 도메인의 목적, 비즈니스 규칙의 배경, 용어의 뜻 |
| 계획서 | 도메인 경계, 설계 결정과 근거, 예외 처리 방침, 테스트 시나리오 |
| 코드 | 실제 엔티티와 스키마, 엔드포인트와 페이로드, 의존성, 설정 값 |

세 입력이 어긋나면 코드를 사실로 쓴다. 어긋난 지점은 문서 본문에 섞지 않고 따로 모아 사용자에게 보고한다.

## 도메인 문서의 필수 항목

### `01_도메인_개요.md`

| 항목 | 주된 근거 | 형식 |
| --- | --- | --- |
| 도메인 정의 | PRD, 계획서 | 산문 두세 문장 |
| 책임 범위 | 계획서 | 담당·비담당 표 |
| 유비쿼터스 용어 사전 | PRD, 코드의 명명 | 용어·영문 표기·정의 표 |
| 핵심 비즈니스 규칙 | PRD, 코드의 분기 조건 | 번호 목록 |
| 예외 케이스 | 계획서의 예외 상황, 코드의 예외 처리 | 상황·처리 표 |

### `02_도메인_모델.md`

| 항목 | 주된 근거 | 형식 |
| --- | --- | --- |
| 엔티티와 값 객체 | 코드의 모델 정의 | Mermaid `erDiagram`과 목록 표 |
| 생명 주기 | 코드의 상태 값과 전이 | 산문. 상태가 있으면 전이 조건까지 |
| 데이터베이스 스키마 | 마이그레이션이나 스키마 정의 | 테이블마다 필드·타입·제약·설명 표 |
| 인덱스와 제약 | 스키마 정의 | 대상·종류·이유 표 |

### `03_API_명세.md`

| 항목 | 주된 근거 | 형식 |
| --- | --- | --- |
| 엔드포인트 목록 | 라우터나 컨트롤러 | 메서드·경로·설명·인증 표 |
| 요청과 응답 | 요청·응답 타입 정의 | 필드 표와 실제 값이 담긴 JSON 예시 |
| 에러 코드 | 코드의 예외 처리 | 상태 코드·코드·발생 조건 표 |
| 이벤트 메시징 | 발행·구독 코드 | 토픽과 메시지 스키마. 쓰지 않으면 "해당 없음" |

### `04_도메인_특화_가이드.md`

| 항목 | 주된 근거 | 형식 |
| --- | --- | --- |
| 외부 의존성 | 패키지 정의와 임포트 | 대상·종류·용도 표 |
| 설정 | 환경 변수와 설정 파일 | 항목·출처·비고 표. 실제 값은 옮기지 않는다 |
| 핵심 테스트 시나리오 | 계획서의 테스트, 기존 테스트 코드 | ID·상황·기대 동작 표 |
| 트러블슈팅 | 계획서의 예외 상황, 코드의 방어 처리 | 증상·원인·조치 표 |

## 상위 두 층의 필수 항목

| 문서 | 항목 |
| --- | --- |
| 글로벌 아키텍처 가이드 | 시스템 개요와 구성도, 도메인 구성과 도메인 간 통신, 기술 스택, 인프라, 공통 보안 원칙, 공통 컨벤션 |
| 공통 에러 코드 | 에러 응답 형식, 공통 코드 목록, 도메인별 코드 규칙 |
| 인증 및 인가 가이드 | 인증 방식과 토큰 구조, 인가 규칙과 엔드포인트 보호, 실패 처리 |

## 서술 규칙

개발자가 문서만 보고 곧바로 코드를 쓸 수 있는 수준으로 구체적으로 적는다.

- 데이터 모델과 페이로드는 설명 대신 실제 필드 이름과 타입이 담긴 표나 예시로 보인다.
- JSON 예시에는 자리 표시자 대신 실제로 가능한 값을 넣는다.
- 어조는 테크니컬 라이팅을 따른다. 평서형으로 끝내고 수식을 줄인다.
- 헤더, 글머리 기호, 표를 적극적으로 쓴다. 세 항목 이상 나열되면 표로 만든다.
- 같은 내용을 두 문서에 복제하지 않고 참조 경로를 적는다.

## 미확인 표기

근거를 찾지 못한 자리는 추측으로 채우지 않는다.

```
<!-- 미확인: 결제 취소 제한 시간의 근거를 코드에서 찾지 못했다 -->
```

| 상황 | 할 일 |
| --- | --- |
| 코드에 해당 구현이 없다 | 미확인 주석을 남기고 무엇을 찾지 못했는지 적는다 |
| 그 항목이 이 도메인에 해당하지 않는다 | 미확인이 아니라 "해당 없음"과 그 이유를 적는다 |
| 확정하려면 사용자 판단이 필요하다 | 미확인 주석을 남기고 확정 단계에서 모아 질문한다 |

미확인 주석이 하나라도 남아 있으면 문서를 확정하지 않는다.
