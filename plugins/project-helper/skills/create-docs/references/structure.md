# 문서 구조

## 목적

생성할 개발 문서의 층위와 배치, 그리고 계획서의 도메인을 문서 디렉터리로 옮기는 규칙을 정한다.

## 보관 경로

[`docs-root.md`](../../_shared/docs-root.md)의 탐색 순서로 문서 루트를 판정하고, 그 루트를 개발 문서의 최상위로 삼는다.

| 상황 | 할 일 |
| --- | --- |
| 계획 최상위 문서에 루트 기록이 있다 | 탐색하지 않고 그 기록을 쓴다 |
| 기록이 없다 | 탐색 순서로 판정하고 결과를 사용자에게 알린다 |
| 계획서에 적힌 루트와 탐색 결과가 다르다 | 계획서의 기록을 우선하고 차이를 보고한다 |
| 그 경로에 다른 문서 체계가 이미 있다 | 덮어쓰지 않고 사용자에게 경로를 확인받는다 |

## 세 층 구조

```
<보관 경로>/
├── 글로벌_아키텍처_가이드.md
├── 공통_인프라_및_컨벤션/
│   ├── 공통_에러_코드.md
│   └── 인증_및_인가_가이드.md
└── 도메인_문서/
    └── <도메인 이름>/
        ├── 01_도메인_개요.md
        ├── 02_도메인_모델.md
        ├── 03_API_명세.md
        └── 04_도메인_특화_가이드.md
```

| 층 | 담는 것 |
| --- | --- |
| 글로벌 아키텍처 가이드 | 시스템 전체 구조, 도메인 목록, 기술 스택, 인프라, 공통 보안 원칙 |
| 공통 인프라 및 컨벤션 | 도메인을 가리지 않고 적용되는 에러 코드와 인증·인가 규칙 |
| 도메인 문서 | 도메인 하나의 개요·모델·API·운영 |

여러 도메인에 같은 내용이 반복되면 상위 층으로 올리고, 도메인 문서에서는 참조 경로만 적는다.

## 계획서 도메인과의 대응

계획서의 도메인 구조를 그대로 문서 디렉터리에 대응시킨다. 도메인 경계를 새로 정하지 않는다.

| 계획서 | 문서 |
| --- | --- |
| 계획 디렉터리 (`<루트>/plans/YYYY-MM-DD-<주제>/`) | 보관 경로 전체 |
| 도메인 디렉터리 하나 | `도메인_문서/<도메인 이름>/` 하나 |
| 기능 계획서 | 대응하는 도메인 문서 네 편의 내용 |

디렉터리 이름은 계획서의 도메인 README에 적힌 도메인 이름을 쓴다. 이름이 영문 코드뿐이면 한글 이름을 사용자에게 확인받아 `회원_도메인(User_Domain)` 형태로 짓는다.

| 상황 | 할 일 |
| --- | --- |
| 계획서에 도메인이 하나뿐이다 | 디렉터리도 하나만 만든다. 세 층 구조는 그대로 유지한다 |
| 계획서의 도메인이 코드의 모듈 경계와 다르다 | 계획서를 따르고, 차이를 사용자에게 보고한다 |
| 계획서에 없는 도메인이 코드에 있다 | 문서를 만들지 않고 발견 사실만 보고한다 |

## 양식 적용

`assets/`의 파일을 보관 경로에 복사한 뒤 내용을 채운다. 양식에 있는 절은 지우지 않는다.

| 상황 | 할 일 |
| --- | --- |
| 해당 사항이 없는 절이다 | 절을 지우지 않고 "해당 없음"과 그 이유를 적는다 |
| 근거를 찾지 못한 자리다 | `<!-- 미확인: ... -->` 주석을 남긴다 |
