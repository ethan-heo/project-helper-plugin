# 초안 집필

## 목적

목차에서 세운 절과 모은 재료를 문장으로 옮겨, 사용자가 고쳐 쓰기만 하면 되는 초안을 만든다.

## 핵심 지시

절마다 두세 문장으로 논지만 세우고, 재료에 없는 내용을 문장으로 지어내지 않는다.

## 절차 흐름

### 문체를 고정한다

| 요소 | 규칙 |
| --- | --- |
| 서술 어미 | 평어체로 쓴다. "…했다", "…였다" |
| 인칭 | 글쓴이를 "나"로 드러내지 않는다. 한 일을 주어 없이 적는다 |
| 어조 | 겪은 일을 적는 기록투로 쓴다. 독자에게 권하거나 설득하는 문장을 쓰지 않는다 |

문체를 매번 묻지 않는다. 사용자가 이번 글에서만 다른 문체를 지정하면 그 지정을 따르되 규칙 자체는 고치지 않는다.

### 분량을 맞춘다

| 대상 | 분량 |
| --- | --- |
| 절 하나 | 두세 문장 |
| 글 전체 | 절의 수에 따라 정해지므로 따로 맞추지 않는다 |

두세 문장은 논지를 세우는 데까지다. 예시를 들거나 근거를 펼치는 문장은 쓰지 않고 사용자가 붙이도록 남긴다.

한 절에 재료가 셋 이상 걸려 두세 문장에 담기지 않으면, 그 절에서 가장 무거운 재료 하나를 골라 쓰고 나머지는 대화에서 알린다. 문장 수를 늘려 다 담지 않는다.

### 재료를 문장으로 옮긴다

재료 한 항목이 문장 하나가 되는 것이 기본이다. 항목에 담긴 인과를 문장에서도 잇는다.

| 이렇게 | 이렇게 말고 |
| --- | --- |
| 확정한 계획을 고칠 수 없게 해 두었더니 추가 작업이 매번 새 계획서로 나갔고, 한 기능에 계획서가 여럿 쌓였다 | 계획서가 여러 개 생기는 문제가 있었다 |
| 파일 수정 시각으로 그날의 작업을 판정하면 열어 보기만 한 문서까지 걸린다 | 수집 기준을 문서 안의 날짜로 정했다 |

왼쪽은 무엇 때문에 무엇이 되었는지를 담고, 오른쪽은 결과만 남겨 읽는 사람이 인과를 다시 세워야 한다.

### 식별자를 걷어낸다

| 근거에 있는 것 | 본문에 쓰는 것 |
| --- | --- |
| 구현 항목 ID (`DEVLOG-DRAFT-001` 같은 것) | 무엇을 만들었는지를 말로 푼 표현 |
| 파일 경로와 디렉터리 이름 | 그 파일이 맡은 역할 |
| 계획서의 절 이름 | 그 절에 적혀 있던 내용 |

식별자는 저장소 안에서만 뜻이 통한다. 계획서도 로컬에만 있어 정리되면 사라지므로, 경로를 남기면 글이 깨진 참조를 안는다.

### 절 제목과 글 제목을 붙인다

| 요소 | 규칙 |
| --- | --- |
| 글 제목 | `# <제목>`. 사용자가 고른 제목 후보를 쓰고, 모두 물리면 가제를 쓴다 |
| 절 제목 | `## <제목>`. 목차에서 정한 제목을 그대로 쓴다 |
| 흐름 단계 | 본문에 적지 않는다. 주석으로도 남기지 않는다 |

흐름 단계는 절을 세울 때 쓰는 기준이지 글의 일부가 아니다. 남겨 두면 게시하기 전에 지워야 할 것이 생긴다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 필수 단계의 재료가 비어 있다 | 그 절의 제목만 세우고 문장을 지어내지 않는다. 비운 자리를 대화에서 알린다 |
| 선택 단계의 재료가 없다 | 그 절을 세우지 않는다 |
| 사용자가 게시할 수준까지 써 달라고 한다 | 뼈대 문장까지가 이 스킬의 범위임을 알린다 |
| 사용자가 제목 후보를 모두 물린다 | 가제 한 줄을 글 제목으로 쓴다 |
| 재료가 서로 어긋난다 | 한쪽을 골라 쓰지 않고 어긋난 사실을 대화에서 알린다 |

## 근거·예시

초안을 뼈대 문장까지만 쓰는 이유는 글의 주인이 사용자이기 때문이다. 문단을 온전히 채워 주면 고쳐 쓰는 일이 남의 글을 다듬는 일이 되고, 그러면 자기 말로 쓸 여지가 오히려 줄어든다.

반대로 목차와 재료만 주면 첫 문장을 백지에서 시작해야 한다. 두세 문장으로 논지를 세워 두면 시작하는 자리가 정해지고, 살을 붙이는 일은 사용자가 자기 말로 할 수 있다.

문체를 규칙으로 고정한 이유는 질문을 늘리지 않기 위해서다. 글마다 문체를 물으면 초안을 받기까지 거치는 확인이 하나 더 늘고, 그러면 스킬을 쓰는 이유가 줄어든다.
