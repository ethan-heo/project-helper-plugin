# 빈자리를 채우는 질문

## 목적

계획서에 남지 않는 것, 곧 그때의 판단과 시행착오를 사용자에게서 받아 목차에 넣는다.

## 핵심 지시

계획서에서 확인할 수 있는 내용은 묻지 않고, 사용자만 답할 수 있는 자리만 질문한다.

## 절차 흐름

### 물을 자리를 고른다

| 자리 | 질문할까 |
| --- | --- |
| 계획서에 적혀 있다 | 묻지 않는다. 그대로 재료로 쓴다 |
| 계획서에 없고 문서로 확인할 수도 없다 | 묻는다 |
| 계획서에 없지만 코드나 커밋에서 확인된다 | 묻지 않고 재료로도 쓰지 않는다. 이 스킬의 근거는 계획서와 PRD뿐이다 |

### 질문의 형태를 정한다

| 빈자리의 유형 | 질문의 형태 |
| --- | --- |
| 결정에 이른 계기 | "왜 이 방식이어야 했는지, 계획서에는 근거만 있고 계기가 없습니다. 무엇을 겪고 이렇게 정하셨습니까?" |
| 고민한 지점 | "이 결정에서 끝까지 망설인 대목이 있었습니까?" |
| 시행착오 | "구현하면서 계획과 어긋난 곳이 있었습니까?" |
| 독자에게 남길 조언 | "같은 문제를 겪는 사람에게 한 가지만 알려 준다면 무엇입니까?" |
| 글의 무게중심 | "이 글에서 가장 하고 싶은 말이 어느 절입니까?" |

한 번에 질문 하나 또는 선택지 한 벌만 제시한다. 절마다 물을 것을 모아 두었다가, 절 순서대로 한 묶음씩 확인한다.

### 답을 목차에 넣는다

받은 답은 그 절의 재료에 넣는다. 답변을 문장으로 다듬어 본문처럼 쓰지 않는다. 글은 사용자가 쓰므로 목차에는 재료로만 남긴다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 사용자가 답하지 않고 넘어간다 | 그 자리를 열린 질문으로 남기고 다음으로 간다. 비운 채 두지 않는다 |
| 답이 절의 방향을 바꾼다 | 그 절의 할 말을 고치고, 흐름이 어긋나면 절 순서를 다시 제안한다 |
| 물을 것이 다섯을 넘는다 | 글의 무게중심에 걸리는 것부터 세 개까지만 묻고 나머지는 열린 질문으로 남긴다 |
| 사용자가 본문까지 써 달라고 한다 | 목차와 재료까지가 이 스킬의 범위임을 알린다 |

## 근거·예시

계획서는 결정의 기록이지 과정의 기록이 아니다. 무엇을 택했는지는 남지만 그 앞에서 무엇을 헤맸는지는 남지 않는다. 그런데 글에서 읽을 만한 대목은 대개 헤맨 자리에 있다.

질문을 다섯으로 제한하는 이유는 목차를 받는 데 걸리는 시간이 길어지면 스킬을 쓰는 이유가 없어지기 때문이다. 빠짐없이 채우는 것보다 글을 시작할 수 있게 하는 것이 목적이다.
