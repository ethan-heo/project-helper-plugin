# 빈자리를 채우는 질문

## 목적

계획서에 남지 않는 것, 곧 그때의 판단과 시행착오를 사용자에게서 받아 초안의 재료로 삼는다.

## 핵심 지시

계획서에서 확인할 수 있는 내용은 묻지 않고, 사용자만 답할 수 있는 자리만 질문한다.

## 절차 흐름

### 물을 자리를 고른다

| 자리 | 질문할까 |
| --- | --- |
| 계획서에 적혀 있다 | 묻지 않는다. 그대로 재료로 쓴다 |
| 계획서에 없고 문서로 확인할 수도 없다 | 묻는다 |
| 계획서에 없지만 코드나 커밋에서 확인된다 | 묻지 않고 재료로도 쓰지 않는다. 이 스킬의 근거는 계획서와 PRD뿐이다 |

### 질문의 형태를 정한다

질문은 두 묶음으로 나눈다. 필수 단계를 채우는 질문과 선택 단계를 세울지 정하는 질문이며, 각각 세 개까지 묻는다.

**필수 단계용 (배경·문제 정의·의사결정·결과)**

| 빈자리의 유형 | 질문의 형태 |
| --- | --- |
| 결정에 이른 계기 | "왜 이 방식이어야 했는지, 계획서에는 근거만 있고 계기가 없습니다. 무엇을 겪고 이렇게 정하셨습니까?" |
| 고민한 지점 | "이 결정에서 끝까지 망설인 대목이 있었습니까?" |
| 글의 무게중심 | "이 글에서 가장 하고 싶은 말이 어느 절입니까?" |

**선택 단계용 (기획 과정·시행착오·회고·향후 개선 방향)**

| 세울지 정할 단계 | 질문의 형태 |
| --- | --- |
| 기획 과정 | "무엇을 먼저 하고 무엇을 뒤로 미룰지 가른 기준이 있었습니까?" |
| 시행착오 | "구현하면서 계획과 어긋난 곳이 있었습니까?" |
| 회고 | "지금 다시 한다면 무엇을 달리하시겠습니까?" |
| 향후 개선 방향 | "이번에 손대지 않고 남겨 둔 것이 있습니까? 남긴 이유는 무엇입니까?" |

선택 단계용 질문에 답이 없으면 그 단계는 절로 세우지 않고 추가 확인 항목으로 내린다. 답을 재촉하지 않는다.

한 번에 질문 하나 또는 선택지 한 벌만 제시한다. 절마다 물을 것을 모아 두었다가, 절 순서대로 한 묶음씩 확인한다.

### 답을 초안에 넣는다

받은 답은 해당하는 절의 재료로 넣고, 선택 단계용 질문의 답이면 그 단계를 절로 새로 세운다. 재료는 초안 단계에서 문장으로 풀리므로, 답변에 담긴 인과를 잃지 않게 받은 말 그대로 재료에 적어 둔다.

사용자가 답하지 않은 자리는 문장으로 지어내지 않는다. 그 절의 제목만 세우고 비었다는 사실을 대화에서 알린다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 사용자가 답하지 않고 넘어간다 | 그 자리를 채우지 않고 다음으로 간다. 무엇이 비었는지는 초안을 보일 때 함께 알린다 |
| 답이 절의 방향을 바꾼다 | 그 절의 할 말을 고치고, 흐름이 어긋나면 절 순서를 다시 제안한다 |
| 한 묶음에서 물을 것이 셋을 넘는다 | 글의 무게중심에 걸리는 것부터 세 개까지만 묻고 나머지는 묻지 않는다. 두 묶음을 합쳐 여섯 개를 넘기지 않는다 |
| 사용자가 게시할 수준까지 써 달라고 한다 | 절마다 두세 문장의 뼈대까지가 이 스킬의 범위임을 알린다 |

## 근거·예시

계획서는 결정의 기록이지 과정의 기록이 아니다. 무엇을 택했는지는 남지만 그 앞에서 무엇을 헤맸는지는 남지 않는다. 그런데 글에서 읽을 만한 대목은 대개 헤맨 자리에 있다.

질문을 여섯으로 제한하는 이유는 초안을 받는 데 걸리는 시간이 길어지면 스킬을 쓰는 이유가 없어지기 때문이다. 빠짐없이 채우는 것보다 글을 시작할 수 있게 하는 것이 목적이다.

묶음을 나눈 이유는 두 질문의 성격이 다르기 때문이다. 필수 단계용 질문은 이미 서 있는 절을 채우지만, 선택 단계용 질문은 절을 세울지 말지를 가른다. 한 상한 안에서 섞어 물으면 절을 세울 기회가 먼저 소진된다.
