# write-devlog

## 역할과 목적

`write-devlog`는 그날 갱신된 계획서와 PRD를 글감으로 삼아, 사용자가 글을 쓸 때 따라갈 목차를 만든다. 글은 사용자가 직접 쓴다. 이 스킬은 무엇을 어떤 순서로 쓸지와 그 재료를 모아 주는 데까지만 관여한다.

## 실행 원칙

**완성된 글을 대신 쓰지 않고, 재료가 없는 자리는 채우지 않고 묻는다.**

사용자가 이 스킬을 명시하면 뒤따르는 답변은 기본적으로 목차 작성의 입력으로 해석한다. 질문이 스킬의 개념이나 사용법만 묻는 설명 요청이면 작성을 진행하지 않고 일반 답변을 제공한다. 작성 입력으로 이어진 실행 맥락은 목차가 저장되거나 사용자가 다른 스킬 또는 일반 질문을 명시할 때까지 유지한다.

근거는 계획서와 PRD 두 가지뿐이다. 코드나 커밋 이력에서 내용을 끌어오지 않는다. 문서에 없는 대목은 추측으로 메우지 않고 사용자에게 물어 채운다.

다른 스킬의 산출물은 읽기만 하고 고치지 않는다. 계획서의 상태 표나 체크박스를 건드리지 않으며 코드도 손대지 않는다. 계획서의 단계가 `계획 완료`든 `완료`든 실행할 수 있다. 그날 무엇을 했는지 기록하는 것이 목적이지 구현이 끝났는지 판정하는 것이 목적이 아니기 때문이다.

## 참조 문서 규칙

이 문서가 `write-devlog`의 실행 지시사항을 정하는 기준 문서다. 작업을 시작할 때 이 문서를 먼저 읽고, 아래 표의 절차에 진입할 때 지정된 참조 문서만 읽는다.

| 문서 유형 | 역할 | 적용 범위 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 분기 | `write-devlog` 전체 |
| `../_shared/docs-root.md` | 문서 루트 판정 규칙 | 수집 단계의 경로 결정 |
| `references/collection.md` | 기준일 판정과 글감 수집 | 수집 단계 |
| `references/outline.md` | 목차의 흐름과 절 구성 | 목차 작성 단계 |
| `references/questioning.md` | 빈자리를 채우는 질문 | 보충 단계 |
| `assets/outline-template.md` | 목차 양식 | 파일을 만들 때 |

참조 문서는 본문에 없는 실행 범위를 추가하지 않는다.

## 작성 절차

### 1. 글감을 모은다

**기준일을 정하고, 그날 갱신된 계획서와 PRD를 모아 목록을 사용자에게 보인다.**

[`collection.md`](references/collection.md)를 읽고 아래 순서로 진행한다.

| 순서 | 할 일 |
| --- | --- |
| 1 | 기준일을 정한다. 사용자가 날짜를 지정하지 않으면 오늘로 본다 |
| 2 | [`docs-root.md`](../_shared/docs-root.md)로 문서 루트를 판정한다 |
| 3 | `<루트>/plans/`와 `<루트>/prds/`에서 `마지막 갱신` 값이 기준일과 같은 문서를 모은다 |
| 4 | 수집 목록과 제외한 문서를 함께 보이고, 뺄 것과 더할 것을 확인받는다 |

| 수집 결과 | 할 일 |
| --- | --- |
| 한 편 이상 | 다음 단계로 넘어간다 |
| 한 편도 없다 | 목차를 만들지 않고 사실을 알린 뒤 다른 날짜를 지정할지 묻는다 |

### 2. 목차를 짠다

**모은 문서에서 배경·결정·구현 결과를 읽어 문제 → 결정 → 결과 흐름의 절을 세운다.**

[`outline.md`](references/outline.md)를 읽고 절마다 제목과 할 말, 재료, 열린 질문을 채운다.

| 상황 | 할 일 |
| --- | --- |
| 글감이 한 갈래다 | 한 편의 목차로 짠다 |
| 글감이 여러 주제로 갈린다 | 몇 갈래로 나눌지 제안하고 사용자가 고르게 한다 |

### 3. 빈자리를 채운다

**계획서에 근거가 없어 비는 자리를 질문해 채운다.**

[`questioning.md`](references/questioning.md)를 읽고 질문을 만든다. 사용자가 답하지 않기로 한 자리는 열린 질문으로 남긴다.

### 4. 저장한다

**목차를 `<루트>/posts/YYYY-MM-DD-<주제>.md`로 남긴다.**

| 상황 | 할 일 |
| --- | --- |
| `posts/`가 없다 | 만들고 `.gitignore`에 등록한다 |
| 같은 날짜의 목차 파일이 이미 있다 | 덮어쓰지 않고 이어 쓸지 새로 만들지 묻는다 |

`assets/outline-template.md`를 복사해 채운다. 저장한 뒤 절 목록과 남은 열린 질문을 사용자에게 알린다.

## 경계

- 완성된 글은 쓰지 않는다. 사용자가 요청해도 목차와 재료까지만 제공하고, 본문 집필은 사용자의 몫임을 알린다.
- 구현 결과를 프로젝트 안의 문서로 정리하는 일은 이 스킬이 아니라 `/create-docs`다.
- 요구사항을 정하는 일은 `/create-prd`, 구현 방식을 정하는 일은 `/create-plan`이다.
- 계획서와 PRD, 코드를 고치지 않는다. 이 스킬이 만드는 파일은 `<루트>/posts/` 아래의 목차뿐이다.
