# create-sub-prd

## 역할과 목적

`create-sub-prd`는 확정된 PRD 한 편을 요구사항 묶음 단위로 나누어 하위 PRD 여러 편으로 옮기고, 그 과정에서 담당 요구사항을 질의응답으로 구체화합니다. 원래 PRD는 목차 역할로 정리합니다.

요구사항을 새로 발굴하지 않으며, 구현 방식도 다루지 않습니다.

사용자는 묶음 단위와 구체화의 결정권자이고, AI는 후보 제안·질문·문서 생성·연결 기록을 맡습니다.

## 실행 원칙

**확정된 상위 PRD만 나누고, 모든 요구사항을 빠짐없이 한 곳에 배정하며, 나누면서 담당 요구사항을 함께 구체화합니다.**

**호출 후 입력은 [스킬 실행 맥락](../_shared/session.md#입력-해석)에 따라 해석합니다.**

하위 PRD는 상위와 같은 여덟 절 양식으로 씁니다. 하위 문서라는 이유로 서술을 성기게 남기지 않으며, 어느 계층을 읽어도 구체성의 수준이 같아야 합니다.

분해는 반복할 수 있습니다. 하위 PRD가 여전히 모호하면 그 문서를 새 상위로 삼아 같은 절차를 다시 시작합니다.

| [`architecture.md`](../_shared/architecture.md) | 후속 스킬 판단 | 확정 후 |
| `../_shared/docs-root.md` | 문서 루트 판정 규칙 | 대상 선정 |

## 분해 절차

### 1. 대상을 정합니다

**사용자가 지정한 PRD를 우선하고, 지정이 없으면 후보를 제시해 고르게 합니다.**

| 상황 | 할 일 |
| --- | --- |
| 사용자가 파일을 지정함 | 그 문서를 대상으로 삼습니다 |
| 지정이 없음 | [`docs-root.md`](../_shared/docs-root.md)로 문서 루트를 판정하고 `<루트>/prds/`의 PRD를 목록으로 제시합니다 |
| 후보가 없음 | 분해할 PRD가 없음을 알리고 `/create-prd`를 안내한 뒤 종료합니다 |

### 2. 확정 여부를 확인합니다

**상위 PRD가 확정 상태일 때만 분해합니다.**

| 확인 대상 | 통과 조건 |
| --- | --- |
| 미해결 질문 | `미해결 질문` 절에 남은 항목이 없습니다 |
| 필수 절 | 여덟 절이 모두 있고 `../_shared/prd/validate-prd.sh`를 통과합니다 |
| 요구사항 표 | 모든 항목이 ID와 필수·선택 구분, 충족 판정을 가집니다 |

하나라도 통과하지 못하면 분해하지 않고 `/create-prd`로 상위 PRD를 먼저 확정하도록 안내합니다.

### 3. 묶음을 확정합니다

**[`grouping.md`](references/grouping.md)를 읽고 묶음 후보를 제안한 뒤, 사용자가 고른 묶음을 배정으로 삼습니다.**

배정의 누락·중복과 사용자 지정 묶음은 [배정 규칙과 예외 처리](references/grouping.md#배정-규칙)를 따릅니다.

### 4. 하위 PRD를 만듭니다

**[`hierarchy.md`](references/hierarchy.md)의 경로와 ID 규칙에 따라 묶음마다 문서 한 편을 만들고, [`detailing.md`](references/detailing.md)의 질문으로 담당 요구사항을 구체화합니다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 상위 문서를 자기 이름의 디렉터리 안 `README.md`로 옮기고, 그 옆에 `../_shared/prd/prd-template.md`를 복사해 하위 PRD를 만듭니다 |
| 2 | `마지막 갱신` 아래에 상위 문서 경로와 담당 요구사항 ID를 한 줄로 적습니다 |
| 3 | 상위에서 확정된 절을 승계합니다. 어느 절을 승계하고 옮기기 전에 무엇을 점검하는지는 `detailing.md`가 정합니다 |
| 4 | 담당 요구사항을 질의응답으로 여러 항목으로 가르고, 각 항목에 관찰 가능한 충족 판정을 붙입니다 |
| 5 | 요구사항 ID는 상위 ID를 이어받아 매깁니다 |
| 6 | 절을 쓸 때 [`writing.md`](../_shared/prd/writing.md)의 서술 규칙과 [`writing-style.md`](../_shared/writing-style.md)의 문체·표기·어휘 규칙을 적용하고, `detailing.md`의 구체화 판정을 대조합니다 |

구체화 결과는 [구체화 판정](references/detailing.md#구체화-판정)을, 미확정 내용은 [PRD 서술 규칙](../_shared/prd/writing.md)을 따릅니다.

### 5. 상위 PRD를 정리합니다

**상위 요구사항 표에 `하위 PRD` 열을 더해 각 행을 담당 문서로 연결합니다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 요구사항 표에 `하위 PRD` 열을 추가하고 각 행에 담당 문서 링크를 넣습니다 |
| 2 | 분해 도중 상위의 요구사항이나 승계한 절의 문구를 고쳐야 했다면 사용자에게 확인받고 수정합니다 |
| 3 | 상위 문서가 옮겨졌으므로 문서 안의 상대 경로 참조와, 한 계층 위에서 이 문서를 가리키는 링크를 고칩니다 |
| 4 | `마지막 갱신`을 오늘 날짜로 맞춥니다 |

상위 PRD의 요구사항 서술은 지우지 않습니다. 상위만 읽어도 전체 범위가 보여야 합니다.

### 6. 검증하고 넘깁니다

**형식과 배정을 모두 검사한 뒤에만 분해를 마칩니다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | `scripts/validate-sub-prd.sh <상위 PRD>`로 배정과 계층, 하위 문서의 형식을 검사합니다 |
| 2 | `writing.md`의 확정 전 점검 목록을 하위 문서마다 대조합니다 |
| 3 | 용어 일관성은 상위와 모든 하위 문서를 한꺼번에 대조합니다 |
| 4 | 불통과 항목이 있으면 해당 절을 사용자와 다시 정리합니다 |

| 결과 | 할 일 |
| --- | --- |
| 하위 PRD에 미해결 질문이 남아 있음 | [PRD 서술 규칙의 예외 처리](../_shared/prd/writing.md#예외-처리) 적용 |
| 하위 PRD가 여전히 모호함 | 그 문서를 새 상위로 삼아 1번부터 다시 시작할 수 있음을 안내합니다 |
| 모두 통과함 | 확정 후 아래 기준으로 다음 스킬 안내 |

**[PRD 확정 후 안내](../_shared/architecture.md#prd-확정-후-안내)에 따라 다음 스킬을 안내합니다.**

## 경계

- 여러 계획이 따를 구조·패턴·계약을 정하는 일은 `/create-architecture`입니다.
- PRD를 처음 쓰는 일은 이 스킬이 아니라 `/create-prd`입니다.
- 요구사항의 구현 방식을 정하는 일은 `/create-plan`입니다.
- 확정되지 않은 PRD는 나누지 않습니다.
- 분해는 이미 확정된 요구사항을 나누고 구체화하는 작업입니다. 상위 요구사항의 범위 밖으로 나가는 새 요구사항은 발굴하지 않습니다.
- 하위 PRD를 다시 하나로 합치는 역방향 병합은 다루지 않습니다.
- 계층을 얼마나 깊게 나눌지는 사용자가 판단합니다. 스킬이 스스로 반복하지 않습니다.
- 요구사항이 하나뿐이거나 이미 충분히 구체적이면 분해하지 않고 그 사실을 알립니다.
