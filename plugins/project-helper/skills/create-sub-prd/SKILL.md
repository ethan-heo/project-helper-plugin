# create-sub-prd

## 역할과 목적

`create-sub-prd`는 확정된 PRD 한 편을 요구사항 묶음 단위로 나누어 하위 PRD 여러 편으로 옮기고, 그 과정에서 담당 요구사항을 질의응답으로 구체화한다. 원래 PRD는 목차 역할로 정리한다. 요구사항을 새로 발굴하지 않으며, 구현 방식도 다루지 않는다. 사용자는 묶음 단위와 구체화의 결정권자이고, AI는 후보 제안·질문·문서 생성·연결 기록을 맡는다.

## 실행 원칙

**확정된 상위 PRD만 나누고, 모든 요구사항을 빠짐없이 한 곳에 배정하며, 나누는 자리에서 함께 구체화한다.**

사용자가 이 스킬을 명시하면 뒤따르는 답변은 기본적으로 분해의 입력으로 해석한다. 질문이 스킬의 개념이나 사용법만 묻는 설명 요청이면 분해를 진행하지 않고 일반 답변을 제공한다. 분해 입력으로 이어진 실행 맥락은 분해가 끝나거나 사용자가 다른 스킬 또는 일반 질문을 명시할 때까지 유지한다.

하위 PRD는 상위와 같은 여덟 절 양식으로 쓴다. 하위 문서라는 이유로 서술을 성기게 남기지 않으며, 어느 계층을 읽어도 구체성의 수준이 같아야 한다.

분해는 반복할 수 있다. 하위 PRD가 여전히 모호하면 그 문서를 새 상위로 삼아 같은 절차를 다시 시작한다.

## 참조 문서 규칙

이 문서가 `create-sub-prd`의 실행 지시사항을 정하는 기준 문서다. 작업을 시작할 때 이 문서를 먼저 읽고, 아래 표의 절차에 진입할 때 지정된 참조 문서만 읽는다.

| 문서 유형 | 역할 | 적용 범위 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 분기 | `create-sub-prd` 전체 |
| `../_shared/docs-root.md` | 문서 루트 판정 규칙 | 대상 선정 |
| `references/grouping.md` | 묶음 후보 생성과 배정 규칙 | 묶음 확정 |
| `references/hierarchy.md` | 계층 경로와 ID 승계, 상위 표기 | 하위 생성과 상위 정리 |
| `references/detailing.md` | 절의 승계와 질의 구분, 요구사항을 좁히는 질문 | 하위 생성 |
| `../_shared/prd/prd-template.md` | PRD 문서 양식 | 하위 문서를 만들 때 |
| `../_shared/prd/writing.md` | 간결성 서술 규칙과 점검 목록 | 절을 쓸 때와 확정 직전 |
| `../_shared/writing-style.md` | 산출물의 문체와 표기 | 절을 쓸 때 |
| `../_shared/prd/validate-prd.sh` | 문서 한 편의 필수 절과 항목 형식 검증 | 하위 문서마다 |
| `scripts/validate-sub-prd.sh` | 배정과 계층의 검증 | 확정 직전 |

참조 문서는 본문에 없는 실행 범위를 추가하지 않는다.

## 분해 절차

### 1. 대상을 정한다

**사용자가 지정한 PRD를 우선하고, 지정이 없으면 후보를 제시해 고르게 한다.**

| 상황 | 할 일 |
| --- | --- |
| 사용자가 파일을 지정했다 | 그 문서를 대상으로 삼는다 |
| 지정이 없다 | [`docs-root.md`](../_shared/docs-root.md)로 문서 루트를 판정하고 `<루트>/prds/`의 PRD를 목록으로 제시한다 |
| 후보가 없다 | 분해할 PRD가 없음을 알리고 `/create-prd`를 안내한 뒤 종료한다 |

### 2. 확정 여부를 확인한다

**상위 PRD가 확정 상태일 때만 분해한다.**

| 확인 대상 | 통과 조건 |
| --- | --- |
| 미해결 질문 | `미해결 질문` 절에 남은 항목이 없다 |
| 필수 절 | 여덟 절이 모두 있고 `../_shared/prd/validate-prd.sh`를 통과한다 |
| 요구사항 표 | 모든 항목이 ID와 필수·선택 구분, 충족 판정을 가진다 |

하나라도 통과하지 못하면 분해하지 않고 `/create-prd`로 상위 PRD를 먼저 확정하도록 안내한다.

### 3. 묶음을 확정한다

**[`grouping.md`](references/grouping.md)를 읽고 묶음 후보를 제안한 뒤, 사용자가 고른 묶음을 배정으로 삼는다.**

후보는 `사용자와 사용 상황` 절의 행마다 관련 요구사항을 모아 만든다. 묶음마다 어떤 요구사항 ID가 들어가는지 함께 보여준다.

| 상황 | 할 일 |
| --- | --- |
| 사용자가 묶음을 직접 지정한다 | 후보에 맞추지 않고 그 지정을 배정으로 삼는다 |
| 어느 묶음에도 들어가지 않은 요구사항이 있다 | 배정을 확정하지 않고 남은 ID를 제시해 배정받는다 |
| 같은 요구사항이 두 묶음에 들어갔다 | 어느 하나를 고르게 하고, 나눠야 할 요구사항이면 5번의 상위 수정 절차로 넘긴다 |

### 4. 하위 PRD를 만든다

**[`hierarchy.md`](references/hierarchy.md)의 경로와 ID 규칙에 따라 묶음마다 문서 한 편을 만들고, [`detailing.md`](references/detailing.md)의 질문으로 담당 요구사항을 구체화한다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 상위 문서를 자기 이름의 디렉터리 안 `README.md`로 옮기고, 그 옆에 `../_shared/prd/prd-template.md`를 복사해 하위 PRD를 만든다 |
| 2 | `마지막 갱신` 아래에 상위 문서 경로와 담당 요구사항 ID를 한 줄로 적는다 |
| 3 | 상위에서 확정된 절을 승계한다. 어느 절을 승계하고 어느 절을 새로 묻는지는 `detailing.md`가 정한다 |
| 4 | 담당 요구사항을 질의응답으로 여러 항목으로 가르고, 각 항목에 관찰 가능한 충족 판정을 붙인다 |
| 5 | 요구사항 ID는 상위 ID를 이어받아 매긴다 |
| 6 | 절을 쓸 때 [`writing.md`](../_shared/prd/writing.md)의 서술 규칙과 [`writing-style.md`](../_shared/writing-style.md)의 문체·표기 규칙을 적용하고, `detailing.md`의 구체화 판정을 대조한다 |

나누기만 하고 구체화하지 않으면 상위의 모호한 서술이 그대로 옮겨 간다. 상위 요구사항의 문장을 옮겨 적은 항목은 남기지 않는다.

확정하지 못한 내용은 추측으로 메우지 않고 그 문서의 `미해결 질문` 절에 남긴다.

### 5. 상위 PRD를 정리한다

**상위 요구사항 표에 `하위 PRD` 열을 더해 각 행을 담당 문서로 연결한다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | 요구사항 표에 `하위 PRD` 열을 추가하고 각 행에 담당 문서 링크를 넣는다 |
| 2 | 분해 도중 상위 요구사항의 문구를 고쳐야 했다면 사용자에게 확인받고 수정한다 |
| 3 | 상위 문서가 옮겨졌으므로 문서 안의 상대 경로 참조와, 한 계층 위에서 이 문서를 가리키는 링크를 고친다 |
| 4 | `마지막 갱신`을 오늘 날짜로 맞춘다 |

상위 PRD의 요구사항 서술은 지우지 않는다. 상위만 읽어도 전체 범위가 보여야 한다.

### 6. 검증하고 넘긴다

**형식과 배정을 모두 검사한 뒤에만 분해를 마친다.**

| 순서 | 할 일 |
| --- | --- |
| 1 | `scripts/validate-sub-prd.sh <상위 PRD>`로 배정과 계층, 하위 문서의 형식을 검사한다 |
| 2 | `writing.md`의 확정 전 점검 목록을 하위 문서마다 대조한다 |
| 3 | 불통과 항목이 있으면 해당 자리를 사용자와 다시 정리한다 |

| 결과 | 할 일 |
| --- | --- |
| 하위 PRD에 미해결 질문이 남아 있다 | 그 문서를 확정하지 않는다. 사용자가 초안 상태로 마무리하기를 요청하면 초안임을 문서에 표시한다 |
| 하위 PRD가 여전히 모호하다 | 그 문서를 새 상위로 삼아 1번부터 다시 시작할 수 있음을 안내한다 |
| 모두 통과한다 | 분해를 마치고, 구현 계획이 필요하면 `/create-plan`으로 이어갈 수 있음을 안내한다 |

## 경계

- PRD를 처음 쓰는 일은 이 스킬이 아니라 `/create-prd`이다.
- 요구사항의 구현 방식을 정하는 일은 `/create-plan`이다.
- 확정되지 않은 PRD는 나누지 않는다.
- 분해는 이미 확정된 요구사항을 나누고 구체화하는 작업이다. 상위 요구사항의 범위 밖으로 나가는 새 요구사항은 발굴하지 않는다.
- 하위 PRD를 다시 하나로 합치는 역방향 병합은 다루지 않는다.
- 계층을 얼마나 깊게 나눌지는 사용자가 판단한다. 스킬이 스스로 반복하지 않는다.
- 요구사항이 하나뿐이거나 이미 충분히 구체적이면 분해하지 않고 그 사실을 알린다.
