# 요구사항 구체화

## 목적

하위 PRD를 쓰면서 담당 요구사항을 더 좁은 항목으로 갈라, 상위의 모호한 서술이 그대로 옮겨 가지 않게 한다.

## 핵심 지시

상위에서 확정된 절은 승계하고, 담당 범위에서 새로 정해야 하는 절만 질의응답으로 채운다.

## 절의 승계와 질의 구분

| 절 | 처리 |
| --- | --- |
| 한 줄 요약 | 새로 쓴다. 담당 요구사항이 누구의 무엇을 해결하는지 한 문장으로 쓴다 |
| 배경과 문제 | 상위에서 승계하고, 담당 범위로 좁힌 문제를 한 줄 더한다 |
| 목적과 목표 | 담당 요구사항의 충족 판정을 근거로 새로 묻는다 |
| 사용자와 사용 상황 | 묶음의 근거가 된 행만 승계한다 |
| 요구사항 | 질의응답으로 상위 요구사항을 여러 항목으로 쪼개고 각각 충족 판정을 붙인다 |
| 범위 밖 | 상위의 제외 항목을 물려받고, 이 계층에서 더 제외할 것을 묻는다 |
| 제약과 전제 | 상위에서 그대로 승계한다 |
| 미해결 질문 | 새로 묻는다 |

승계한 절은 상위의 문장을 그대로 옮긴다. 요약해 줄이지 않는다. 계층 사이의 상세도를 맞추기 위해서다.

## 요구사항을 좁히는 질문

| 순서 | 질문 | 넘어갈 조건 |
| --- | --- | --- |
| 1 | 이 요구사항이 성립하려면 무엇이 각각 가능해야 합니까 | 담당 요구사항이 둘 이상의 항목으로 갈렸다 |
| 2 | 각 항목은 무엇을 보면 충족된 줄 압니까 | 모든 항목에 관찰 가능한 충족 판정이 붙었다 |
| 3 | 그중 없으면 성립하지 않는 것은 무엇입니까 | 모든 항목이 필수와 선택 중 하나로 갈렸다 |
| 4 | 이 범위에서 하지 않기로 할 것이 있습니까 | 제외 항목마다 이유가 함께 나왔다 |

열린 질문을 먼저 던진다. 답변만으로 항목을 가르기 어려우면 선택지 두셋과 각 선택이 만드는 차이를 제시한다. 선택지가 둘에서 셋이면 `1.`, `2.`, `3.` 형식으로 번호를 붙인다.

## 구체화 판정

아래를 모두 만족해야 그 하위 PRD의 요구사항 절을 확정한다.

| 점검 항목 | 통과 기준 |
| --- | --- |
| 서술 이전 | 상위 요구사항의 문장을 그대로 옮겨 적은 항목이 없다 |
| 판정 가능성 | 모든 항목에 관찰 가능한 충족 판정이 붙어 있다 |
| 구분 | 모든 항목이 필수와 선택 중 하나로 표시되어 있다 |
| 범위 | 상위 요구사항이 정한 범위 밖의 항목이 없다 |
| ID | 항목의 ID가 상위 ID를 이어받아 매겨져 있다 |

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 상위 요구사항이 더 갈라지지 않는다 | 항목을 억지로 늘리지 않고 충족 판정만 구체화한 뒤 그 사실을 알린다 |
| 승계할 절의 내용이 담당 범위와 맞지 않는다 | 승계하지 않고 그 절만 새로 묻는다 |
| 답변이 구현 방식으로 흐른다 | PRD의 범위가 아님을 알리고 목적과 요구사항으로 되돌린다 |
| 사용자가 구체화를 건너뛰자고 요청한다 | 절을 비우지 않고 미확정 내용을 `미해결 질문`으로 옮긴 뒤 진행한다 |

## 근거·예시

나누기만 하고 구체화하지 않으면 모호함이 문서 수만 늘린 채 그대로 남는다. 예를 들어 "묶음 후보를 제안하고 사용자가 고른 묶음을 분할 단위로 삼는다"라는 상위 요구사항은, 하위에서 "후보를 무엇에서 만드는가", "후보마다 무엇을 보여주는가", "선택을 어떻게 확정으로 기록하는가" 세 항목으로 갈리고 각각 충족 판정을 갖는다.
