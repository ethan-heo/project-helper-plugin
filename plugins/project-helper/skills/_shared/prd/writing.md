# PRD 서술 규칙

## 목적

읽는 사람이 한 번 읽고 이해할 수 있는 PRD를 만듭니다.

## 핵심 지시

**한 절은 한 가지만 말하고, 판정할 수 없는 표현을 남기지 않습니다.**

## 서술 규칙

문체와 표기, 서술 단위의 길이, 어휘, 용어를 푸는 방식은 [`writing-style.md`](../writing-style.md)를 따릅니다. 아래는 PRD에만 해당하는 규칙입니다.

- 한 문장에는 하나의 주장만 담습니다. 접속으로 이어 붙인 문장은 나눕니다.
- 판정 기준은 관찰 가능한 것으로 씁니다. "빠르다", "편리하다"처럼 사람마다 다르게 읽히는 표현은 수치나 관찰 가능한 상태로 바꿉니다.
- 목표 이름은 이루려는 상태를 그대로 적습니다. 판정 기준을 읽기 전에도 무엇을 이루려는지 알 수 있어야 합니다.
- 범위 밖의 이유에는 그 항목을 빼도 되는 근거를 적습니다. 다른 요구사항이 대신하면 그 ID와 대신하는 방법을 적습니다.
- 항목이 셋 이상이면 표로 정리합니다. 산문으로 나열하지 않습니다.
- 해법과 구현 방식은 쓰지 않습니다. 무엇을 왜 만드는지만 다룹니다.
- 같은 내용을 두 절에 반복해 적지 않습니다. 한 절에만 두고 나머지는 참조합니다.
- 확정하지 못한 내용은 추측으로 메우지 않고 `미해결 질문`으로 옮깁니다.

## 확정 전 점검 목록

각 항목의 판정 기준을 그대로 적용합니다. 하나라도 불통과이면 확정하지 않습니다.

| 점검 항목 | 통과 기준 |
| --- | --- |
| 한 줄 요약 | 이 문장만 읽고 제품이 무엇인지 말할 수 있습니다 |
| 문제의 구체성 | 문제 서술에 현재 사람들이 겪는 상황이 하나 이상 적혀 있습니다 |
| 목표의 판정 가능성 | 모든 목표에 관찰 가능한 성공 판정 기준이 적혀 있습니다 |
| 목표 이름 | 목표 이름만 읽고 무엇을 이루려는지 말할 수 있습니다 |
| 사용자 특정 | 사용자 항목이 직군이나 상황으로 좁혀져 있고 "모든 사용자"가 아닙니다 |
| 요구사항 구분 | 모든 요구사항이 필수와 선택 중 하나로 표시되어 있습니다 |
| 요구사항의 판정 가능성 | 모든 요구사항에 충족 판정 기준이 적혀 있습니다 |
| 범위 밖의 이유 | 이유만 읽고 그 항목을 빼도 되는 근거를 말할 수 있습니다 |
| 해법 혼입 | 구현 방식이나 기술 선택을 지시하는 문장이 없습니다 |
| 중복 | 같은 내용이 두 절 이상에 반복되지 않습니다 |
| 어휘 | `writing-style.md`의 어휘 절에 어긋나는 말이 없습니다 |
| 용어 일관성 | 같은 대상을 가리키는 용어가 문서 묶음 전체에서 하나입니다 |
| 미해결 잔존 | 미해결 질문 절에 남은 항목이 없습니다 |
| 분량 | 절마다 표 하나 또는 문단 셋 이내입니다 |

## 예외 처리

사용자가 미해결 항목을 남긴 채 마무리하기를 요청하면, 확정 대신 초안 상태임을 문서에 표시하고 남은 항목을 그대로 둡니다.

## 근거·예시

판정 기준이 없는 목표는 나중에 달성 여부를 두고 다시 논쟁이 열립니다. "응답이 빠르다"는 "첫 화면이 2초 안에 표시된다"로 바꿉니다.
