# 산출물 표기 기준

## 목적

스킬이 만드는 문서의 문체와 표기를 한 문서에서 정합니다. 계획서, PRD, 학습 문서가 모두 같은 규칙을 씁니다.

## 핵심 지시

**저장소에 표기 기준 문서가 있으면 그것을 먼저 따르고, 없거나 다루지 않는 항목만 아래 규칙으로 채웁니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| 프로젝트 지시사항이 표기 기준 문서를 지정함 | 그 문서를 읽고 우선 적용합니다 |
| 지정된 문서가 어떤 항목을 다루지 않는다 | 그 항목만 아래 규칙으로 채웁니다 |
| 지정된 문서가 없음 | 아래 규칙만 적용합니다 |

저장소 문서를 우선하는 이유는, 산출물이 그 저장소의 기존 문서 옆에 놓이기 때문입니다.

## 문장

**읽는 사람이 한 번에 이해하는 문장을 씁니다. 문법적 정확성은 그다음입니다.**

문법에 맞아도 두 번 읽어야 뜻이 잡히는 문장은 고칩니다. 번역문이 아니라 한국어로 직접 쓴 실무 보고서의 문체를 씁니다.

| 규칙 | 판정 |
| --- | --- |
| 한 문장 한 정보 | 한 문장이 핵심 정보 하나만 담습니다 |
| 구체적인 동사 | 추상적인 명사로 뭉뚱그린 서술이 없습니다 |
| 완곡 표현 | 판단을 흐리는 서술이 없습니다 |
| 번역투 | 긴 수식과 불필요한 수동 표현이 없습니다 |

| 쓰지 않는 표현 | 쓰는 표현 |
| --- | --- |
| 검토를 진행합니다 | 검토합니다 |
| 적용이 이루어집니다 | 적용합니다 |
| 중요하다고 할 수 있습니다 | 중요합니다 |
| 필요성이 제기됩니다 | 필요합니다 |

## 문단

**첫 문장에 핵심을 적고 근거와 설명을 뒤에 둡니다.** 문맥상 다른 순서가 자연스러우면 그 순서를 따릅니다.

| 규칙 | 판정 |
| --- | --- |
| 핵심 우선 | 첫 문장만 읽어도 문단의 결론을 알 수 있습니다 |
| 한 문단 한 생각 | 한 문단이 두 주제를 다루지 않습니다 |
| 인과 표시 | 두 문장의 관계를 읽는 사람이 짐작하지 않아도 됩니다 |
| 연결어 절제 | `이를 통해`, `나아가`, `이러한 맥락에서`, `또한`, `따라서`, `특히`, `기반으로`, `효과적으로`가 논리상 필요한 문장에만 있습니다 |

인과관계는 접속어를 덧붙이기보다 정보 순서와 문장 구조로 드러냅니다. 같은 연결어를 연달아 반복하지 않습니다.

## 문체

| 규칙 | 판정 |
| --- | --- |
| 종결 어미 | 서술 문장이 `~합니다`체로 끝납니다 |
| 주어 생략 | 앞 문장에서 드러난 주어를 되풀이하지 않습니다 |
| 어미 일관성 | 한 문단 안에서 종결 어미가 섞이지 않습니다 |

명령을 지시하는 문장은 문체 규칙의 적용 대상이 아닙니다. 명령은 굵게 쓴 한 문장입니다. 표의 셀 값은 아래 표 셀 값 절이 따로 정합니다.

## 서술 단위의 길이

**표 셀과 목록 항목은 한 문장으로 적고, 마흔 자를 넘기지 않습니다.** 형태를 표나 목록으로 바꿔도 길이 제한이 없으면 셀 안에서 다시 줄글이 됩니다.

| 규칙 | 판정 |
| --- | --- |
| 한 문장 | 셀과 항목에 문장이 둘 이상 들어 있지 않습니다 |
| 길이 | 셀과 항목이 마흔 자를 넘지 않습니다 |
| 뜻 보존 | 셀만 읽고 무엇이 무엇을 하는지 말할 수 있습니다 |

| 줄이기 전 | 줄인 뒤 |
| --- | --- |
| 루틴 안에서 순서대로 수행하는 업무 하나의 표현 | 루틴을 이루는 업무 하나 |
| 사용자가 직접 결정해야 하는 항목들을 모아 둔 목록 | 사용자 결정 항목의 목록 |
| 진입 모듈이 내보내는 이름과 그 타입의 모양을 알아야 하는 관계 | 재수출된 이름과 타입의 모양 |

한 문장에 담기지 않으면 담을 내용을 줄입니다. 문장을 둘로 나누어 한 셀에 넣지 않습니다.

줄일 때는 수식어와 평가어를 먼저 뺍니다. 동작과 그 대상은 남깁니다. `R8의 응답 화면만으로 충분한 확인`처럼 동작이 빠지고 평가만 남은 셀을 만나면 읽는 사람이 뜻을 짐작해야 합니다. `권한 부족은 R8의 거절 응답으로 대신 확인`처럼 무엇을 무엇으로 하는지 적습니다.

같은 내용이 두 절에 걸치면 뒤에 나오는 절에서 줄입니다. 앞 절이 이미 밝힌 것을 되풀이하지 않습니다.

## 표 셀 값

**모든 표의 셀 값은 명사절로 적습니다.** 표를 세로로 훑기 때문입니다. 행마다 형태가 달라지면 값을 비교하기 전에 문장을 읽어야 합니다.

| 쓰지 않는 형태 | 쓰는 형태 |
| --- | --- |
| 달라짐 | 동작 변경 |
| 새로 생김 | 신규 추가 |
| 그대로 | 변경 없음 |
| 타입이 해결된다 | 타입 해결 |

조건을 담는 열은 예외입니다. 판정 기준을 서술해야 하므로 문장으로 적습니다.

## 어휘

**문자 그대로 읽어도 뜻이 통하는 말을 씁니다.** 비유나 뜻이 넓은 명사를 쓰면 읽는 사람이 그 말의 대상을 짐작해야 하고, 짐작은 사람마다 갈립니다.

| 규칙 | 판정 |
| --- | --- |
| 비유 어휘 | 일반 명사와 동사를 비유어로 바꿔 쓴 곳이 없습니다 |
| 넓은 명사 | `자리`, `흐름`, `성격` 대신 가리키는 대상을 씁니다 |
| 이름 | 목표와 묶음의 이름이 표어가 아니라 내용을 그대로 적은 말입니다 |
| 옮겨 온 말 | 답변이나 상위 문서의 비유를 뜻을 확인한 뒤 풀어 씁니다 |

| 쓰지 않는 말 | 쓰는 말 |
| --- | --- |
| 판단할 자리, 취소 자리 | 판단 단계, 취소 버튼 |
| 화면 조각을 쌓는다 | 컴포넌트를 배치한다 |
| 요청의 성격 | 요청 유형 |
| 막다른 곳이 없는 거절 | 대안을 함께 제시하는 거절 |
| 비용이 붙습니다 | 비용이 늘어납니다 |

판정이 어려우면 그 낱말을 빼고 가리키는 대상을 직접 적어 봅니다. 대상을 적을 수 있으면 대상을 씁니다. `실행 흐름`, `번호를 붙인다`처럼 분야의 관용으로 정착해 일반어로 바꾸면 오히려 어색한 표현은 그대로 씁니다.

사용자가 답변에 쓴 비유도 그대로 옮기지 않습니다. 사용자는 대화의 맥락 안에서 말했지만, 문서를 읽는 사람에게는 그 맥락이 없습니다.

## 용어

**설명 없이 전문 용어를 쓰지 않습니다.** 읽는 사람이 뜻을 모르면 읽기를 멈추고 문서 밖에서 찾아야 합니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 산출물에 용어를 모으는 절이 있음 | 그 절의 표에 뜻을 적습니다 |
| 그런 절이 없음 | 처음 쓰는 문장에서 한 번 풀어 씁니다 |
| 읽는 사람이 이미 아는 용어다 | 그대로 씁니다 |

보충 설명을 본문 여기저기에 흩지 않습니다. 본문을 읽는 흐름이 끊기기 때문입니다.

**같은 대상에는 함께 읽히는 문서 전체에서 하나의 용어를 씁니다.** 상위·하위 PRD나 계획서의 세 층처럼 서로 링크된 문서는 한 묶음으로 봅니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 묶음 안에 이미 쓰인 용어가 있음 | 그 용어를 씁니다 |
| 다른 용어로 바꿔야 함 | 묶음 안에서 쓰인 곳을 모두 함께 바꿉니다 |
| 처음 쓰는 대상임 | 사용자가 쓴 말을 우선하고, 비유어면 풀어 씁니다 |

문서마다 용어가 다르면 읽는 사람은 두 말이 같은 대상인지부터 확인해야 합니다.

## 사실 보존

**사용자가 말한 사실관계와 조건을 그대로 옮기고, 근거 없는 내용을 더하지 않습니다.** 산출물을 읽는 사람은 대화를 보지 못하므로 문서에 적힌 내용만으로 판단합니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 답변에 조건이나 예외가 붙어 있음 | 조건과 예외를 함께 적습니다 |
| 분량을 줄여야 함 | 수식어를 빼고 조건과 예외는 남깁니다 |
| 사용자가 말하지 않은 내용이 필요하다 | 지어내지 않고 사용자에게 묻습니다 |

## 표기

| 대상 | 표기 |
| --- | --- |
| 날짜 | `YYYY-MM-DD` |
| 파일 경로·명령·코드 식별자 | 인라인 코드 |

## 서식 선택

| 담을 내용 | 서식 |
| --- | --- |
| 순서가 없는 짧은 항목 | `-` 목록 |
| 순서가 있는 절차 | 번호 목록 |
| 비교·매핑·조건 분기 | 표 |
| 한두 문장으로 끝나는 설명 | 문단 |

## 번역어 판정

**정착된 번역어가 있으면 쓰고, 없으면 원어를 그대로 둡니다.** 억지로 옮긴 말은 뜻을 전하는 대신 읽는 사람이 원어를 되짚게 만듭니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 한국어 기술 문서에서 널리 쓰이는 번역어가 있음 | 그 번역어를 씁니다 |
| 번역어가 있으나 뜻이 좁거나 낯설다 | 원어를 그대로 쓰고 용어 표에서 뜻을 밝힙니다 |
| 번역어가 없음 | 원어를 그대로 씁니다 |
| 원어도 낯설다 | 하는 일을 풀어 쓰고 괄호에 원어를 답니다 |

| 억지 번역 | 쓰는 말 |
| --- | --- |
| 재수출 | re-export |
| 부수 효과 | 사이드 이펙트 |
| 갈래 나누기 | 분기 |
| 통과 여부 | 검사 결과 |

판정이 갈리면 원어 쪽을 고릅니다. 원어는 검색이 되지만, 한 번만 쓰인 번역어는 찾을 수 없습니다.

## 파일 이름

파일 이름은 영문 kebab-case를 기본으로 합니다. 다만 이름이 커밋 제목이나 사용자가 정한 주제에서 그대로 오는 산출물은 한국어를 그대로 둡니다. 이름이 원본과 어긋나면 읽는 사람이 대상을 다시 찾아야 하기 때문입니다.

| 산출물 | 이름 |
| --- | --- |
| 참조 문서, 스크립트 | 영문 kebab-case |
| 계획서 디렉터리 | 날짜와 주제 |
| 학습 문서 | 날짜와 짧은 해시와 커밋 제목 |

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 저장소 문서와 이 문서의 규칙이 충돌함 | 저장소 문서를 따르고 그 사실을 사용자에게 알립니다 |
| 저장소 문서가 가리키는 경로에 파일이 없음 | 이 문서의 규칙으로 진행하고 경로가 어긋난 사실을 알립니다 |
| 산출물이 놓일 디렉터리의 기존 문서가 다른 문체를 씀 | 기존 문체를 따르고 사용자에게 확인받습니다 |

## 근거·예시

문체가 산출물마다 흔들리면 같은 스킬이 만든 문서인지 알아보기 어렵습니다. 규칙을 스킬마다 따로 적으면 한 곳을 고칠 때 나머지가 남습니다. 그래서 이 문서 하나를 기준으로 두고 각 스킬이 참조합니다.
