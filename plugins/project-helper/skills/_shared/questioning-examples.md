# 질문 예시

## 목적

질의응답으로 문서를 채우는 스킬이 질문과 선택지에 예시를 붙이는 기준을 정합니다. 예시가 있으면 사용자는 질문의 뜻과 답해야 할 내용을 한 번 읽고 파악할 수 있습니다. 이 문서를 참조하는 스킬에만 적용합니다.

## 핵심 지시

**사용자에게 정의나 판단을 요청하는 질문에는 예시를 함께 제시합니다.**

| 질문 유형 | 붙일 예시 |
| --- | --- |
| 열린 질문 | 필요한 구체성을 보여 주는 답변 한두 개 |
| 선택지를 제시하는 질문 | 선택지마다 달라지는 코드·문서·동작 |
| 추상적인 용어가 들어간 질문 | 그 용어가 현재 작업에서 가리키는 대상 |
| 부족한 답변을 다시 묻는 질문 | 받은 답변과 충분한 답변의 비교 |

## 예시 작성 규칙

**예시는 사용자의 프로젝트에서 가져와 짧게 쓰고, 사용자의 결정을 대신하지 않게 합니다.**

| 규칙 | 판정 |
| --- | --- |
| 출처 | 조사한 파일이나 기존 문서, 앞선 답변에서 가져옵니다 |
| 분량 | 예시 하나가 세 줄을 넘지 않습니다 |
| 표시 | 예시가 `예:`나 `예시 답변:`으로 시작합니다 |
| 중립 | 해법을 묻는 질문에 방향이 다른 예시를 둘 이상 보입니다 |
| 위치 | 예시가 선택지 설명이 아닌 메시지 본문에 있습니다 |

프로젝트에서 가져올 내용이 없을 때만 일반 사례를 쓰고, 일반 사례라는 사실을 밝힙니다.

예시를 하나만 보이면 사용자는 그 예시를 권장안으로 받아들이기 쉽습니다. 방향이 다른 예시를 둘 이상 만들기 어려우면 답의 내용 대신 형식만 보입니다.

`AskUserQuestion`의 선택지 설명에 예시를 넣으면 설명이 길어져 답변 영역이 가려집니다. 질문과 예시는 본문에 먼저 쓰고, 선택지 설명에는 선택한 결과만 짧게 적습니다.

## 예외 처리

| 선행 상태 | 할 일 |
| --- | --- |
| 예·아니요로 확인하는 질문 | 예시를 생략합니다 |
| 같은 유형의 질문에 이미 구체적으로 답함 | 예시를 생략합니다 |
| 사용자가 예시를 원하지 않는다고 말함 | 그 대화가 끝날 때까지 예시를 생략합니다 |
| 사용자가 예시를 그대로 답으로 고름 | 기록하기 전에 현재 작업에 맞는지 확인합니다 |

## 근거·예시

예시가 없으면 사용자는 무엇을 얼마나 자세히 답해야 할지 짐작해서 답합니다. 짐작으로 한 답은 필요한 수준에 미치지 못할 때가 많고, 그러면 같은 내용을 다시 물어야 합니다.

열린 질문에는 다음처럼 예시를 붙입니다.

```text
이 제품이 성공했다고 판단할 근거는 무엇입니까?

예시 답변: "새로 쓴 계획서의 80% 이상이 추가 질문 없이 impl-plan으로 구현된다"
예시 답변: "PRD를 쓰는 시간이 반나절에서 한 시간 이내로 줄어든다"
```

선택지를 제시할 때는 다음처럼 붙입니다.

```text
검증 스크립트가 실패했을 때의 처리는 어디에서 맡을까요?

1. 스크립트가 직접 종료 — 예: validate-plan.sh가 exit 1로 끝나고, SKILL.md는 종료 코드만 확인합니다
2. SKILL.md가 분기 — 예: 스크립트는 검사 결과만 출력하고, 실패했을 때 할 일은 SKILL.md의 표가 정합니다
```
