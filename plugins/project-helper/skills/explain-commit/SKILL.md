# explain-commit

## 역할과 목적

`explain-commit`은 사용자가 지정한 커밋을 읽어, 그 변경을 이해할 수 있는 학습 문서로 남긴다. 커밋 하나가 문서 한 편이다. 코드를 고치지 않으며, 잘못을 지적하지도 않는다. AI는 조사와 서술을 맡고, 무엇을 배울지 고르는 일은 사용자가 한다.

## 실행 원칙

**커밋에서 확인한 사실만 쓰고, 확인되지 않은 자리는 추측으로 메우지 않는다.**

사용자가 이 스킬을 명시하면 뒤따르는 답변은 기본적으로 대상 지정의 입력으로 해석한다. 질문이 스킬의 개념이나 사용법만 묻는 설명 요청이면 문서를 만들지 않고 일반 답변을 제공한다. 실행 맥락은 문서 생성이 끝나거나 사용자가 다른 스킬 또는 일반 질문을 명시할 때까지 유지한다.

산출물은 대상 커밋마다 문서 한 편이다. 한 문서가 두 커밋을 담지 않고, 한 커밋이 두 문서로 갈리지도 않는다.

이 스킬은 최신 코드의 구조를 설명하지 않는다. 문서는 그 커밋 시점의 기록이며, 나중에 코드가 바뀌어도 따라가지 않는다.

## 참조 문서 규칙

이 문서가 `explain-commit`의 실행 지시사항을 정하는 기준 문서다. 작업을 시작할 때 이 문서를 먼저 읽고, 아래 표의 절차에 진입할 때 지정된 참조 문서만 읽는다.

| 문서 유형 | 역할 | 적용 범위 |
| --- | --- | --- |
| `SKILL.md` | 실행 절차와 분기 | `explain-commit` 전체 |
| `references/collecting.md` | 커밋 지정 형식과 중복·오류 판정 | 대상 수집과 목록 확인 |
| `references/document.md` | 문서의 절 구성과 설명 깊이 | 문서 생성 |
| `references/writing.md` | 서술 근거와 보관 경로·파일명 | 문서 생성 |
| `../_shared/docs-root.md` | 문서 루트 판정 규칙 | 보관 경로 결정 |
| `assets/commit-doc-template.md` | 학습 문서 양식 | 문서를 만들 때 |
| `scripts/validate-commit-doc.sh` | 필수 절과 파일명 검증 | 결과 보고 직전 |

참조 문서는 본문에 없는 실행 범위를 추가하지 않는다.

## 실행 절차

### 1. 대상을 수집한다

**[`collecting.md`](references/collecting.md)를 읽고, 인자로 받은 커밋 지정을 커밋 목록으로 펼친다.**

| 입력 형태 | 처리 |
| --- | --- |
| 커밋 해시 하나 또는 여럿 | 나열된 순서가 아니라 저장소의 시간 순서로 정렬한다 |
| `A..B` 범위 표기 | 구간에 든 커밋을 모두 펼친다 |
| 지정 없음 | 최근 커밋 목록을 제시해 사용자가 고르게 한다 |

문서를 만들기 전에 모든 입력을 검사한다. 하나라도 저장소에 없으면 문서를 만들지 않고 멈춘다.

### 2. 목록을 확인받는다

**대상 커밋의 짧은 해시와 제목을 보여주고, 이미 문서가 있는 커밋은 건너뜀으로 표시한다.**

보관 경로는 [`docs-root.md`](../_shared/docs-root.md)로 판정한 문서 루트 아래 `commits/`다. 같은 커밋의 문서가 이미 있으면 만들지 않는다.

### 3. 커밋마다 조사한다

**커밋 하나를 처리할 때 diff와 커밋 메시지, 연결된 계획서를 읽어 근거를 모은다.**

이 셋이 서술의 근거이며, 그 밖의 자료를 근거로 삼지 않는다. 근거를 찾지 못한 자리는 확인 필요 표시로 남긴다.

### 4. 문서를 만든다

**[`document.md`](references/document.md)의 절 구성으로 쓰고, [`writing.md`](references/writing.md)의 서술 규칙과 파일명 규칙을 적용한다.**

`assets/commit-doc-template.md`를 복사해 여섯 절을 채운다. 문서를 만든 뒤 `scripts/validate-commit-doc.sh`로 형식을 검사한다.

### 5. 결과를 보고한다

**만든 문서, 건너뛴 커밋, 실패한 커밋을 나누어 알린다.**

| 구분 | 알릴 내용 |
| --- | --- |
| 만든 문서 | 커밋의 짧은 해시와 생성된 파일 경로 |
| 건너뛴 커밋 | 짧은 해시와 이미 있는 문서의 경로 |
| 실패한 커밋 | 짧은 해시와 어느 단계에서 멈췄는지 |

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 저장소에 없는 해시가 섞여 있다 | 문서를 만들기 전에 멈추고 어느 입력이 문제인지 알린다 |
| 범위 표기의 양 끝이 조상 관계가 아니다 | 펼치지 않고 사용자에게 범위를 확인받는다 |
| 대상 커밋의 문서가 이미 있다 | 만들지 않고 건너뛴 뒤 결과 보고에 포함한다 |
| 커밋 하나의 문서 생성이 실패한다 | 나머지 커밋을 계속 처리하고 실패한 커밋을 따로 보고한다 |
| 현재 디렉터리가 git 저장소가 아니다 | 절차를 시작하지 않고 그 사실을 알린다 |

## 경계

- 계획서대로 코드를 고치는 일은 `/impl-plan`이다.
- 이 스킬은 코드를 고치지 않는다.
- 코드의 품질을 평가하거나 개선을 제안하지 않는다. 설명만 한다.
- 커밋되지 않은 변경은 대상으로 삼지 않는다.
- 이미 만든 문서는 코드가 바뀌어도 갱신하지 않는다. 그 커밋 시점의 기록이기 때문이다.
- 사용자의 이해도를 묻거나 채점하지 않는다.
