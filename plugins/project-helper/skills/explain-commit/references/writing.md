# 서술과 보관

## 목적

학습 문서의 서술이 커밋의 사실에서만 나오게 하고, 문서를 나중에 다시 찾을 수 있는 자리에 둡니다.

## 핵심 지시

근거 셋으로 확인되는 것만 쓰고, 확인되지 않은 자리는 표시로 남깁니다.

문체와 표기는 [`writing-style.md`](../../_shared/writing-style.md)를 따릅니다. 이 문서는 그 위에 학습 문서에만 해당하는 규칙을 더합니다.

## 서술 근거

문서의 사실 서술은 아래 셋에서만 끌어옵니다.

| 근거 | 무엇을 얻는가 |
| --- | --- |
| 커밋 diff | 무엇이 어떻게 바뀌었는가 |
| 커밋 메시지 | 작성자가 밝힌 변경의 목적 |
| 연결된 계획서 | 그 변경이 어느 결정에서 나왔는가 |

세 근거 밖의 자료를 끌어오지 않습니다. 근거를 셋으로 못 박아야 추측이 사실처럼 섞이지 않습니다.

계획서는 커밋 메시지의 항목 ID로 찾습니다. ID가 없으면 계획서를 근거로 쓰지 않습니다.

## 확인 필요 표시

근거를 찾지 못한 자리는 추측으로 메우지 않고 아래 형식으로 남깁니다.

```
<!-- 확인 필요: 무엇을 확인해야 하는가 -->
```

표시가 남은 문서도 그대로 보관합니다. 사용자가 직접 메울 지점이기 때문입니다.

## 문장 규칙

| 규칙 | 판정 |
| --- | --- |
| 한 문장 한 주장 | 접속으로 두 주장을 이어 붙인 문장이 없다 |
| 코드 인용 | 인용마다 그것을 왜 보여주는지 설명이 붙어 있다 |
| 판정 가능성 | "개선되었다"처럼 사람마다 다르게 읽히는 서술 대신 무엇이 어떻게 달라졌는지 쓴다 |
| 계획서 참조 | 항목 ID가 계획서 파일을 가리키는 링크다 |
| 고정 값 열 | 종류 열과 출처 열의 값이 정해진 표기 중 하나이거나 비어 있다 |

## 표 셀 값과 서술 길이

셀 값의 문체와 서술 단위의 길이는 [`writing-style.md`](../../_shared/writing-style.md)가 정합니다. 학습 문서에서 특히 흐트러지는 자리만 아래에 적습니다.

| 자리 | 지킬 것 |
| --- | --- |
| 용어와 배경 표의 뜻 열 | "무엇인가"에 답하는 명사구 |
| 실행 흐름 표의 단계 열 | 구성 요소 표가 밝힌 역할의 생략 |

용어 표의 뜻 열이 서술형으로 흐르기 쉽습니다. 뜻을 문장으로 풀고 싶어지면 명사구로 끝맺습니다.

## 고정 값 열

구성 요소 표의 종류 열과 실행 흐름 표의 출처 열은 값이 닫혀 있습니다. 자유롭게 서술하지 않고 아래 표기 중 하나를 씁니다.

| 열 | 쓸 수 있는 값 |
| --- | --- |
| 구성 요소 표의 종류 | `<종류> · 공개`, `<종류> · 내부`, 공개 범위를 판정할 수 없으면 `<종류>`만 |
| 실행 흐름 표의 출처 | `필수적 복잡성`, `우발적 복잡성`, 근거가 없으면 빈 셀 |

`<종류>` 자리에는 타입, 인터페이스, 함수, 설정 파일처럼 그 요소가 무엇인지를 적습니다.

값이 몇 개로 닫혀 있어야 여러 문서를 나란히 놓고 훑을 때 비교됩니다. 출처 열을 근거 없이 채우면 스킬이 하지 않기로 한 품질 판단이 문서에 섞이므로, 빈 셀을 그대로 둡니다.

## 계획서 참조

변경 의도 절에서 계획서를 근거로 들 때는 항목 ID 자체를 링크로 만듭니다. 경로 문자열을 본문에 늘어놓지 않습니다.

```
[SETUP-WORKSPACE-003](../plans/2026-09-02-dev-environment/setup/workspace.md)은
저장소 인터페이스의 선언을 항목의 내용으로 정했습니다.
```

링크 경로는 학습 문서가 놓인 `commits/`를 기준으로 한 상대 경로입니다. 항목 ID를 찾지 못하면 링크를 만들지 않고, 계획서를 근거에서 뺍니다.

## 보관 경로

문서 루트는 [`docs-root.md`](../../_shared/docs-root.md)의 탐색 순서로 판정하고, 보관 경로는 `<루트>/commits/`로 삼습니다. 디렉터리가 없으면 만듭니다.

## 파일 이름

이름을 짓는 원칙은 [`writing-style.md`](../../_shared/writing-style.md)가 정합니다. 학습 문서의 형식은 아래와 같습니다.

```
YYYY-MM-DD-<짧은 해시>-<제목>.md
```

날짜는 커밋의 작성 날짜이고, 짧은 해시는 일곱 자리입니다. 제목은 커밋 제목에서 따오되 공백은 하이픈으로 바꿉니다.

예를 들어 2026년 9월 4일에 작성된 `936e70c` 커밋의 문서는 `2026-09-04-936e70c-validate-sub-prd-검사-개정.md`가 됩니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 문서 루트를 판정할 수 없다 | `docs/`를 쓰고 그 사실을 사용자에게 알립니다 |
| `commits/`가 없다 | 만들고 진행합니다 |
| 커밋 메시지에 항목 ID가 없다 | 링크를 만들지 않고 계획서를 근거에서 뺍니다 |
| 출처 열을 채울 근거가 없다 | 셀을 비워 둡니다. 둘 중 가까운 쪽으로 고르지 않습니다 |
| 요소의 공개 범위를 판정할 수 없다 | 종류만 적고 공개 범위 표기를 생략합니다 |
| 한 문장으로 줄이면 뜻이 달라진다 | 담을 내용을 줄이고, 빠진 것은 용어 표로 옮깁니다 |
| 계획서 파일이 저장소에 없다 | 항목 ID를 링크 없이 적고 확인 필요 표시를 남깁니다 |
| 커밋 제목에 파일명으로 쓸 수 없는 문자가 있다 | 그 문자를 빼고 짧은 해시로 구분을 유지합니다 |
| 커밋 제목이 너무 길다 | 앞에서부터 잘라 씁니다. 짧은 해시가 있으므로 구분은 유지됩니다 |
| 같은 이름의 파일이 이미 있다 | 덮어쓰지 않고 건너뜁니다 |

## 근거·예시

정확하지만 읽히지 않는 문서와, 읽히지만 사실과 다른 문서는 둘 다 학습에 쓸모가 없습니다. 근거를 셋으로 한정하는 규칙이 앞의 문제를, 문장 규칙이 뒤의 문제를 막습니다.

파일 이름에 짧은 해시를 넣는 이유는 같은 날 같은 제목의 커밋이 둘일 수 있기 때문입니다. 날짜와 제목만으로는 이름이 겹칩니다.
