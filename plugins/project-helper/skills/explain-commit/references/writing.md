# 서술과 보관

## 목적

학습 문서의 서술이 커밋의 사실에서만 나오게 하고, 문서를 나중에 다시 찾을 수 있는 자리에 둔다.

## 핵심 지시

근거 셋으로 확인되는 것만 쓰고, 확인되지 않은 자리는 표시로 남긴다.

## 서술 근거

문서의 사실 서술은 아래 셋에서만 끌어온다.

| 근거 | 무엇을 얻는가 |
| --- | --- |
| 커밋 diff | 무엇이 어떻게 바뀌었는가 |
| 커밋 메시지 | 작성자가 밝힌 변경의 목적 |
| 연결된 계획서 | 그 변경이 어느 결정에서 나왔는가 |

세 근거 밖의 자료를 끌어오지 않는다. 근거를 셋으로 못 박아야 추측이 사실처럼 섞이지 않는다.

계획서는 커밋 메시지의 항목 ID로 찾는다. ID가 없으면 계획서를 근거로 쓰지 않는다.

## 확인 필요 표시

근거를 찾지 못한 자리는 추측으로 메우지 않고 아래 형식으로 남긴다.

```
<!-- 확인 필요: 무엇을 확인해야 하는가 -->
```

표시가 남은 문서도 그대로 보관한다. 사용자가 직접 메울 지점이기 때문이다.

## 문장 규칙

| 규칙 | 판정 |
| --- | --- |
| 한 문장 한 주장 | 접속으로 두 주장을 이어 붙인 문장이 없다 |
| 코드 인용 | 인용마다 그것을 왜 보여주는지 설명이 붙어 있다 |
| 용어 | 설명 없이 쓰인 전문 용어가 없다 |
| 판정 가능성 | "개선되었다"처럼 사람마다 다르게 읽히는 서술 대신 무엇이 어떻게 달라졌는지 쓴다 |
| 표 셀 값 | 모든 표의 셀 값이 명사절이다 |
| 계획서 참조 | 항목 ID가 계획서 파일을 가리키는 링크다 |

## 표 셀 값

문서의 모든 표는 셀 값을 명사절로 적는다. 실행 흐름 표의 변경 열도 마찬가지다.

| 쓰지 않는 형태 | 쓰는 형태 |
| --- | --- |
| 달라짐 | 동작 변경 |
| 새로 생김 | 신규 추가 |
| 그대로 | 변경 없음 |
| 타입이 해결된다 | 타입 해결 |

문체를 맞추는 이유는 표를 세로로 훑기 때문이다. 행마다 형태가 달라지면 값을 비교하기 전에 문장을 읽어야 한다.

## 계획서 참조

변경 의도 절에서 계획서를 근거로 들 때는 항목 ID 자체를 링크로 만든다. 경로 문자열을 본문에 늘어놓지 않는다.

```
[SETUP-WORKSPACE-003](../plans/2026-09-02-dev-environment/setup/workspace.md)은
저장소 인터페이스의 선언을 항목의 내용으로 정했다.
```

링크 경로는 학습 문서가 놓인 `commits/`를 기준으로 한 상대 경로다. 항목 ID를 찾지 못하면 링크를 만들지 않고, 계획서를 근거에서 뺀다.

## 보관 경로

문서 루트는 [`docs-root.md`](../../_shared/docs-root.md)의 탐색 순서로 판정하고, 보관 경로는 `<루트>/commits/`로 삼는다. 디렉터리가 없으면 만든다.

## 파일 이름

```
YYYY-MM-DD-<짧은 해시>-<제목>.md
```

날짜는 커밋의 작성 날짜이고, 짧은 해시는 일곱 자리다. 제목은 커밋 제목에서 따오되 공백은 하이픈으로 바꾼다.

예를 들어 2026년 9월 4일에 작성된 `936e70c` 커밋의 문서는 `2026-09-04-936e70c-validate-sub-prd-검사-개정.md`가 된다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 문서 루트를 판정할 수 없다 | `docs/`를 쓰고 그 사실을 사용자에게 알린다 |
| `commits/`가 없다 | 만들고 진행한다 |
| 커밋 메시지에 항목 ID가 없다 | 링크를 만들지 않고 계획서를 근거에서 뺀다 |
| 계획서 파일이 저장소에 없다 | 항목 ID를 링크 없이 적고 확인 필요 표시를 남긴다 |
| 커밋 제목에 파일명으로 쓸 수 없는 문자가 있다 | 그 문자를 빼고 짧은 해시로 구분을 유지한다 |
| 커밋 제목이 너무 길다 | 앞에서부터 잘라 쓴다. 짧은 해시가 있으므로 구분은 유지된다 |
| 같은 이름의 파일이 이미 있다 | 덮어쓰지 않고 건너뛴다 |

## 근거·예시

정확하지만 읽히지 않는 문서와, 읽히지만 사실과 다른 문서는 둘 다 학습에 쓸모가 없다. 근거를 셋으로 한정하는 규칙이 앞의 문제를, 문장 규칙이 뒤의 문제를 막는다.

파일 이름에 짧은 해시를 넣는 이유는 같은 날 같은 제목의 커밋이 둘일 수 있기 때문이다. 날짜와 제목만으로는 이름이 겹친다.
