# 대상 수집

## 목적

어느 커밋을 학습 문서로 만들지 정하고, 문서를 만들기 전에 잘못된 입력을 걸러냅니다.

## 핵심 지시

입력을 커밋 목록으로 펼치고, 목록 전체를 검사한 뒤에만 문서 생성에 들어갑니다.

## 입력 형식

| 형태 | 예 | 할 일 |
| --- | --- | --- |
| 커밋 해시 하나 | `936e70c` | 그 커밋 하나를 대상으로 삼습니다 |
| 커밋 해시 여럿 | `936e70c 09d22d9` | 나열 순서를 무시하고 저장소의 시간 순서로 정렬합니다 |
| 범위 표기 | `22c74cc..936e70c` | 구간에 든 커밋을 모두 펼칩니다. 시작점은 포함하지 않습니다 |
| 지정 없음 | — | 최근 커밋 스무 개를 짧은 해시와 제목으로 제시해 고르게 합니다 |

해시는 짧은 형태와 전체 형태를 모두 받습니다. 태그나 브랜치 이름처럼 커밋 하나로 풀리는 표기도 그대로 받습니다.

## 목록을 확정하는 순서

| 순서 | 할 일 |
| --- | --- |
| 1 | 입력을 커밋 목록으로 펼칩니다 |
| 2 | 각 커밋이 저장소에 있는지 확인합니다 |
| 3 | 보관 경로에 같은 커밋의 문서가 있는지 확인합니다 |
| 4 | 짧은 해시, 제목, 상태(생성 예정 또는 건너뜀)를 표로 보여줍니다 |
| 5 | 사용자가 목록을 확인한 뒤 문서 생성에 들어갑니다 |

2번에서 하나라도 걸리면 3번으로 가지 않습니다. 절반만 만들어진 상태로 끝나면 어디까지 되었는지 사용자가 다시 확인해야 하기 때문입니다.

## 중복 판정

같은 커밋의 문서가 있는지는 보관 경로의 파일 이름에 든 짧은 해시로 판정합니다. 파일이 있으면 내용을 열어 보지 않고 건너뜁니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 저장소에 없는 해시가 섞여 있다 | 문서를 하나도 만들지 않고 멈춘 뒤, 문제된 입력을 모두 나열합니다 |
| 범위 표기의 양 끝이 조상 관계가 아니다 | 펼치지 않고 사용자에게 범위를 확인받습니다 |
| 범위에 든 커밋이 하나도 없다 | 대상이 없음을 알리고 종료합니다 |
| 대상 커밋의 문서가 이미 있다 | 목록에 건너뜀으로 표시하고 결과 보고에도 포함합니다 |
| 병합 커밋이 대상에 들어 있다 | 커밋 하나로 다루며 갈래마다 문서를 나누지 않습니다 |
| 커밋 하나의 문서 생성이 실패한다 | 나머지 커밋을 계속 처리하고 실패한 커밋을 따로 보고합니다 |
| 현재 디렉터리가 git 저장소가 아니다 | 절차를 시작하지 않고 그 사실을 알립니다 |

## 근거·예시

이해가 막힌 커밋을 콕 집어 넘기는 경우와, 하루치 작업을 한 번에 훑는 경우가 모두 있습니다. 그래서 해시 나열과 범위 표기를 둘 다 받습니다.

같은 커밋을 다시 지정했을 때 덮어쓰지 않는 이유는, 학습 문서가 그 시점의 기록이고 사용자가 읽으며 남긴 메모가 그 안에 있을 수 있기 때문입니다.
