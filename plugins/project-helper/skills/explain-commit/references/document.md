# 문서 구성

## 목적

학습 문서가 어떤 절을 어떤 순서로 담고, 각 절을 어느 깊이로 쓰는지 정한다.

## 핵심 지시

일곱 절을 고정된 순서로 쓰고, 절마다 판정 기준을 만족할 때까지 채운다.

## 절 구성

| 순서 | 절 | 담는 것 | 채워진 줄 아는 기준 |
| --- | --- | --- | --- |
| 1 | 한 줄 요약 | 이 커밋이 무엇을 바꿨는지 한 문장 | 이 문장만 읽고 커밋의 대상과 변화를 말할 수 있다 |
| 2 | 변경 전 상태와 문제 | 직전 코드가 어떻게 동작했고 무엇이 한계였는지 | 변경 전 동작과 그 한계가 각각 서술되어 있다 |
| 3 | 변경 의도 | 왜 그렇게 바꿨는지와 그 근거 | 의도 서술마다 근거가 된 커밋 메시지나 계획서가 함께 적혀 있다 |
| 4 | 구성 요소 | 뒤 두 절에 나오는 코드 식별자의 정체 | 실행 흐름과 의존 관계에 등장하는 식별자 중 표에 없는 것이 없다 |
| 5 | 실행 흐름 | 입력부터 결과까지의 단계 | 단계마다 파일과 함수 이름이 붙어 있고, 이 커밋으로 달라진 단계가 표시되어 있다 |
| 6 | 의존 관계 | 구성 요소 사이의 연결 | mermaid 블록이 있고, 그림의 모든 화살표에 문장 설명이 붙어 있다 |
| 7 | 용어와 배경 | 본문에 나온 개념의 뜻 | 본문의 전문 용어 중 표에 없는 것이 없다 |

절의 순서를 바꾸거나 절을 더하지 않는다. 문서를 나란히 놓고 같은 자리를 찾아 읽기 위해서다.

## 설명의 깊이

### 구성 요소

이 절은 뒤 두 절을 읽기 전에 이름의 정체를 알려 주는 자리다. 관계부터 설명하면 읽는 사람이 이름을 되짚어 찾게 되므로, 실행 흐름과 의존 관계보다 앞에 둔다.

요소마다 이름, 종류, 위치, 역할을 표의 한 행으로 적는다.

| 열 | 담는 것 |
| --- | --- |
| 구성 요소 | 코드에 쓰인 이름 그대로 |
| 종류 | 타입, 인터페이스, 함수, 설정 파일처럼 무엇인지 |
| 어디에 | 그 이름이 선언된 파일 |
| 역할 | 이 커밋의 맥락에서 무엇을 맡는지 한 줄 |

시그니처나 선언을 인용하지 않는다. 이 절은 훑어보고 위치를 잡는 자리이며, 인용은 분량만 늘린다.

담는 범위는 실행 흐름과 의존 관계에 등장하는 코드 식별자로 한정한다. 커밋이 건드리지 않은 인접 요소라도 뒤 두 절에 나오면 함께 적는다.

### 실행 흐름

파일 목록을 나열하지 않고, 입력이 들어와 결과가 나올 때까지를 순서로 추적한다. 단계마다 어느 파일의 어느 함수에서 일어나는지 밝힌다.

이 커밋으로 달라진 단계는 표시로 구분해, 변경 전 흐름과 대비되게 쓴다.

### 의존 관계

바뀐 구성 요소만 그리지 않는다. 그 요소가 연결되는 주변까지 포함해, 변경이 어디에 닿는지 보이게 한다. 다이어그램에는 커밋이 건드리지 않은 인접 요소가 최소 하나 들어간다.

다이어그램은 mermaid로 그린다. 그림만 두지 않고, 화살표마다 어떤 의존인지 문장으로 설명한다.

### 용어와 배경

커밋에 등장한 용어와 개념만 다룬다. 범위를 열어 두면 문서가 교재로 번져 커밋을 이해한다는 목적에서 멀어진다.

코드 식별자는 이 절에 넣지 않는다. 네 번째 절이 이미 맡았기 때문이다. 이 절은 식별자가 아닌 개념과 배경 지식을 담는다. 도메인 낱말, 표기법, 도구의 동작 방식이 그런 예다.

| 표에 넣을 자리 | 판정 |
| --- | --- |
| 구성 요소 | 코드에 그 이름으로 선언되거나 표기된 식별자 |
| 용어와 배경 | 코드 식별자가 아닌 개념과 배경 지식 |

보충 설명은 본문에 흩지 않고 두 표에 모은다. 본문을 읽는 흐름이 끊기지 않게 하기 위해서다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 커밋이 문서만 고쳐 실행 흐름이 없다 | 실행 흐름 절에 해당 없음과 그 이유를 적고 나머지 절은 채운다 |
| 의존 관계가 한 파일 안에서 끝난다 | 파일 내부의 함수 관계를 다이어그램으로 그린다 |
| 커밋 메시지에 의도가 없고 계획서도 없다 | 의도를 추측하지 않고 확인 필요 표시를 남긴다 |
| 변경 규모가 커서 흐름이 여러 갈래다 | 갈래마다 실행 흐름 절의 하위 항목으로 나눈다 |
| 본문에 쓸 용어가 하나도 없다 | 용어 표에 해당 없음을 적는다. 절을 지우지 않는다 |
| 커밋에 코드 식별자가 하나도 없다 | 구성 요소 표에 해당 없음을 적는다. 절을 지우지 않는다 |
| 구성 요소가 지나치게 많다 | 실행 흐름과 의존 관계에 등장하는 것만 적는다. 그 밖의 식별자는 넣지 않는다 |

## 근거·예시

파일 단위로 "무엇이 바뀌었다"만 적으면 diff를 다시 열어야 흐름이 보인다. 어느 함수가 무엇을 받아 무엇을 넘기는지 순서로 이어야, 코드를 열지 않고도 변경을 설명할 수 있다.

다이어그램에 바뀐 요소만 그리면 변경의 파급이 보이지 않는다. 검증 스크립트 한 편을 추가한 커밋이라면, 그 스크립트를 부르는 스킬 문서까지 그려야 무엇이 달라졌는지 읽힌다.
