# experiment

## 역할과 목적

`experiment`는 학습자가 설명을 듣고 이해한 내용을 직접 확인하게 하는 단축키입니다. 무엇을 바꾸거나 비교할지와, 이해한 대로라면 어떤 결과가 나와야 하는지를 먼저 보여 주고, 학습자가 실험한 결과를 예상과 비교합니다.

## 실행 원칙

**첫 설명만 확인 방법 제안과 실험으로 시작하고, 실험이 끝난 뒤에는 [`session.md`](../_shared/rules/session.md)의 배정 표로 질문을 이어 받습니다.**

학습의 시작과 경로 마무리는 `session.md`를 따릅니다. 실험의 커밋과 기록은 [`experiment-designer.md`](../_shared/roles/experiment-designer.md)와 [`record.md`](../_shared/rules/record.md)를 따릅니다.

## 참조 문서 규칙

이 문서가 `experiment`의 실행 절차를 정하는 기준 문서입니다. 아래 표의 시점에 지정한 문서만 읽고, 나머지 문서는 `session.md`의 참조 문서 표가 정한 시점에 읽습니다.

| 문서 | 맡는 일 | 읽는 시점 |
| --- | --- | --- |
| [`rules/session.md`](../_shared/rules/session.md) | 시작 절차, 질문 배정, 경로 마무리 | 호출하자마자 |
| [`rules/record.md`](../_shared/rules/record.md) | 기록 파일, 실험 기록, 실험 커밋 | 확인 대상을 찾을 때와 실험을 기록할 때 |
| [`roles/experiment-designer.md`](../_shared/roles/experiment-designer.md) | 확인 방법 제안, 전후 비교, 실험 커밋 | 확인 방법을 제안할 때와 실험이 끝날 때 |
| [`roles/knowledge-navigator.md`](../_shared/roles/knowledge-navigator.md) | 끝나지 않은 경로와 다음 탐색 후보 | 경로 도중에 불렸을 때와 실험이 끝날 때 |

## 실행 절차

**진행 중인 학습**은 `state.json`에 `sessionStatus: in_progress`와 현재 패키지가 저장된 상태를 뜻합니다.

| 호출 상황 | 할 일 |
| --- | --- |
| 진행 중인 학습이 없음 | `session.md`의 시작 절차 1~7단계를 거친 뒤 첫 설명 시작 |
| 설명 경로 도중에 호출 | 현재 단계의 현상을 알려 주고, 남은 단계를 다음 탐색 후보로 남긴 뒤 첫 설명 시작 |
| 진행 중인 학습이 있고 경로가 끝남 | 곧바로 첫 설명 시작 |

설명 경로 도중에 부르면 Question Gate 전이 표의 "다른 질문"과 똑같이 처리합니다. 원래 경로의 남은 단계는 `state.md`의 `## 다음 탐색 후보`에 남깁니다(`knowledge-navigator.md`).

### 첫 설명

"배열에 직접 넣으면 어떻게 돼?"처럼 확인 내용과 함께 부르면 그 내용으로 실험합니다. 확인 내용 없이 부르면 확인 대상을 아래 순서로 찾고, Experiment Designer로 그 대상의 확인 방법을 제안합니다.

1. 이 세션에서 마지막으로 끝낸 설명 경로
2. 학습 패키지 `records/` 아래 날짜 디렉터리와 순번 파일 가운데 가장 늦은 질문 파일
3. 둘 다 없으면 확인할 설명이 아직 없다고 알리고, 탐색 질문 후보 2~3개를 번호로 제시

2번에서 찾은 질문은 확인 방법을 제안하기 전에 학습자에게 알려, 어떤 설명을 확인하는지 알 수 있게 합니다. 3번에서 학습자가 후보를 고르면 그 질문의 설명 경로를 관찰 유도로 시작합니다.

### 실험 뒤

| 실험 종류 | 할 일 |
| --- | --- |
| 코드 변경형 | 결과를 예상과 비교하고, 전후 비교를 보여 준 뒤 곧바로 실험 커밋 |
| 구조 비교형 | 결과를 예상과 비교하고, 커밋 없이 기록만 다음 커밋에 포함 |

실험의 질의응답은 `state.json.record`가 가리키는 질문 파일에 `## 실험: <대상 질문>` 절로 적습니다(`record.md`). 실험이 끝나면 다음 탐색 후보 2~3개를 번호로 제시하고, 이후 질문은 `session.md`의 배정 표로 받습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 학습자가 준 확인 내용이 현재 예제에 없는 대상 | 예제 안의 대상이 아니라고 알리고 확인 내용을 다시 물음 |
| 실험 뒤 검증 스크립트가 실패함 | 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사 |

## 경계

- 학습자가 `/experiment`로 호출하지 않은 질문이나 코드 작업에는 이 스킬을 쓰지 않습니다.
- 학습 폴더와 범위 밖 기능의 경계는 `session.md`를 따릅니다.
