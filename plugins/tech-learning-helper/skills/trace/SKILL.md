# trace

## 역할과 목적

`trace`는 학습 중인 예제의 설명을 실행 관점으로 곧바로 전환하는 단축키입니다. 학습자가 질문 문장에 관점을 드러내지 않아도, 이벤트·함수 호출·데이터 흐름·상태 변화·렌더링처럼 코드가 실행되며 일어나는 과정부터 설명합니다.

## 실행 원칙

**첫 설명만 실행 관점으로 시작하고, 그 설명 경로가 끝난 뒤에는 [`session.md`](../_shared/rules/session.md)의 배정 표로 질문을 이어 받습니다.**

관점을 한 번 바꾸는 단축키이므로, 첫 경로 뒤에 구조를 물으면 배정 표에 따라 구조 관점으로 설명합니다. 학습의 시작과 경로 마무리는 `session.md`를 따릅니다.

## 참조 문서 규칙

이 문서가 `trace`의 실행 절차를 정하는 기준 문서입니다. 아래 표의 시점에 지정한 문서만 읽고, 나머지 문서는 `session.md`의 참조 문서 표가 정한 시점에 읽습니다.

| 문서 | 맡는 일 | 읽는 시점 |
| --- | --- | --- |
| [`rules/session.md`](../_shared/rules/session.md) | 시작 절차, 질문 배정, 경로 마무리 | 호출하자마자 |
| [`roles/knowledge-navigator.md`](../_shared/roles/knowledge-navigator.md) | 설명 경로 선택과 끝나지 않은 경로 | 첫 설명의 경로를 고를 때 |
| [`roles/example-builder.md`](../_shared/roles/example-builder.md) | 실행 관점 경로와 탐색 질문 생성 | 저장된 실행 관점 경로가 없을 때 |
| [`roles/question-gate.md`](../_shared/roles/question-gate.md) | 공개 단계와 전이 표 | 경로의 단계마다 |
| [`roles/logic-explainer.md`](../_shared/roles/logic-explainer.md) | 실행 관점 설명 | 경로의 단계마다 |

## 실행 절차

**진행 중인 학습**은 이 대화에서 이미 패키지를 정해 학습을 시작한 상태를 뜻합니다. 파일이 아니라 지금 대화의 맥락으로 판단합니다.

| 호출 상황 | 할 일 |
| --- | --- |
| 진행 중인 학습이 없음 | `session.md`의 시작 절차 1~7단계를 거친 뒤 첫 설명 시작 |
| 설명 경로 도중에 호출 | 현재 단계의 현상을 알려 주고, 남은 단계를 다음 탐색 후보로 남긴 뒤 첫 설명 시작 |
| 진행 중인 학습이 있고 경로가 끝남 | 곧바로 첫 설명 시작 |

설명 경로 도중에 부르면 Question Gate 전이 표의 "다른 질문"과 똑같이 처리합니다. 원래 경로의 남은 단계는 그 패키지 `state.json`의 `nextCandidates`에 남깁니다(`knowledge-navigator.md`).

### 첫 설명

| 호출 | 첫 설명 |
| --- | --- |
| 질문과 함께 호출 | 그 질문의 실행 관점 설명 경로를 관찰 유도로 시작 |
| 질문 없이 호출 | 현재 예제의 실행 관점 탐색 질문 후보 2~3개를 번호로 제시하고, 고르면 시작 |

질문은 `questions-store.sh toc <패키지>`의 목차에서 같은 뜻이면서 관점도 실행인 질문을 찾고, 있으면 `get`으로 경로를 받습니다. 같은 뜻의 질문이 구조 관점으로만 등록되어 있으면, Example Builder의 규칙으로 실행 관점 경로를 새로 만들어 `add`로 등록합니다. 다음 탐색 후보도 실행 관점의 질문을 먼저 제시하고, 경로는 학습자가 후보를 고른 뒤에 만듭니다.

경로의 단계마다 Question Gate로 공개 단계를 정하고 Logic Explainer로 설명합니다. 경로가 끝나면 `session.md`의 경로 마무리를 따르고, 이후 질문은 배정 표로 받습니다.

## 경계

- 학습자가 `/trace`로 호출하지 않은 질문이나 코드 작업에는 이 스킬을 쓰지 않습니다.
- 학습 폴더와 범위 밖 기능의 경계는 `session.md`를 따릅니다.
