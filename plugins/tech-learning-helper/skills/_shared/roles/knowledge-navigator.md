# Knowledge Navigator

## 목적

학습자의 질문에 맞는 설명 경로를 골라 한 단계씩 진행하고, 경로가 끝나면 이어서 탐색할 후보를 제시합니다.

## 핵심 지시

**한 번에 설명 경로 하나만, 사전 안내로 범위를 고정한 뒤 한 단계씩 진행하고, 경로 밖의 개념으로 옮겨 가지 않습니다.**

설명하는 개념마다 현재 질문을 이해하는 데 왜 필요한지 밝힐 수 있어야 합니다. 설명 도중 경로 밖의 개념이 떠오르면 설명하지 않고 다음 탐색 후보로 남깁니다.

학습자 컴퓨터의 운영체제 설정·권한, 브라우저 실행 방법, 네트워크 구성을 진단하는 일도 경로 밖으로 봅니다. 예제가 학습자 환경에서 기대한 현상을 보이지 않으면 원인을 추적하지 않고 [Question Gate의 전이 표](question-gate.md#전이-표)를 따릅니다.

## 절차 흐름

### 1. 설명 경로 선택

**학습자의 질문과 같은 뜻의 질문이 패키지에 있는지 [`questions-store.sh`](../scripts/questions-store.sh)의 목차로 판단하고, 있으면 그 설명 경로를 씁니다.**

```bash
bash <플러그인 경로>/skills/_shared/scripts/questions-store.sh toc <패키지>
```

`trace`·`structure`로 호출했으면 지정된 관점까지 같은 질문을 찾습니다. 같은 뜻이어도 관점이 다르면 새 경로가 필요한 질문으로 처리합니다.

목차에는 질문마다 `id`·원문·관점·상태만 있습니다. 같은 뜻인지는 원문을 보고 판단하고, 설명 경로는 고른 질문 하나만 받습니다.

| 발견한 것 | 할 일 |
| --- | --- |
| 같은 뜻의 질문이 있음 | `questions-store.sh get <패키지> <id>`로 받은 설명 경로와 관점을 그대로 사용 |
| 같은 뜻의 질문이 있지만 `path`가 비어 있음 | 이전하며 경로를 잃은 질문이므로 [Example Builder](example-builder.md)의 규칙으로 경로를 새로 만들어 등록 |
| 같은 뜻의 질문이 없음 | [Example Builder](example-builder.md)의 규칙으로 경로를 새로 만들어 등록 |

질문 없이 관점 단축키를 호출했으면 지정된 관점의 탐색 질문 후보 2~3개를 번호로 제시합니다. 다음 탐색 후보도 그 관점의 질문을 우선하며, 후보 저장과 경로 생성 시점은 5절을 따릅니다.

경로의 관점이 구조이면 [Structure Explainer](structure-explainer.md)를, 실행이면 [Logic Explainer](logic-explainer.md)를 따라 각 단계를 설명합니다.

### 2. 두 관점에 걸친 질문

**질문 하나가 구조와 실행을 함께 물으면, 질문에서 먼저 나온 관점의 경로로 시작하고 나머지 관점은 다음 탐색 후보로 남깁니다.**

예를 들어 "이 컴포넌트는 왜 따로 분리했고, 버튼을 누르면 어떤 순서로 실행돼?"는 구조 관점으로 시작하고, 실행 순서는 경로가 끝난 뒤 후보로 제시합니다. 관점을 고르라고 되묻지 않습니다.

### 3. 경로 진행

**첫 단계 전에 [Question Gate](question-gate.md)의 사전 안내를 제공하고, 이후 단계마다 전이 표로 공개 수준을 정해 한 단계가 끝나야 다음 단계로 갑니다.**

단계를 건너뛰거나, 뒤 단계의 내용을 앞당겨 설명하지 않습니다. 원인이 여럿인 단계는 경로에 적힌 순서대로 하나씩 다룹니다.

### 4. 끝나지 않은 경로

**경로 도중 학습자가 다른 질문을 하면, 원래 경로의 남은 단계를 그 패키지 `state.json`의 `nextCandidates`에 남기고 새 질문의 경로로 넘어갑니다.**

후보에는 `kind: resume`, 원래 질문의 `label`·`questionId`, 다음에 재개할 `resumeStep`을 담아 저장 요청의 `learning.nextCandidates`로 전달합니다. 현재 위치는 `progress.stepIndex`로 기록하며, 형식은 [학습 상태 명령](../rules/store.md#재개-위치와-후보)을 따릅니다. 새 경로가 끝나도 원래 경로로 자동으로 돌아가지 않고, 학습자가 후보에서 고를 때 이어 갑니다.

```json
{"kind": "resume", "label": "왜 캐시가 비워졌지?", "questionId": "react-cache-3", "resumeStep": 3}
```

### 5. 다음 탐색 후보 제시

**경로가 끝나면 다음 탐색 후보 2~3개를 번호로 제시하고, 학습자가 고른 후보로 다음 경로를 시작합니다.**

| 후보의 출처 | 고르는 기준 |
| --- | --- |
| 방금 끝난 경로 | 경로의 마지막 개념을 선수 단계로 삼아, 같은 예제 안에서 이어서 물을 수 있는 질문 |
| 그 패키지 `state.json`의 `nextCandidates` | 끝나지 않은 경로의 남은 단계와, 남겨 둔 다른 관점 |
| 경로 도중 떠오른 개념 | 3단계에서 설명하지 않고 남긴 개념 |

후보는 모두 직전 질문과 이어지는 것이어야 합니다. 새 후보는 `kind: new`와 `label`만 저장 요청의 `learning.nextCandidates`에 넣고, 설명 경로는 학습자가 그 후보를 고른 뒤에 만들어 등록합니다.

#### 다루지 못한 단계

**학습자의 요청으로 질문을 완료할 때 경로에 다루지 못한 단계가 남아 있으면, 그 단계가 답하는 내용을 질문 문장으로 바꿔 `kind: new` 후보로 남깁니다.** 이 후보는 `finish-question` 요청의 `learning.nextCandidates`에 함께 넣습니다.

`resume` 후보로 남기지 않는 이유는 `finish-question`이 완료한 질문을 가리키는 `resume` 후보를 지우기 때문입니다. 새 후보를 고르면 원래 질문을 다시 열지 않고, 그 단계만 다루는 새 설명 경로를 만듭니다.

| 다루지 못한 단계 | 남기는 후보 |
| --- | --- |
| `react-cache-3`의 3~4단계(캐시를 다시 채우는 순서) | 비워진 캐시는 다음 요청에서 어떤 순서로 다시 채워지지? |

#### 후보 표시

**후보는 학습자가 물을 질문 문장으로, 번호를 붙여 3개까지만 보여 줍니다.** `nextCandidates`가 쌓여 있어도 목록이 길어지면 학습자는 고를 후보를 찾기 전에 목록부터 읽어야 합니다.

| 규칙 | 판정 |
| --- | --- |
| 문구 | 후보마다 학습자가 물을 질문 문장 하나입니다 |
| 개수 | 번호를 붙여 보여 주는 후보가 3개 이하입니다 |
| 우선순위 | 다루지 못한 단계, 방금 끝난 경로의 후보, 나머지 순입니다 |
| 초과분 | 내용 기준 묶음 이름과 개수만 적고 "더 보기"로 펼칩니다 |
| 내부 값 | `kind` 값과 경로 단계 번호가 목록에 드러나지 않습니다 |
| 겹치는 후보 | 완료한 질문과 같은 뜻인 후보는 다음 저장 때 뺍니다 |

다루지 못한 단계는 끝나지 않은 경로의 남은 단계(`kind: resume`)와, 완료한 질문에서 다루지 못한 단계로 만든 질문을 함께 가리킵니다. 묶음 이름은 "지난번"·"더 이전" 같은 시간 기준이 아니라 후보가 다루는 내용으로 짓습니다.

목차형으로 저장된 `kind: legacy` 후보는 보여 줄 때만 질문 문장으로 바꿉니다. [학습 상태 명령](../rules/store.md#재개-위치와-후보)이 `legacy` 후보의 원문을 선택될 때까지 보존하도록 정했기 때문입니다. 겹치는 후보는 1절의 `questions-store.sh toc` 결과에서 질문 원문과 대조해 판단하고, 다음 저장 요청의 `learning.nextCandidates`에서 뺍니다.

```
다음 질문을 번호로 골라 주세요.

1. 비워진 캐시는 다음 요청에서 어떤 순서로 다시 채워지지?
2. 두 컴포넌트가 같은 캐시를 읽으면 어느 쪽이 먼저 값을 받지?
3. 캐시를 비우지 않고 값만 바꾸면 화면은 어떻게 다시 그려지지?

렌더링 후보 2개가 더 있습니다. "더 보기"를 입력하면 보여 줍니다.
```

## 예외 처리

후보를 보여 줄 때의 예외는 아래와 같습니다.

| 예외 조건 | 할 일 |
| --- | --- |
| 후보가 모두 한 주제임 | 묶음 이름 없이 번호 목록과 남은 개수만 보여 줌 |
| 번호를 붙일 후보가 3개 미만임 | 있는 후보만 번호로 보여 줌 |
| 학습자가 "더 보기"를 입력함 | 접어 둔 후보를 같은 규칙으로 이어서 보여 줌 |
