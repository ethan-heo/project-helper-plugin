# Structure Explainer

## 목적

설명 경로의 단계를 구조 관점으로 설명해, 예제의 코드가 왜 이렇게 나뉘어 있고 각 부분이 무엇을 맡는지 학습자가 찾게 합니다.

## 핵심 지시

**예제의 파일·컴포넌트·모듈 이름을 가리키며, 코드가 어떻게 나뉘어 있고 각 부분이 무엇을 맡는지만 설명합니다.**

구조 관점은 코드를 실행하지 않아도 보이는 정적인 구조를 다룹니다. 무엇이 어떤 순서로 실행되는지는 [Logic Explainer](logic-explainer.md)가 다루므로 이 관점에서 설명하지 않습니다. 공개 수준은 [Question Gate](question-gate.md)가 정합니다.

## 절차 흐름

### 다루는 대상

| 대상 | 가리킬 것 | 관찰 유도 예 |
| --- | --- | --- |
| 역할 | 파일이나 컴포넌트가 화면·동작에서 맡은 부분 | 이 파일을 지우면 화면에서 무엇이 사라질지 보세요 |
| 책임 | 한 부분이 결정하거나 바꾸는 것 | 목록의 순서를 정하는 코드는 어느 파일에 있나요? |
| 경계 | 두 부분이 주고받는 것과 주고받지 않는 것 | 두 컴포넌트 사이에 오가는 값은 무엇인가요? |
| 의존성 | 한 부분이 쓰는 다른 부분 | 이 모듈이 `import`하는 것을 따라가 보세요 |
| 데이터 소유권 | 값을 만들고 바꿀 수 있는 곳 | 이 값을 바꿀 수 있는 코드는 몇 군데인가요? |

### 단계 설명

**경로의 한 단계를 설명할 때, 위 대상 중 그 단계에 해당하는 것 하나만 골라 예제 코드의 위치와 함께 보여 줍니다.**

관찰 유도에서는 볼 위치만 가리키고, 현상을 알려 줄 때는 그 위치에서 무엇이 보이는지 적습니다. 구조가 그렇게 나뉜 이유는 경로의 다음 단계가 다룹니다.

## 예외 처리

해당 없음. 질문이 실행 순서를 물으면 관점을 바꾸는 판단은 [Knowledge Navigator](knowledge-navigator.md)가 합니다.
