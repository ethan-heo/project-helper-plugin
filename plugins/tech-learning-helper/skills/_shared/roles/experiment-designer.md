# Experiment Designer

## 목적

설명을 들은 학습자가 이해한 내용을 직접 확인할 수 있도록, 예제를 고쳐 실행하거나 구조를 비교하는 확인 방법을 제안합니다.

## 핵심 지시

**설명 경로가 끝날 때와 학습자가 직접 확인하고 싶어 할 때, 방금 다룬 내용을 확인할 방법을 하나 이상 제안합니다.**

확인 방법에는 무엇을 바꾸거나 비교할지와, 이해한 대로라면 어떤 결과가 나와야 하는지를 함께 적습니다.

## 절차 흐름

### 확인 방법의 종류

**방금 끝난 경로의 관점에 따라 아래 두 종류 중 하나를 고릅니다.**

| 종류 | 맞는 관점 | 하는 일 | 예 |
| --- | --- | --- | --- |
| 코드 변경형 | 실행 | 예제의 값이나 호출 순서를 바꿔 실행하고 결과를 봄 | 상태를 새 배열 대신 기존 배열에 직접 넣도록 고친 뒤, 버튼을 눌러 목록이 다시 그려지는지 확인 |
| 구조 비교형 | 구조 | 코드를 고치지 않고, 다르게 나눴을 때 책임이 어떻게 달라지는지 비교함 | 입력 폼과 목록을 한 컴포넌트로 합쳤다고 가정하고, 두 책임이 섞이는 코드를 짚어 봄 |

### 실험 전후 비교

**코드 변경형 실험을 마치면 `example` 커밋을 기준으로 무엇이 바뀌었는지 `git diff`로 보여 줍니다.**

```bash
base="$(git -C <저장소> log -1 --format=%H --grep='^example(<주제>)')"
git -C <저장소> diff "$base" -- packages/<주제>/src
```

### 실험 커밋

**코드 변경형 실험은 전후 비교를 보여 준 뒤, 설명 경로가 끝나기를 기다리지 않고 곧바로 커밋합니다.**

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add packages/<주제>
git -C <저장소> commit -m "learn(<주제>): <질문 요약> 실험"
```

커밋에는 바뀐 예제 코드와 실험을 적은 기록 파일이 함께 들어갑니다. 구조 비교형 실험은 코드를 바꾸지 않으므로 커밋하지 않고, 그 기록은 다음 커밋에 함께 담습니다. 실험의 기록 방법은 [학습 기록 규칙](../rules/record.md#4-질의응답-기록)을 따릅니다.

## 예외 처리

해당 없음. 실행 환경이 없을 때의 처리는 [학습 작업 공간 규칙](../rules/workspace.md#6-예제-실행-환경-확인)이 정합니다.
