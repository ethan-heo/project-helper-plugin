# Example Builder

## 목적

학습에 필요한 기술 지식과 예제를 요청 시점에 만들고, 한 번 만든 것은 기술 저장소에 저장해 다시 씁니다.

## 핵심 지시

**저장된 지식이 있으면 불러오고, 학습 목표에 필요한데 없는 것만 새로 만들어 저장합니다.**

개념은 별도 목록에 두지 않고 설명 경로의 서술 안에만 둡니다. 탐색 질문과 설명 경로는 학습 패키지의 `questions.json`에 두고, 등록·개별 조회에는 [`questions-store.sh`](../scripts/questions-store.sh)를 사용하고, 학습 중 상태 처리는 [학습 상태 명령](../rules/store.md)에 맡깁니다. 탐색 질문은 그 패키지 예제의 코드와 동작 안에서만 나옵니다. 이 문서는 가르치는 순서와 공개 단계를 다루지 않습니다.

## 절차 흐름

### 1. 개념 재사용 확인

**설명 경로에 넣을 개념이 저장소 `state.json`의 `discoveredConcepts`에 이미 있으면 새로 설명하지 않고, 없는 개념만 그 경로 단계에서 처음 설명합니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| 저장소 `discoveredConcepts`에 있음 | 그 경로 단계를 "이미 다룬 개념"으로만 참조 |
| 저장소 `discoveredConcepts`에 없음 | 그 경로 단계에서 처음 설명 |

`discoveredConcepts`는 [학습 재개 규칙](../rules/resume.md#저장소-statejson)이 정하는 저장소 `state.json`의 필드이며, 이 절차는 재개 때 받은 `context.discoveredConcepts`를 사용합니다.

### 2. 예제

**학습 목표를 담고, 고치지 않고 바로 실행되는 예제를 패키지의 `src/`에 만듭니다.**

| 기술의 생태계 | 예제 언어 |
| --- | --- |
| 웹·JavaScript 생태계 | TypeScript |
| 그 밖의 기술, 가져온 코드 | 학습 대상 기술의 언어나 가져온 코드의 언어 |

예제에는 학습 목표와 관계없는 문법이나 설정을 넣지 않습니다. 관찰할 현상이 운영체제 권한, 브라우저 정책, 네트워크 구성처럼 학습 목표와 관계없는 환경 조건에 따라 달라지지 않게 만듭니다. 실행 준비는 [학습 작업 공간 규칙](../rules/workspace.md#5-학습-패키지-생성)을 따릅니다.

### 3. 사전 안내, 탐색 질문과 설명 경로

**학습자가 실제로 물은 질문이나 다음 탐색 후보에서 고른 질문마다 사전 안내와 설명 경로를 만들어 `questions-store.sh add`로 등록합니다. 예제를 준비할 때 질문을 미리 여러 개 만들어 두지 않습니다.**

사전 안내는 `scope`·`terms`·`observations` 세 항목으로 이루어집니다. `scope`에는 이번 경로에서 다룰 범위와 용어가 이어지는 순서를 적고, `terms`에는 용어별 설명을, `observations`에는 예제에서 확인할 대상을 적습니다.

**안내의 범위는 학습자가 실행한 예제에서 관찰할 수 있는 것으로 한정합니다.**

예제에서 드러나는 값·로그·호출은 모두 안내에 씁니다. 학습자 환경에서 재현되지 않는 다른 환경의 상황은 넣지 않습니다.

**용어마다 아래 순서로 씁니다.**

| 순서 | 쓰는 것 |
| --- | --- |
| 1 | 정체 — 그 용어가 무엇인지 |
| 2 | 역할 — 연결된 다른 용어와 어떤 관계로 무엇을 하는지 |
| 3 | 구성 요소 — 안에 어떤 값이 들어 있는지 |
| 4 | 사용 시점 — 예제의 어느 지점에서 쓰이는지 |

이름과 뜻만 적은 한 줄은 이 순서를 만족하지 못합니다. 구성 요소가 없는 용어는 그 항목을 건너뜁니다. 개념 사이의 관계는 2번 안에 함께 쓰고 따로 모으지 않습니다.

용어는 선행 관계가 앞에 오도록 배열합니다. A를 알아야 B를 이해할 수 있으면 A를 앞에 둡니다. 학습자에게 보여 줄 때 이 순서를 그대로 씁니다.

**안내에는 현재 기준 번호를 `standard`로 함께 저장합니다. 이번 기준의 번호는 `1`입니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| `orientation`이 없음 | 현재 기준으로 만들어 저장 |
| `standard`가 없음 | 현재 기준으로 다시 만들어 저장 |
| `standard`가 현재 기준과 같음 | 저장된 안내를 그대로 사용 |

옛 안내에 남아 있는 `map`은 읽기 호환으로만 허용하며 새 안내에는 넣지 않습니다.

```bash
bash <플러그인 경로>/skills/_shared/scripts/questions-store.sh add <패키지> <관점> <기록경로> <질문원문> --orientation '<JSON>' <단계1> <단계2> ...
```

위 표에서 다시 만들기로 판정한 안내는 `update-orientation <패키지> <질문 ID> '<JSON>'`으로 저장합니다.

스크립트가 `<저장소>-<패키지>-<순번>` 형태의 `id`를 만들어 출력하고, 이후 이 질문은 그 `id`로 가리킵니다. `<관점>`은 `구조`나 `실행`, `<기록경로>`는 [학습 기록 규칙](../rules/record.md)이 이 질문에 만든 기록 파일입니다.

설명 경로는 관찰할 현상에서 시작해 직접 원인, 그 원인의 원인을 거쳐 개념에 이르는 단계 목록입니다. 경로는 갈라지지 않습니다.

| 발견한 것 | 할 일 |
| --- | --- |
| 원인이 둘 이상임 | 경로를 둘로 가르지 않고, 같은 경로 안에서 차례로 나열 |
| 이해하려면 선수 개념이 필요함 | 선수 개념을 경로의 한 단계로 넣음 |

### 4. 가져온 자료

**학습자가 링크·로컬 파일·코드를 가져오면 원본을 기반으로 예제를 만들고, 원본 참조와 질문에 해당하는 발췌를 `source.md`에 남깁니다.**

| 자료 | 예제 | `source.md` |
| --- | --- | --- |
| 링크 같은 공개 자료 | 원본 구간을 옮기고 실행에 부족한 부분만 채움 | 링크와 질문에 해당하는 발췌 |
| 로컬 파일, 출처를 모르는 붙여 넣은 코드 | 질문한 동작만 남긴 최소 실행 예제로 줄이고 업무용 이름·데이터를 일반화 | 파일 경로와 줄 범위, 질문에 필요한 줄로 한정한 발췌 |
| 원본에 접근할 수 없거나 너무 작음 | 같은 동작의 예제를 새로 만듦 | 원본 참조와 접근 실패 사유 |

로컬 파일과 붙여 넣은 코드를 줄이는 이유는, 회사 프로젝트 코드가 학습 저장소의 git 이력에 그대로 남지 않게 하기 위해서입니다.

### 5. 재현되지 않는 예제

**[Question Gate](question-gate.md#전이-표)가 경로를 멈추면, 예제를 고칠지 현재 질문을 보류할지 학습자에게 묻습니다.**

| 학습자 선택 | 할 일 |
| --- | --- |
| 예제 수정 | 현상을 좌우하는 환경 조건을 예제에서 빼거나 다른 방법으로 대신하고, 학습자가 다시 실행하게 한 뒤 멈춘 단계의 관찰 유도부터 이어 감 |
| 질문 보류 | 멈춘 단계를 `kind: resume` 후보로 남기고 [다음 탐색 후보](knowledge-navigator.md#5-다음-탐색-후보-제시)를 제시 |

고칠 부분은 예제 코드와 학습자가 전한 결과만으로 정하고, 학습자에게 환경을 진단하게 하지 않습니다. 고친 예제로도 현상이 나오지 않으면 질문 보류로 처리합니다.

예제를 고치면 검증 스크립트를 통과시킨 뒤 곧바로 커밋합니다. 실험 전후 비교는 가장 최근 `example` 커밋을 기준으로 삼으므로, 이 커밋이 새 비교 기준이 됩니다.

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add packages/<주제>/src packages/<주제>/README.md
git -C <저장소> commit -m "example(<주제>): <수정 요약> 수정"
```

## 양식

### questions.json 항목

`questions-store.sh`가 쓰는 형식입니다. 파일을 직접 고치지 않습니다.

```json
{
  "id": "react-cache-3",
  "question": "왜 캐시가 비워졌지?",
  "viewpoint": "실행",
  "orientation": {
    "scope": "캐시가 비워지는 호출 순서. 이벤트가 상태를 바꾸고 그 변경이 다음 렌더링에서 캐시를 비운다",
    "standard": 1,
    "terms": [
      "상태는 컴포넌트가 다시 그려져도 남는 값이다. 이벤트 처리기가 이 값을 바꾸면 리액트가 다음 렌더링을 예약한다. 안에는 현재 값과 그 값을 바꾸는 함수가 들어 있다. 예제에서는 버튼을 누를 때 바뀐다.",
      "캐시는 계산 결과를 상태와 함께 보관해 두는 저장소다. 상태가 바뀌면 보관한 결과가 낡으므로 지워진다. 예제에서는 상태 변경 직후의 로그에서 비워지는 시점을 볼 수 있다."
    ],
    "observations": ["캐시를 비우는 함수 호출", "호출 직후의 상태"]
  },
  "path": ["<관찰할 현상>", "<직접 원인>", "<그 원인의 원인>", "<이르는 개념>"],
  "status": "진행",
  "record": "records/2026-09-14/03-cache-cleared.md"
}
```

### source.md

```markdown
# <주제 표시 이름> 원본 자료

## 원본 참조

- 종류: 링크 | 로컬 파일 | 붙여 넣은 코드
- 위치: <링크, 또는 파일 경로와 줄 범위>
- 접근: 성공 | 실패(<사유>)

## 발췌

<질문에 해당하는 구간만>
```
