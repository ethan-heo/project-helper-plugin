# 학습 정리 규칙

## 목적

학습 패키지 하나에서 다룬 질문과 발견한 개념을 그 패키지의 상태 파일에서 모아, 다시 볼 수 있게 보여 줍니다.

## 핵심 지시

**정리를 요청받으면 학습 패키지 하나의 `state.json` 값을 그대로 옮겨 채팅에 보여 줍니다. 새 파일을 만들거나 커밋하지 않습니다.**

모든 값은 아래 표의 파일에서 옮기고, 새로 풀어 쓴 설명이나 요약 문장은 넣지 않습니다. 배운 내용을 자기 말로 정리하는 일은 학습자의 몫이기 때문입니다.

## 절차 흐름

### 1. 정리 대상

**진행 중인 학습이 있으면 지금 학습하는 패키지를, 없으면 [이어 하기 목록](resume.md#2-이어-하기-목록)에서 학습자가 고른 패키지를 정리합니다.**

선택한 패키지의 정리 데이터는 [학습 상태 명령](store.md)으로 한 번 조회합니다. 이번 정리에서 이미 받은 결과가 있으면 다시 호출하지 않습니다.

### 2. 값 옮기기

**`review-data` 결과를 아래 순서로 옮겨 채팅에 보여 줍니다.**

```bash
bash <플러그인 경로>/skills/_shared/scripts/learning-store.sh review-data <패키지>
```

| 순서 | 옮기는 값 | 결과 필드 |
| --- | --- | --- |
| 학습 목표 | 목표 원문 | `goal` |
| 다룬 질문 | 질문·도달한 개념·날짜·기록 링크 | `questions` |
| 발견한 개념 | 이름 목록 | `discoveredConcepts` |
| 부분 이해 개념 | 개념과 남은 설명 | `partialConcepts` |
| 다음 탐색 후보 | 후보와 재개 위치 | `nextCandidates` |

질문은 반환 순서를 유지하고, 날짜와 링크는 `date`·`recordPath`를 사용합니다. 완료한 질문의 도달한 개념은 `lastStep` 문장에서 읽습니다. 값이 없으면 `경로 없음`으로 표시합니다. 진행 중인 질문은 `resumeStep`에서 남은 위치를 표시하고, 위치가 불명확하면 그 사실을 적습니다. 정리만 하려고 재개 위치를 확인하거나 기록 전문을 읽지 않습니다.

질문별 `toc`·`get`을 추가 호출하지 않습니다. 후보의 표시 문장은 `label`이며, 재개할 질문과 단계는 `questionId`·`resumeStep`입니다. 항목이 없는 값은 `없음`이라고 보여 줍니다.

### 3. 표시

**진행 중인 기록·상태 변경이 있으면 [중단된 변경 커밋](resume-commit.md)으로 먼저 커밋한 뒤, 정리 내용을 학습자에게 그대로 보여 줍니다.**

## 양식

### 정리 표시 순서

```markdown
# <주제 표시 이름> 학습 정리

## 학습 목표

<패키지 README.md의 학습 목표>

## 다룬 질문

| 질문 | 도달한 개념 | 날짜 | 기록 |
| --- | --- | --- | --- |
| <질문 원문> | <설명 경로의 마지막 개념> | 2026-09-14 | [질문 기록](records/2026-09-14/01-question-slug.md) |
| <끝나지 않은 질문> | 미도달(남은 단계 3~4) | 2026-09-14 | [질문 기록](records/2026-09-14/02-question-slug.md) |

## 발견한 개념

| 개념 |
| --- |
| <개념> |

## 부분 이해 개념

| 개념 | 남은 설명 |
| --- | --- |
| <개념> | <아직 공개하지 않은 부분> |

## 다음 탐색 후보

| 후보 | 이어지는 질문이나 남은 경로 단계 |
| --- | --- |
| <개념이나 질문> | <어디서 이어지는가> |
```

항목이 없는 절에는 표 대신 `없음`을 적습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 정리할 패키지에 기록 파일이 없음 | `## 다룬 질문`에 `없음`을 적고 나머지 절을 정리 |
