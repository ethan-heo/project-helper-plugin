# 학습 기록 규칙

## 목적

학습 상태와 질의응답을 파일로 남겨, 새 세션에서도 학습을 이어 가고 학습자가 배운 내용을 다시 정리할 근거를 만듭니다.

## 핵심 지시

**학습 상태는 기술 저장소의 `state.md` 하나에, 질의응답은 학습 패키지의 날짜별 기록 파일에 남기고, 설명 경로 하나가 끝날 때마다 커밋합니다.**

새 세션은 이전 대화를 기억하지 못합니다. 이어 하기에 필요한 정보는 모두 파일에서 읽습니다. 상태를 바꿀지는 학습 진행 절차가 판단하고, 이 규칙은 받은 내용을 남기는 방법만 정합니다.

## 절차 흐름

### 1. 최근 기술 저장소 찾기

**기술 이름 없이 이어 하기를 요청받으면, 학습 폴더 아래 git 저장소 중 마지막 커밋 시각이 가장 늦은 저장소를 후보로 보여 주고 확인받습니다.**

저장소마다 `git -C <저장소> log -1 --format=%ct`로 마지막 커밋 시각을 읽어 비교합니다. 후보를 보여 줄 때 그 저장소 `state.md`의 `## 마지막 학습 패키지`를 함께 보여 줍니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 학습자가 후보를 받아들임 | 그 저장소와 마지막 학습 패키지에서 이어 감 |
| 학습자가 다른 기술을 말함 | 그 기술로 새 학습을 시작 |
| 학습 폴더에 저장소가 없음 | 배울 기술이나 자료를 물음 |

### 2. 중단된 세션의 변경 커밋

**학습을 시작할 때 기술 저장소에 커밋되지 않은 기록·상태 변경이 있으면, 다른 작업보다 먼저 커밋합니다.**

`git -C <저장소> status --porcelain`으로 `state.md`와 `packages/*/records/`의 변경을 찾습니다. 설명 경로가 끝나기 전에 세션이 닫혀 남은 변경입니다.

```bash
git -C <저장소> add state.md packages/<주제>/records
git -C <저장소> commit -m "learn(<주제>): 중단된 탐색 기록"
```

`<주제>`는 변경된 기록 파일이 속한 패키지 이름입니다. 여러 패키지에 걸치면 `state.md`의 마지막 학습 패키지를 씁니다.

### 3. 학습 상태 읽기

**학습을 시작하면 `state.md`를 읽어 학습 진행 절차에 넘깁니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| `state.md`가 있음 | 다섯 절을 읽어 이전 학습 상태로 사용 |
| `state.md`가 없음 | 아래 양식으로 빈 상태 파일을 만들고, 모든 절에 `없음`을 적음 |

### 4. 질의응답 기록

**질의응답이 오갈 때마다 `packages/<주제>/records/YYYY-MM-DD.md`에 순서대로 덧붙입니다.**

그날 파일이 없으면 첫 줄이 `# YYYY-MM-DD`인 파일을 만듭니다. 날짜는 학습자 컴퓨터의 오늘 날짜입니다. 새 질문이 나오면 질문 원문을 `##` 제목으로 삼고, 그 아래에 학습자와 설명을 번갈아 적습니다. 학습자의 말은 원문 그대로 적습니다.

### 5. 설명 경로 종료

**설명 경로 하나가 끝나면 `state.md`를 갱신하고, 검증 스크립트를 통과시킨 뒤 `learn` 커밋을 남깁니다.**

| 절 | 갱신 내용 |
| --- | --- |
| `## 마지막 학습 패키지` | 방금 학습한 패키지 |
| `## 발견한 개념` | 이번 경로에서 공개한 개념 추가 |
| `## 부분 이해 개념` | 공개했지만 전체 설명에 이르지 않은 개념 |
| `## 미공개 개념` | `knowledge.md`에 있지만 아직 공개하지 않은 개념 |
| `## 다음 탐색 후보` | 직전 질문과 이어지는 개념과, 끝나지 않은 경로의 남은 단계 |

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add state.md knowledge.md packages/<주제>
git -C <저장소> commit -m "learn(<주제>): <질문 요약> 탐색"
```

검사에 실패하면 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사합니다.

## 커밋 규칙

| 커밋 시점 | 메시지 형식 | 포함 파일 |
| --- | --- | --- |
| 예제를 처음 넣었을 때 | `example(<주제>): <예제 요약> 추가` | 패키지의 예제와 `README.md`, `source.md` |
| 설명 경로 하나가 끝났을 때 | `learn(<주제>): <질문 요약> 탐색` | 기록·상태 파일과 새로 저장한 지식 |
| 다음 `learn` 시작 때 커밋되지 않은 변경이 있을 때 | `learn(<주제>): 중단된 탐색 기록` | 커밋되지 않은 기록·상태 파일 |

괄호 안에는 학습 패키지 이름을 넣어 `git log`로 주제별 이력을 걸러 낼 수 있게 합니다. 설명은 한국어 명사형으로 끝냅니다. `example` 커밋의 절차는 [학습 작업 공간 규칙](workspace.md#7-example-커밋)에 있습니다.

## 양식

### state.md

```markdown
# <기술 표시 이름> 학습 상태

## 마지막 학습 패키지

`<주제>`

## 발견한 개념

| 개념 | 발견한 패키지 |
| --- | --- |
| <개념> | `<주제>` |

## 부분 이해 개념

| 개념 | 남은 설명 |
| --- | --- |
| <개념> | <아직 공개하지 않은 부분> |

## 미공개 개념

| 개념 |
| --- |
| <개념> |

## 다음 탐색 후보

| 후보 | 이어지는 질문이나 남은 경로 단계 |
| --- | --- |
| <개념이나 질문> | <어디서 이어지는가> |
```

항목이 없는 절에는 표 대신 `없음`을 적습니다.

### 기록 파일

```markdown
# 2026-09-14

## 왜 캐시가 비워졌지?

- 관점: 실행
- 설명 경로: `questions.md`의 같은 질문

**학습자** — 왜 캐시가 비워졌지?

**설명(관찰 유도)** — <관찰을 유도한 문장>

**학습자** — 모르겠어

**설명(현상)** — <관찰해야 했던 현상>
```

설명 줄의 괄호에는 그 설명의 공개 단계를 적고, 관찰해야 했던 현상을 알려 준 설명에는 `현상`을 적습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 설명 경로 도중 세션이 끝남 | 다음 `learn` 시작 때 2단계로 커밋되지 않은 변경을 먼저 커밋 |
