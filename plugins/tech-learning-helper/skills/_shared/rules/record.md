# 학습 기록 규칙

## 목적

질의응답을 질문별 파일로 남기고 설명 경로가 끝날 때마다 누적 학습 상태를 확정해, 학습자가 배운 내용을 다시 읽고 정리할 근거를 만듭니다.

## 핵심 지시

**질의응답은 학습 패키지의 날짜 디렉터리 안 질문별 기록 파일에 남기고, 설명 경로 하나가 끝날 때마다 그 패키지의 `state.json`을 갱신해 커밋합니다.**

두 `state.json`(저장소 루트·패키지)의 필드와 새 세션의 재개, 이어 하기 목록은 [학습 재개 규칙](resume.md)이, 상태 값을 그대로 보여 주는 학습 정리는 [학습 정리 규칙](review.md)이 정합니다.

## 절차 흐름

### 1. 질의응답 기록

**질의응답이 오갈 때마다 `packages/<주제>/records/YYYY-MM-DD/NN-question-slug.md`에 기록하고, 세션을 보지 않은 사람이 해당 기록 파일만 읽고 따라갈 수 있게 적습니다.**

새 질문이 나오면 그날 디렉터리가 없을 때 만들고, 그 안에 다음 순번의 `NN-question-slug.md`를 만든 뒤 패키지 `state.json`의 `record`를 그 경로로 바꾸고 `questions`에 `status: 진행`인 항목을 더합니다. 날짜는 학습자 컴퓨터의 오늘 날짜입니다. 파일의 첫 줄은 `# YYYY-MM-DD`로 두고, 질문 원문과 학습자·설명을 기록합니다. 같은 질문의 설명 경로와 실험은 하나의 파일에 둡니다. 기존 `records/YYYY-MM-DD.md`는 읽기 호환 대상으로만 처리합니다.

| 규칙 | 판정 |
| --- | --- |
| 설명 전문 | 학습자에게 보여 준 설명을 줄이거나 고쳐 쓰지 않았습니다 |
| 표·코드 보존 | 설명 속 표·코드 블록·목록이 기록에도 그대로 있습니다 |
| 가리키는 대상 | `이 표`, `위 로그`가 가리키는 대상이 기록 안에 있습니다 |
| 실행 결과 | 설명이 기댄 실행 결과는 필요한 줄을 코드 블록으로 옮겼습니다 |
| 학습자 원문 | 학습자의 말은 입력한 문장 그대로입니다 |
| 인용문 | 학습자의 말은 줄마다 `> `를 붙인 인용문입니다 |
| 발화 이름 | `**학습자**`, `**설명(<괄호>)**`가 한 줄을 따로 차지합니다 |
| 설명의 괄호 | 공개 단계를 적고, 관찰해야 했던 현상을 알려 준 설명은 `현상`, 실험을 안내한 설명은 `실험`을 적습니다 |
| 예제 파일 링크 | 패키지 파일은 기록 파일 기준 상대 링크로 겁니다 |

학습자는 세션이 끝난 뒤 기록 파일을 마크다운 문서로 다시 읽습니다. 그때는 세션 화면이 없으므로, 세션에서만 보여 준 표나 코드를 설명이 가리키면 그 대상을 찾을 수 없습니다. 발화 이름 뒤에 본문을 이어 쓰면 설명에 표와 코드 블록을 넣을 수 없고, 학습자가 번호 목록으로 답해도 둘째 줄부터는 앞 줄에 붙어 한 문단으로 보입니다. 그래서 발화 이름과 본문을 빈 줄로 나누고, 학습자의 말은 인용문으로 감쌉니다.

실험의 질의응답은 대상 질문 파일에 `## 실험: <대상 질문>` 절로 덧붙입니다. 대상 질문은 실험으로 확인하려는 설명 경로의 질문 원문입니다.

학습자가 설명 경로 도중 다른 질문을 하면, 그 질문은 다음 순번의 새 기록 파일에만 적습니다. 이전 파일에는 학습자 줄 없이 현재 단계의 현상 설명을 이어 적습니다. 새 질문 바로 뒤에 현상 설명이 오면, 그 설명이 새 질문의 답으로 읽히기 때문입니다.

### 2. 설명 경로 종료

**설명 경로 하나가 끝나면 패키지 `state.json`을 갱신하고 저장소 `state.json`을 `idle`로 바꾼 뒤, 검증 스크립트를 통과시키고 `learn` 커밋을 남깁니다.**

| 필드(패키지 `state.json`) | 갱신 내용 |
| --- | --- |
| `questions`의 해당 항목 | `status`를 `완료`로 바꿈 |
| `discoveredConcepts` | 이번 경로에서 공개한 개념 추가 |
| `partialConcepts` | 공개했지만 전체 설명에 이르지 않은 개념 |
| `nextCandidates` | 직전 질문과 이어지는 개념과, 끝나지 않은 경로의 남은 단계 |

패키지 `state.json`의 `discoveredConcepts`에 새로 더한 이름은 저장소 `state.json`의 `discoveredConcepts`에도 더합니다. 저장소 `state.json`은 `lastPackage`를 방금 학습한 패키지로 두고, `activePackage`를 `null`로, `sessionStatus`를 `idle`로 바꿉니다.

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add state.json packages/<주제>/state.json packages/<주제>
git -C <저장소> commit -m "learn(<주제>): <질문 요약> 탐색"
```

검사에 실패하면 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사합니다.

## 커밋 규칙

| 커밋 시점 | 메시지 형식 | 포함 파일 |
| --- | --- | --- |
| 예제를 처음 넣었을 때 | `example(<주제>): <예제 요약> 추가` | 패키지의 예제와 `README.md`, `source.md` |
| 설명 경로 하나가 끝났을 때 | `learn(<주제>): <질문 요약> 탐색` | 기록 파일, 저장소 `state.json`, 패키지 `state.json`, 새로 저장한 지식 |
| 코드 변경형 실험이 끝났을 때 | `learn(<주제>): <질문 요약> 실험` | 바뀐 예제 코드, 기록 파일, 저장소 `state.json`, 패키지 `state.json` |
| 학습 정리를 마쳤을 때 | 해당 없음(새 파일을 만들지 않음) | 해당 없음 |
| 다음 학습 시작 때 커밋되지 않은 변경이 있을 때 | `learn(<주제>): 중단된 탐색 기록` | 커밋되지 않은 기록·상태 파일 |

괄호 안에는 학습 패키지 이름을 넣어 `git log`로 주제별 이력을 걸러 낼 수 있게 합니다. 설명은 한국어 명사형으로 끝냅니다. `learn` 커밋에 저장소 `state.json`을 함께 담아야 다음 세션이 남은 상태 변경을 중단된 탐색으로 오인하지 않습니다. 각 커밋의 절차는 아래 문서에 있습니다.

| 커밋 | 절차 |
| --- | --- |
| `example` | [학습 작업 공간 규칙](workspace.md#7-example-커밋) |
| `learn` 탐색 | 이 문서의 2절 |
| `learn` 실험 | [Experiment Designer](../roles/experiment-designer.md#실험-커밋) |
| 중단된 탐색 기록 | [학습 재개 규칙](resume.md#4-중단된-변경-커밋) |

## 양식

패키지 `state.json`의 필드와 값 구성은 [학습 재개 규칙의 양식](resume.md#패키지-statejson)을 따릅니다. `questions`·`discoveredConcepts`·`partialConcepts`·`nextCandidates`에 항목이 없으면 빈 배열로 둡니다.

### 기록 파일

```markdown
# 2026-09-14

## 왜 캐시가 비워졌지?

- 관점: 실행
- 설명 경로: [`questions.md`](../../questions.md)의 같은 질문

**학습자**

> 왜 캐시가 비워졌지?

**설명(관찰 유도)**

<학습자에게 보여 준 설명 전문. 표와 코드 블록도 그대로 둠>

**학습자**

> 모르겠어

**설명(현상)**

<관찰해야 했던 현상>

**설명(관찰 유도)**

<다음 단계의 설명 전문>

**설명(현상)**

<학습자가 다른 질문으로 넘어가 알려 준 현상. 다른 질문은 다음 순번 파일에 적음>
```

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 설명 경로 도중 세션이 끝남 | 다음 학습 시작 때 [학습 재개 규칙](resume.md#4-중단된-변경-커밋)으로 커밋되지 않은 변경을 먼저 커밋 |
| 검증 스크립트가 실패함 | 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사 |
