# 학습 기록 규칙

## 목적

학습 상태와 질의응답을 파일로 남겨, 새 세션에서도 학습을 이어 가고 학습자가 배운 내용을 다시 정리할 근거를 만듭니다.

## 핵심 지시

**누적 학습 상태는 기술 저장소의 `state.md`에, 중간 세션 재개 상태는 `state.json`에, 질의응답은 학습 패키지의 날짜별 기록 파일에 남기고, 설명 경로 하나가 끝날 때마다 커밋합니다.**

새 세션은 이전 대화를 기억하지 못합니다. 재개에 필요한 정보는 `state.json`에서, 누적 학습 정보는 `state.md`에서 읽습니다. 기록 전문은 질의응답 보존과 정리 근거로만 사용하며, 현재 질문을 추정하는 기준으로 사용하지 않습니다.

## 절차 흐름

### 1. 이어 하기 목록

**새 세션에서 이어 할 학습을 고르게 할 때, 아래 두 목록 중 요청에 맞는 것을 번호 목록으로 보여 줍니다.**

| 목록 | 보여 주는 때 | 한 줄의 내용 | 정렬 |
| --- | --- | --- | --- |
| 기술 저장소 목록 | 기술 이름 없이 `learn`을 호출함 | 저장소 이름, 마지막 학습 패키지, 마지막 커밋 날짜 | 마지막 커밋 시각이 늦은 순 |
| 학습 패키지 목록 | 기술 이름만 주었는데 그 저장소가 있음 | 패키지 이름, 학습 목표, 마지막 학습 날짜 | 마지막 학습 패키지를 맨 위에 두고 나머지는 마지막 학습 날짜가 늦은 순 |

값은 아래에서 읽습니다.

| 값 | 읽는 곳 |
| --- | --- |
| 마지막 커밋 시각과 날짜 | 저장소마다 `git -C <저장소> log -1 --format=%ct` |
| 마지막 학습 패키지 | 그 저장소 `state.md`의 `## 마지막 학습 패키지` |
| 학습 목표 | 저장소 `README.md`의 `## 학습 패키지` 표 |
| 패키지의 마지막 학습 날짜 | 패키지 `records/`에서 가장 늦은 파일 이름 |

마지막 학습 패키지 줄에는 `(마지막 학습)`을 붙입니다. 목록이 5개를 넘으면 5개씩 끊어 보여 주고, 첫 줄에 `(1~5 / 전체 N개)`처럼 보이는 범위를 적습니다. 5개 이하면 끊지 않습니다.

```
이어서 학습할 저장소를 번호로 골라 주세요. (1~5 / 전체 8개)

1. react          — state-basics      · 2026-09-14
2. tanstack-query — query-cache       · 2026-09-12
3. python         — merge-sort        · 2026-09-10
4. typescript     — invoice-discount  · 2026-09-08
5. node           — event-loop        · 2026-09-05

"다음"을 입력하면 6~8번을 보여 줍니다.
새 기술을 배우려면 기술 이름을 입력하세요.
```

```
tanstack-query 저장소에 학습 패키지가 3개 있습니다.
이어서 학습할 패키지를 번호로 골라 주세요. (1~3 / 전체 3개)

1. query-cache (마지막 학습) — 같은 queryKey의 캐시 공유 · 2026-09-14
2. mutation-refresh          — 추가 뒤 목록 갱신         · 2026-09-11
3. loading-states            — 로딩·에러 상태 변화       · 2026-09-09

새 주제를 시작하려면 "새 주제"를 입력하세요.
```

| 학습자 입력 | 할 일 |
| --- | --- |
| 번호 | 저장소 목록이면 그 저장소의 마지막 학습 패키지에서, 패키지 목록이면 그 패키지에서 이어 감 |
| "다음", "이전" | 다음이나 이전 5개를 같은 모양으로 보여 줌 |
| 기술 이름 (저장소 목록에서) | 그 기술로 학습을 시작 |
| "새 주제" (패키지 목록에서) | [Example Builder](../roles/example-builder.md)로 예제 후보 2~3개를 제시 |
| 학습 폴더에 저장소가 없음 | 배울 기술이나 자료를 물음 |

### 2. 세션 상태 파일

**기술 저장소 루트의 `state.json`에 현재 세션의 재개 정보를 저장합니다.**

```json
{
  "sessionStatus": "in_progress",
  "inputMode": "learning",
  "package": "<주제>",
  "record": "packages/<주제>/records/YYYY-MM-DD.md",
  "activeQuestion": "<현재 질문>",
  "viewpoint": "<구조|실행>",
  "path": "<설명 경로>",
  "stage": "<관찰 유도|힌트|부분 설명|전체 설명>",
  "awaiting": "<다음에 기대하는 학습자 입력>",
  "nextCandidates": ["<다음 탐색 후보>"],
  "lastTurn": { "speaker": "<학습자|assistant>", "type": "<발화 유형>" }
}
```

`sessionStatus`는 `idle`, `awaiting_selection`, `in_progress`, `recovery_required` 중 하나입니다. `inputMode`는 `selection` 또는 `learning`이며, 목록을 보여 준 직후에만 `selection`으로 설정합니다. 번호 입력은 `selection`일 때만 목록 선택으로 처리하고, `learning`일 때는 현재 공개 단계의 학습 답변으로 처리합니다.

학습자 입력 전후에 현재 질문, 공개 단계, 다음 기대 입력, 마지막 발화 유형을 갱신합니다. 설명 경로가 끝나면 `state.md`를 갱신하고 `state.json`을 `idle`로 바꿉니다.

### 3. 중단된 세션의 변경 커밋

**학습을 시작할 때 기술 저장소에 커밋되지 않은 기록·상태 변경이 있으면, 다른 작업보다 먼저 커밋합니다.**

`git -C <저장소> status --porcelain`으로 `state.json`, `state.md`, `packages/*/records/`의 변경을 찾습니다. 설명 경로가 끝나기 전에 세션이 닫혀 남은 변경입니다.

```bash
git -C <저장소> add state.json state.md packages/<주제>/records
git -C <저장소> commit -m "learn(<주제>): 중단된 탐색 기록"
```

`<주제>`는 변경된 기록 파일이 속한 패키지 이름입니다. 여러 패키지에 걸치면 `state.md`의 마지막 학습 패키지를 씁니다.

### 4. 학습 상태 읽기

**학습을 시작하면 `state.json`을 먼저 읽어 재개 여부를 판단하고, `state.md`를 누적 학습 상태로 넘깁니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| `state.json`이 있음 | JSON 형식을 검사하고 현재 세션 상태로 사용 |
| `state.json`이 없음 | 복원 가능한 기록인지 확인하고, 모호하면 `recovery_required`로 둠 |
| `state.md`가 있음 | 다섯 절을 읽어 누적 학습 상태로 사용 |
| `state.md`가 없음 | 아래 양식으로 빈 상태 파일을 만들고, 모든 절에 `없음`을 적음 |

### 5. 질의응답 기록

**질의응답이 오갈 때마다 `packages/<주제>/records/YYYY-MM-DD.md`에 순서대로 덧붙이되, 세션을 보지 않은 사람이 기록 파일만 읽고 따라갈 수 있게 적습니다.**

그날 파일이 없으면 첫 줄이 `# YYYY-MM-DD`인 파일을 만듭니다. 날짜는 학습자 컴퓨터의 오늘 날짜입니다. 새 질문이 나오면 질문 원문을 `##` 제목으로 삼고, 그 아래에 학습자와 설명을 번갈아 적습니다.

학습자는 세션이 끝난 뒤 기록 파일을 마크다운 문서로 다시 읽습니다. 그때는 세션 화면이 없으므로, 세션에서만 보여 준 표나 코드를 설명이 가리키면 그 대상을 찾을 수 없습니다.

| 규칙 | 판정 |
| --- | --- |
| 설명 전문 | 학습자에게 보여 준 설명을 줄이거나 고쳐 쓰지 않았습니다 |
| 표·코드 보존 | 설명 속 표·코드 블록·목록이 기록에도 그대로 있습니다 |
| 가리키는 대상 | `이 표`, `위 로그`가 가리키는 대상이 기록 안에 있습니다 |
| 실행 결과 | 설명이 기댄 실행 결과는 필요한 줄을 코드 블록으로 옮겼습니다 |
| 학습자 원문 | 학습자의 말은 입력한 문장 그대로입니다 |
| 인용문 | 학습자의 말은 줄마다 `> `를 붙인 인용문입니다 |
| 발화 이름 | `**학습자**`, `**설명(<공개 단계>)**`가 한 줄을 따로 차지합니다 |
| 예제 파일 링크 | 패키지 파일은 기록 파일 기준 상대 링크로 겁니다 |

발화 이름 뒤에 본문을 이어 쓰면 설명에 표와 코드 블록을 넣을 수 없습니다. 학습자가 번호 목록으로 답해도 둘째 줄부터는 앞 줄에 붙어 한 문단으로 보입니다. 그래서 발화 이름과 본문을 빈 줄로 나누고, 학습자의 말은 인용문으로 감쌉니다.

실험의 질의응답은 그날 기록 파일에 `## 실험: <대상 질문>` 절로 덧붙이고, 실험을 안내한 설명의 발화 이름은 `**설명(실험)**`으로 적습니다. 대상 질문은 실험으로 확인하려는 설명 경로의 질문 원문입니다.

학습자가 설명 경로 도중 다른 질문을 하면, 그 질문은 새 `##` 절에만 적습니다. 이전 절에는 학습자 줄 없이 현재 단계의 현상 설명을 이어 적습니다. 새 질문 바로 뒤에 현상 설명이 오면, 그 설명이 새 질문의 답으로 읽히기 때문입니다.

### 6. 설명 경로 종료

**설명 경로 하나가 끝나면 `state.md`를 갱신하고, 검증 스크립트를 통과시킨 뒤 `learn` 커밋을 남깁니다.**

| 절 | 갱신 내용 |
| --- | --- |
| `## 마지막 학습 패키지` | 방금 학습한 패키지 |
| `## 발견한 개념` | 이번 경로에서 공개한 개념 추가 |
| `## 부분 이해 개념` | 공개했지만 전체 설명에 이르지 않은 개념 |
| `## 미공개 개념` | `knowledge.md`에 있지만 아직 공개하지 않은 개념 |
| `## 다음 탐색 후보` | 직전 질문과 이어지는 개념과, 끝나지 않은 경로의 남은 단계 |

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add state.md knowledge.md packages/<주제>
git -C <저장소> commit -m "learn(<주제>): <질문 요약> 탐색"
```

검사에 실패하면 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사합니다.

### 7. 학습 정리

**정리를 요청받으면 학습 패키지 하나의 `summary.md`를 저장된 파일의 값으로 덮어쓰고, 검증 스크립트를 통과시킨 뒤 `review` 커밋을 남깁니다.**

정리 대상은 진행 중인 학습이 있으면 지금 학습하는 패키지이고, 없으면 1단계의 이어 하기 목록에서 학습자가 고른 패키지입니다. 파일은 `packages/<주제>/summary.md`이며, 정리할 때마다 새로 씁니다.

| 절 | 옮기는 값 | 읽는 곳 |
| --- | --- | --- |
| `## 학습 목표` | 패키지의 학습 목표 | 패키지 `README.md`의 `## 학습 목표` |
| `## 다룬 질문` | 질문, 도달한 개념, 날짜, 기록 파일 링크 | `records/`의 질문 절, `questions.md` |
| `## 발견한 개념` | 이 패키지에서 발견한 개념과 그 뜻 | `state.md`의 `## 발견한 개념`, `knowledge.md` |
| `## 부분 이해 개념` | 개념과 남은 설명 | `state.md`의 `## 부분 이해 개념` |
| `## 다음 탐색 후보` | 후보와 이어지는 질문이나 남은 단계 | `state.md`의 `## 다음 탐색 후보` |

| 값 | 옮기는 방법 |
| --- | --- |
| 다룬 질문 | 기록 파일의 `##` 질문 절을 날짜 순으로 옮기고, `## 실험:` 절은 넣지 않음 |
| 도달한 개념 | `questions.md`에서 같은 질문의 설명 경로를 찾아, 마지막 단계에 적힌 개념 |
| 끝나지 않은 경로의 도달한 개념 | `state.md`의 `## 다음 탐색 후보`에 남은 단계가 적힌 질문은 `미도달(남은 단계 3~4)`처럼 남은 단계를 적음 |
| 발견한 개념 | `state.md`에서 발견한 패키지가 이 패키지인 행만 골라 `knowledge.md`의 뜻을 붙임 |
| 부분 이해 개념, 다음 탐색 후보 | 패키지 열이 없으므로 `state.md`의 표를 그대로 옮김 |

모든 값은 위 파일에서 옮기고, 새로 풀어 쓴 설명이나 요약 문장은 넣지 않습니다. 배운 내용을 자기 말로 정리하는 일은 학습자의 몫이기 때문입니다. 항목이 없는 절에는 `없음`을 적습니다. 다 쓰면 `summary.md`의 내용을 학습자에게 그대로 보여 줍니다.

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <저장소>
git -C <저장소> add state.md packages/<주제>/summary.md
git -C <저장소> commit -m "review(<주제>): 학습 정리 갱신"
```

## 커밋 규칙

| 커밋 시점 | 메시지 형식 | 포함 파일 |
| --- | --- | --- |
| 예제를 처음 넣었을 때 | `example(<주제>): <예제 요약> 추가` | 패키지의 예제와 `README.md`, `source.md` |
| 설명 경로 하나가 끝났을 때 | `learn(<주제>): <질문 요약> 탐색` | 기록·상태 파일과 새로 저장한 지식 |
| 코드 변경형 실험이 끝났을 때 | `learn(<주제>): <질문 요약> 실험` | 바뀐 예제 코드, 기록 파일, `state.md` |
| 학습 정리를 마쳤을 때 | `review(<주제>): 학습 정리 갱신` | `summary.md`, `state.md` |
| 다음 `learn` 시작 때 커밋되지 않은 변경이 있을 때 | `learn(<주제>): 중단된 탐색 기록` | 커밋되지 않은 기록·상태 파일 |

괄호 안에는 학습 패키지 이름을 넣어 `git log`로 주제별 이력을 걸러 낼 수 있게 합니다. 설명은 한국어 명사형으로 끝냅니다. `example` 커밋의 절차는 [학습 작업 공간 규칙](workspace.md#7-example-커밋)에 있습니다.

## 양식

### state.md

```markdown
# <기술 표시 이름> 학습 상태

## 마지막 학습 패키지

`<주제>`

## 발견한 개념

| 개념 | 발견한 패키지 |
| --- | --- |
| <개념> | `<주제>` |

## 부분 이해 개념

| 개념 | 남은 설명 |
| --- | --- |
| <개념> | <아직 공개하지 않은 부분> |

## 미공개 개념

| 개념 |
| --- |
| <개념> |

## 다음 탐색 후보

| 후보 | 이어지는 질문이나 남은 경로 단계 |
| --- | --- |
| <개념이나 질문> | <어디서 이어지는가> |
```

항목이 없는 절에는 표 대신 `없음`을 적습니다.

### 기록 파일

### summary.md

```markdown
# <주제 표시 이름> 학습 정리

## 학습 목표

<패키지 README.md의 학습 목표>

## 다룬 질문

| 질문 | 도달한 개념 | 날짜 | 기록 |
| --- | --- | --- | --- |
| <질문 원문> | <설명 경로의 마지막 개념> | 2026-09-14 | [2026-09-14](records/2026-09-14.md) |
| <끝나지 않은 질문> | 미도달(남은 단계 3~4) | 2026-09-14 | [2026-09-14](records/2026-09-14.md) |

## 발견한 개념

| 개념 | 뜻 |
| --- | --- |
| <개념> | <knowledge.md의 뜻> |

## 부분 이해 개념

| 개념 | 남은 설명 |
| --- | --- |
| <개념> | <아직 공개하지 않은 부분> |

## 다음 탐색 후보

| 후보 | 이어지는 질문이나 남은 경로 단계 |
| --- | --- |
| <개념이나 질문> | <어디서 이어지는가> |
```

항목이 없는 절에는 표 대신 `없음`을 적습니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 설명 경로 도중 세션이 끝남 | 다음 `learn` 시작 때 2단계로 커밋되지 않은 변경을 먼저 커밋 |
| 정리할 패키지에 기록 파일이 없음 | `## 다룬 질문`에 `없음`을 적고 나머지 절을 정리 |
| 새로 쓴 `summary.md`가 이전과 같음 | 커밋하지 않고 정리 내용만 보여 줌 |
