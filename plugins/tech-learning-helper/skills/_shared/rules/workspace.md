# 학습 작업 공간 규칙

## 목적

학습 폴더와 기술 저장소, 학습 패키지를 만들고, 예제를 바로 실행할 수 있는 상태로 준비합니다.

## 핵심 지시

**학습자가 작업 중인 프로젝트에는 파일을 만들지 않고, 모든 예제를 학습 폴더 아래 기술 저장소에 둡니다.**

기술 저장소는 기술 하나에 git 저장소 하나이고, 그 안을 학습 주제별 패키지로 나눕니다. 패키지는 의존성을 공유할 수 있지만 각자 따로 실행되어야 합니다.

## 절차 흐름

### 1. 실행 환경 확인

**학습을 시작하기 전에 `git --version`으로 git이 있는지 확인합니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| git이 있음 | 2단계로 진행 |
| git이 없음 | 학습을 시작하지 않고 git 설치 방법 안내 |

기술 저장소가 git 저장소라는 전제와, 실험 전후 비교·학습 과정 이력이 모두 git에 기대므로 git 없이는 시작하지 않습니다.

### 2. 설정 파일

**`~/.config/tech-learning-helper/config.json`에서 `learningDir`을 읽어 학습 폴더로 씁니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| 파일이 있고 `learningDir`의 폴더가 있음 | 그 폴더를 학습 폴더로 사용 |
| 파일이 없음 | 학습 폴더 위치를 물은 뒤 설정 파일을 만들어 저장 |
| `learningDir`의 폴더가 없음 | 새로 만들지 확인하고, 동의하면 생성. 거절하면 위치를 다시 물음 |

학습자가 준 경로는 절대 경로로 바꿔 저장합니다. Claude Code와 Codex가 같은 파일을 읽으므로, 어느 도구에서 배우든 같은 학습 폴더를 씁니다.

### 3. 기술 판정 확인

**가져온 자료가 있으면, 구간의 동작을 결정하는 기술 중 가장 좁은 기술을 저장소로 제안하고 학습자에게 확인받습니다.**

예를 들어 React 파일 안에서 TanStack Query의 `useQuery`를 쓰는 구간은 `tanstack-query`로, 라이브러리 없이 Python으로만 짠 정렬 코드는 `python`으로 제안합니다.

| 선행 상태 | 할 일 |
| --- | --- |
| 비슷한 이름의 저장소가 이미 있음 | 새로 만들지 않고 그 저장소를 제안 |
| 학습자가 제안을 받아들임 | 제안한 저장소 사용 |
| 학습자가 제안을 거절함 | 학습자가 말한 기술의 저장소 사용 |

비슷한 이름은 두 이름을 소문자로 바꾸고 영문자와 숫자만 남겼을 때 같거나, 한쪽이 다른 쪽을 포함하는 경우입니다. 기술 이름만으로 시작한 요청도 비슷한 이름의 저장소가 있으면 그 저장소를 씁니다.

### 4. 기술 저장소 생성

**학습 폴더에 `<기술>/` 저장소가 없으면 만들고 `git init`으로 초기화합니다.**

`<기술>`은 영문 kebab-case로 짓습니다. 저장소 루트에는 아래 양식의 `README.md`를 둡니다. `knowledge.md`는 [Example Builder](../roles/example-builder.md)가, `state.md`는 [학습 기록 규칙](record.md)이 만듭니다.

| 기술의 생태계 | 루트에 더 둘 파일 |
| --- | --- |
| 웹·JavaScript 생태계 | `package.json`(`"private": true`), `pnpm-workspace.yaml`(`packages: ["packages/*"]`) |
| 그 밖의 언어 | 없음 |

### 5. 학습 패키지 생성

**학습 주제마다 `packages/<주제>/`를 만들고, 같은 이름의 패키지가 있으면 새로 만들지 않고 그 패키지에서 이어 갑니다.**

`<주제>`는 영문 kebab-case로 짓습니다. 패키지에는 아래 양식의 `README.md`와 예제를 담을 `src/`를 둡니다. `questions.md`와 `source.md`는 Example Builder가, `records/`는 학습 기록 규칙이 만듭니다. 새 패키지를 만들면 저장소 `README.md`의 `## 학습 패키지` 표에 한 행을 더합니다.

| 기술의 생태계 | 패키지의 실행 준비 |
| --- | --- |
| 웹·JavaScript 생태계 | 패키지 `package.json`에 `start` 스크립트를 둠. 화면 없는 예제는 `tsx src/index.ts`, 화면 있는 예제는 `vite` |
| 그 밖의 언어 | 그 언어의 기본 실행 명령을 `README.md`의 `## 실행 방법`에 적음. 외부 라이브러리가 필요하면 패키지 안에 가상 환경을 만듦 |

웹·JavaScript 생태계의 예제는 저장소 루트에서 `pnpm install` 뒤 `pnpm --filter <주제> start`로 실행합니다.

### 6. 예제 실행 환경 확인

**예제를 넣은 뒤, 실행에 필요한 도구가 학습자 컴퓨터에 있는지 확인합니다.**

| 선행 상태 | 할 일 |
| --- | --- |
| 필요한 도구가 모두 있음 | 의존성을 설치하고 예제를 한 번 실행해 결과 확인 |
| pnpm이 없음 | 설치 명령(`npm install -g pnpm`)을 안내하고, 설치될 때까지 실행 단계로 넘어가지 않음 |
| 예제 언어의 실행 환경이 없음 | 설치 방법을 안내하고, 설치될 때까지 실행 단계로 넘어가지 않음 |

### 7. example 커밋

**예제를 처음 넣었으면 검증 스크립트를 통과시킨 뒤 `example` 커밋을 남깁니다.**

[검증 스크립트](../scripts/validate-learning-repo.sh)는 이 플러그인의 `skills/_shared/scripts/`에 있습니다.

```bash
bash <플러그인 경로>/skills/_shared/scripts/validate-learning-repo.sh <학습 폴더>/<기술>
git -C <학습 폴더>/<기술> add packages/<주제> README.md
git -C <학습 폴더>/<기술> commit -m "example(<주제>): <예제 요약> 추가"
```

이 커밋은 실험 전후를 비교하는 기준이 됩니다. 검사에 실패하면 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사합니다. 커밋 규칙 전체는 [학습 기록 규칙](record.md#커밋-규칙)에 있습니다.

## 양식

### config.json

```json
{
  "learningDir": "/Users/<사용자>/learning"
}
```

### 기술 저장소 README.md

```markdown
# <기술 표시 이름>

## 학습 패키지

| 패키지 | 학습 목표 |
| --- | --- |
| `<주제>` | <이 패키지로 이해하려는 동작이나 개념> |
```

### 학습 패키지 README.md

```markdown
# <주제 표시 이름>

## 학습 목표

<예제 하나로 이해하려는 개념, 동작, 코드 구간>

## 실행 방법

<저장소 루트에서 실행하는 명령과, 실행하면 무엇이 보이는지>
```

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| 학습자가 정한 학습 폴더가 존재하지 않음 | 새로 만들지 확인한 뒤 생성 |
| git이 설치되어 있지 않음 | 학습을 시작하지 않고 git 설치 안내 |
| pnpm이나 예제 언어의 실행 환경이 없음 | 설치 명령을 안내하고, 설치 전에는 실행 단계로 넘어가지 않음 |
| 학습자가 기술 판정 결과를 거절함 | 학습자가 말한 기술의 저장소 사용 |
| 같은 이름의 학습 패키지가 이미 있음 | 새로 만들지 않고 그 패키지에서 이어 감 |
