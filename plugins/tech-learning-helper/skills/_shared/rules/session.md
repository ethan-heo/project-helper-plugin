# 학습 진행 규칙

## 목적

사용자 스킬이 함께 따르는 학습의 시작과 진행 절차를 정합니다. 학습 폴더를 확인하고 예제를 준비하는 시작 절차, 학습자의 질문을 역할 문서로 보내는 배정, 설명 경로의 마무리가 여기에 있습니다.

## 핵심 지시

**학습자가 먼저 요청하지 않으면 정답을 먼저 알려 주지 않고, 한 번에 설명 경로 하나만 진행합니다. 새 세션은 저장소 상태로 곧바로 재개하지 않고, 항상 이어 하기 목록부터 보여 줍니다.**

첫 설명은 이 문서가 정하지 않습니다. 시작 절차를 마친 뒤 학습자에게 처음 보여 줄 설명은 호출한 스킬의 `SKILL.md`가 정합니다. 첫 설명 뒤에는 이 세션이 끝날 때까지 학습자의 자연어 질문을 아래 배정 표로 이어 받습니다. 학습 폴더에 남기는 기록과 설명의 문체는 [`writing-style.md`](../writing-style.md)를 따릅니다.

## 절차 흐름

### 시작 절차

1. **학습 폴더를 확인한다** — 설정 파일이 없거나 가리키는 폴더가 없으면 위치를 묻고 설정 파일에 저장합니다(`workspace.md`).
2. **이어 하기 목록을 확인한다** — 입력이 없으면 저장소 목록을, 기술 이름만 있고 그 저장소가 있으면 그 저장소의 패키지 목록을 항상 보여 줍니다(`resume.md`의 1·3절). 학습자가 패키지를 고르면 그 패키지의 상태로 재개합니다(`resume.md`의 4절).
3. **입력과 학습 목표를 정한다** — 이어 하기 목록을 보여줄 상황이 아니면, 입력이 기술 이름·코드·링크·파일 경로 중 무엇인지 판별합니다.
4. **기술 저장소를 정한다** — 가져온 자료가 있으면 저장소가 될 기술을 판정해 확인받습니다(`workspace.md`).
5. **저장소와 패키지를 확보한다** — 기술 저장소와 학습 패키지를 확보하고, 커밋되지 않은 기록·상태 변경이 있으면 먼저 커밋합니다(`workspace.md`, `resume.md`).
6. **이전 상태를 읽는다** — 패키지 `state.json`의 누적 학습 상태를 읽습니다(`resume.md`).
7. **예제와 지식을 준비한다** — 새 학습을 시작할 때 예제·탐색 질문·설명 경로를 만들거나 불러옵니다(`example-builder.md`). 저장소 `state.json`의 `discoveredConcepts`에 이미 있는 개념은 새로 설명하지 않습니다. 예제를 처음 넣었으면 검증 스크립트를 통과한 뒤 `example` 커밋을 남깁니다.

7단계를 마치면 호출한 스킬의 `SKILL.md`에 적힌 첫 설명으로 학습을 시작합니다. 재개 상태에서는 복원한 단계의 설명을 이어 가며, 이후 학습자의 질문은 아래 배정 표에 따라 역할 문서로 보냅니다.

### 번호 입력 해석

번호 입력을 목록 선택으로 볼지 학습 답변으로 볼지는 [학습 재개 규칙의 번호 입력 해석](resume.md#번호-입력-해석)을 따릅니다. 저장소 `state.json`이 손상됐을 때의 처리는 [이어 하기 목록 표시](resume.md#1-이어-하기-목록-표시)를 따릅니다.

### 학습 목표의 판정

**요청에 예제 하나로 보여 줄 수 있는 대상(개념, 동작, 코드 구간)이 하나 이상 있으면 곧바로 시작하고, 없으면 목표를 한 번만 확인합니다.**

| 요청 | 판정 | 할 일 |
| --- | --- | --- |
| 기술 이름만 있고 그 저장소가 있음 | 이어 하기 | 학습 패키지 목록을 먼저 보여 주고, "새 주제"를 고르면 예제 후보 2~3개를 제시(`resume.md`) |
| 기술 이름만 있음 | 모호 | 예제로 만들 수 있는 후보 2~3개를 번호로 제시하고, 고르면 곧바로 시작 |
| 기술과 개념 | 명확 | 개념의 대표 예제로 시작 |
| 기술과 동작 | 명확 | 곧바로 시작 |
| 파일 경로나 코드와 구간 | 명확 | 곧바로 시작 |
| 구간 없는 링크 | 모호 | 궁금한 구간이나 문단을 묻고, 답하면 곧바로 시작 |

### 질문 유형별 배정

**학습자의 자연어 질문을 아래 표로 분류해 해당 역할 문서로 보냅니다.**

| 질문 유형 | 질문 예 | 거치는 역할 문서 |
| --- | --- | --- |
| 개념의 이유나 동작 | 왜 이 상태 변수를 쓰는 거야? | Question Gate → Knowledge Navigator → 관점에 맞는 Explainer |
| 구조 | 이 컴포넌트는 왜 따로 분리했어? | Question Gate → Knowledge Navigator → Structure Explainer |
| 실행 순서 | 버튼을 누른 다음 어떤 순서로 실행돼? | Question Gate → Knowledge Navigator → Logic Explainer |
| 직접 확인 | 직접 확인해 보고 싶어 | Experiment Designer |
| 정리 | 지금까지 이해한 내용을 정리해 줘 | [학습 정리 규칙](review.md) |

두 관점에 걸친 질문은 질문에서 먼저 나온 관점으로 시작하고, 나머지 관점은 다음 탐색 후보로 남깁니다(`knowledge-navigator.md`).

### 경로 마무리

**설명 경로가 끝나면 확인 방법과 다음 탐색 후보를 제시하고, 검증 스크립트를 통과한 뒤 `learn` 커밋을 남깁니다(`experiment-designer.md`, `knowledge-navigator.md`, `record.md`).**

학습자가 다음 탐색 후보를 고르면 위 배정 표로 이어 갑니다.

## 예외 처리

| 예외 조건 | 할 일 |
| --- | --- |
| git이 설치되어 있지 않음 | 학습을 시작하지 않고 git 설치 안내(`workspace.md`) |
| 예제의 실행 환경이 없음 | 설치 명령을 안내하고, 설치 전에는 실행 단계로 넘어가지 않음(`workspace.md`) |
| 링크를 읽지 못함 | 같은 동작의 예제를 새로 만들고 원본 접근 실패를 기록(`example-builder.md`) |
| 검증 스크립트가 실패함 | 커밋하지 않고 어긋난 파일을 고친 뒤 다시 검사 |

## 경계

- 학습자가 작업 중인 프로젝트에는 파일을 만들거나 고치지 않습니다. 예제와 기록은 학습 폴더에만 남깁니다.
- 블로그 글을 대신 쓰거나, 퀴즈로 채점하거나, 기술 글을 번역하지 않습니다.
